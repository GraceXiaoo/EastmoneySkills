## 4. 图表产出规范（**双形态：Markdown 用围栏，Office 用 PNG**）

**每张图在两个通道各出现一次，同源不重复维护：**

1. **Markdown 交付件（含在线协同文档）用图表围栏**：` ```echarts ` / ` ```mermaid `（结构图、层级图用 mermaid；数据图用 echarts）。编辑器前端可直接渲染，因此**交付后的 MD 不存在「图片解析不到、显示占位框」的问题**。
2. **Word / PDF / HTML 用同一张图在本地渲染好的 PNG**：写入输出目录 `assets/`，由 `save_report.py` 自动替换。
3. 两个通道用**定位注释**绑定，写法固定：

````markdown
<!--img:assets/trend_close.png-->
```echarts
{"xAxis":{"type":"category","data":["2024Q1","2024Q2"]},"yAxis":{"type":"value"},"series":[{"type":"line","data":[1,2]}]}
```
````

- `save_report.py` 生成 docx/pdf/html 时，会把「`<!--img:…-->` + 紧随其后的图表围栏」整体折叠成 `![](assets/xxx.png)`；**Markdown 交付件原样保留围栏**。没有定位注释的围栏不折叠、不删除。
- **禁止**在 Markdown 里只写 `![](assets/xxx.png)`（在线协同态会变成占位框），也**禁止**只写围栏不带定位注释（Word/PDF 会丢失该图）。
- echarts option **必须由 `mcp-echarts` 生成或校验后原样嵌入**，不得手工改写、增删键或二次 `JSON.stringify`；不得包含函数、注释、DOM。
- **饼图必须是环状**：`series[0].radius` 形如 `["32.5%","56%"]`（内径 ≥30%），禁止实心饼。
- **尺寸统一**：同类图尺寸必须完全一致，统一 `width:600, height:320`；禁止只给部分图设尺寸。
- **类目归并**：饼图类目 **> 9 个**时按降序保留前 8 项、其余合并为「其他」（否则 ECharts 竖排图例在 320px 高度下溢出错位）。归并只需在 Office 版 PNG 里保留全量，正文或图下注写明「图表版将小类归并为其他」即可。
- **饼图必须显示占比（默认，不用等用户提）**：①**图例逐项写全**「名称 数量 · 占比」（如 `电子 46只 · 68.7%`）；②占比 **≥5%** 的扇区在**环带内部**再标一次百分比（`label.show=true, position="inside"`），并按扇区明暗手动取对比色（深底白字 / 浅底深字，ECharts 不会自动反色）；③占比 **<5%** 的扇区**不标**，避免小扇区标签互相压盖；④tooltip 保留 `{b}: {c} ({d}%)`。matplotlib 侧同口径：`autopct` 仅对 ≥5% 赋值，图例逐项带「数量 · 占比」。
- PNG 仍需生成（matplotlib，中文字体跨平台回退），规范见 §4.1~§4.3。

### 4.1 产业链层级结构图（第 4 章必备）

- **必须体现层级**：「产业环节（上游/中游/下游）」→「一级节点」→「二级节点」→（三级节点示例）逐层展开；仅罗列公司名或用扁平列表代替视为**未完成**。

### 4.2 走势图

- 四环节各一条曲线，配色 `#5470C6` / `#E74C3C` / `#27AE60` / `#F39C12`；纵轴随真实值动态调整（不必从 0 起）；图例置于左上、`ncol=4`、无边框。
- 若某环节指标出现极端值（如 PE 为负或绝对值异常），**改用 `symlog` 轴并在图题中注明**，不要让一条异常曲线压扁其余三条。

### 4.3 饼图（样式要求，此前做得偏小偏挤，按此重做）

- **图形必须为环状（环形）饼图，不得画成实心饼**：`ax.pie(..., wedgeprops={"width": 0.42, "lw": 0.6, "edgecolor": "white"})`，即内半径约为外半径的 58%（与产品内 ECharts 默认 `innerRadius=0.58` 对齐）。环心留白，用于标注合计。
- **⚠️ 同一产物内所有饼图必须「环径完全一致」，用固定布局实现，禁止 `plt.tight_layout()`**：
  - `tight_layout` 会按**图例行数**与**标题长度**重排坐标区，实测同一批 6 张图圆环外径在 265~334 px 之间浮动（差约 26%），肉眼可见大小不一。
  - 正确做法：固定画布 `fig = plt.figure(figsize=(3.8, 4.2), dpi=170)`；用 `fig.add_axes([0.125, 0.25, 2.85/3.8, 2.85/4.2])` 给出**固定且正方形**的环区（2.85 英寸）；`ax.set_aspect("equal")`；标题用 `fig.text(0.5, 0.975, ..., va="top")`；图例用 `fig.legend(..., loc="upper center", bbox_to_anchor=(0.5, 0.238))`。以上坐标全部写死，不随数据变化。
  - 验收标准：6 张 PNG 画布尺寸相同（本例 646×714 px），环外径偏差 ≤1 px。
- **尺寸**：画布 `(3.8, 4.2)` 英寸、`dpi=170`；**同一产物内饼图画布与环径都必须一致**。
- **颜色**：使用固定高质量色板（如 `#5470C6,#91CC75,#FAC858,#EE6666,#73C0DE,#3BA272,#FC8452,#9A60B4,#EA7CCC,#5B8FF9`），避免默认色板过浅。
- **扇区标签**：标注 ≥5% 的占比；`pctdistance` 取 (1+innerRadius)/2 ≈ 0.79（落在环带中间）；标签颜色按扇区亮度自动取黑/白（不要一律白字，浅色扇区会看不清）；字号 6。
- **图例**：置于环形图**下方**、`ncol=2`、字号 6.8、无边框；**每个扇区都要逐项列出「名称  数量 · 占比」**（如 `[50,200亿)  6只 · 35.3%`）。图例行数随条目数变化是允许的——**只有环径必须恒定**。
- **环心**：标注「环节名 + 合计数量」（如「上游 / 72只」），字号 8.5、加粗；环心为纯白底，禁止把文字压在扇区上。
- **标题**：两行（如「具身智能上游环节成分市值分布\n按申万行业(一级)」），字号 8.5，位置固定。
- 禁止出现「只标注大扇区、小扇区无任何数字」的图。

- 市值 7 档口径：`[0,50亿)`、`[50,200亿)`、`[200,500亿)`、`[500,1000亿)`、`[1000,5000亿)`、`[5000,10000亿)`、`[10000亿,∞)`。
- 对话内交互预览（ECharts/SVG）**可选、可降级**，不作为交付内容。

## 5. 写作硬规则

1. **严禁把原始 MQL 返回 JSON 直接注入 prompt**，必须先按 `reference/mql-recipes.md` §5 格式化。
2. 数据不足时的行业聚焦原则：只基于可用有效信息提炼，**不得用其他行业的逻辑/数据替代或混淆**。
3. 区分事实与推断：预测、目标、一致预期须明示非已实现；测算表须有「测算来源说明」。
4. 章节层级与编号：「最新政策」等并列条目章节用 `### 3.1 / 3.2` 分节 + `1. 2. 3.` 有序编号，不要 `-` 平铺无编号列表。
5. 投资建议章节**不要**重复插入「不构成投资建议」类中间提示；免责声明统一放文末。
6. 行文不两端对齐（justify），避免中文字间距不均。
7. 文末「数据来源」只写一句「数据来源：东方财富 Choice。」，不展开报表名/字段/采样口径；必要口径说明（如季末周采样）就近写在对应图表下方一行。
8. 所有带 `[source:N]` 的工具/搜索结论，在 **Markdown 正文中保留标记**（Word/PDF 由脚本自动剔除，HTML 自动转可点击）。
9. **严禁把格式要求写进正文**：prompt 里的「加粗」「居中」「表格居中展示」「不标序号」等是对**排版动作**的指令，不是正文内容。正文里**绝不允许出现「（加粗）」「（居中）」「（表格）」这类字样**——格式一律靠 Markdown 语法实现（`**…**`、表格、有序列表）。交付前必须全文搜索 `（加粗）`、`（居中）` 并清零。
10. **子序号规则**：所有「并列的多条目章节」都要有子序号，不得用加粗段落平铺，**更不得把多指标、多维度的分析写成一整段**。产业链报告：第 4 章产业结构用 `### 4.1 / 4.2 / 4.3`、第 6 章竞争分析用 `### 6.1 / 6.2 / 6.3 / 6.4`、7.1 用 `1. 2. 3. 4.`。产业指数报告：第 4 章用 `### 4.1 收盘点位趋势 / 4.2 PE_TTM 走势 / 4.3 PB_MRQ 走势 / 4.4 PS_TTM 走势`、第 5 章用 `### 5.1 成分股与市值规模 / 5.2 行业与市值分布结构 / 5.3 集中度与竞争格局 / 5.4 格局判断与竞争焦点`、6.1 用 `1. 2. 3. 4.`。每节自成一段或多段，禁止「趋势分析：…」式的单段堆叠。
11. **图一律写「定位注释 + 图表围栏」，不得只写 PNG 路径**（默认写法，不是仅在线文档才这么做）：Markdown 里每张图写成 `<!--img:assets/xxx.png-->` 紧跟 ```` ```echarts ````／```` ```mermaid ```` 围栏；`save_report.py` 会自动把这对内容折叠成 PNG 塞进 Word/PDF/HTML，Markdown 本身保留围栏供编辑器直接渲染。**只写 `![](assets/xxx.png)` 会导致在线协同态显示占位框；只写围栏不带定位注释会导致 Word/PDF 丢图。** 饼图一律环状、同类图尺寸一致；若某张图确实无法显示，直接删除该图节点，严禁留下「暂无数据」这类占位内容。详见 §4。
12. **溯源不得出现空壳标签**：`[source:N]` 的 HTML 可点击标签只对「能装配出真实标题或链接」的标记渲染；装配不出元数据的标记由脚本直接删除，**严禁**显示「未提供该标记的来源元数据」。元数据由脚本自动扫描 `{outdir}/.sources/source-<N>.json` 装配（检索类读 title/url/published_at，MQL 报表类自动生成「东方财富 Choice 报表：{报表名}」），一般无需手工准备 sources.json。
13. **溯源标签显示报告内顺序编号**：`[source:N]` 的编号在整个会话内全局分配（跨多次报表连续累加，常出现 200+ 这类数字），因此 HTML 中的可点击溯源标签显示**本报告内顺序编号（1、2、3…，按正文首次出现顺序）**；真实编号保留在标签的 `data-marker` / `data-marker-id` 属性中（界面不展示；弹窗内**不得**再出现「标记原文 `[source:N]`」这类用户看不懂的字段），仍与来源台账一一对应。该行为已固化在 `save_report.py` 的 `render_source_trace`（返回 `local` 映射并交给前端脚本），禁止改回显示全局数字或对标记本身重新编号。Markdown 交付物正文仍**必须保留原始 `[source:N]`**，不得改写编号。另：结构化取数类来源（金融数据/宏观数据/选股）无标题字段时，脚本用调用问句生成「东方财富 Choice 数据查询：{问句}」标签，避免其标记因缺元数据被整体丢弃。
14. **正文不得暴露取数实现**：报告正文与「数据口径说明」中**不得出现 MQL 字样**，也不得出现报表名/报表路径、排序与截断参数（如「按周交易日降序 + Head」）、取数规模描述（如「1,384 行 × 6 列」「整表」）等实现细节。口径说明只保留：采样频率、观测点数、起止区间、指标口径、降级事实。违例时改写句子，不能删掉降级声明。
