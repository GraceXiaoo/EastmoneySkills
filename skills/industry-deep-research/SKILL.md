# 产业深度分析报告 Skill

## 0. 本版设计：首屏只吃这一页

- **首屏只加载本文件。** `reference/` 下的明细一律**按需 Read**，不要在开始时就全部读入。
- 每读一个 `reference/` 文件前，先确认「按需加载索引」里对应步骤已到达。

- 下表报表路径已于 **2026-10-02 实测校准**，可直接使用；若执行报错再按下文检索规则重检索。

## 2. 两种报告形态

| 报告形态 | 检索对象 | 章节数 | 差异 |
|---|---|---|---|
| 产业链报告 | 市场主题产业 / 标准产业 | 7 章 | 含「产业结构与代表公司」 |
| 产业指数报告 | 产业类股票指数（如「中芯概念」） | 6 章 | **不含**「产业结构与代表公司」，其余同 |

**路由（三态）**：先查产业链（市场主题 + 标准产业）→ 无高相关则查产业指数 → 有高相关指数出产业指数报告，否则回退中相关产业链，仍无则提示未找到。

**统一标题**：《**{{主体名称}}产业深度分析报告**》（产业链取 `TYPE_NAME`，产业指数取 `INDEX_ABBR`）。不得使用其他形式标题。

**无感路由**：不得向用户暴露「市场主题 / 标准产业 / 产业指数」「走了哪条链路」等内部术语；仅在存在**多个候选**需消歧时展示候选编号（不标注类型）。单一候选直接生成，不询问确认。

## 4. 执行流程（骨架）

```
Step 0  前置：确认 MQL 工具链可用（刚性）；妙想搜索可选（可降级）；记录 {{TOPIC}}
Step 1  提取产业关键词 {{TOPIC}}
Step 2  产业链搜索与匹配（市场主题 + 标准产业，两条独立 MQL）
          ├─ 有高相关产业链 → 路线 A
          └─ 无高相关 → Step 2b
Step 2b 产业指数识别与匹配 → 有高相关指数 → 路线 B；否则回退中相关产业链 / 提示未找到
Step 3  路线 A：产业结构 + 指数业绩 + 成分股 + 妙想搜索
Step 3b 路线 B：指数基本信息 + 业绩 + 成分股 + 成分行业分布(兜底) + 妙想搜索
Step 4  数据加工（模型上下文 / 脚本辅助）
Step 5  按章节生成（prompts/<章节号>.txt 逐个替换占位符）
Step 6  组装正文，标题 + 文末固定免责声明
Step 7  save_report.py 出四类产物 → 交付
```

MQL 检索链路：`Get_MQL_Reference` → `Search_Business_Knowledge`（记全部 typeCodes）→ `Search_Context`（首次原样全量传 typeCodes）→ `Execute_MQL`。检索工作流**只做一次**生成参考，后续补调基于前序结果。

**路线 A 的指数代码规则（⚠️ 环节映射必须以「指数名称」为准，不得按后缀序号推断）**：

- 四个指数恒为 `{{TYPE_CODE}}.EI`、`{{TYPE_CODE}}+1.EI`、`+2.EI`、`+3.EI`，**但 `+1/+2/+3` 与「上/中/下游」的对应关系并不固定**。
- 实测 1：具身智能（8880781）→ 782=上游、783=中游、784=下游。
- 实测 2：**标准产业「光电器件」（8870531）→ 782=上游、783=下游、784=中游**（与实测 1 相反）。
- **正确做法**：先执行「指数基本信息」取回 4 个指数的**指数名称**（如「Choice光电器件上游产业指数」），据名称中的「上游/中游/下游」字面完成环节映射；`{{TYPE_CODE}}.EI` 恒为产业整体。**严禁**直接写死「+1=上游、+2=中游、+3=下游」。
- 成分股数的权威口径取「指数基本信息」的 `SAMPLE_NUM`；与「成分股详情」实际行数可能不等（部分成分股在报告期无有效总市值记录），两者需在正文中注明。

## 4.1 章节产出物硬约束（不可简化，先读再写）

> **写每一章之前，必须先 Read 该章对应的 `prompts/<编号>.txt`，并逐条满足其【输出结构】/【输出格式要求】。**
> 表格（列名、行数、位置）、图示、加粗小标题、字数上限、标题格式，**一个都不能少**；不得以「内容看起来够了」为由省略表格或图。逐章完整契约见 `reference/chapters.md` §3。

**高频被省略、但绝不允许省略的产出物**：

| 章节 | 不可省略的产出物 |

| 1.1 需求端分析 | **市场空间测算表**（第一列＝产品/指标名称，第一行＝未来年份 E；量化数据保留 2 位小数；居中）＋「需求特性/市场空间发展/市场空间测算/测算来源说明」四段加粗小标题 |

**第 4 章的产业链层级结构图**与第 5/6 章的趋势图、饼图同为**必备图示**（生成规范见 `reference/chapters.md` §4）。结构图须体现「上游/中游/下游 → 一级节点 → 二级节点（→ 三级节点）」的层级关系，**不得只列公司名或用扁平列表代替**。

**六条交付前必查**（对照 `reference/chapters.md` §5 规则 9、10 与 `reference/output-spec.md` §3、§5）：
1. 正文**不得出现「（加粗）」「（居中）」「（表格）」等格式提示字样**——那是排版动作指令，不是正文内容；全文搜索 `（加粗）`、`（居中）` 必须为 0。
2. **并列多条目章节必须有子序号**，不得用加粗段落平铺、更不得把多指标分析堆成一整段：产业链报告第 4 章 `4.1/4.2/4.3`、第 6 章 `6.1~6.4`、7.1 用 `1. 2. 3.`；**产业指数报告第 4 章 `4.1 收盘点位趋势 / 4.2 PE_TTM 走势 / 4.3 PB_MRQ 走势 / 4.4 PS_TTM 走势`、第 5 章 `5.1 成分股与市值规模 / 5.2 行业与市值分布结构 / 5.3 集中度与竞争格局 / 5.4 格局判断与竞争焦点`**。
3. **图统一写「定位注释 + 图表围栏」，不要只写 PNG 路径**（默认写法，四类产物同源）：正文每张图写成 `<!--img:assets/xxx.png-->` 紧跟 ```` ```echarts ````／```` ```mermaid ```` 围栏，`save_report.py` 自动把这对内容折叠成 PNG 塞进 Word/PDF/HTML，Markdown 保留围栏供编辑器直接渲染。**只写 `![](assets/xxx.png)` 会在在线协同态显示占位框；只写围栏不带定位注释会让 Word/PDF 丢图。** 饼图必须环状、同类图尺寸统一（600×320）、类目 >9 个归并为「其他」；**饼图必须显示占比**（图例逐项带「数量 · 占比」，≥5% 的扇区在环带内再标百分比，<5% 不标）。任何图若确实无法渲染，**直接删掉该图节点，不得留「暂无数据」占位框**。详见 `reference/chapters.md` §4 与 `reference/output-spec.md` §5。
4. **溯源不得出现空壳**：`[source:N]` 在 HTML 中只对能装配出真实元数据（标题或链接）的标记渲染可点击标签；无元数据的标记由脚本直接删除，**严禁**渲染成「未提供该标记的来源元数据」。元数据由脚本自动扫描 `{outdir}/.sources/source-<N>.json` 装配，无需手工准备。
5. **溯源标签显示报告内顺序编号**：HTML 中的可点击溯源标签显示**本报告内顺序编号（从 1 开始，按正文首次出现顺序）**，不显示 `[source:N]` 的原始数字（该编号为**整个会话全局累加**，跨多次报表后会出现 200+ 这类与正文序号观感不符的数字）。真实编号保留在标签的 `data-marker` / `data-marker-id` 属性中（不在界面展示，弹窗内也**不得**再出现「标记原文 [source:N]」这类难以理解的字段），仍与来源台账一一对应。该行为已固化在 `save_report.py`（`render_source_trace` 返回 local 映射）；**MD 交付物正文仍必须保留原始 `[source:N]`，禁止重新编号**。
6. **正文不得暴露取数实现**：四类产物（MD / Word / PDF / HTML）的正文与「数据口径说明」中**不得出现 MQL 字样**，也不得出现报表名或报表路径、「按周交易日降序 + Head」这类排序/截断参数、`1,384 行 × 6 列` 这类取数规模描述等实现细节。口径说明只保留读者需要的信息：采样频率（如「季末采样」）、观测点数、起止区间、指标口径（PE/PB/PS）与降级事实（如「非逐周全量」「未覆盖完整五年」）。数据来源统一写「数据来源：东方财富 Choice。」

## 5. MQL 硬规则（最小集，生成前必读）

1. 每次 MQL 执行是独立脚本，`ReportBlock` 编号从 `#1` 起、连续递增。
2. `OutputBlock()` **不接受参数**；需指定输出块时不写或写 `OutputBlock()`。
3. 三张指数报表 `reportStandardCodeSupported=true`，**必须 `SetCodes(["XXXXXX.EI"])`**，不能只靠 `SetReportFilter`。
4. **成分股详情报表必须带 `SetReportFilter({交易日期} >= "<近1~2周日期>")`，否则 0 行。**
5. `REPORT_FIELD("中文名")` 必须与本次检索返回的 `reportFields[].column_name_cn` 完全一致；`SetReportFilter` 只能用 `reportFilterColumns[].column_name_cn`（两个名称空间不通用）。
6. 报「先调用 MQL 生成参考」→ 补一次生成参考后重试；**不得盲目重复同一段失败 MQL**。

**取数粒度（强制）**：明细类报表（估值通道周频、成分股详情）禁止整表全量回传。
- 单次 MQL 回传数据单元（行 × 列）**控制在 1,000 以内**。实测：周频估值单指数 **346 行**，4 指数全量即 ~1,384 行 × 6 列 ≈ 8,304 单元，被放大约 15 倍——必须先用 `Sort({周交易日},"DESC")` + `Head(N)` 限定窗口（近五年 ≈ 20~60 个季末/月末观测点）。
- 成分股一律走 `ReportBlock → GroupBlock` 聚合，不为画饼图/算集中度拉回成百上千行明细。完整范式见 `reference/mql-recipes.md`。

## 6. 交付（四类产物，缺一不可）

**分享链接（URL）+ Word（.docx）+ PDF（.pdf）+ Markdown（.md）。**

```bash
  --title "{{主体名称}}产业深度分析报告" \

```
