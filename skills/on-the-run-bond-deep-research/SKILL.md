# 活跃券 F9 一页纸研究报告（on-the-run-bond-deep-research）

基于东方财富数据中心（Choice）数据，针对**单只利率债活跃券**（10 年期国债或国开债最活跃券），通过 MQL MCP 取数、模型生成结构化解读，最终渲染为自包含 HTML 一页纸报告。

本技能仅支持**单个活跃标的**，不支持一次分析多只债券。

## 触发条件（何时调用本技能）

当用户明确要求：
- "活跃券研究"、"利率债活跃券一页纸"、"国债活跃券分析"、"国开债活跃券分析"、"国债活跃券一页纸"、"国开债活跃券一页纸"、"活跃券一页纸"、"活跃券分析"
- 或要求全面分析某只利率债活跃券的一级发行定价、上市后流动性、一级/二级价差、成为活跃券的预期利差与供给节奏
- 或提供"国债走势"、"国开债走势"等对单只活跃券的深度解读请求

若场景涉及转债、信用债、股票、正股联动、转股价值、溢价率，不应使用本技能。

## 2. 数据来源与 MQL MCP 工具

所有取数通过 **MQL MCP** 完成，服务器与工具如下：

## 3. 市场快照：9 类输入数据（数据输入层）

围绕目标活跃券，采集以下 9 类指标（统一在一个 MQL 脚本内执行或分块执行）：

1. **基本面**：债券类型、债券简称、债券代码、剩余期限、中债估价修正久期。
2. **资金面**：DR007、R007、当日公开市场操作(OMO) 7 日逆回购净投放、6 个月 MLF 操作、1 年 MLF 到期、周度净投放、月度净投放。
3. **曲线形态**：1Y-30Y 整条收益率曲线关键点、10-1Y 期限利差、30-10Y 期限利差及其历史百分位。
4. **品种利差**：10Y 国开收益率、10Y 国开-国债利差及其历史百分位。
5. **一级-二级利差**：10Y 国债/国开一级拍卖中标利率、中标利率相对二级成交的偏离（一级-二级利差）。
6. **供给日历**：国债净融资、发行数量、发行总额。
7. **微观结构**：成交笔数、换手率、盘口价差、隐含税率及其历史百分位、国债期货主力合约持仓量与成交量。
8. **机构行为**：债券分歧指数——银行、基金、证券、保险十大机构，`0→50` 表示买方增强，`0→-50` 表示卖方增强。
9. **外部环境**：10Y 美债收益率、美元指数。

## 4. 市场讨论检索（可选）

在需要补充市场观点增量以增强解读时，检索利率债市场讨论/新闻（通过 `Search_Business_Knowledge` 或妙想搜索 API `http://llm-platform-cid.bdeastmoney.net/llm-platform-search-api/search/modelV2`），query 主题为"利率债市场讨论"/"新发利率债市场讨论"，time 窗口 `T-30 到 T`（时间窗口 T 为用户请求当日，通常近一个月）。用于摘要与驱动因素拆解的背景支撑，不作为单独输出节。

**图表占位符规则**：
- 支持最多 5 张图表，占位符形如 `{图表名称}`。
- 每张图表最多渲染 1 次。
- 图表只能出现在第 1-5 节（含第 3 节估值图）；**第 6 节（策略逻辑）与摘要中不可出现图表**。
- 缺少数据时省略对应内容，或注明"依据不足"，不得编造。

### 债券类型差异化指令

设定活跃债券与非活跃/老券的差异化视角：

- **国开活跃券**（如 10YCDB.IB 250215.IB）：以 **交易情绪 → 隐含税率 → 流动性溢价** 为主线拆解，强调国开-国债利差的低位与收敛/走阔驱动。
- **次活跃券/老券**（如 250011.IB 等次新活跃）：以 **利差位置与收敛空间** 为主线，强调期限利差、流动性溢价的驱动，简洁交代历史分位。

## 7. MQL 语法约束（严格执行）

取数脚本 `Execute_MQL` 内必须遵循：

- `SetReportFilter` 条件用 `==`（不是 `=`），多条件用 `AND`。
- **不支持 `in` 运算符**；多值用 `OR` 链。
- **不支持 `Limit()` / `Top()`**；用 `OutputBlock()` 控制输出。
- `SetReportFilter` 只能用于**加载列**，不能用于返回列。
- `Sort()` 必须放在**所有 `REPORT_FIELD` 声明之后**。
- 路径分隔符用**单反斜杠** `\`（如 `'000000002.IB'`）。
- `REPORT_FIELD("中文列名")` 使用完整中文列名（含括号），例如：
  - `REPORT_FIELD("估价修正久期（中债）")`
  - `REPORT_FIELD("隐含税率(%)")`
  - `REPORT_FIELD("最新价")`
- 输出列名以中文为准；不使用未经验证的英文列名。

### 取数模板（方案，供 `mql` 参数使用）

示例：行情快照
```
// #mkt_snapshot2
OutputBlock()
{
    ROWS::SET
    APPEND
    {
        REPORT_FIELD("证券代码") ;
        REPORT_FIELD("证券简称") ;
        REPORT_FIELD("最新价") ;
        REPORT_FIELD("成交量") ;
        REPORT_FIELD("成交额") ;
    }
    SETREPORT  "RPT_MARKET_SNAPSHOT2" ;
    SetReportFilter "(证券代码=='250215.IB')"
    <...继续追加其余 REPORT_FIELD / SETREPORT / SetReportFilter>
}
```

> 具体 MQL 脚本以 `Get_MQL_Reference` 返回协议 + 业务知识 `Search_Business_Knowledge("债券")` 指导下、且已实际获取到数据的写法为准；禁止凭空断言列名。

```html
  <p>…正文（≥800字全篇，分节散落）…</p>

<!-- 数据表格用 <table class="data-table"> -->
```

- 报告为单文件 HTML，内联 CSS 与 JS；无外部依赖（除 ECharts CDN）。
- **标题**：`<h1>` 格式固定为 `{活跃券名称}({活跃券代码})活跃券研究`（如 `10年期国债活跃券(10YGB.IB)活跃券研究`）；「活跃券名称 / 活跃券代码」取**平台券种标识**（如"10年期国债活跃券" / `10YGB.IB`），**不以实际债券名称为主标题**；实际券名与债券代码（如 `25附息国债15` / `250215.IB`）在页眉以 `<span class="tag">` 标签标注，摘要须点明实际标的。
- 正文分析全篇 ≥800 字，按"四件套"结构组织（h2 节标题 + h3 图表标题 + div#chartN + p 解读）。
- 生成时间为**秒级**精确，如 `2026-09-28 12:00:00`。

### 输出纪律（语言与格式）

- 全程中文，术语规范。
- **禁止**输出词汇：`买入`、`卖出`、`持有`、`必定`、`稳赚`；避免极端看空措辞（`看空中国`、`做空中国`、`崩盘`、`危机`、`衰退`）；可用 `回调`、`盘整`、`区间震荡`、`中枢上移`、`再定价` 等中性表述。
- 不暴露底层原始字段名（如 `DIFF`、`TURNOVER` 等英文列），统一用中文语义。
- **活跃券报告内不得出现 "新券/次新券" 字样**；如确涉及新发标的，提示用户改用 `new-bond-research`。
- 数据缺失的指标：省略该节或明确标注"依据不足"，**不得编造数据或结论**。

## 9. 已知问题与规避

1. 中文目录名在磁盘上可能被误存为乱码，技能标识以 frontmatter `name` 为准；工作区文件使用 ASCII 命名中间产物。
2. `SetReportFilter` 误用 `=` 会静默失败——必须用 `==`。
3. RPT 报表重名时（`_SPDETE` / `_SPDETE_HIS`），务必按时间窗口选对表。
4. `Execute_MQL` 超时大数据集时，先 `OutputBlock` 限制行数再取数。
5. MQL 取不到某字段时优先在 `Search_Business_Knowledge` 检索业务口径，而非改名臆测。
6. ECharts 部署区无法联网时 `cdn.jsdelivr.net` 可能加载失败——内置缩容，降级纯文本表格。
7. 时间窗口用近一年（或 `T-30~T`）统一口径，避免跨表口径不一致。
8. 每个交易日 12:00、18:00 生成时，注意当日一级发行/拍卖数据是否已更新。
9. `Sort` 写在列声明前会语法报错。
10. 列名含中文括号时，整体作为字符串（含括号），勿拆分。
11. 外部环境图（美债/美指）表更新慢于利率表，需做时间对齐。
12. 机构分歧指数为 -50~50 区间，超出视为数据异常，需复核。

## 10. 质量检查清单（生成后自检）

1. ① 是否指定了 单只 活跃券标的，未混入多券?
2. ② 摘要 ≤400 字，不带图表？
3. ③ 分节解读是否覆盖"核心矛盾/驱动/估值/机构/策略"5 节？
4. ④ 第 6 节（策略）是否避免图表？
5. ⑤ 图表数 ≤5、每图 ≤1 次？有无跨节重复？
6. ⑥ 图表数据是否与 9 类市场快照口径一致？
7. ⑦ 是否对每张图给出 ≥1 句解读文本（四件套完整）？
8. ⑧ 正文全篇 ≥800 字？
9. ⑨ 是否含表格 `<table class="data-table">` 与"生成时间"秒级？
10. ⑩ 是否出现禁用词（买入/卖出/持有/必定/稳赚/悲观字眼）？
11. ⑪ 是否不出现 "新券/次新券"？
12. ⑫ 数据缺失是否标注"依据不足"而非编造？
13. ⑬ 机构分歧指数是否解读为 0→50 买增/0→-50 卖增？
14. ⑭ 品种/期限利差是否给出历史百分位？
15. ⑮ 一级-二级利差是否对齐最新发行数据？
16. ⑯ 信用/转债误报组织是否规避？
17. ⑰ 外部环境（10Y 美债/美元指数）是否与利率表时间点对齐？
18. ⑱ 全文是否中文、无英文字段名透出？
19. ⑲ 免责声明是否存在？
20. ⑳ HTML 是否符合单一自包含文件，无外链图片？
21. ㉑ 是否已用 `computer://` 链接交付文件并给出简短摘要？

## 11. 操作流程（端到端）

1. 解析用户输入的活跃券标的（代码/简称）；确认单标的。
2. 校验 MQL 路径：`Get_MQL_Reference` → `Search_Business_Knowledge`（varieties=enums，user_query=标的）。
3. `Execute_MQL` 采集 9 类市场快照数据（可拆多次、产出中间 CSV/JSON 存于工作目录）。
4. `Execute_MQL` 采集 5 张图数据（按 §7 映射）。
5. 可选：检索市场讨论（§4）。
6. 组装"三明治"Prompt，按 §6 参数生成 JSON 解读。
7. 校验 JSON ≥800 字、节与图表规则（§10 清单）。
8. 渲染 HTML：标题（`{活跃券名称}({活跃券代码})活跃券研究` 格式，如 `10年期国债活跃券(10YGB.IB)`）、meta（秒级时间 + 实际券名标签）、5 节正文、5 图（IIFE）、数据表格、免责声明。
9. 交付：输出 HTML 文件绝对路径，附 `computer://` 链接，2-3 句总结。

## 超时与重复调用

本 skill 为提示词型流程（无可执行脚本），调用 MQL / RAG 等 MCP 工具时须遵循以下限制：单个工具调用失败后最多退避重试 2 次（退避等待 30s / 90s）；单次调用最长等待 1200 秒，超过该时长即判定为超时失败。模型不得因失败重复调用同一 `query`，同一 `query` 累计调用不超过 2 次。若调用超时被中断或返回失败，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的重试。
