# 执行工作流（Required Workflow）

> 本文件是 `SKILL.md`「执行工作流」的**完整版**。`SKILL.md` 只保留一句话总览与指路，细则一律以本文件为准。
> 九步顺序**不可调换**：先归一化 → 再定取数路径 → 再取数（资讯检索与 MQL 两条通道无依赖，可并行准备） → 再逐章生成 → 最后渲染与校验。
>
> 相关文档：数据通道分工见 `数据通道与来源对应.md`；MQL 细则见 `MQL-取数规程.md` 与 `MQL-报表路径固化表.md`；
> 资讯检索细则见 `资讯检索-取数规范.md`；交付口径见 `输出契约与数据契约.md`；红线与降级见 `合规与降级.md`。

## 0. 超时与重复调用（硬约束）

脚本内部已实现有限次退避重试（最多 2 次，退避 30s / 90s），单次调用最长等待 1200 秒，超过该时长即判定为超时失败；模型不得因失败重复调用同一 `query`，同一 `query` 累计调用不超过 2 次。若命令超时被中断或返回非 0 退出码，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的重试。

## 1. 工作流九步

1. **归一化输入代码或公司名**。代码必须带交易所后缀；4-5 位纯数字默认补成港股五位代码，6 位纯数字走沪深京候选并经 MQL 确认。名称换码必须通过 MQL `searchEntity`，不得靠记忆。

2. **取数前读规程并做版本校验**。每次取数前读取 [MQL-取数规程.md](MQL-取数规程.md)，执行 `Get_MQL_Reference` 并校验 `Execute_MQL` 工具描述里的执行器版本。MQL 检索与执行同属 `mcp-mql-tools` 一个服务。若 `Execute_MQL` 未挂载、未信任或读不到版本，停止并告知用户。

3. **先查固化表决定取数路径**。打开 [MQL-报表路径固化表.md](MQL-报表路径固化表.md)（或跑 `python scripts/mql_api.py --list`）。
   - **命中** → 走零检索直取（规程 §2A）：路径/字段中文名/加载列枚举**原样取自固化表**，直接拼 MQL 调 `Execute_MQL`；**不再**调 `Search_Business_Knowledge` / `Search_Context`。**推荐用 `python scripts/mql_api.py --script <批次名> --code <SECUCODE>` 一次生成整段可执行脚本（Block 编号连续、参数顺序固定）**，详见 `取数脚本一次成型.md`。
   - **未命中** → 读 [市场路由与取值范围.md](市场路由与取值范围.md)，用 `Search_Business_Knowledge` 与 `Search_Context` 完成市场路由、取值范围和上市状态校验，得到带后缀的 `SECUCODE` 与公司名称（规程 §2B）。
   - 零检索分支下，**市场路由与上市状态校验**改由固化表对应报表的返回列承担（如 `沪深F9_基础资料_公司介绍` 返回 `证券代码`/`证券简称`；港股 `上市状态` 在 `港股F9_资料_公司简况` 返回列中）。
   - 零检索分支下，**输入代码归一化**仍须做：代码必须带交易所后缀；纯数字按规则补后缀，**不得靠记忆**。4-5 位纯数字补 `HK`，6 位按首位判 `SH`/`SZ`/`BJ`（`6`→`.SH`、`0`/`3`→`.SZ`、`8`/`4`→`.BJ`），复权/存疑时回退 `Search_Context.searchEntity`。
   - 固化表**只固化报表路径与字段，不固化证券实体**；名称换码在任何分支下都必须走 `Search_Context.searchEntity`，不得靠记忆。

4. **章节文字描述取数（一次性完成）**：读取 [资讯检索-取数规范.md](资讯检索-取数规范.md)。
   - **Agent 侧（检索）**：按 `scripts/news_api.py` 的 `SCENES` 场景注册表（`【公司名称】` 为唯一变量）**分 3 批并发调用 `mx_finance_search`（每批 3–4 个场景，禁止逐个串行；批次划分见规范 §10.1）**——场景 `1` 用 `【公司名称】近况跟踪`（近 1 个月），场景 `2`-`9` 用对应句式（近半年）；每次调用后把返回条目（`标题`/`发布时间`/`来源`/`链接`/`摘要`/`[source:N]`）结构化为 `raw/{scene}.json` 落盘（契约见规范 §5），并发返回须按 `query` 与场景键一一对应落盘、不得串号。
   - **脚本侧（归一化）**：`python scripts/news_api.py --company "公司名" --raw-dir "raw" --all --with-meta --out "text_公司名.json"` 完成窗口兜底 / 同源去重 / 时间倒序 / chunk 拼接（规范 §6/§7），落盘为 `{{ZWSMSJ}}`。单场景失败（raw 缺失或为空）按规范 §9 降级，其余场景照常输出；组装 `data.json` 时把各场景 `sources` 溯源清单挂到对应章节（供 hover+click 溯源）。
   - **事件库（章节 1 催化事件时间表）**：调用 `mx_api_invoke(apiId=newsEventSearch)`（已发生事件库）与 `mx_api_invoke(apiId=futureEventSearch)`（未来事件库），返回结构化落盘 `raw/事件库_已发生.json` / `raw/事件库_未来.json`（不经 `news_api.py` 归一化）；接口清单、取值映射与降级见 [事件库-取数规范.md](事件库-取数规范.md)。

5. **按市场读取对应清单**：沪深京读 [沪深京-分章节MQL清单.md](沪深京-分章节MQL清单.md)；港股读 [港股-分章节MQL清单.md](港股-分章节MQL清单.md)，如需换汇再读 [汇率换算规则.md](汇率换算规则.md)。

6. **章节 3-8 的表格与图表只通过 MQL 取数**：命中固化表则直接 `Execute_MQL`（零检索）；未命中才走 `Get_MQL_Reference` -> `Search_Business_Knowledge` -> `Search_Context` -> `Execute_MQL`。不得回退旧妙想中台 HTTP 接口（`datacenter-choice.eastmoney.com`）、构造旧通道 URL、凭记忆补路径/参数/字段名、或编造数据。

7. **逐章生成前只读取相关 prompt**，不要一次性加载全部 prompt。每章输入 = **该章资讯检索场景的拼接文本** + 该章 MQL 数据（如适用）。章节 4/6/7/8 可在同一 MQL 批次取数；章节 5 可独立批次；港股换汇批次必须先执行。

8. **渲染与校验 + 交付**：用 `scripts/build_report.py` 从结构化 `data.json` 渲染自包含 HTML，再用 `scripts/validate_report.py` 校验。P0 失败不得交付。校验通过后用 `scripts/render_markdown.py --input data.json` 由**同一份** `data.json` 生成会话正文，**回复正文即报告内容本身**（章节 1-9 + 各表），另加 1 行文件指引；禁止把执行过程、校验结果、数据缺口/降级/口径说明与技术细节写进回复（见 [输出契约与数据契约.md](输出契约与数据契约.md) §1「会话回复正文」）。

9. **溯源**：`data.json` 各章节可选携带 `sources`（溯源清单：`title`/`time`/`source`/`link`/`source_marker`，取自 `{{ZWSMSJ}}` 对应场景的 `sources` 聚合；章节 3 聚合 `3.1`+`3.2`）；渲染器据此为正文段落、催化事件表、风险提示等资讯内容自动生成「来源」锚点（**hover 显示来源浮层、click 打开原文链接**）。无 `sources` 的章节不渲染溯源锚点，不影响交付。

## 2. MQL 取数批次编排（对应第 3 / 6 步）

批次划分、各批次内容与"报告期基准必须先由批次 1 确定"的顺序约束，
**唯一权威定义见 [MQL-取数规程.md](MQL-取数规程.md) §8**，本文件不复述。
批次 1 / 2 / 3 可用 `python scripts/mql_api.py --script 批次1|批次2|批次3 --code <SECUCODE>` 一次生成整段可执行脚本，详见 `取数脚本一次成型.md`。
