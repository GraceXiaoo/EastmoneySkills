# 市场路由与取值范围（Step 0）

> 目标：把用户输入的"公司代码或公司名称"归一化为 `SECUCODE`（带交易所后缀），并判定走沪深京链路还是港股链路。所有后续章节取数都依赖本步骤产物。
> 本步骤及后续全部取数均走 **MQL**（妙想查询语言），规程见 `reference/MQL-取数规程.md`。

## 1. 输入识别与代码归一化

| 用户输入形态 | 处理规则 | 归一化结果示例 |
|---|---|---|
| 带后缀 A 股代码 | 直接使用 | `300476.SZ`、`600519.SH`、`430047.BJ` |
| 带后缀港股代码 | 直接使用（补齐 5 位） | `09992.HK`、`00001.HK` |
| 纯 6 位数字 | 默认按 A 股处理，进入取值范围校验 | `300476` → `300476.SZ` |
| 纯 4-5 位数字 | 默认按港股处理，进入取值范围校验 | `9992` → `09992.HK` |
| 公司简称/全称 | 走 MQL 检索：`Search_Business_Knowledge`（定品种）→ `Search_Context` 的 `searchEntity.words` 传入名称 → 取候选的"实体代码"作为 SECUCODE | `宁德时代` → `300750.SZ` |

规则：
1. 归一化后**必须**经"取值范围"取数确认在覆盖范围内（正常上市），不在范围内立即终止并告知用户。
2. 同名/同码多市场（A+H 等）时，默认取用户显式后缀；无后缀时提示用户确认市场。
3. 本版本覆盖 **沪深京 + 港股**；美股/其他市场预留扩展位，命中时明确提示"暂不支持"。
4. 名称换码**不得靠记忆**：`searchEntity` 返回多个候选且无法唯一确定时，先向用户确认，不猜。

## 2. 前置调用顺序（MQL 强制）

**⚡ 零检索快车道（v2.2.0）**：若目标报表命中 `reference/MQL-报表路径固化表.md`，
可跳过 `Search_Business_Knowledge` 与 `Search_Context`，直接用固化路径直取（只保留 `Get_MQL_Reference` 做版本校验）：
见 `MQL-取数规程.md` §2A。**换码（公司简称 → SECUCODE）仍必须走 `Search_Context` 的 `searchEntity`**（固化表只固化报表路径，不固化证券实体）。

```
【零检索分支】命中固化表
Get_MQL_Reference（校验执行器版本 → 取参考）
  → Search_Context（仅当需换码：searchEntity 传公司名，不带 searchIndicator）
  → 生成 MQL → Execute_MQL

【标准分支】未命中固化表
Get_MQL_Reference（校验执行器版本 → 取参考）
  → Search_Business_Knowledge（varieties / typeCodes）
  → Search_Context（searchEntity 换码 + searchIndicator 取取值范围相关对象）
  → 生成 MQL → Execute_MQL
```

- `varieties`：沪深京 → `["沪深股票"]`；港股 → `["港股"]`。
- `typeCodes`：沪深京实测 `["1","2","3","4","5","6","203","216","222","236"]`；港股实测 `["71","72","73","74","79"]`。**必须以当次 `Search_Business_Knowledge` 返回值为准**，不得凭此处数字硬编码。**零检索分支下 `Search_Business_Knowledge` 免调，该行不适用**。
- `searchEntity.words`：同时传 `SECUCODE` 与公司名（如 `["300750.SZ","宁德时代"]`），一次提交。

> **零检索分支的脚本生成**：路径与字段确定后，整段 MQL 一律用
> `python scripts/mql_api.py --script <批次名> --code <SECUCODE>` 一次成型生成
> （Block 编号自动连续、加载列条件按固定顺序书写），不要手写 Block；用法见 `取数脚本一次成型.md`。

| 项 | 内容 |

| 基线路径（**未固化、需检索**） | `Choice报表\报表指标\Choice金融终端\A股F9\公司一页纸\前置接口\沪深F9_基础资料_公司介绍\|RPT_HSF9_BASIC_ORGINFO`（与固化路径**同 metricId**） |

## 5. 报告期统一口径（全局约定）

- "近 5 年" = 系统日期往前推 5 年的滑动窗口（例：今天 2026-06-12 → 2021-06-13 ~ 2026-06-12）。
- 报告期取值用 MQL **报告期动态函数字符串**（选项原文来自候选 `parameters[].options`）：
  - 最近 1 个年报：`{报告期} = "GetReportDate(1, \"Q4\")"`
  - 2 年前年报：`{报告期} = "GetReportDate(2, \"Q4\")"`（依此类推至 5 年前）
  - 最新报告期（含中报/季报）：`{报告期} = "最新一期(MRQ)"`
- 表格类口径（4.2 / 7.2）：**最新报告期 + 近 5 个年报期**，同期去重；列从左到右降序、最新报告期在最左。
  **该口径通过传参一次表达（`SetReportFilter` 的"窗口 OR 最新报告期"条件，或报告期参数一次传 6 个取值），执行后不对报告期窗口做本地二次筛选去重**——完整定义与两种 MQL 写法见 `MQL-取数规程.md` §11。
  成表时 4.2 与 7.2 **各自独立**剔除「整列为空」的报告期列，**两表列集合允许不一致**（`MQL-取数规程.md` §11.2 第 4 条）。
- 8.1 一致预测的历史年（A）= **最近 3 个已披露的年报报告期**（见 `MQL-取数规程.md` §11.4）。
- 金额统一换算为**人民币亿元，保留 2 位小数**；百分比保留 2 位小数。
- **比率类（毛利率/净利率/ROE/资产负债率/占比）不做汇率换算**（无量纲）。
- 港股非人民币报表折人民币：按**各报告期末**历史汇率，见 `汇率换算规则.md`。

| 判定 | 链路 | 数据层文档 |
|---|---|---|
