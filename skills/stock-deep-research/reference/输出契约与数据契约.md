# 输出契约与数据契约

> 本文件是 `SKILL.md`「输出契约（Output Contract）」与「数据契约（Data Contract）」的**完整版**。
> 渲染实现见 [报告版式与图表规范.md](报告版式与图表规范.md)；各章样例颗粒度见 [章节示例对照表.md](章节示例对照表.md)。

## 1. 输出契约

- **文件名**：`{公司名}({SECUCODE})股票研究_{YYYYMMDD}.html`，HTML 优先。
- **结构**：报告包含 1-9 个一级章节标题，顺序固定：1 公司近况跟踪；2 核心推荐逻辑；3 公司简介；4 公司业务拆分；5 公司产销链分析；6 公司研发实力；7 公司财务分析；8 公司盈利预测与估值分析；9 公司风险提示。**1-9 一级标题在任何数据情况下都齐全**，`validate_report.py` 按此做 P0 校验。
- **空数据口径（已冻结，一级与二级分别处理）**：
  - **一级章节标题一律保留**，以保证报告结构完整，不因缺数据而删除。
  - **二级小节标题、图表、正文**在对应数据缺失时整段不渲染，且不输出任何解释性空状态。
  - 即：**保留标题、仅不出正文**。章节 5 无客户/供应商数据时，不渲染 `**主要客户情况**` / `**主要供应商情况**` 二级小标题及其正文，但一级章标题「5 公司产销链分析」照常保留。
- **语言**：简体中文；金额统一人民币亿元、2 位小数；百分比、PE/PB/PEG 保留 2 位小数；港股非人民币报表按各报告期末历史汇率折人民币，比率类不换汇。
- **8.1 一致预测表（沪深京）固定 10 个指标行，行名与行序逐字、一行都不得少返回**：`营业总收入(亿元)` / `营业总收入增长率(%)` / `归母净利润(亿元)` / `归母净利润增长率(%)` / `EPS(稀释)` / `基准股本(百万股)` / `ROE(摊薄)(%)` / `ROA(%)` / `PE` / `PEG`；某期无值即**单元格留空、整行照常渲染**（不得删行）。行 ↔ MQL 返回列 ↔ 单位加工对照见 [报告版式与图表规范.md](报告版式与图表规范.md) §8.1；港股无 `基准股本` 数据源 → 该行不渲染（9 行）。
- **展示**：版式、图表、表格、资料来源和页脚遵循 [报告版式与图表规范.md](报告版式与图表规范.md)。
- **无交付后记（硬约束）**：交付物 = 大标题 + 章节 1-9 + 页脚，**到此为止**；禁止在正文后追加「数据缺口与口径声明」「交付说明」等任何声明性段落（报告内与会话回复均适用）。数据缺失的对外表现只有一种：对应内容不渲染。该规则由 `validate_report.py` P0 机读校验。会话回复的**正向**构成见下两条。
- **会话回复正文（硬约束）**：**对话正文就是报告正文本身，不是过程汇报**。校验通过后，会话回复只允许三段内容，此外不得有任何多余文字：
  1. **报告正文**（必有）：与 HTML **同源同值**的 Markdown——章节 1-9 一级标题（标题文字与渲染器 `CHAPTER_TITLES` 逐字一致）、正文段落，以及章节 3 简介表 / 4.2 分板块表 / 7.2 主要财务指标表 / 8.1 一致预测表（8.1 固定 10 行、缺值单元格留空但整行保留）；数字口径与 HTML 完全一致（金额人民币亿元 2 位小数，百分比与 PE/PB/PEG 2 位小数）。
  2. **文件指引**（必有，仅 1 行）：HTML 文件名 +「排版版见附件/预览」一句，不解释格式、不描述生成过程。
  3. **免责**（可选，至多 1 行）：与 HTML 页脚同义，不得扩写为口径说明。
  - 机读实现：`python scripts/render_markdown.py --input data.json --out 会话正文.md`——与 `build_report.py` **共用同一套**报告期降序、4.2/7.2 各表独立剔除整列为空报告期的口径函数，**禁止另行手写正文**（手写必然漏表或改口径）。
- **会话回复负面清单（硬约束）**：以下内容**禁止**出现在会话回复中（报告内同样禁止）：
  - 执行过程叙述（"我先…""已解压…""分 3 批取数…""已补录固化表…"）；
  - 校验结果与自检结论（"P0 全部通过""P1 警告 N 条""校验 N 项通过"）；
  - 数据缺口 / 降级 / 口径 / 未取到项说明（"本节降级为仅一级标题""通道未挂载""服务端接口故障"）；
  - 技术细节（工具名、报表名与 metricId、接口名、Block/脚本/批次编号、字段名、失败原因与报错原文）；
  - 交付话术（"已生成""已完成""请查收""如需要可…"）与后续建议邀约。
- **缺数据章节的会话表现**：与 HTML 一致——**保留一级标题、不输出正文，且不加任何解释行**（不得写"本节数据缺失/未取到"）。会话正文与 HTML 不一致时，以 HTML 为准并同步修正会话正文。

- **溯源**：资讯类内容（正文段落、催化事件表、简介/客户/供应商文字、风险提示）挂「来源」锚点，支持 **hover 显示来源浮层（标题/时间/来源/`[source:N]`，可点击跳转原文）+ click 打开首个可跳转链接**；MQL 表格/图表保留「资料来源：Choice 金融终端」文字。溯源实现内联于 HTML（CSS+JS+`#srcdata` JSON），无外部依赖、可离线打开。

## 3. 关键报告期规则

- 4.2 与 7.2 共用**同一份取数口径**：最新报告期 + 近 5 个年报期（同期去重，最多 6 列），列从左到右降序、最新报告期在最左。
- **4.2 与 7.2 各自独立剔除「整列为空」的报告期**：某报告期在该表内没有任何有效数据 → 该表不展示这个报告期（整列删除）；仅个别单元格为空仍保留该列、单元格留空。因此**两表的报告期列集合允许不一致**，不需要对齐（完整定义见 `MQL-取数规程.md` §11.2 第 4 条）。
- 报告期窗口必须在 MQL 侧通过传参或 `SetReportFilter` 一次表达；渲染器只做两件事——展示顺序保护（降序）+ 4.2 / 7.2 的空报告期列剔除（`scripts/build_report.py` 的 `drop_all_empty_periods`），不重算窗口、不做其他二次裁剪。
- 8.1 历史年（A）= 最近 3 个已披露年报；预测年（E）= FY1/FY2/FY3；A -> E 时间递进。

> 报告期口径的完整三段式定义（时间窗 / 报告期类型 / 并集）与两种 MQL 实现形态见
> [MQL-取数规程.md](MQL-取数规程.md) §11，本文件不复述。
