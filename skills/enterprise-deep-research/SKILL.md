# 企业深度研究

本技能用于对**单一企业主体**生成本地化企业深度分析报告。HTML 属于报告交付环节，文件必须由本地报告正文生成。

## 核心原则

- **本地成文**：所有分析逻辑、章节路由和成文提示词均存放在本技能本地文件中；不得依赖服务端返回整篇报告。
- **正文与附件同时交付**：最终回复直接展示完整报告，用户在对话中即可阅读全部实际生成的章节；正文之后按“完整正文 → 免责声明 → 附件（HTML）”交付。Markdown 仅用于正文排版，不代表生成 `.md` 文件；附件不能代替报告全文。
- **MQL 主取数与同业务回退**：企业类型判定和前 14 个原始数据板块的正式取数均必须通过 MQL MCP 获取。已固化的 MQL 模板优先按 [references/data-sources/mql-templates.md](references/data-sources/mql-templates.md) 和 `scripts/render_mql_template.py` 使用，只替换企业代码、证券代码、日期等运行时变量，不重新生成完整 MQL；模板没有覆盖、模板执行失败或字段版本发生变化时，才按 `Get_MQL_Reference → Search_Business_Knowledge → Search_Context → Execute_MQL` 检索并执行同业务候选。skill 中用户确认的原始路径始终是首选正式路径，必须保留；若该路径本次不可召回、执行失败、字段不能绑定或关键结果不可用，继续用 MQL 检索并执行同业务候选路径。只有该数据集全部同业务 MQL 候选都失败、超时或缺关键字段时，才使用本地 Python REST 兜底。每个数据集最终只选一个有效来源，不混拼不同候选返回行；回退路径不可删除或取代原主路径。`重点关注`不取原始数据，必须在前 14 个板块成文后接收其分析结果。
- **MQL 使用真实字段名**：`REPORT_FIELD()`、`SetReportFilter()`、`FILTER_ROWS()` 和 `SetCodes()` 中涉及的字段、参数、过滤列，必须逐字采用本次 `Search_Context` 与 MQL Runtime 实际暴露的名称。对报表查询，`REPORT_FIELD()` 的请求名和当前 Block 中的字段名以 MQL Runtime 实际可绑定的 `column_name_cn` 为准（例如信用分析报表中的 `公司代码`、`最新主体评级`），不得把 Python REST 字段别名直接写进 MQL；普通指标的参数必须采用实际参数 `name`，本地逻辑别名只允许在 MQL 返回后做展示整理。
- **板块数据一一对应**：前 14 个原始数据板块必须通过 MQL 单独取数并形成独立数据包，只能传入该板块对应的 prompt；不同板块的数据包、资讯、内部审计元数据不得混传、串用或合并后统一投喂。即使多个板块复用同一底层表，也必须在传入 prompt 前按板块拆成各自字段子集。
- **固定样例版本核对**：样例与实际 MQL 元数据或返回字段冲突时，以实际可绑定字段为准，核实主体、时间、指标含义、单位和过滤枚举后调整样例并复测。不能删掉关键字段或条件换取执行成功；查询通过、字段有值和板块业务完整须分别判断。优先查看核验记录的 `latest_template_checks` 与 `current_blockers`，历史错误仅作审计。
- **正文视觉组件**：报告正文不是纯文字交付。需要图形时，直接在对话中提出“生成环状图”“生成折线图”或“生成柱状图”等需求，并提供整理后的对应数据，由平台生成图形组件图片；无需写图表引擎名、其它技能名或图表代码。需要表格时，提出“生成表格”，并以 Markdown 表格格式输出，由妙想前端自动渲染。各模块组件严格从属于对应模块：只有模块经路由选中、实际生成有效正文并保留在最终报告中，才可追加该模块图表/表格；未分析或未输出的模块不得展示组件。股东情况、经营状况、ESG分析、两类财务状况、发行概述、债券发行人定价分析、偿债分析、信用分析和司法风险按实际数据及专项规则追加组件；偿债分析中的负债结构与发行和到期统计是两个独立图表，其余多图/表合并组件按 [references/visual-assets.md](references/visual-assets.md) 规定的顶层名称和编号执行。所有组件均按正文实际出现顺序命名为“图表1、图表2……”并只使用当前板块独立数据包。
- **双通道输入**：普通数据板块 prompt 中的 `{{数据}}` 只能来自当前板块最终选定的 MQL `block_data_package`（全部同业务 MQL 候选失败后才可使用同板块 Python REST 兜底包）；`{{资讯}}` 只能来自当前板块通过 `mx-finance-search` 获取的 `block_news_package`。`{{数据}}` 与 `{{资讯}}` 必须分别维护状态、分别传入，不得互相替代或混合。`重点关注`是唯一例外：其输入只能是前 14 个板块已经生成的分析正文，不接收原始数据，不发起新的 MQL 或资讯查询。
- **分析输入与审计信息分离**：传入 `{{数据}}` 的只能是当前板块的可读业务数据投影；数据库、报表/库表名称、函数名、字段名、字段代码、查询路径、过滤条件、MQL/REST 状态、Python 兜底状态和内部数据包名称只保存在内部审计包中，不得进入分析 prompt 或正式报告。
- **科创能力专属数据包**：科创能力板块只接收 `sci_tech_profile`、`sci_tech_property_summary`、`sci_tech_property_yearly`、`sci_tech_patent_distribution`、`sci_tech_trademark_distribution`、`sci_tech_rd_exp_emp`、`sci_tech_titles`、`sci_tech_industry` 八个科创专属数据分区；知识产权、研发费用与人员、科创称号和行业数据必须分别由 MQL 取数并记录数据集状态。科创板块资讯 query 固定为 `<企业全名> 专利 知识产权 科技创新 相关资讯 最新动态`。MQL 报表字段必须以 `Search_Context` 和 Runtime 实际返回为准，不能把 UI 展示名或 Python 字段别名直接写进 MQL。
- **全模块 input 截断**：全部 15 个模块的最终完整 input 分别不得超过 16000 字符，包含原 prompt、企业名称、材料及包装文本。按“专业数据库数据优先 → 权威度由高至低 → 发布时间由近及远”排序，逐个保留完整信源；加入第 N 条超限时，剔除第 `[N, ∞)` 条，不切片、不跳过后补。重点关注以完整前序模块分析结果为单元，同样受限。具体字段归一、输入隔离、排序键和截断算法见 [references/news-processing.md](references/news-processing.md)。
- **Python 最后兜底取数**：MQL 不可用，或对应数据集的主路径与所有已发现的同业务 MQL 候选均报错、超时或缺关键字段时，只能运行本技能下的本地 Python 数据脚本做 REST 数据获取/清洗兜底；单条报表路径失败后不得立即跳过其它 MQL 候选。Python 兜底不得调用企业一页纸报告生成服务。
  - **本地附件交付**：本次路由选中的板块（含`重点关注`）正文完成并通过最终章节编号检查后，使用同一份最终正文组件清单生成一个完整 HTML 报告附件。HTML 须保留正文、表格、图表和真实可查看的来源链接；每个“来源”标识必须绑定真实、可访问的原始网页 URL，并使用有效 `href` 或宿主平台等价跳转属性。鼠标悬浮或键盘聚焦/触摸点击时显示包含来源标题、时间、来源机构和真实 URL 的弹窗；同一事实位置允许多个来源标识，不限制数量。不得使用空链接、内部 source id、工作区/会话路径或 HTML 自身链接替代真实 URL；平台未提供真实 URL 时，不得编造链接或生成无效来源图标，若事实无法保留有效溯源则不纳入 HTML。清理 `[source:]` 等内部占位标记，但不得清除真实来源名称和链接。附件内容只能来自本次最终正文，不得重新取数、重新分析、混入原始数据底稿或内部审计信息；交付前必须逐项检查所有来源图标、弹窗、`href` 和跳转目标，任一来源 URL 缺失或不可跳转则 HTML 验收不通过，不得交付伪造或不完整附件。附件生成和校验遵循 [references/report-artifacts.md](references/report-artifacts.md)。
- **单一主体**：一次只分析一个企业。企业不明确、多个企业未指明对象、机构代码候选多义时，先请用户确认，确认前不取数、不生成报告。
- **不编造**：所有事实、金额、日期、评级、判定标签和风险结论必须来自 MQL、Python 兜底数据或用户明确提供的数据。

## 15 个分析板块

本技能最终只允许使用以下 15 个板块，按路由规则选择和排序。此处仅列出可选模块，不分配报告标题序号；标题序号只能由本次实际输出章节的位置决定。

- 基本情况
- 股东情况
- 所处行业
- 经营状况
- ESG分析
- 财务状况
- 财务状况（债券发行人）
- 发行概述
- 定价分析（债券发行人）
- 定价分析（城投）
- 科创能力
- 偿债分析
- 信用分析
- 司法风险
- 重点关注

## 板块路由规则

确定报告板块前，必须先完成一次“企业类型判定”前置取数。该前置取数的正式路径必须是 MQL MCP：先用 `Search_Context`/实体识别确认目标企业，再用 `Execute_MQL` 取回 ESG、城投、科创、发债人四类判定所需字段。若正式路径失败，继续尝试已登记或动态发现的同业务 MQL 候选；只有全部同业务 MQL 候选失败、超时或缺关键字段时，才允许运行本技能本地 Python 脚本做同源 REST 兜底。不得在未完成判定的情况下直接按企业名称、行业印象或本地写死经验选择板块。

每家企业均先分析四个固定开头模块，顺序固定为：

```text
基本情况 → 股东情况 → 所处行业 → 经营状况
```

然后按以下决策树继续：

1. 判断企业是否在 ESG 范围中。
   - 是：追加 `ESG分析`。
   - 否：跳过 `ESG分析`。
2. 判断企业是否为城投企业。
   - 是：追加城投路径：`财务状况（债券发行人） → 发行概述 → 定价分析（城投） → 偿债分析`，然后进入固定收尾模块。
   - 否：进入非城投路径。
3. 非城投路径先判断企业是否为科创企业。
   - 是：追加 `科创能力`。
   - 否：跳过 `科创能力`。
4. 非城投路径再判断企业是否为发债人。
   - 是：追加发债人路径：`财务状况（债券发行人） → 发行概述 → 定价分析（债券发行人） → 偿债分析`，然后进入固定收尾模块。
   - 否：仅追加 `财务状况`，然后进入固定收尾模块。
5. 所有路径最后均追加三个固定收尾模块，顺序固定为：

```text
信用分析 → 司法风险 → 重点关注
```

完整路径示例：

- ESG 范围内城投企业：`基本情况 → 股东情况 → 所处行业 → 经营状况 → ESG分析 → 财务状况（债券发行人） → 发行概述 → 定价分析（城投） → 偿债分析 → 信用分析 → 司法风险 → 重点关注`
- 非 ESG 城投企业：`基本情况 → 股东情况 → 所处行业 → 经营状况 → 财务状况（债券发行人） → 发行概述 → 定价分析（城投） → 偿债分析 → 信用分析 → 司法风险 → 重点关注`
- 非城投、科创、发债人：`基本情况 → 股东情况 → 所处行业 → 经营状况 → ESG分析（如适用） → 科创能力 → 财务状况（债券发行人） → 发行概述 → 定价分析（债券发行人） → 偿债分析 → 信用分析 → 司法风险 → 重点关注`
- 非城投、非科创、非发债人：`基本情况 → 股东情况 → 所处行业 → 经营状况 → ESG分析（如适用） → 财务状况 → 信用分析 → 司法风险 → 重点关注`

债券存续状态补充规则：城投企业或非城投发债人路径均以“发行概述”专属取数结果判断债券是否仍在存续。发行一览完成去重、排除同业存单并按 `到期日期 >= 系统日` 过滤后，若查询成功且结果为空，视为本次没有可用存续债券：跳过 `发行概述` 和 `偿债分析`，保留对应的财务状况（债券发行人）及定价分析板块。若查询失败、超时或关键字段无法核对，存续状态为未知，不能误判为无债券，按原路径保留这两个板块；未进入城投或发债人路径的企业本来不生成这两个板块。章节最终编号按实际输出结果重新连续生成。

## 企业类型判断规则

企业类型判断必须由 MQL MCP 先取数完成，判定字段和执行模板见 [references/data-sources/enterprise-type.md](references/data-sources/enterprise-type.md)；通用 MQL、内部审计和数据包约束见 [references/data-sources/common.md](references/data-sources/common.md)。本地规则只负责解析 MQL 返回字段并生成布尔标记，不得替代 MQL 取数本身。正式路径及所有同业务 MQL 候选均失败后，才能调用 `scripts/get_data.py fetch --org <ORG_CODE>` 作为 Python REST 兜底。

MQL 主路径固定为两组前置判定数据：

| 判定组 | MQL 数据源 | 核心字段/指标 |
|---|---|---|
| ESG 范围 | 中诚信绿金 ESG 评分指标，股票口径和发行人口径均可查询 | `中诚信绿金ESG评分` 非空 |
| 城投/科创/发债人 | `Choice报表\报表指标\Choice金融终端\企业F9\表头\企业F9_机构基本信息`；城投新增条件使用已验证的“发行人发行债券类型” MQL 报表 | `TAG_CODE`、`SECUCODE_BJN`、`IS_LFP`、`TECH_FIELD`、`TECH_TITLE`、`IS_ISSUE_OB`；城投新增条件使用 `信用主体代码`、`筛选类型编码`、`是否剔除同业存单`、`到期日期` 过滤，并读取有效 `筛选内容` |

前置判定需要产出以下四个布尔标记，并在生成报告前固定下来：`is_esg_scope`、`is_urban_investment`、`is_sci_tech`、`is_bond_issuer`。后续板块路由只能读取这四个标记，不得在某个板块生成过程中重新猜测或改写企业类型。

- ESG 范围：MQL 主路径查询股票口径或发行人口径的 `中诚信绿金ESG评分` 指标；任一口径评分非空，即判定企业在 ESG 范围中；否则判定为不在 ESG 范围中。评分为 `0` 是有效值，不得当作空值。Python REST 兜底时才查询 `RPT_ESG_IS_SECUINDU;RPT_ESG_IS_DETAILS`，评级机构名称固定传 `中诚信绿金`，以 `ESG_SCORE` 非空作为同口径判定。
- 城投企业：MQL 主路径必须同时满足两组条件才判定为城投企业：第一，`企业F9_机构基本信息` 返回的 `TAG_CODE` 中任一标签代码以 `003005` 开头；第二，在已验证的“发行人发行债券类型”报表中按 `信用主体代码=当前企业`、`筛选类型编码=1`、`是否剔除同业存单=1`、`到期日期>=系统日` 过滤后，返回至少一条有效 `筛选内容`，且 `筛选内容` 不为空、不为 `-` 等占位符。任一条件不满足即判定为非城投企业。该专项报表不应追加未经验证的 `IS_GROUP` 条件；`IS_LFP` 仅作校验字段，不覆盖双条件主判定。
- 科创企业：仅读取非城投路径企业的实际字段 `TAG_CODE`，只要任一标签代码以 `003002` 开头，即判定为科创企业；否则判定为非科创企业。实际字段 `TECH_FIELD`、`TECH_TITLE` 可作为科创能力板块数据，不覆盖标签代码主判定。
- 发债人：仅对非城投企业判断。首先必须满足通用条件：实际字段 `SECUCODE_BJN` 非空，且 `TAG_CODE` 不存在以 `003001` 或 `003005` 开头的标签。然后查询发债人专项报表 `RPT_CUSTOM_BOND_BS_SAMEISSUERFILTER` 的发行人视角：按 `发行人代码=当前企业`、`集团系=0`、`筛选类型编码=1`、`是否剔除同业存单=1`、`到期日期>系统日或为空` 过滤，读取 `筛选内容`。专项返回的债券类型中，只要至少一条精确命中白名单（短期融资券、超短期融资券、中期票据、集合票据、项目收益票据、定向工具(PPN)、一般公司债、项目收益专项债、私募公司债、一般企业债、项目收益债、中小企业集合债），则通用条件与白名单命中必须同时满足；若返回的全部债券类型均不在白名单内，则专项条件不适用，沿用通用条件。一家企业有多只债券时，命中一只即可纳入，不要求所有债券类型均命中。实际字段 `IS_ISSUE_OB`、`SECUCODE_BJNZ`、`SECUCODE_BJNZ_ISSUER` 仅作交叉校验字段。城投企业已进入城投路径，不再按一般发债人路径处理。

发债人专项的 MQL 非空到期日分支已实测。当前 Runtime 无法表达到期日期空值条件，应先尝试 MQL，再仅对该专项使用 Python REST 的完整 `到期日期>系统日或为空` 条件兜底，具体模板和实测结果见 `references/data-sources/enterprise-type.md`。不得通过删除日期条件规避限制，也不得把接口错误当作“全部类型不在白名单”。

MQL 判定结果必须记录查询状态和数据集来源；若切换 Python 兜底，也必须在状态中记录 `fallback`。这些内部审计信息不传入分析 prompt，也不出现在报告正文。若 ESG 查询无法取得目标企业证券代码、`企业F9_机构基本信息` 返回字段缺失、机构代码不匹配或 MQL 与 Python 兜底均无法取得上述关键字段，不得继续猜测类型，应停止完整报告生成并说明缺失的判定字段。

`重点关注`不适用上述原始数据双通道规则。它必须在前 14 个板块逐一生成正文之后，接收一个固定 14 槽位的本地分析结果交接包：每个槽位只放该板块已经生成的正文及其逐句对应的有效原始引用；企业类型路由未选中的板块、或尚未生成有效正文的板块，槽位均为空字符串。该交接包不得包含任何原始 MQL/Python 表格、资讯全文、企业类型布尔标记、内部审计元数据或错误对象；`key-concerns.md` 原文保持不变，渲染时只替换其中实际存在的占位符。

## 数据获取流程

1. 从用户 query 识别企业全称、简称/曾用名和可能的 完整机构代码。
2. 若 query 直接包含 完整机构代码，先采用该代码并用企业名称交叉校验；否则用 MQL 实体识别候选。候选多义时请用户确认。
3. 先读取 [references/data-sources/mql-templates.md](references/data-sources/mql-templates.md) 的当前板块模板键，再查看 [references/data-sources/mql-verification.json](references/data-sources/mql-verification.json) 对应核验记录。`ok=true` 才能作为成功证据，`ok=false` 不得作为固定模板；同时检查 `row_count`、`error`、`unresolved_metadata` 和 `rest_checks`。读取 [references/data-sources/README.md](references/data-sources/README.md)、[references/data-sources/common.md](references/data-sources/common.md) 和当前板块数据源文件。
4. 先识别实体并替换固定模板变量，使用 `scripts/render_mql_template.py --json` 渲染，再将 JSON 解码后的完整字符串传给 `Execute_MQL`。固定模板不重新生成路径、字段和过滤结构；只有模板不存在、执行失败或元数据变化时，才调用 `Get_MQL_Reference`、`Search_Business_Knowledge` 和 `Search_Context` 检索候选。动态生成时，首次 `Search_Context` 必须原样带回全部 `typeCodes`，并优先识别发行人实体（typeCode 248，代码形如 `10169711.FXR`，仅去掉 .FXR 后缀，保留完整机构代码）。无论模板还是动态候选，报表字段都必须采用 MQL Runtime 实际可绑定的字段名；不得把 Python REST 字段别名或未经确认的英文 `column_name` 直接写入 MQL。
5. 先用 `Execute_MQL` 执行企业类型判定数据集，取得 ESG、城投、科创、发债人四类标记，再按判定结果确定本次报告板块顺序。
6. 按已选的前 14 个数据板块逐板块制定 MQL 取数计划，并用 `Execute_MQL` 分别取数。每个板块必须形成独立的 `block_data_package`，包内只包含该板块的数据表、字段、过滤条件和查询结果；内部状态信息单独保存，不进入分析 prompt。禁止先取一份全局混合数据包再统一投喂所有 prompt。只有 `Execute_MQL` 返回的数据才能作为普通板块 `{{数据}}` 的 MQL 结构化事实依据。`重点关注`不执行本步骤。
7. 按已选的前 14 个数据板块逐板块制定资讯检索计划，并使用 `mx-finance-search` 获取该板块需要的公告、研报、新闻、政策或舆情信息。每个板块必须形成独立的 `block_news_package`，包内只包含该板块的检索 query、返回正文/摘要、来源分类、权威度、发布时间/来源；按 [references/news-processing.md](references/news-processing.md) 排序，并在与当前板块数据组装时执行 16000 字符完整 input 上限及整条信源前缀截断。禁止把一个全局资讯检索结果统一传给所有 prompt；重点关注不建立资讯包。
8. 逐个普通板块读取对应 prompt，并只传入当前板块的 `block_data_package` 到 `{{数据}}`、当前板块的 `block_news_package` 到 `{{资讯}}`、当前板块允许使用的前置判定结果和该 prompt 要求的必要上下文；禁止把其它板块数据包、资讯包、内部状态或已生成正文传入当前 prompt。若某次 MQL 查询或资讯检索因效率原因同时返回多个板块可用内容，也必须先按当前板块数据源文件的配置拆包，再分别传入对应 prompt。完成前 14 个板块后，才读取 `key-concerns.md`，将已生成正文按固定 14 槽位组装为本地交接包；未选板块对应值为空，不新增 MQL 或资讯输入。
   文字分析完成并确定最终保留章节后，按 [references/visual-assets.md](references/visual-assets.md) 只为实际输出的模块追加组件；模块未被分析、正文为空或被剔除时，其组件一并不展示。组件按最终正文中的实际出现顺序连续命名为“图表N <组件名称>”。每个顶层组件必须紧跟对应板块正文之后；一个组件内部的多个图形/表格不另行编号，明确要求为独立组件的图表分别编号。组件只引用当前板块数据包的实际值；组件数据不足或来源字段未验证时跳过，不输出内部缺失说明。信用分析表格还须满足 14 个指定字段至少一个有实质内容的门槛。两类财务状况即使底层数据相同，也分别组装、分别嵌入。
   所有模块送入分析前，必须校验最终完整 input 不超过 16000 字符。重点关注对完整前序分析结果执行相同的排序与前缀截断，剔除的结果在输入副本中置空，保留已有报告正文和底稿。全部可选材料置空后固定文本仍超限时，停止该模块分析，不修改原 prompt，也不发送超限 input。
9. 若 MQL 工具可用但某条报表/指标路径不可召回、执行报错、字段不能绑定或返回缺关键日期/金额/主体标识，先用 `Search_Context` 按相同业务意图查找并执行同业务 MQL 候选；候选检索时优先保留该板块所需主体过滤和字段语义，不得仅因名字相近就采用不等价数据。仅当主路径与全部可用同业务 MQL 候选均失败、超时或缺关键字段时，该数据集才可切换到本地 Python 兜底脚本。每个数据集内部记录主路径、候选路径的尝试状态及最终来源；只把最终选定来源的有效结果传入对应板块包，不混合多候选原始行。不得因一个非关键数据集失败而放弃已取得的其他数据。企业类型判定属于关键数据集，全部 MQL 候选失败后必须先尝试 Python 兜底，兜底仍失败则停止完整报告生成。
10. Python 兜底只允许调用 Choice/东财结构化数据接口并输出本地 JSON 数据底稿；禁止调用服务端一页纸报告生成接口、禁止返回服务端整篇报告作为正文。Python 兜底结果也必须按板块拆成独立数据包，不得作为全局混合数据输入。
11. 将每一次 MQL 查询、每个 Python 兜底数据集、每次 `mx-finance-search` 资讯检索、每份用户明确提供或后续明确配置的补充资料记录为内部数据集状态，标明所属板块、占位符用途（`{{数据}}` 或 `{{资讯}}`）、过滤条件和结果状态；这些信息仅用于排序、截断和排错，不传入分析 prompt，不输出到报告正文。
12. 本次路由选中的板块（含`重点关注`）正文和视觉组件全部完成后，按 [references/report-artifacts.md](references/report-artifacts.md) 生成并校验 HTML，最终按“完整正文 → 免责声明 → 附件（HTML）”的顺序输出。

### 财务图表年度范围

普通财务状况和财务状况（债券发行人）均按“取六年、展示最近五年”准备收入趋势和利润趋势组合图：以最新已披露的完整年度报告期为终点，额外取展示首年的上一年度作为同比基期。先计算同比，再截取五个展示年度；基期不进入图表横轴、柱状系列或近五年表格。数据可比且上年值非零时，两个图均须提供五个年度的同比点，不得默认将展示首年留空。取数、缺失处理和图表校验见 [财务年度序列规则](references/data-sources/financial-general.md#财务年度序列规则)。分析 prompt 原文保持不变。

## 执行超时要求（必须遵守）

本技能的脚本可能进入耗时较长的数据获取或报告组装阶段。执行本技能下的任何脚本时，必须持续等待结果返回，并将工具层 `timeout` 设置为至少 `300000` 毫秒。

如果接口超时重试超过 10 次，则返回调用失败，中断当前生成过程，不得继续编造或改用服务端报告生成接口。

## 输出规范

- 在对话最终回复中直接输出完整、可渲染的报告正文，以 `# <企业全称>深度分析` 开始，随后展示各板块标题、完整分析段落及按视觉组件规则追加的表格/图表；Markdown 是消息排版语法，不是文件交付格式，不用代码围栏包裹报告。
- 正文结束后必须交付一个本地附件：报告正文 HTML。附件必须来自最终组装后的完整正文，文件名固定为 `<企业全称>深度分析.html`；不得交付数据底稿、prompt、运行日志或旧版服务端文件代替报告附件。
- 固定交付顺序为：完整正文 → `内容由 AI 生成，仅供研究参考，不构成投资建议。` → `**附件：**` → 紧接 HTML 附件卡片。不得再输出带文件名和 URL 的 Markdown 链接行；文件名、真实链接和下载入口由平台附件卡片展示。不得用“报告已生成/已交付，请下载查看”等完成通知代替正文或附件。
- 正文较长也须按各板块原 prompt 的篇幅要求完整展示；附件不减少正文，不以“报告路由”“核心发现速览”、章节目录或要点摘要替代完整章节。最终发送前确认回复本身已包含全部实际生成的章节正文。
- 正式报告只陈述有依据的企业事实与分析，不展示取数或数据质量说明。所有板块（含重点关注）的正文、括号、表格和注释均不得出现“字段为空”“接口未返回”“未检索到”“数据未提供/未披露”“无法判断”等因输入缺失而产生的说明；无有效材料支撑的分析角度直接略去，不凑字数。正文及附件不得出现“已通过来源链接与图表校验”“含悬浮来源弹窗与交互图表”“附件已生成”“artifact 已创建”等内部生成、验收或实现过程话术；发现后删除，不得作为正文内容输出。
- 正文、表格、图表标题、图注、脚注和附件不得出现内部取数或实现信息，包括数据库名称、数据源名称、报表/库表名称、函数名、MQL、REST、Choice、东方财富数据库、报表路径、字段名、字段代码、标签代码、内部数据包名称，以及“按某数据库口径”“根据某报表”等表述。应将内部字段转换为自然业务语言，例如将概念标签代码改写为已取得的标签名称或业务结论，将主营构成改写为“按产品/行业/地区口径”；不得把原始字段名或内部代码直接带入正文。平台提供的可点击来源标记可以按引用规则保留，但来源标记旁不得追加库表名或技术说明。
- 正文只呈现数据对应的主体、期间、单位、业务口径、变化趋势和信用分析结论。查询路径、MQL 执行状态、Python 兜底状态、报表函数及字段映射只保留在内部审计信息中，不得作为“数据来源”“取数说明”或解释性括号输出。
- 空值、缺字段或查询无记录不等于业务事实不存在，不得据此断言“无公开主体评级”“未纳入评级范围”“无发债记录”“无评级需求”“无担保”或“无风险”。发现此类句子时，删除缺失说明及其无依据结论，不能只删除括号而保留结论；规则和检查步骤见 [references/analysis-prompt.md](references/analysis-prompt.md#成文输出检查)。
- 只输出路由规则选中且有有效正文的板块，顺序不得调换。先完成板块路由和空章节剔除，再在最终组装时统一生成二级标题，格式为 `## <中文汉字序号>、<展示板块名>`。序号只按本次实际输出章节的位置，从一开始连续递增；未选中或无正文的板块均不占号。禁止沿用模块清单、数据源文档章节号、重点关注交接槽位或单板块结果中的固定序号，具体步骤见 [最终章节编号](references/analysis-prompt.md#最终章节编号)。
- 发送正文前逐一核对所有板块标题：第一章为“一”，后一章比前一章递增一，不跳号、不重号。例如财务状况已是第六章，且随后三个板块均有正文时，必须输出 `六、财务状况 → 七、信用分析 → 八、司法风险 → 九、重点关注`，不能跳到“十三、信用分析”。若又略去其中任一章节，必须对剩余章节重新连续编号。
- 输出标题中的展示板块名默认等于路由板块名；但 `财务状况（债券发行人）` 输出为 `财务状况`，`定价分析（债券发行人）` 和 `定价分析（城投）` 均输出为 `定价分析`，不得带括号及括号内内容。内部路由、prompt 映射和数据包 `block_name` 仍使用完整路由板块名，以区分不同分析路径。
  - 分析报告正文中须可查看溯源：使用平台原生可点击引用，紧跟其支持的句子或独立事实分句，随后继续本段正文。对每个有原始来源支持的事实句，必须把 `[source:N]` 标记逐句挂载到对应的事实句之后，再由平台渲染为可点击引用；不得只在段落末尾或章节末尾统一补标。每个来源标识必须绑定真实、可解析、可跳转的原始网页 URL；不同句子分别对应来源，即使共用同一来源也逐句标注；同一句或同一位置由多个来源支持时，可以分别显示多个来源标识，不限制来源数量，但每条来源都必须与对应事实绑定。平台未提供真实 URL 时，不得填空链接、内部编号或编造 URL 代替。禁止把整段引用统一堆在段落末尾、章节末尾或报告末尾。段落最后一句的引用只能支持该句，不能代替前面各句的引用；具体规则见 [句内溯源规则](references/analysis-prompt.md#句内溯源规则)。
- 某个已选板块仅部分材料为空时，只分析其余有效材料；数据和资讯均无可用内容时，按该板块 prompt 返回内部结果 `暂无数据`，正式报告不输出该章节、空标题或缺失说明，重点关注对应槽位传空字符串。若 prompt 未提供，停止生成并说明该板块提示词尚未配置。
- 整份报告没有任何可用数据时，返回 `暂无数据`。
- 结尾另起一行写：`内容由 AI 生成，仅供研究参考，不构成投资建议。`

## 异常处理

以下异常用于执行控制和内部排错，不写入正式报告章节。关键判定或必要配置失败导致无法生成完整报告时，单独向用户说明任务未完成，不伪装成企业信用结论；非关键字段缺失按输出规范略去对应分析。

| 异常场景 | 处理方式 |
|---|---|
| 企业名称缺失或多主体未确认 | 请用户补充/确认，确认前不取数 |
| 机构代码解析失败或候选多义 | 展示候选并请用户确认，不猜测 |
| ESG 证券代码或评分关键字段缺失 | 先用 MQL 补取证券代码和 ESG 明细，并继续尝试同业务候选；全部 MQL 候选失败后再用 Python REST 兜底；仍无法确认则标记判定未完成并停止完整报告；只有查询正常完成且评分为空才判为不在范围 |
| 城投/科创/发债人关键判定字段缺失 | 先用 MQL 补取 `企业F9_机构基本信息` 并尝试同业务候选；全部 MQL 候选失败后再用 Python REST 兜底查询 `RPT_COP_ORG_INFO`；仍缺失则停止完整报告生成 |
| MQL 工具不可用 | 无法执行 MQL 候选时，按板块切换本地 Python 数据兜底；兜底未配置时如实说明 |
| MQL 单个数据集报错或字段缺失 | 先尝试该数据集已登记及动态发现的同业务 MQL 候选；全部候选失败后才使用该数据集 Python 兜底。其他板块和已成功数据继续使用，仍需保持板块数据包隔离 |
| mx-finance-search 单个板块检索失败 | 仅将该板块 `{{资讯}}` 记为空或失败，并按 prompt 规则生成/跳过资讯相关内容；不得用其它板块资讯替代 |
| Python 兜底脚本返回失败 | 原样说明失败原因，不调用服务端报告生成接口 |
| 板块 prompt 文件缺失 | 不生成该板块，提示对应 prompt 尚未配置 |
| 数据为空 | 不编造；按板块 prompt 或输出规范处理 |
