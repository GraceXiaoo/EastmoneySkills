# 重点关注数据源

### 15. 重点关注

MQL 验证状态：不适用。本模块只读取已生成的前序分析结果，不为核验而新增取数。

状态：已配置为本地分析结果交接。固定收尾板块之一，不使用 MQL、不使用 Python 原始数据兜底、不使用 `mx-finance-search` 资讯。

#### 15.1 输入范围

重点关注必须在前 14 个板块已经按路由顺序完成分析后生成。输入固定包含以下 14 个槽位，顺序不可改变：

```text
基本情况
股东情况
所处行业
经营状况
ESG分析
财务状况
财务状况（债券发行人）
发行概述
定价分析（债券发行人）
定价分析（城投）
科创能力
偿债分析
信用分析
司法风险
```

每个槽位只能放对应板块已经生成的分析正文及其逐句对应的有效原始引用。企业类型路由未选中的板块必须传入空字符串；已选但没有生成有效正文的板块也传入空字符串，不得用该板块的原始 MQL 表格或其它板块内容补位。保留正文中有原始材料绑定的引用，不做统一清除；总结时按每句实际依据重新对应引用，禁止集中堆在段末。内部审计信息不进入交接包，具体见 [句内溯源规则](../analysis-prompt.md#句内溯源规则)。

`key-concerns.md` 当前原文中的 `{{股东股权内容}}`、`{{所处行业内容}}`、`{{经营状况内容}}`、`{{ESG分析内容}}`、`{{科创能力分析}}`、`{{财务状况（债券发行人）内容}}`、`{{发行概述内容}}`、`{{定价分析（城投）内容}}`、`{{定价分析（债券发行人）内容}}`、`{{偿债分析内容}}`、`{{财务状况内容}}`、`{{信用分析内容}}`、`{{司法风险内容}}` 由对应分析正文替换；前 14 槽位仍保留 `基本情况`，但因用户原文 prompt 没有 `{{基本情况内容}}` 占位符，不擅自修改 prompt，也不强行插入该内容。

#### 15.2 交接包边界

本板块唯一输入数据包为 `key_concerns_context`，结构化内容包括：

```json
{
  "analysis_results": {
    "基本情况": "",
    "股东情况": "",
    "所处行业": "",
    "经营状况": "",
    "ESG分析": "",
    "财务状况": "",
    "财务状况（债券发行人）": "",
    "发行概述": "",
    "定价分析（债券发行人）": "",
    "定价分析（城投）": "",
    "科创能力": "",
    "偿债分析": "",
    "信用分析": "",
    "司法风险": ""
  },
  "prompt_inputs": {},
  "active_blocks": [],
  "empty_blocks": []
}
```

`prompt_inputs` 只用于按 `key-concerns.md` 原文占位符渲染；`active_blocks` 和 `empty_blocks` 只用于校验哪些正文实际进入分析。交接包不得包含企业类型布尔标记、内部审计元数据、错误对象、原始 MQL/Python 表格或资讯全文。

#### 15.3 输入截断

最终传入本板块的完整 input 也不得超过 16000 字符，计入原提示词固定文本、企业名称、入选正文、随文原始引用和分隔文本。执行 [news-processing.md](../news-processing.md) 中的重点关注规则：

- 以每个前序模块的完整正文及其有效原始引用为一个单元，依据该模块本地输入审计记录中实际入选材料的分类、权威度、发布时间排序；多个材料取优先级最高者作为排序依据，缺失元数据不补造，审计记录不传入 prompt。
- 首个加入后超限的单元及后续全部单元均剔除，不切片、不重写摘要、不跳过后补；实际渲染仍使用原 prompt 的槽位顺序。
- 剔除结果只在本次输入副本中置空，同步更新 `analysis_results`、`prompt_inputs`、`active_blocks`、`empty_blocks`；原始 14 槽位交接包和已有报告章节保留完整。
- `基本情况`没有对应原文占位符，不强行插入，也不占用本板块 input 预算。固定文本单独超限则停止本模块分析。
