##### 财务年度序列规则

普通财务状况、财务状况（债券发行人）及其所有正式 MQL 路径、同业务 MQL 候选和 Python 兜底，统一遵循：

1. 以系统日为数据截止日，按实际报告期类型确认最新已披露的完整年度 `Y`，不能将最新季度/半年度当作年报。展示 `Y-4` 至 `Y` 五个年度，额外获取 `Y-5` 年的同口径收入和归母净利润作为同比基期。例如展示 2021-2025 年，需取得 2020-2025 年数据；2020 年只用于计算 2021 年同比，不展示。不硬编码这组示例年份；港美股按实际完整财年，不一律按自然年末。
2. 尽量在同一次 MQL 查询中覆盖六个年度；指标逐期取数时也必须包含基期。结果需校验年度覆盖与分页，不能把六条季度/半年度记录当成六年。只有五年时，先在同一来源补取展示首年的前一年，不得直接将首年同比置空；范围扩大后仍无基期，再按既有同业务候选规则寻找完整可比序列。不同候选不能只拼一条基期与原五年金额混算。
3. 同比必须比较本年度与其紧邻上一完整年度，采用相同主体、指标、合并/单体口径、币种、单位和调整版本；缺一年时不能与上一条隔年记录相除。先用未四舍五入的原始金额计算 `（本年度值 / 上年度值 - 1）× 100%`，再截取五个展示年度、换算展示单位并统一精度。当前年度为 0、上年度非零时，同比为 -100%，不是缺失；只有上年度为 0、两期任一值缺失或不可比时才保留空点，禁止补 0、插值或猜值。
4. 基期留在当前财务板块的图表计算数据中，不能在计算前被五年裁剪或分析 input 截断删掉；不作为第六年传入展示系列，也不进入近五年表格或正文的年度展示范围。文字分析 prompt 不改，仍按原要求接收本板块业务数据；图表使用同板块保留的完整计算数据。
5. 两张图分别检查五年金额和五年同比是否一一对齐。六年数据完整、可比且分母非零时，首个展示年度必须有同比点。企业历史不足或补取后仍缺少可比基期时，仅相应同比点留空，保留其余有依据的金额、同比及表格，不因基期缺失删掉整张图，也不缩短到四年掩盖缺失。趋势图仍按至少两个有效展示年度的原门槛判断。

#### 6.3 财务状况板块数据包与资讯

`financial-general.md` 的 `{{数据}}` 必须由以下两个数据集组成，并保持独立登记：

```text
financial_summary：财务摘要（报告期）或等价发行人财务指标 MQL 结果
credit_analysis：信用分析 MQL 结果
```

数据包只保留本板块需要的报告期、利润、资产负债、现金流、财务比率、评级、展望、担保与授信字段。不得把债券发行、司法、股东、主营构成或 ESG 数据混入。

财务状况图表在正文分析完成后从当前板块 `financial_summary` 单独组装，包含收入趋势组合图、利润趋势组合图和近五年财务状况表格三部分，共用一个图表标题。收入趋势组合图由营业总收入金额柱状图和营业总收入同比增长率折线图组成；利润趋势组合图由归属于母公司股东的净利润金额柱状图和归母净利润同比增长率折线图组成。按上述“财务年度序列规则”先用六年数据计算同比，再筛选五个展示年度；只要基期有效，展示首年也必须有同比点。表格按相同五个展示年度展示营业总收入、归母净利润、经营活动现金流净额、资产负债率和加权 ROE 中实际有效的指标，不包含基期。所有内容保持同一可比口径，金额指标与增长率/比例指标使用不同单位和坐标轴。财务状况（债券发行人）虽然复用同一底层来源，也必须生成自己的独立数据包和完整组件，不能复制普通财务状况已组装的图表对象。

收入趋势与利润趋势必须分别在对话中请求“生成柱状图和同比增长率折线图组合图”，并随各自请求提供五个展示年度、与其一一对齐的金额柱状系列和已计算的同比增长率折线系列、金额单位、增长率单位（%）及合并/单体口径；不让平台只拿五年金额重新计算同比，不将基期混入展示系列。平台生成的图形组件图片放在同一“图表N 财务状况”组件下。趋势组合图至少需要两个同频、同口径的有效年度报告期；报告期频率不一致或数据点不足时，只跳过对应趋势组合图，不影响另一张趋势组合图和近五年表格。近五年数据请求“生成表格”，并以 Markdown 表格格式输出，由前端渲染。

`{{资讯}}` 必须使用 `mx-finance-search`，query 固定为：

```text
<企业全名> 相关资讯 最新动态
```

示例：

```text
中国民生银行股份有限公司 相关资讯 最新动态
```

#### 6.4 Python REST 兜底

仅当本板块对应 MQL 数据集的正式路径、已验证候选和动态发现的同业务候选均执行失败、超时、元数据错误或关键字段缺失时，才允许调用本地 Python 兜底：

`fetch_financial_summary` 默认初查起日为系统年份减六年的 1 月 1 日，截止日为系统日，保留原有年报/中报等正文取数条件和最新期分支。该日期范围只是初查窗口，不等于已经取得六个年报；解析后仍需按“财务年度序列规则”校验实际财年。若最新完整年报滞后或基期早于默认窗口，可对同一企业、同一市场调用该函数并传入 `history_start`（日期类型，取基期财年的起日或更早）扩展范围；此参数只允许扩大历史范围，不缩减默认窗口，不修改脚本源码或换主体。下方 `<取数起日>` 指该实际起日。

```text
# 沪深/发行人
reportName=RPT_CUSTOM_ORGF9_FIN_SUMMARY
columns=FIN_INDICATOR1
filter=(ORG_CODE="<ORG_CODE>")(TYPE_CODE in ("1","2","3"))(DATE_TYPE_NEW in ("1"))(((REPORT_DATE>='<取数起日>')(REPORT_DATE<='<系统日>')(DATE_TYPE_CODE in ("5","6")))(|IS_NEWEST="1"))
pageNumber=1&pageSize=100&sortColumns=STD_REPORT_DATE&sortTypes=-1&source=choice&client=SW

# 港股
reportName=RPT_HKORGF9_FIN_SUMMARY
columns=FIN_SUMMARY
filter=(ORG_CODE="<ORG_CODE>")(TYPE_CODE in ("2"))(DATE_TYPE_NEW in ("1"))(((REPORT_DATE>='<取数起日>')(REPORT_DATE<='<系统日>')(DATE_TYPE_CODE in ("1","5","3","6","8")))(|IS_NEWEST="1"))

# 美股
reportName=RPT_USORGF9_FIN_SUMMARY
columns=FIN_SUMMARY
filter=(ORG_CODE="<ORG_CODE>")(TYPE_CODE in ("2"))(DATE_TYPE_NEW in ("1"))(((REPORT_DATE>='<取数起日>')(REPORT_DATE<='<系统日>')(DATE_TYPE_CODE in ("1","5","3","6","8")))(|IS_NEWEST="1"))
```

沪深接口返回的 `FIN_INDICATOR1`、港股和美股接口返回的 `FIN_SUMMARY` 均按 JSON 字符串二次解析；Python 数据包需整理为报告期行和指标键值，不得把未解析的大字符串直接冒充 MQL 字段。信用分析缺字段时，同源兜底使用 [信用分析数据源](credit-analysis.md) 的 `RPT_CUSTOM_ORG_CREDITANALYSIS`，保留 `ORG_CODE` 与 `END_DATE` 条件并裁剪本板块字段；不得用 `RPT_COP_ORG_INFO` 冒充信用分析。
