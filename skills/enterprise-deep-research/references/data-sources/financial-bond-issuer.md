# 财务状况（债券发行人）数据源

### 7. 财务状况（债券发行人）

状态：来源与普通财务状况相同，主报表存在元数据阻塞，已验证等价指标子集；详见 [MQL核验记录](mql-verification.json)。适用于城投企业或非城投发债人路径。本板块使用独立的 `financial-bond-issuer.md` prompt，但 `{{数据}}` 与 `{{资讯}}` 的来源逻辑均与普通 `财务状况` 板块一致；必须单独形成“财务状况（债券发行人）”自己的 `block_data_package` 和 `block_news_package`，不得直接引用普通 `财务状况` 已组装完成的数据包或分析结论。

#### 7.1 数据来源与 MQL 逻辑

`{{数据}}` 仅由以下两个数据集组成：

```text
financial_summary：财务摘要（报告期）或等价发行人财务指标 MQL 结果
credit_analysis：信用分析 MQL 结果
```

两组数据的 MQL 路径、真实字段名、财务摘要元数据冲突处理、等价指标切换规则和 Python REST 兜底，全部沿用[financial-general.md 第 6 节](financial-general.md)的配置。即：先尝试财务摘要（报告期）报表；若出现元数据错误，则继续用已核对的发行人财务指标 MQL，再按同业务语义动态检索并验证候选；只有全部 MQL 数据集失败、超时或关键字段缺失时，才对该数据集使用本地 Python REST 兜底。

本板块同样使用 `DATE_TYPE_NEW` 作为财务摘要合并类型字段，同一业务字段存在新旧版本时选用实际存在的 `NEW`/`new` 版本；这不减少正文和图表所需的报告期范围。完整执行[财务年度序列规则](financial-general.md#财务年度序列规则)：取最近五个展示年度及其前置一年的基期，先计算同比，再截取展示序列；基期只用于计算，不进入图表或近五年表格。

该板块不得把债券发行、债券存续、发行利率或司法数据混入 `{{数据}}`；这些数据由后续发行概述、定价分析和偿债分析板块分别取数并形成各自数据包。

文字分析完成后，本板块从自己的 `financial_summary` 数据集单独生成收入趋势组合图、利润趋势组合图、近五年财务状况表格三部分，共用一个“图表N 财务状况”标题。收入和利润组合图均由金额柱状图与同比增长率折线图组成。计算使用六年可比数据，展示仅使用最近五个年度及其同比结果；取得有效基期后，两张图的首个展示年度也必须有同比点。货币指标与比例指标分开标注；不得复制普通财务状况板块已经生成的图表对象。指标与组件结构遵循[financial-general.md](financial-general.md)。

其中收入趋势、利润趋势各自请求“生成柱状图和同比增长率折线图组合图”，并随请求提供该板块内五个展示年度、一一对应的金额柱状系列和已计算的同比增长率折线系列、单位和口径；不能只传五年金额让平台重算同比。近五年财务状况请求“生成表格”，以相同五个展示年度输出 Markdown 表格，不含基期。分别判断两张趋势组合图和表格的数据充分性，一项不满足生成条件不影响其它有效部分。图形触发、数据口径及附件复用规则遵循[financial-general.md](financial-general.md)。

#### 7.2 资讯来源与 query

`{{资讯}}` 使用 `mx-finance-search`，query 与普通 `财务状况` 板块完全一致：

```text
<企业全名> 相关资讯 最新动态
```

例如：

```text
中国民生银行股份有限公司 相关资讯 最新动态
```

虽然 query 和底层检索逻辑相同，但仍需为本板块单独登记来源、单独生成 `block_news_package`，再传入 `financial-bond-issuer.md`；不得把普通 `财务状况` 的资讯包直接复用到本板块。
