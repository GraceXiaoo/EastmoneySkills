#### 10.2 区域对比：`RPT_CUSTOM_DEBTREMOVE_REGION_COMPARE`

区域对比的主体筛选逻辑为：先从企业基本信息取得发行人所在省及省级区域代码，再在区域对比报表中取该省记录，并保留全国排名。至少需要覆盖以下指标：

- 区域经济：GDP、人均 GDP、GDP 占比、国家级园区数；
- 区域财政：一般公共预算收入、财政自给率、政府性基金收入、上市公司数量；
- 区域债务：负债率、债务率（宽口径、全辖）、区域城投债券余额增速、城投短期有息债务占比、区域高收益债务占比；
- 区域土地：常住人口、二手房均价、城投债最高收益率、国有资本经营收入对区域债务覆盖率；
- 区域债务地位：发债规模占比；
- 日期与排名：指标对应 `END_DATE`/数据日期，以及省级数值对应的全国排名和排名分母。

已确认加载列为 `地区编码`（AREA_CODE，来自基本信息的省份编码）和 `截止日期`（END_DATE）。END_DATE 是期间选择器：年度转 YYYY-12-01、季度转季末月份的 01 日、月度转该月 01 日，不直接使用 `END_DATE<=系统日` 代替。省份不等于注册城市，不传机构代码充当地区编码。

返回列只有 `地区编码、指标名称、指标类型、指标值、全省排名、全国排名`，期间应在来源条件中保留；没有返回日期或排名分母时不能编造。本轮江苏省 320000、2025-12-01 的带后缀/无后缀路径均报“报表服务请求失败”，不能视为区域数据为空。

查询时以系统日为上限，取不晚于系统日的最新有效区域期间；若同一指标存在多个日期，保留最新有效日期对应的数值和排名。空指标保持为空，不以排名或其他指标倒推数值。

实际路径：`Choice报表\报表指标\Choice金融终端\企业F9\企业一页纸\城投企业一页纸专项数据\区域对比\区域对比|RPT_CUSTOM_DEBTREMOVE_REGION_COMPARE`。

#### 10.4 主体利差：`RPT_BOND_ISMARGIN_ORGM`

用户确认以下三个字段语义不同，必须保留实际大小写并分别绑定：

| 物理字段 | 含义 | 本板块用法 |
|---|---|---|
| `StartDate` | 查询数据范围的开始日期 | 近 12 个月窗口的起点，取系统日前一个公历年的对应日期；闰日落到非闰年时取 2 月 28 日 |
| `EndDate` | 查询数据范围的截止日期 | 与 `StartDate` 成对设置，定义返回数据的查询范围，默认取运行时系统日 |
| `TDATE` | 查询结果中债券存续口径的截止日期 | 只控制纳入结果的债券自身截止口径，不是查询范围端点，也不是利差观测日期；仅按明确指定或已核实的接口默认口径使用 |

不得把 `TDATE` 替代为 `StartDate` 或 `EndDate`，也不得把 `TDATE` 当作返回记录的交易日期。`StartDate` 与 `EndDate` 必须成对表达查询范围；未明确存续债截止日时，不猜测 `TDATE` 取值。如果接口要求必传且没有已核实的默认值，登记该条件待确认，不删除必需条件后声称完成查询。

2026-09-30 该函数已召回，但 `EndDate` 和 `TDATE` 两个加载过滤字段均映射为 `截止日期`，执行报 `REPORT_METADATA_INVALID`。这是不同语义参数的中文绑定名冲突，不能合并成一个字段；冲突发生在 Runtime 元数据层，不是把两个业务条件写成同一字段即可解决。再次执行须核对 `StartDate`、`EndDate`、`TDATE` 各自的唯一绑定；若重名仍在，应先用 `Search_Context` 查找并执行同业务利差候选，全部 MQL 候选仍失败后才对本数据集尝试同源 Python 兜底，不能因本地明确了字段语义就声称 MQL 已跑通。

主体利差按当前发行人主体筛选，设置 `StartDate=<系统日前一个公历年对应日>`、`EndDate=<系统日>`，并单独保留所采用的存续债截止口径。具体发行人代码字段和返回交易日期字段以 `Search_Context` 返回的 MQL Runtime 实际绑定名称为准。按附件逻辑同时取两类结果：

- 最新交易日：系统日前最新一个有效主体利差交易日及其主体利差（BP）；
- 月度序列：近 12 个月每月最后一个有有效主体利差数值的日期及其利差，并额外保留窗口内最新有效日。

区域利差和主体利差必须保留各自来源、日期、单位和筛选条件，不能把主体利差当作区域利差，也不能把最新交易日数值覆盖月度序列。

#### 10.5 Python REST 兜底

仅当本板块对应 MQL 数据集的正式路径、已登记或动态发现的同业务候选均执行失败、超时、字段元数据不可绑定或关键字段缺失时，才允许使用本地 Python REST 兜底。三张报表的 REST 函数名如下，但具体筛选字段和日期字段仍不得凭经验写死：

```text
# 区域对比
reportName=RPT_CUSTOM_DEBTREMOVE_REGION_COMPARE
columns=ALL
filter=(AREA_CODE="<省份编码>")(END_DATE='<期间选择值 YYYY-MM-01>')
# 元数据已确认，REST 可用性尚未验证；不得登记为成功兜底

# 区域利差时间序列
reportName=RPT_CUSTOM_DEBTREMOVE_MARGIN_ANALYSIS_TS
columns=ALL
filter=<AREA_TYPE + AREA_CODE + 日期窗口；具体字段待 Search_Context 核对>

# 发行人主体利差
reportName=RPT_BOND_ISMARGIN_ORGM
columns=ALL
filter=(ORG_CODE="<ORG_CODE>")(StartDate='<系统日前一个公历年对应日 yyyy-MM-dd>')(EndDate='<系统日 yyyy-MM-dd>')
# 明确指定存续债截止日时，另加 (TDATE='<存续债截止日 yyyy-MM-dd>')，不自动复制 EndDate
# StartDate/EndDate 控制查询范围，TDATE 控制存续债口径；三者均不是观测日期
# 已同步本地兜底实现，更新后的线上请求仍待验证
```

Python 整理时必须生成三个独立数据集：`pricing_urban_region_compare`、`pricing_urban_margin_analysis_ts`、`pricing_urban_issuer_margin`。在未确认三张报表可用 REST 字段和枚举前，兜底只能返回空状态及明确错误，不得编造区域经济、财政、利差或排名数据。

主体利差必须使用已核对的返回交易日期字段，选取每月最后一个有效利差日，不依赖接口行顺序。即使返回数据包含 `TDATE`，也仅保留其存续债截止日语义，不得用于交易日期识别、窗口筛选或月末抽样；`StartDate`、`EndDate` 同样不得作为观测日期。缺少真实观测日期/利差或全部落在窗口外时，不得回退使用未过滤的原始记录；失败原因仅保留在内部审计中。
