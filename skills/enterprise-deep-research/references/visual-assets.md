# 报告视觉组件

本文件规定正文报告中的固定表格和图表。表格组件使用“生成表格”需求，并以 Markdown 表格格式输出，由前端自动渲染；图形组件按实际图形类型直接提出“生成环状图”“生成折线图”“生成柱状图”或“生成柱状图和折线图组合图”等需求，由平台生成图形组件图片。需求中不写图表引擎名称、其它技能名或图表代码。两者均属于正文内容，不是单独的 Markdown 报告文件，也不能替代对应板块的文字分析。组件只使用当前板块独立的 `block_data_package`，不得重新取数、调用旧版服务端或把其它板块数据混入。组件严格隶属于对应分析板块：只有该板块被企业类型路由选中、实际生成有效正文并保留在最终报告中时，才允许生成它的组件；板块未选中、正文为空或被最终组装剔除时，该板块的所有图表和表格一并省略，即使数据包里有数据也不单独展示。

## 图表名称与编号

本技能将下列表格和图形统一作为“图表”组件处理。组件标题必须使用“图表N <组件名称>”格式，其中 `N` 为本次报告中实际生成组件的连续编号，从 1 开始。编号按组件在最终正文中的实际出现顺序分配；组件因数据不足而跳过时不占用编号，也不补空图。组件名称固定如下：

| 所属板块 | 组件名称 |
|---|---|
| 股东情况 | 股东情况 |
| 经营状况 | 经营状况 |
| ESG分析 | 一级指标评级明细 |
| 财务状况 | 财务状况 |
| 财务状况（债券发行人） | 财务状况 |
| 发行概述 | 发行概述 |
| 定价分析（债券发行人） | 发行人监控 |
| 偿债分析 | 负债结构 |
| 偿债分析 | 发行与到期统计 |
| 信用分析 | 信用分析 |
| 司法风险 | 司法风险 |

两类财务状况均需独立生成组件；即使组件名称相同，也必须分别按实际出现顺序分配不同的图表编号。图表编号是正文组件编号，不是章节编号；附件中的图表标题、编号和正文必须保持一致。

所有图表必须紧跟所属板块的正文之后放置，不得集中放在报告末尾，不得放入其他板块，也不得插入该板块正文段落之间。先确认所属板块在最终正文中确实存在，再检查组件自身的数据充分性；不得预生成未选中板块的图表、表格或附件组件。表格按“生成表格”需求以 Markdown 格式输出；图形按图形类型以“生成环状图”“生成折线图”“生成柱状图”或“生成柱状图和折线图组合图”等需求触发平台图形组件。经营状况的环状图和表格、ESG/发行概述/发行人监控/信用分析/司法风险的表格，以及财务状况组件内部的三部分，均属于一个顶层图表组件，不分别占用图表编号。偿债分析的“负债结构”和“发行与到期统计”是两个独立组件，分别占用图表编号，并依次排列。

## 组件规则

### 主要股东表格

组件标题使用“图表N 股东情况”。

- MQL 数据源优先使用完整路径 `Choice报表\报表指标\Choice金融终端\企业F9\企业一页纸\股东股权\股东明细\股东明细\主要股东|789604172179402`，按企业发行人代码和截止日期查询。主路径字段为 `股东名称`、`持有数量/金额`、`持有比例(%)`、`股东是否为发行人`，并按持有比例降序取前 15 行。
- 表格固定展示四列：股东名称、持有数量(股)、持有比例(%)、股东是否为发行人。将接口返回的合计行移到最后，股东名称显示“合计”；`股东是否为发行人` 返回 `1` 显示“是”，空值显示“-”。不得自行汇总前十大生成合计；接口未返回合计行时不补造。
- 不展示持股变动数、持股比例变动或其它字段。持股数量和比例按接口原始单位展示；不得把内部字段名或技术字段代码写入表头、表注或正文。
- 表格紧跟股东情况正文之后，始终保留四个固定列；`股东是否为发行人` 没有具体值时显示“-”，不编写“字段为空”等说明，也不以其它数据补齐。股东名称、持有数量和持有比例均无具体值的明细行不展示。

### 经营状况图表

组件标题使用“图表N 经营状况”。

- 一个组件内依次包含主营构成环状图和 Markdown 明细表；两部分共用同一个“图表N 经营状况”标题，不再各自编号。完成数据整理后，直接请求“生成环状图”，并在请求中提供最新报告期、单一有效口径下的分类名称、收入金额、占比和单位；不得只写“见上表”让平台自行抽取，也不得以 Markdown 表格代替环状图。明细表按“生成表格”需求输出 Markdown 表格。
- 使用经营状况数据包中最新报告期的单一口径。产品口径有有效数据时不得切换或合并地区口径；地区口径仅作为产品口径无有效数据时的替代。
- 环形图按主营业务收入构成展示。扇区数值必须使用营业收入金额（万元），仅用营业收入金额计算扇区大小；收入占比只作为显示百分比使用，不得同时把“金额+百分比”拼入同一个数值字段。优先使用接口返回的收入占比；占比不可用时，只有在项目收入同期间、同币种且数据有效时，才可按收入金额计算构成占比，并在图注注明“按收入金额整理”。先排除“合计”项目和同比增长率等派生行，再生成环状图；不把不同报告期、币种或计算方式的记录混在一起。仅展示实际项目，不为凑图虚构“其他”。
- 环状图显示规则固定为：图内标签只显示“产品名称 + 占比（%）”一次；鼠标浮窗只显示“产品名称：营业收入金额（万元）及占比（%）”一次，禁止将同一个百分比重复放在括号内外，也禁止把占比字段作为扇区金额再次显示。金额与百分比均保留接口实际精度，按统一口径格式化。
- 紧随环形图放置明细表，表头固定为：产品名称、营业收入(万元)、营业成本(万元)。产品名称使用实际披露项目名称；收入和成本按 MQL 元数据确认的单位整理为万元。若原币种不是人民币或原始单位无法确认，不得将数值标作人民币万元或自行汇率折算；保留可确认的原币种/单位。收入有具体值而成本为空时，仍保留该行和固定成本列，成本单元格显示 `-`，不输出缺失说明。
- 图注标明报告期、产品/地区口径及必要的币种/单位说明；组件紧跟经营状况正文之后，不显示数据库、报表或函数名称。

### ESG 一级指标评级明细（专项细则见下）

- 组件为表格，固定展示“所属子项、一级指标、评分”三列；数据来源及明细字段可用性按下方规则核验。
- 组件标题使用“图表N 一级指标评级明细”，紧跟 ESG 分析正文之后；不以汇总评分或资讯拼造指标明细。

### ESG 与财务组件补充规则

#### ESG 明细表

“一级指标评级明细”组件为表格，标题使用“图表N 一级指标评级明细”，固定表头为：所属子项、一级指标、评分。仅使用企业最新有效 ESG 报告期的 MQL 一级指标明细，保留来源明细粒度，不自行汇总、重算或补齐评分。`UPDATEDATE` 仅用于选择报告期，不作为表格列。明细数据的实际字段绑定须以 MQL Runtime 元数据为准并映射到三个展示列；如果当前 ESG 数据包只有评分汇总或更新时间列表、没有完整明细行，不得以汇总分或资讯代替，也不生成空表。

组件标题使用“图表N 财务状况”。普通财务状况与财务状况（债券发行人）分别从各自数据包生成独立组件，完整三部分结构见下方规则，并按正文实际出现顺序分别取得不同的 `N`。收入趋势、利润趋势使用金额柱状图与同比增长率折线图组合图；近五年财务状况以 Markdown 表格输出。

### 发行、偿债与司法组件

#### 财务状况组件的固定结构

无论普通财务状况还是财务状况（债券发行人），单个“图表N 财务状况”均按可用数据依次生成三部分：收入趋势组合图、利润趋势组合图、近五年财务状况表格。收入趋势组合图和利润趋势组合图分别同时包含金额柱状图与同比增长率折线图，并使用金额轴和增长率轴；三部分共用一个顶层图表标题，不另行编号。两类财务板块仍各自生成完整且独立的组件。三个子组件独立判断数据充分性，一项不满足趋势图条件不得导致其它有效子组件被省略。

- 收入趋势按年度展示营业总收入，利润趋势按年度展示归属于母公司股东的净利润；数据必须来自当前财务板块的同一年度、合并/单体口径和币种。实际可比指标不同的，图例明确显示实际指标名称，不按近似字段猜映射。
- 两张趋势图均执行[财务年度序列规则](data-sources/financial-general.md#财务年度序列规则)：取六年、展示最近五年。前置一年仅留作同比计算基期，先计算各年同比再裁剪展示序列；基期不进入图表横轴、柱状系列或表格。已取得有效基期时，展示首年也必须有同比点；不能默认首年留空。缺少基期先按同板块规则补取，确实缺失、上年为 0 或不可比时才留空，不补零、不插值、不用隔年数据计算。
- 收入趋势和利润趋势分别直接请求“生成柱状图和同比增长率折线图组合图”，并在各自请求中给出图表标题、五个展示年度的横轴报告期、金额柱状系列、已计算的同比增长率折线系列、金额单位、增长率单位（%）、双纵轴含义及合并/单体口径。不能仅传五年金额让平台重新计算同比。生成后分别核对金额和同比是否与五个年份对齐；数据完整且可比、分母非零时，应为五个柱值和五个同比点，不能只有后四年的折线点。不得只输出趋势数据表，或留到附件生成时才补图。至少有两个有效且可比的年度报告期才生成趋势组合图；年度与半年度/季度数据不可混画为同一年度趋势。近五年数据则请求“生成表格”并按 Markdown 格式输出。收入图、利润图和表格分别判断，一项数据不足只跳过该子组件，不影响其它有效部分。
- 近五年表格按年度逐行展示营业总收入、归属于母公司股东的净利润、经营活动现金流净额、资产负债率、加权 ROE；某项指标在当前来源不可用时，不补零或用其它指标替代。表格及两张趋势图使用一致的年度范围和口径，金额与比例单位分别标明。

### 发行概述表格

组件标题使用“图表N 发行概述”，形式为债券明细表格，紧跟发行概述正文之后。固定展示字段为：债券代码、债券简称、债券类型、债券余额、币种、发行日期、到期日期、剩余期限、最新债项评级、最新主体评级、票面利率、信用主体、所属集团。仅展示当前发行概述数据包真实返回的值；按原始定义标明债券余额、剩余期限及票面利率单位，不猜补缺失值。若路由因无有效存续债券而跳过发行概述，则不生成此组件。

### 发行人监控表格

组件标题使用“图表N 发行人监控”，仅用于`定价分析（债券发行人）`路径，形式为统计表格，紧跟该板块正文之后。按实际可用监控数据以统计周期和指标组织表格；可展示成交笔数、CFETS/交易所成交量、成交天数、平均偏离、最大正负偏离及日期、平均/最大/最小利差及日期，并保留接口实际提供的 1/7/30/90 日等统计窗口。单位、窗口、指标和数据日期须清晰。不得用拟合曲线、发行概述债券明细、其它板块数据或资讯构造监控表；监控来源/字段未返回时不生成空表。

### 信用分析表格

组件标题使用“图表N 信用分析”，仅当信用分析章节已生成有效正文时评估是否展示。按“指标 | 数值 | 指标 | 数值”组织为最多 7 行，固定字段为：最新主体评级、评级展望、变动方向、实质违约债券只数、最新实质违约债券、展期债券只数、当前逾期本息(万元)、前十大对外担保对象、银行授信总额度(万元)、银行授信已使用额度(万元)、前十大授信银行、授信机构数量、对外担保余额占净资产比例、对外担保余额占总资产比例。字段语义按信用分析数据源说明映射，评级优先使用规范化展示值。

- 展示门槛按上述 14 项逐项判断：空值、仅空白字符、`无`、`-`/`—`、`NULL`/`None`/`N/A` 以及数值零均不算实质内容；数值文本先忽略千分位、币种/单位和百分号格式再判断是否为零（如 `0.00`、`0%`、`0.00万元`）。只要至少一项不是这些占位/零值，且信用分析正文有效，即生成表格；若 14 项全部为空、为“无”或为零，则不生成表格。
- 门槛只决定表格是否出现，不把真实返回的 0 或“无”擅自改成空值；表格生成后保留可确认的实际返回值，真正空缺的单元格用 `-`，不得输出“字段为空”等解释。只有整行两项均无返回值时才可省略该行；已返回的零值、否定值及其它有效内容不得遗漏。
- 指标值仅取信用分析当前板块数据包中的对应字段，不以其它模块、资讯或分析结论补值。表格紧跟信用分析正文之后；若信用分析章节未被路由选择、未能生成有效正文或最终被剔除，整个表格不生成且不占用图表编号。

### 偿债分析图表

偿债分析正文之后依次放置两个独立图表，各自取得一个连续图表编号：

- `负债结构`：标题为“图表N 负债结构”，形式为环状图。仅使用偿债分析专属负债结构数据的同一最新有效报告期，按短期借款、长期借款、应付债券、应付票据、应付账款及其它负债项目展示实际有效构成值。直接请求“生成环状图”，并提供实际项目、金额、单位和报告期。图例标明项目、金额、单位和报告期；空值不视为零，不混入财务状况模块数据。
- `发行与到期统计`：标题为“图表N 发行与到期统计”，形式为按季度展示发行额和到期额的折线图。只有当前偿债数据包同时包含时间、币种及口径一致的季度发行额与到期额序列时才生成；直接请求“生成折线图”，并提供完整季度、发行额与到期额两组数值、单位和统计口径。若来源只提供偿债总额、到期只数或其中一个金额序列，不得将其冒充发行额/到期额，也不得生成误导性图表。
- 两个组件分别判断数据充分性，缺少一项不影响另一项；各自标明期间、单位和统计口径。

组件标题使用“图表N 司法风险”。

- 仅使用四张指定汇总表：失信被执行人、被执行人、限制高消费、终本案件。按 `TYPE` 映射为本公司、实控人、主要股东、参股控股子公司；当前与历史分列，不能相加。
- 表格列建议为：风险类型、关系主体、当前案件数、当前金额（万元）、当前未履行金额（万元）、当前未履行比例、历史案件数、历史金额（万元）、历史未履行金额（万元）、历史未履行比例。对不适用某类风险的金额列保留空白，不把另一张表的金额填入。
- 只保留至少有一个有效指标的行；不把空行渲染成“0”，不写“字段为空”等缺失说明。失信、被执行、限高和终本的金额口径必须按各自原始字段标注，禁止跨表相加或自行换算单位。
- 表格紧跟司法风险正文之后；正文无有效司法数据时不生成空表。

## 正文与附件组装

1. 先按原始板块 prompt 生成文字正文，并完成模块路由与空章节剔除；只为最终报告中实际保留的模块检查组件数据，再按最终正文中的实际出现顺序分配 `图表N` 编号并追加组件。模块未被分析或未保留时，其图表/表格一律不展示、不占编号。不得修改 `references/analysis-prompts/` 中的原始 prompt，也不得让组件规则覆盖其分析口径。
2. 组件属于当前板块正文，外层章节标题仍由最终章节编号统一生成；组件内部不得再生成“第六章”等固定编号。`财务状况（债券发行人）` 和两类定价模块的展示标题规则仍按 `analysis-prompt.md` 执行。
3. 表格按“生成表格”需求直接输出可读 Markdown 表格，由前端自动渲染；图形按类型直接提出“生成环状图”“生成折线图”“生成柱状图”或“生成柱状图和折线图组合图”等自然语言需求，并提供本板块已验证的结构化数值，由平台返回图形组件图片。无需调用其它 skill、编写图表代码或生成 Markdown 文件，也不得期待平台从长篇正文自行抽取数据。不输出组件 JSON、Python 调试对象、数据底稿路径、数据库/报表名称或 `.md` 文件。图形生成失败时，保留同源 Markdown 数据表；不得伪造图片、输出失效图片链接或用图片说明冒充图形。
4. HTML 必须从最终正文组装，并保留同样的全部已生成组件，包括股东情况、经营状况、一级指标评级明细、两类财务状况、发行概述、发行人监控、信用分析、偿债分析的负债结构/发行与到期统计及司法风险；仅保留最终正文中实际输出模块所拥有的组件，图片不得缺失或替换，附件不能重新取数或重新分析。
5. 组件生成脚本若发生接口超时，工具层 `timeout` 至少为 `300000` 毫秒并持续等待；接口超时重试超过 10 次立即中断本次生成，不用空图、假图或伪造附件替代。

## 空数据处理

组件没有足够有效数据时直接跳过该组件，继续保留有依据的正文；不输出“字段为空”“数据未提供”“无法生成图表”等内部处理信息，也不把空值解释为零或没有风险。组件使用的每一个数值都必须能回溯到当前板块 MQL 结果或同板块 Python 兜底结果。
