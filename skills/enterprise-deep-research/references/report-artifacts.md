# 报告附件交付

本文件规定 `enterprise-deep-research` 完成正文后的 HTML 附件交付流程。附件只使用本次已经组装完成的最终报告正文，不重新取数、不重新分析，也不调用其它报告技能或旧版服务端报告接口。

## 交付要求

1. 完成全部有效板块、`重点关注`、最终章节编号和视觉组件后，生成一个 `<企业全称>深度分析.html` 文件。
2. HTML 必须包含对话正文中的全部有效章节、标题顺序、分析段落、Markdown 表格、平台生成的图表组件、图表标题和免责声明。
3. 表格、图表和图注必须紧跟所属板块正文，组件编号、名称、内容、报告期、单位和图例与最终正文一致；未输出板块的组件不得写入附件。
4. 不得用摘要、目录、数据底稿、prompt、运行日志或错误日志替代正文或写入附件。
5. 正式正文及附件可见内容不得出现附件生成、验收或实现过程话术，包括“已通过来源链接与图表校验”“含悬浮来源弹窗与交互图表”及其同义改写；这类内容只能作为内部检查，不得输出给用户。
6. 附件链接必须以宿主平台实际下发的真实可访问 URL 为准，来源只能是 `DeliverAttachments` 返回值或平台注入的附件地址。URL 格式必须为 `https://llm-platform-midas.eastmoney.com/midas/share/<shareId>/assets/artifacts/<artifactId>.html`。模型侧未收到真实的 `shareId` 与 `artifactId` 时，禁止按附件 ID、任意数字、文件名或路径自行拼接 URL；此时交付行只输出 `附件：`，并紧跟平台 HTML 附件卡片，蓝色文件名链接省略，或交由前端依据卡片地址渲染。不得伪造、猜测或补全附件 URL。

## 溯源要求

- HTML 中保留真实来源名称及平台提供的真实可点击链接，链接必须指向原始 URL 或 URI，不得编造。
- 引用应紧跟其支持的事实句，不能集中移动到段落末尾、章节末尾或报告末尾。
- 生成 HTML 前，清除正文、表格单元格、图注、脚注、超链接显示文本和 `alt` 文本中的 `[source:]`、`[source:N]`、`source:` 等内部占位标记；不得删除真实来源名称或真实链接。

### 来源图标与悬浮弹窗

- HTML 正文中的每条可查看溯源，必须在对应事实句之后显示一个带有“来源”两个字的紧凑来源标识，不得只显示裸 URL、内部编号或 `[source:N]`。
  - “来源”标识必须与该事实句的来源绑定，并使用有效 `href` 或宿主平台等价跳转属性实现；每条来源必须绑定真实、可访问的原始网页 URL，并在弹窗中展示标题、时间、来源机构和该 URL。不得使用空 `href`、`#`、`javascript:`、内部 source id、工作区/会话路径或 HTML 附件自身链接替代真实 URL，也不得自行猜测或拼接 URL。
  - 如果原始材料没有真实 URL，不得生成来源图标、空链接或占位引用，也不得用内部编号代替；若该事实因此无法保留有效溯源，则不纳入 HTML。相同事实位置允许多个来源标识，不限制来源数量，并须保留全部实际绑定的来源。
- 鼠标悬浮在“来源”标识上时，显示来源弹窗；键盘聚焦或触摸设备点击该标识时，也应能打开或查看同一来源内容。
- 来源弹窗至少展示：来源序号或条目序号、来源标题、发布时间、来源名称/机构，以及可点击的真实原始链接；资讯来源有摘要或正文时，可展示与该事实相关的简短内容片段。
- 弹窗必须定位在对应“来源”标识附近，不能遮挡来源标识本身；内容较长时允许滚动，并支持移入弹窗查看。来源标识、弹窗和正文均不得出现内部审计编号、MQL、REST、数据库路径或 `[source:]` 等内部占位文本。
- 同一事实或同一正文位置有多个来源时，各来源可以分别显示“来源”标识并分别打开对应弹窗，但必须保留每条来源与对应事实的绑定关系。
- HTML 生成和验收时，逐条检查正文事实句与来源标识的绑定关系、悬浮/点击交互、来源标题和真实链接是否完整；若仅保留来源文字而无法查看链接或弹窗，则附件验收不通过。

## 生成与校验

1. 从最终正文解析标题、段落、表格、图表图片、图注、脚注和超链接，保持原有顺序。
2. 将最终正文中的 Markdown 表格转换为 HTML 原生表格；将 `**文字**` 转换为 HTML 的 `<strong>文字</strong>`（或等价的加粗标签），不得把 `**` 标记原样写入 HTML 可见文本；其它 Markdown 强调标记也须按 HTML 语义转换或清理。图表组件复用本轮实际生成的图形图片，不重新制图，不以文字或占位图替代。
3. 生成后确认文件存在、非空、浏览器可打开，中文正常显示，正文和免责声明完整，章节顺序连续。
4. 逐项核对最终正文与 HTML：每个 `图表N <名称>` 标题均出现，组件数量和顺序一致，表格未截断，图表未缺失；HTML 可见文本中不得残留成对或孤立的 Markdown `**` 加粗标记；每个来源图标均绑定真实 URL，弹窗中的每条 URL 均可点击并指向原始网页，不能跳转到 HTML 附件自身或工作区/会话路径；内部占位标记不存在。任一来源 URL 缺失、无效或不可跳转，或 Markdown 标记未完成转换时，HTML 验收不通过，不得交付该附件。
5. 若 HTML 生成或校验失败，不得伪造附件路径或附件卡片；保留完整正文并明确说明附件交付失败原因。
