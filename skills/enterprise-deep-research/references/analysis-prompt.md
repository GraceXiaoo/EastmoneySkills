# 企业深度研究本地提示词索引

本文件不再作为整篇报告的统一成文提示词。`enterprise-deep-research` 采用**每个分析板块一个独立 prompt 文件**的方式：先按 `SKILL.md` 的路由规则确定本次应生成的板块，再逐个读取对应 prompt，结合该板块 `{{数据}}` 与 `{{资讯}}` 生成内容，最后按路由顺序剔除空章节、连续编号并组装。

后续用户提供某个板块的 `analysis-prompt` 时，必须将其原文写入下表对应文件，不得改写、压缩、润色、合并或拆分用户提供的 prompt 内容。

## 存续债券路由

城投企业和非城投发债人路径在生成发行概述前，必须先完成发行一览的跨市场去重、同业存单排除和 `到期日期 >= 系统日` 过滤。查询成功且过滤结果为空时，将其视为无可用存续债券，跳过发行概述和偿债分析；财务状况（债券发行人）及对应定价分析仍按路由生成。查询失败、超时或关键字段无法核对时，存续状态为未知，不得误判为空，保留原路由。路由完成后，最终章节编号只按实际生成的章节连续排列；上述状态不写入正式报告正文。

## 通用组装流程

1. 按 `SKILL.md` 识别单一企业主体和 8 位机构代码。
2. 按 `references/data-sources/README.md`、`references/data-sources/common.md` 和后续配置的判定规则取数，形成结构化数据包。企业类型判定和每个已选的前 14 个原始数据板块的正式取数必须先走 MQL；结构化数据包必须按板块拆分为独立的 `block_data_package`，不得只形成一个全局混合数据包。重点关注不取原始数据，使用前 14 个板块成文后的本地交接包。所有固定表格和图表按 [visual-assets.md](visual-assets.md) 从其对应板块数据包另行组装。
3. 按当前板块对应的 `references/data-sources/*.md` 文件和后续配置的资讯需求，使用 `mx-finance-search` 为前 14 个原始数据板块逐板块检索资讯，形成独立的 `block_news_package`，并按 [news-processing.md](news-processing.md) 完成来源分类、权威度、发布时间排序。全部 15 个模块在最终组装时独立执行 16000 字符完整 input 上限和完整信源前缀截断；重点关注的单元是完整的前序分析结果。不得只形成一个全局混合资讯包；重点关注不建立资讯包。
4. 对每一次 MQL 查询、每个 Python 兜底数据集、每次 `mx-finance-search` 资讯检索、每份用户明确提供的补充资料记录内部状态，标明所属板块、占位符用途、过滤条件和结果状态；审计信息仅用于排序、截断和排错，不传入分析 prompt。
5. 按路由规则确定本次报告板块顺序。
6. 对前 14 个原始数据板块读取对应 prompt 文件，将当前板块的可读业务数据投影传入 `{{数据}}`，将当前板块的 `block_news_package` 传入 `{{资讯}}`，并传入当前板块允许使用的前置判定结果和该 prompt 明确需要的上下文。可读业务数据投影不得包含 `dataset`、`report`、`fields`、`filter`、`query_path`、`source`、`status`、`fallback`、数据库/报表路径、函数名或内部字段映射等审计元数据；这些内容只留在内部审计包。禁止把其它板块的原始数据、资讯或已生成正文传入当前板块 prompt。完成前 14 个板块后，重点关注改用本地分析结果交接包，不再读取 `{{数据}}` 或 `{{资讯}}`。
   实际送入分析的是通过长度校验的输入副本。信源排序后加入第 N 条超限，即剔除第 `[N, ∞)` 条；数据和资讯仍分别填入原占位符。固定提示词不改写，必要包装计入长度，最终完整 input 必须不超过 16000 字符；固定文本单独超限则停止该模块分析。重点关注的剔除结果仅在输入副本中置空，不删除原章节正文。
7. 完成各板块正文及重点关注后，先确定最终保留章节，再按 [visual-assets.md](visual-assets.md) 将每个固定表格和图表紧跟所属板块正文之后追加，不得集中放在报告末尾或插入其他板块。组件只属于其对应模块；未分析、无有效正文或最终被剔除的模块，其图表/表格一并省略。信用分析表格须额外满足 14 项指定指标至少一项有实质内容的条件。完成组件组装后，再执行下方“最终章节编号”，将完整正文按路由顺序拼接并直接写入对话最终回复；Markdown 仅用于消息排版，不生成 `.md` 报告附件。组件数据必须来自当前板块数据包，不能用组件代替文字分析。回复以 `# <企业全称>深度分析` 开始。每个板块单独输出二级标题，格式为 `## <中文汉字序号>、<展示板块名>`，标题下展示该板块按原 prompt 生成的完整分析正文及其组件，不重新压缩成摘要。`财务状况（债券发行人）` 的展示板块名为 `财务状况`，`定价分析（债券发行人）` 和 `定价分析（城投）` 的展示板块名均为 `定价分析`，其余板块展示名等于路由板块名。内部路由、prompt 映射和数据包 `block_name` 仍使用完整路由板块名。
8. 正文完成后，读取并执行 [报告附件交付](report-artifacts.md)：仅使用最终完整正文在本地生成并校验一个 HTML 附件。HTML 须保留正文、表格、图表和真实可查看的来源名称及链接；Markdown `**文字**` 必须转换为 HTML 加粗效果，不得在附件可见文本中残留 `**`。每条可查看溯源在对应事实句后显示“来源”标识，鼠标悬浮或键盘聚焦/触摸点击时显示来源弹窗。生成附件前清除 `[source:]`、`[source:N]`、`source:` 等内部来源占位标记，但不得清除真实来源链接。正文和附件可见内容不得出现“已通过来源链接与图表校验”“含悬浮来源弹窗与交互图表”等附件生成、验收或实现过程话术。按“完整正文 → 免责声明 → 附件（HTML）”的顺序交付；附件不减少正文，也不接收或写入原始数据底稿、prompt、内部审计信息或错误日志。
9. 结尾另起一行写：`内容由 AI 生成，仅供研究参考，不构成投资建议。`

## 最终章节编号

标题编号只在最终报告组装时分配，不由单板块 prompt、模块清单、数据源文档章节号或重点关注的固定 14 槽位决定。

1. 按企业类型路由顺序收集已生成的有效章节，包括有有效正文的重点关注；移除未选中的板块、空结果及内部结果为 `暂无数据` 的板块，不保留空标题或占位章节。
2. 按保留章节的位置从 1 开始编号，依次使用 `一、二、三、四、五、六、七、八、九、十、十一、十二、十三、十四、十五`。每实际输出一章才递增一次，跳过板块时不递增。
3. 使用当前位置的中文序号和展示板块名统一生成外层二级标题。单板块结果若已带外层章节标题，替换该标题，不保留旧号或叠加第二个标题；不改写原 prompt 文件、正文内容或引用。内部板块名及重点关注槽位保持不变。
4. 发送前核对最终章节数与标题数一致，序号恰好从“一”连续至最后一章，无跳号、重号；若组装或检查时删去某章，对所有保留章节重新编号。数据源中“13. 信用分析”等仅是文档索引，禁止直接转成报告标题“十三、信用分析”。

例如，本次有效章节为基本情况、股东情况、所处行业、经营状况、ESG分析、财务状况、信用分析、司法风险、重点关注时，标题应为：`一、基本情况 → 二、股东情况 → 三、所处行业 → 四、经营状况 → 五、ESG分析 → 六、财务状况 → 七、信用分析 → 八、司法风险 → 九、重点关注`。若 ESG分析被跳过，其后章节均前移一位，不保留空号。

## 报告附件交付

- 附件只在所有实际输出章节完成、最终章节编号通过检查后生成，唯一内容源是最终对话正文；不得调用旧版报告接口、重新取数或重新分析。
- 必须生成并校验一个报告正文 HTML 文件。文件名固定为 `<企业全称>深度分析.html`，附件必须包含与对话正文一致的全部章节、标题顺序、已生成的“股东情况”“经营状况”“一级指标评级明细”“财务状况”“发行概述”“发行人监控”“负债结构”“发行与到期统计”“司法风险”图表组件及免责声明；图表编号与组件内容须和正文一致。
- 最终回复中的交付顺序固定为：完整正文、`内容由 AI 生成，仅供研究参考，不构成投资建议。`、`**附件：**`，随后直接紧接平台 HTML 附件卡片。不得再输出带文件名和 URL 的 Markdown 链接行；文件名、链接和下载入口由平台附件卡片展示。若模型侧未收到真实附件地址，不得自行拼接 URL，附件卡片由平台依据实际下发地址渲染。

## 板块数据隔离规则

- 前 14 个原始数据板块对应一个且仅一个主 prompt 文件，也对应一个独立 `block_data_package` 和一个独立 `block_news_package`；重点关注对应一个 `key_concerns_context` 本地交接包，不建立 MQL/Python 原始数据包或资讯包。
- 普通板块的 `{{数据}}` 只能接收当前板块 `block_data_package`；该数据包必须优先来自正式 MQL 路径，正式路径失败后继续尝试同业务 MQL 候选，全部候选失败时才可使用同板块 Python REST 兜底包。
- 普通板块的 `{{资讯}}` 只能接收当前板块 `block_news_package`；该资讯包必须来自 `mx-finance-search` 的当前板块检索结果，检索失败则保留空包或 failed 状态。重点关注不使用这两个输入通道，而使用前 14 个已生成正文的本地交接包。
- `{{资讯}}` 传入 prompt 前，必须保留每条资讯的完整标题、元数据和正文/摘要；所有模块都只能按 `news-processing.md` 的顺序规则剔除完整超限信源及其后全部单元，不得做单条字符级截断、跳过长条目后补或跨板块补资讯。
- 普通板块的 `block_data_package.block_name` 与 `block_news_package.block_name` 必须都等于当前板块名；`prompt_file` 必须与上表映射一致。重点关注的 `key_concerns_context` 仍必须标记 `block_name=重点关注`。
- 一个板块的数据或资讯不得作为另一个板块的输入，除非当前板块对应的数据源文件明确声明该前置判定结果、上游摘要或资讯摘要允许复用；即便允许复用，也只能复用字段子集或摘要，不能传递完整原始数据包或完整资讯包。
- “重点关注”只能使用已经生成板块的结论摘要/正文及其有效原始引用，不得直接吞入全部原始数据形成第二次混合分析。它固定接收前 14 个槽位：`基本情况`、`股东情况`、`所处行业`、`经营状况`、`ESG分析`、`财务状况`、`财务状况（债券发行人）`、`发行概述`、`定价分析（债券发行人）`、`定价分析（城投）`、`科创能力`、`偿债分析`、`信用分析`、`司法风险`。未被企业类型路由选择的板块必须传入空字符串，不参与重点关注分析。重点关注不新增 MQL/Python 数据查询和资讯检索，不接收企业类型标记、内部审计元数据或错误对象。
- 若某数据表同时服务多个板块，必须按各板块数据源文件分别登记用途和字段；执行时可复用同一次 MQL 结果，但传入 prompt 前必须拆分为各板块自己的字段子集。
- 若一次 `mx-finance-search` 检索返回多个板块可用资讯，必须按板块拆分 query 结果和摘要；传入 prompt 前只保留当前板块需要的资讯子集。
- Python REST 兜底只替代失败的“当前板块当前数据集”，不得把兜底脚本输出的完整 JSON 作为所有 prompt 的共同输入。

## 成文输出检查

以下规则适用于全部 15 个板块。逐板块成文时，将这些约束作为通用成文指令与该板块原 prompt 一起执行，新增指令计入 16000 字符 input 上限；不改写任何原始 prompt 文件。

- 交付前检查最终回复本身已包含报告标题、按序编号的各章节及全部已生成正文，用户无需打开文件即可阅读；同时检查 HTML 来自同一份最终正文且已存在、非空、可在浏览器打开。不得以附件、“报告路由”或“核心发现速览”代替完整正文，不用代码围栏包裹报告。
- 标题必须通过“最终章节编号”检查：只按最终保留的章节连续编号，不能沿用资源文档或交接槽位的固定编号；每个章节只有一个外层二级标题，使用规定的展示板块名。
- 正文只写有材料支撑的事实及分析。输入缺失属于内部处理信息，正文、括号、表格及注释中均不写“字段为空”“字段缺失”“接口未返回”“未检索到”“暂无相关信息”“数据未提供”“数据未披露”“异常值”“无法判断”等缺失说明，也不改写为“信息有限”“尚待补充”等同义话语。缺少依据的分析角度直接略去，不为凑字数补充套话。
- 正文、表格、图表标题、图注、脚注和附件不得出现数据库名称、数据源名称、报表/库表名称、函数名、MQL、REST、Choice、东方财富数据库、报表路径、字段名、字段代码、标签代码、内部数据包名称，以及“按某数据库口径”“根据某报表”等技术表述。将内部字段和代码转换为自然业务语言，只呈现主体、期间、单位、业务口径、数据变化和分析结论；平台原生引用标记按句内引用规则保留，但不在其旁边追加库表名或技术说明。
- 正文、表格、图表标题、图注、脚注和附件不得出现附件生成、来源链接校验、图表校验或 HTML 实现说明，例如“已通过来源链接与图表校验”“含悬浮来源弹窗与交互图表”“附件已生成”“artifact 已创建”等；发现此类模型自述或验收话术时，直接删除整句或整段。
- 交付前对正文、表格、图表标题、图注、脚注和附件执行技术词扫描；发现数据库、报表、函数、查询路径、字段代码或内部数据包等内容时，必须改写为自然业务语言后再交付，不能仅依赖模型自行规避。
- 技术词扫描至少覆盖：`MQL`、`REST`、`Choice`、`RPT_`、`reportName`、`REPORT_FIELD`、`SetReportFilter`、`ORG_CODE`、`TAG_CODE`、`SECUCODE`、`dataset`、`block_data_package`、`block_news_package`、`query_path`、`filter`、`fields`、`source`、`fallback`、数据库/报表/库表/接口/函数/查询路径等实现性表述。扫描命中时，结合实际数值改写为主体、期间、单位、业务口径或分析结论；无法自然改写的技术片段直接删除，不得把技术名称原样交付。
- 区分“未知”与有明确依据的“无”：空值、缺列、查询零行及失败不能自动解释为零、无评级、无发行、无担保、无风险、未纳入评级范围或无评级需求。明确的数值 `0`、业务布尔值或公告事实可在其主体、日期与业务口径内使用，不扩大为全面否定或评价。评级展望、评级变动等信息缺失时，只陈述有依据的评级部分。
- 每个板块生成后、交给重点关注前，以及整篇拼接后逐句检查。若一句话包含缺失说明，核对其主句和因果结论：没有独立材料支持的结论一并删除；有依据的事实保留并改写成自然的分析语句。不机械地只删除“字段为空”等词或括号，也不误删有明确证据的负面事实。
- 例如仅有“最新主体评级、评级展望为空”时，整句“公司无公开主体评级（最新主体评级、评级展望字段为空）”均不输出；同样不能从发行或评级字段为空推出“未纳入评级范围，因此无外部评级需求”。继续分析本板块其余有效材料，无有效材料的子项及其小标题一并略去。
- 已选板块的数据与资讯均无可用内容时，原 prompt 的 `暂无数据` 仅作为内部空结果，正式报告不输出该章节或空标题，重点关注对应槽位置空；只有整份报告无任何可用数据时，才按 `SKILL.md` 返回 `暂无数据`。关键取数失败需要中断时，任务状态单独说明，不混入报告。
- 全部板块（含重点关注）统一执行下方句内溯源规则，引用紧跟对应事实句；保留分析所需的报告期、日期和单位。
- 组装输入时保留本板块材料实际返回的原始引用及其与材料的绑定关系；仅随入选材料传入最小溯源信息。内部 `sources` 审计表、本地自编 `source_id`/`source_ids`、查询错误和日志仍不传入 prompt，不能冒充平台引用；原始返回和审计信息保留在底稿。
- 每个板块生成后、交给重点关注前及最终拼接后，核对引用是否紧邻其实际支持的句子。历史正文若仅在段末集中引用，须根据原材料重新匹配到对应句子，不把整组引用复制给每句，也不简单搬到最后一句。只保留确有原始材料绑定的引用，引用位置调整不改动事实内容；章节序号仍按“最终章节编号”规则统一生成。

## 句内溯源规则

  - 使用当前平台/工具提供且可解析为可点击入口的原始引用格式。每个有原始来源支持的事实句，必须把 `[source:N]` 标记逐句挂载到对应事实句之后，再由平台渲染为可点击引用；不得遗漏事实句的来源标记，也不得把多个句子的标记统一移到段落末尾。每个可查看引用必须绑定真实、可解析、可跳转的原始网页 URL，并保留标题、时间和来源机构。不要自行绘制链接图标、编造或拼接 URL，也不将本地审计编号包装成引用；平台未提供真实 URL 时，不得填入空链接或使用内部 source id 代替，该来源不能作为可查看溯源使用。同一句或同一位置可以绑定多个来源，不限制来源数量。
- 引用放在被支持的句子之后，保持在同一段内，后面继续下一句；一句包含来自不同来源的多个独立事实时，在对应分句之后分别标注，必要时拆成短句。每个引用必须直接支持紧邻的事实，不能仅因主题相关就挂在句后。
- 不同句子即使使用同一来源，也各自在对应位置标注。同一句由多个来源共同支持时，可以分别标注多个来源，但每条来源都必须与对应事实保持绑定。禁止为简洁而将前面数句的引用合并到段末；段落末句可有引用，但仅对应末句本身。
- 正确位置示意（不是最终输出格式）：事实句甲〔甲的原始引用〕。事实句乙〔乙的原始引用〕。事实句丙〔丙的原始引用〕。不得输出为“事实句甲。事实句乙。事实句丙〔甲、乙、丙的全部引用〕”。
- 重点关注保留前序分析的真实原始引用，并按总结中每个句子的依据重新对应；只使用本次保留的前序分析，不新增取数，不将前序章节编号作为来源。纯分析判断不挂不支持该判断的引用，无有效原始引用时不得伪造入口。
- 引用不单独成行，不在段后、章节后或报告末尾追加汇总来源清单。正文引用位置保持句内；附件只保留对应的可读引用或真实可点击来源，不新增来源清单。

## 通用禁止事项

- 禁止编造数据、主体标签、评级、价格、债券发行状态、司法风险或经营结论。
- 禁止将集团、母公司、子公司、关联方、行业或其他主体数据归属于目标企业。
- 禁止把公告日、披露日或更新时间直接当作业务发生日，除非字段定义明确如此。
- 禁止用资讯数值覆盖数据库指标；使用资讯指标时必须确认实体、时间和指标名称。
- 板块 prompt 原文保持不变；统一成文时遵守上述正式报告措辞、空值处理和句内溯源规则，所有分析依据仍必须来自实际取得的材料。
