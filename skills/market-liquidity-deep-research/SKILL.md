# 宏观资金面一页纸（market-liquidity-deep-research）

按"市场解读 + 8 分析维度"框架，输出一份约 1200-1500 字（中文）的 HTML 一页纸报告，研判指定日期（无指定默认系统日期）的资金面松紧与未来 1-5 日推演。

**核心约束：取数优先全部经 MQL 相关 MCP 从 Choice 数据中心获取；当某维度数据 MQL 无法获取（报表缺失、返回为空、鉴权失败等）时，允许引用或展示外部新闻、网站或其他 API 数据，但必须在报告中明确标注来源与日期；严格区分事实、推断、建议，禁止编造数字。**

## 一、产出规范

- 交付物：单个自包含 HTML 文件（内联 CSS/JS，无外部依赖），标题与文件名统一为"宏观资金面一页纸(xxxx年xx月xx日)"
- 正文字数：约 1200-1500 字（不含图表与图注）
- 结构顺序（七段式，见 `references/html-guide.md`）：
  1. 结论摘要（3-5 条；只陈述事实性结论与未来判断，不添加"中性/偏紧/偏松"评分徽章）
  2. 资金面温度计（-2 极紧 / -1 偏紧 / 0 中性 / +1 偏松 / +2 极松，含分项评分与加权总分）
  3. 分维度分析表：| 维度 | 现状 | 驱动 | 关键指标 | 判断 | 风险 |
  4. 未来推演（1-5 日 / 1-2 周 / 节后或税期后）
  5. 跟踪清单表：| 指标 | 当前值 | 偏松阈值 | 偏紧阈值 | 信号 |
  6. 策略建议（杠杆、久期、备付、融入融出、存单、交易所）
- 语言：中文；金额单位为亿元，利率单位为 bp/% 并注明
- 页脚免责声明：本报告数据来源于 Choice 数据中心等公开渠道，仅供参考，不构成投资建议

## 二、工作流程（顺序执行，不可跳步）

### 步骤 1：确定日期
以用户指定日期为准；未指定时用系统当前日期作为报告日 `today`（YYYY-MM-DD）。

### 步骤 2：读取方法论
先读取 `references/analysis-framework.md`（分析框架、温度计、判断规则库），再读取 `references/mql-data-map.md`（取数映射、MQL 模板、后处理与容错）。**不加载这两份 reference 直接作答属于违规。**

### 步骤 3：MQL 取数
按 `references/mql-data-map.md` 的流程取数：

1. **参考查询**：调用 `Get_MQL_Reference` 获取工作流与语法约束；调用 `Search_Business_Knowledge` 检索品种与业务知识；必要时调用 `Search_Context` 确认报表路径与字段。**禁止臆造报表路径与字段名。**
2. **构造 MQL 脚本**：以 `references/mql-data-map.md` §4 的已验证模板为基线，替换日期占位符（按当前报告日计算 `start45/start30/start60` 窗口），一次 `Execute_MQL` 调用执行全部 Block。
3. **解析响应**：取 `result.content[0].text` 做 JSON 解析，导航到 `result.output.blocks[]`，按 blockId 读取各 Block 的 `column_schema` 与 `rows`。若返回 `result_file.path`，按该路径读取大结果。
4. **容错重试**：任一 Block 报"报表不存在/字段不存在"时，回到参考查询重新定位报表与字段，不得硬凑；单个 Block 失败不影响其他 Block，该 Block 对应维度改用步骤 4.5 的外部兜底或整体省略（见 `references/mql-data-map.md` §5 容错规则）。

### 步骤 4：后处理与评分
在内存中完成后处理（政策利率提取、按日汇总、利率序列、时点事件识别等，见 `references/mql-data-map.md` §4.6），再按 `references/analysis-framework.md` 执行温度计评分与 8 维度分析。

### 步骤 4.5：数据兜底（MQL 无法获取时）
按 `references/mql-data-map.md` §5 的降级规则，对 MQL 取不到（报表缺失、0 行、鉴权/网络失败等）的维度启用外部数据兜底：

1. **降级顺序**：MQL（首选）→ 外部补齐（`WebSearch`/`WebFetch` 检索权威来源，如央行官网、财政部、中国货币网、公开财经媒体、其他数据 API）
2. **引用要求**：外部数据必须可核实、标注来源名称与日期（如"据中国人民银行公告（2026-09-xx）"）；首页 meta 与页脚可将数据来源标注扩展为"Choice 数据中心与公开渠道"
3. **一致性校验**：外部来源与 MQL 已取数据冲突时，以 MQL 数据为准，冲突内容省略，不在正文展示矛盾数据
4. **不可用标注**：MQL 与外部来源均无法获取时，该维度整体省略，不写缺口说明，不猜测编造

### 步骤 5：生成 HTML
按 `references/html-guide.md` 的版式规范（配色、图表规格、段落样式）生成七段式 HTML。图表演进：央行日度净投放柱状图 + DR007 与政策利率对比折线图（有数据则必画）。

### 步骤 6：交付
将 HTML 写入工作目录（文件名：宏观资金面一页纸(xxxx年xx月xx日).html），用 `present_files` 呈现给用户，并在对话中给出简短文字摘要（资金面评级 + 核心变化点），不复述报告全文。

## 三、关键约束

- **数据红线**：取数优先来自 Choice 数据中心并经 MQL MCP 取数；某维度 MQL 无法获取且经 `WebSearch`/`WebFetch` 或其他 API 核实到权威外部数据时，**允许引用或展示**（须标注来源与日期）；禁止凭记忆输出数字，禁止编造，禁止把外部未知来源当成事实
- **来源标注**：数据来源在头部 meta（数据截至行注明"Choice 数据中心"；若使用外部兜底数据则扩展为"Choice 数据中心与公开渠道")
- **外部兜底**：MQL 取不到的数据，经 `WebSearch`/`WebFetch` 或其他 API 检索权威外部来源（央行官网、财政部、中国货币网、公开财经媒体等）后允许引用展示，在正文或图表图注中标注确切来源与日期；外部数据与 MQL 冲突时以 MQL 为准
- **政策利率**：从 OMO 明细中提取 7 天逆回购最新中标利率，禁止硬编码政策利率
- **时效校验**：确认数据是否覆盖目标交易日；非交易日使用最近交易日数据并标注日期
- **判断纪律**：不把单日净回笼或利率小幅上行直接定性为趋势收紧；跨季/缴税期偏紧属季节性，需结合历史分位数校准判断
- **缺口处理**：MQL 无法获取的数据优先走步骤 4.5 外部兜底（引用权威外部数据并标注来源）；MQL 与外部均不可得时对应维度整体省略，不写缺口说明；若 MQL 调用因鉴权/网络等系统性原因整体失败，可整体降级为外部数据源取数（`WebSearch`/`WebFetch`/其他 API），并在报告头部与页脚注明"数据来源：公开渠道"，同时提示用户检查 MQL MCP 配置（`em_api_key` 与连接器信任状态）

## 五、禁止事项

- 不展示内部评分值以外的任何推导过程；温度计分项与加权分仅作为内部依据，报告中只展示结论标签与分项状态
- 不引用未知来源的外部数据（必须经 `WebSearch`/`WebFetch`/已授权 API 核实并标注来源与日期，才可引用展示）；不硬编码政策利率；不把参考模板中的日期/数值当作当前数据使用
- MQL 为取数首选通道；仅在 MQL 无法获取（报表缺失、返回为空、鉴权/网络失败）时降级使用外部数据源（除非用户另行指示）

## 六、超时与重复调用

本 skill 为提示词型流程（无可执行脚本），调用 MQL / RAG 等 MCP 工具时须遵循以下限制：单个工具调用失败后最多退避重试 2 次（退避等待 30s / 90s）；单次调用最长等待 1200 秒，超过该时长即判定为超时失败。模型不得因失败重复调用同一 `query`，同一 `query` 累计调用不超过 2 次。若调用超时被中断或返回失败，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的重试。
