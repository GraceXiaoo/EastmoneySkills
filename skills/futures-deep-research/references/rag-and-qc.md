# RAG 素材、已知问题与质检清单（按需加载）

> 本文件在取 RAG 观点前、以及交付前自检时加载，包含：RAG 双工具关键词清单、时效性约束、已知问题与规避方案、质量检查清单、超时与重复调用规则。

## 一、RAG 双工具与调用方式

通过 `mcp_mx-ds-mcp` 连接文本能力，两个工具均只接受一个 `query` 字符串参数：

- `mx_finance_search_news`：新闻资讯、研究报告、机构观点、供需与政策讨论、市场情绪
- `mx_finance_search_notice`：交易所公告（仓单日报、风险提示、限仓/保证金调整）、产业与公司公告

**调用纪律**：不要在报告或日志中展示、复述、写入任何 API Key、密钥或内部地址；RAG 片段仅作观点素材，须标注来源类型与材料日期。

## 二、关键词清单（按合约/品种动态构造）

以 `{品种中文名}`（如「沪铜」「螺纹钢」「沪金」）与 `{品种代码}` 组合构造，每组各调用一次，合并去重：

**工具1：mx_finance_search_news**（多关键词循环，合并去重）

1. `"{品种中文名} 期货 走势 研报"`
2. `"{品种中文名} 供需 库存 仓单"`
3. `"{品种中文名} 基差 期限结构 月差"`
4. `"{品种中文名} 期货 持仓 资金"`
5. `"{品种中文名} 价格 政策 宏观 预期"`
6. `"{品种中文名} 技术面 均线 支撑 压力"`（技术面观点素材）
7. 板块/宏观增补：如 `"有色金属 板块 行情 展望"`、`"商品市场 资金 情绪"`、`"美元指数 实际利率 大宗商品"`、`"{品种中文名} 外盘 内外价差"`（按品种所属板块选择 1-2 条）

**工具2：mx_finance_search_notice**（多关键词循环，合并去重）

1. `"{品种中文名} 交易所 仓单 日报"`
2. `"{品种中文名} 保证金 限仓 公告"`
3. `"{品种中文名} 交割 公告"`

> 关键词须与合约品种对应；不要使用与品种无关的通用词。股指/国债期货以「股指期货 基差 贴水 对冲」「国债期货 基差 CTD 资金面」等替换。
> 宏观变量与外盘价格的**数值**来自 `mx_macro_data` / 综合查询（见 `mql-spec.md` 2.6），RAG 仅提供观点与解读，两者不可混用。

## 三、RAG 时效性约束

- 注入报告的材料日期须与报告生成日期 `{T}` 吻合；默认时间窗口为近 **30 天**。
- 若返回材料中最新一条日期早于 `{T-7}`（一周前），须内部标注「RAG 时效性偏离」并降低权重，优先依赖结构化数据展开分析，不得以陈旧材料作为核心论据。
- 引用 RAG 内容时标注其原始日期与来源类型（新闻/研报/公告），并区分事实、公告披露与市场观点。
- RAG 材料只用于解释市场观点，不得引入与结构化数据冲突的确定性结论；冲突时以结构化数据为准。

## 四、已知问题与规避方案

1. **单合约取数用 SetCodes 返回 0 行**：`期货F10_所有期货合约_日行情` 虽标注支持标准代码，但 `SetCodes` 实测返回 0 行。规避：改用 `SetReportFilter({交易日期} >= ... AND <= ...)` + `FILTER_ROWS({期货代码} == "{合约}")` + `Sort`。

2. **报表路径写成多反斜杠导致语法错误**：路径必须用**单个**反斜杠 `\`；工具返回 JSON 中的多反斜杠是转义表示，写入 MQL 前须确保每个路径边界只有一个反斜杠。

3. **指标路径写在双引号里导致转义报错**：指标/报表路径不得放入字符串。指标引用用 `{Choice指标\...|ID}(...)`，报表用 `ReportBlock(#1, {Choice报表\...|ID})`。

4. **ReportBlock 无输出列报错**：每个 Block 至少一条 `:` 输出列语句，否则报「每个 Block 至少需要一个输出列」。

5. **`SetWindow` 参数名易错**：时间序列读取优先用报表**日期区间过滤**，避免使用 `SetWindow`（参数名不易命中，易报「SetWindow 缺少开始时间、结束时间或周期」）。

6. **期限结构混入连续/加权代码**：同品种过滤会带出 `CU0/CUS/CUM` 等连续或加权代码。规避：只保留匹配「品种+4位数字+交易所后缀」的合约代码，再按到期月份排序。

7. **会员持仓表含汇总行**：返回行中「会员公司名称」为「本日合计 / 上日合计 / 总量增减」的为汇总行，须剔除后再取前列会员；「净多单」「净空单」互斥出现，合并为净持仓。

8. **现货价报表需内码**：`期货合约对应商品现货最新价` 只能用「证券内码(合约)」过滤，须先用行情报表取到该合约「期货内码」再查；部分合约无映射现货（0 行），省略基差小节。

9. **成交额单位**：行情报表成交额单位为万元，展示时换算为亿元（÷10000）并注明单位。

10. **数据点过多**：近 N 日序列建议控制在 60 个点以内；超过 60 个点时等间隔采样并保留端点，避免 HTML 内联数据膨胀。

11. **多图表变量冲突**：多个图表必须各自用 IIFE 包裹，避免同名 `option`/`chart` 变量互相覆盖。

12. **非交易日**：目标日无行情时顺延至最近交易日取数，并在报告中标注实际数据日期。

13. **MQL `EdbBlock` 不受支持**：宏观/产业数据不要用 `EdbBlock`，一律改用 `mx_macro_data`（见 `mql-spec.md` 2.6）；两者都取不到时省略该维度。

14. **技术指标需自算**：MA/MACD/支撑压力由行情报表的收盘价序列在内存中计算，序列不足 60 个交易日时省略 MA60 与 MACD，不臆造数值。

15. **不得输出操作指令**：不得出现建仓/加仓/减仓、目标价、止损价、仓位或对冲比例等交易指令；走势判断只做条件化情景与关键位描述。

16. **无效代码导致反复取数**：合约代码不存在时（如 `CU9999.SHF`），直接对行情/其它报表反复过滤会一直返回 0 行，或被误判为「取数失败」而触发重试，造成空转。**规避：取数前先做「存在性校验（模板 0）」**——0 行即判定代码无效，立即中断并告知用户，不做任何重试。

## 五、质量检查清单（交付前逐项自检）

1. 入参是否为**期货代码**（未用现货/股票/指数代码替代）
2. 是否已解析出合约的品种代码、交易所、合约乘数、合约简称（而非臆造）
3. 是否经 `Get_MQL_Reference` / `Search_Context` 复核了报表路径与字段未变
4. 是否完成了六类取数（合约概况、序列、期限结构、仓单、会员持仓、现货基差），并对缺失维度做了省略而非编造；是否按需经 `mx_macro_data` 补充了供需基本面、宏观资金与外盘数据
5. 是否在报告中暴露了底层接口字段名（若有须改为业务语言）
6. 是否在报告中出现任何**研报下载地址、内网地址或密钥**（不得出现）
7. 是否在 HTML 或文件名中写入了固定产物路径（不得写入）
8. 是否调用了 `mx_finance_search_news` 与 `mx_finance_search_notice`，且 RAG 材料日期与报告日期吻合、无超 30 天陈旧材料
9. 是否区分了事实、公告披露与市场观点，并标注材料日期
10. 是否没有编造缺失数据；数据不足处是否用「依据不足」表述或省略
11. 是否无「买入/卖出/持有/必涨/必跌/稳赚」等禁用表述
12. 标题是否为 `{合约简称}（{期货代码}）期货一页纸`，生成时间是否精确到秒
13. 是否包含结论摘要（3-5 条）、合约概况表、跟踪清单表
14. 图表是否符合规范（Choice 色板、红涨绿跌、emptyCircle、2px 线宽、双轴指定 yAxisIndex、每类≤1 次）
15. 多图表是否 IIFE 隔离、`resize` 是否统一重绘、`echarts` 判空是否健壮
16. 正文字数（不含图表）是否达 900-1800 字
17. 是否含免责声明，且数据来源统一表述为「数据来源：Choice数据」
18. 数据日期是否正确（非交易日是否标注）
19. 数值单位是否统一并注明（成交额亿元、价格单位等）
20. 是否含**走势判断与情景推演**段，且以条件化句式（「若……则……」）描述、未输出建仓/目标价/止损/仓位/对冲等操作指令
21. 是否含**独立且编号的风险提示**段（≥3 条）
22. 是否含**技术面**段（MA5/MA10/MA20/MA60、MACD、支撑/压力），且指标由行情序列如实计算、口径已注明
23. 是否含**参考资料**编号列表，正文以 `[n]` 上标引用且与列表一一对应，标注来源类型与材料日期
24. 若入参为品种主力合约，是否标注「主力合约」并给出交割月提示（仅提示不指令）
25. 宏观/产业/外盘数据是否取自 `mx_macro_data`（而非 `EdbBlock` 或臆造），口径与口径不明者是否已省略
26. **每一张图表下方是否均紧跟数据来源标注，且全文来源统一为「数据来源：Choice数据」（无「Choice 数据中心」等其它写法）**
27. **每张图表是否无坐标轴/图例/轴名称重叠**：`legend.top:0` 且 `grid.top` ≥ 44（两行图例取 56）、有右轴时 `grid.right` ≥ 56、`xAxis.axisLabel.hideOverlap:true`、横向柱 `grid.left` ≥ 96；未出现图例压住坐标轴或轴名压住刻度
28. **是否在取数前完成合约存在性校验（模板 0）**；若代码无效，是否已中断任务并以失败话术告知用户（未校验即取数、或对无效代码反复重试，均属违规）

## 六、超时与重复调用规则

- 单个工具调用失败后最多退避重试 2 次（退避等待 30s / 90s）；单次调用最长等待 1200 秒，超过即判定超时失败。
- **例外：合约存在性校验（模板 0）不适用退避重试**——返回 0 行即判定代码无效，立即中断并告知用户，属终态。
- 不得因失败反复重复同一 `query`；同一 `query` 累计调用不超过 2 次。
- 若调用超时被中断或返回失败，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的硬凑。
