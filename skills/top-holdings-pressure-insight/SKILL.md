# 重仓股潜在买卖压力透视

## 适用与触发场景

当请求基金申赎、基金持仓映射、重仓股潜在买卖压力、日度与近30日榜单、买入卖出 TOP20、压力榜交叉分析或同类报告生成时，优先使用本 Skill。

常见触发表达包括但不限于：

- 基金申赎压力、基金压力榜、基金申赎透视。
- 重仓股潜在买入压力、日度和近30日买卖压力、潜在卖出压力、资金压力 TOP20。
- 压力共振、持续性、方向切换、反转、行业聚集。
- 重新生成、更新、解读或优化基金压力 HTML/PDF 报告。

用户未显式说出 Skill 名称，但任务实质符合上述场景时，也应自动调用。若获取部分榜单，仍使用本 Skill 对可用数据做降级分析，并明确数据边界。

## 目标

通过 MQL 读取四张已经计算完成的 TOP20 报表，识别潜在买卖压力的持续性、边际变化、方向切换、行业聚集和产品覆盖特征，并交付 HTML 与 PDF 报告。

本 Skill 支持溯源：用户在 HTML 中 hover 可看到“点击查看原始数据”提示，click 后可查看对应报表本次实际生成的完整数据表；不向用户展示报表请求、路径或 MQL 脚本等技术细节。

## 前置环境校验

开始取数前必须检查当前环境是否具备 MQL 能力：

1. 确认存在 MQL 参考与上下文检索工具，以及可执行完整 MQL 的 Runtime 工具。
2. 读取 MQL Reference，并核对其要求的 Runtime 兼容版本与当前执行器版本。
3. 若 MQL 工具缺失、不可连接、版本不兼容且无法继续，停止取数和报告生成，明确列出缺失能力、检测结果及环境配置建议；不得虚构数据，也不得静默改用网络搜索或样例数据。
4. 环境可用后，按 MQL 工作流取得报表元数据，再执行完整脚本。不得仅凭本 Skill 内置参考跳过当次元数据确认。

## 数据源

每次正式分析必须通过 MQL 获取以下四张报表：日度潜在买入 TOP20、日度潜在卖出 TOP20、近30日潜在买入 TOP20、近30日潜在卖出 TOP20。

取数前完整阅读 [references/mql-report-reference.md](references/mql-report-reference.md)。该文件包含四张报表的完整路径、过滤条件、字段差异、可复用 MQL 和调用说明。

统一入参为 `TRADE_DATE <= 系统日期`。调用时将系统日期转换成 `YYYY-MM-DD`，在 MQL 中使用：

```mql
SetReportFilter(
    {交易日期} <= "YYYY-MM-DD"
);
```

不得使用 `SetCodes()` 或 `GetSectors()`；四张报表均不支持标准证券代码入参。

## 取数流程

1. 获取当前系统日期，并依次完成 MQL Reference、业务知识和上下文检索。
2. 在上下文结果中确认四张报表的完整路径、`reportFilterColumns`、`reportFields` 和 `reportStandardCodeSupported`。
3. 使用参考文件中的结构生成四段完整 MQL，将日期替换为当次系统日期；字段必须以当次元数据为准。
4. 分别执行四张报表，记录行数、数据日期、执行状态和报表路径。
5. 验证四张表是否齐全、日期是否一致、股票代码与简称是否匹配、是否存在重复证券、空记录或字段解析异常。
6. 将每张报表本次实际返回的完整数据行保存为 HTML 数据查看载荷。报表路径和 MQL 仅用于内部取数及核验，不得放入面向用户的点击弹层。

若单张报表失败，可对其进行一次基于明确诊断的修正重试。仍失败时，分析其余成功榜单并明确降级边界；不得把缺失榜单描述成无压力或零值。

## 超时与重复调用

脚本内部已实现有限次退避重试（最多 2 次，退避 30s / 90s），单次调用最长等待 1200 秒，超过该时长即判定为超时失败；模型不得因失败重复调用同一 `query`，同一 `query` 累计调用不超过 2 次。若命令超时被中断或返回非 0 退出码，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的重试。

## 字段规则

- 使用“股票代码带后缀”作为跨榜单匹配键，不仅凭股票简称合并。
- 保留源数据的排名、压力值、压力展示字符串、影响描述、近1年百分位、行业和基金数量。
- 日度榜没有主要贡献基金字段，不得增加关联基金空列或从近30日榜回填。
- 主要贡献基金代码和简称仅在近30日源数据实际提供时使用。
- `潜在买入/卖出压力` 为带 `%ADV` 的展示字符串；`潜在买入/卖出压力值` 为数值。不得自行重算、改写口径或据此推导实际成交。
- “持有基金数”衡量产品覆盖广度，但不能证明基金来自不同管理人，也不能称为机构共识。

## 证据充分度分层

每条榜单记录在原始压力指标之外，必须在内部基于现有字段判断证据充分度。该判断只用于筛选、排序和校准结论措辞，不作为最终报告的展示内容，不输出证据等级、覆盖等级、观察等级、评分或分布统计。

### 基金覆盖度

| 覆盖等级 | 基金数量 | 解读 |
|---|---:|---|
| 广覆盖 | 不少于20只 | 涉及基金较多，但不能据此判断管理人独立性 |
| 中等覆盖 | 5—19只 | 有一定产品覆盖，可结合其他证据观察 |
| 低覆盖 | 2—4只 | 样本有限，不宜形成强结论 |
| 单基金驱动 | 1只 | 高度集中，代表性有限 |
| 覆盖未知 | 缺失或异常 | 不评价覆盖度，不默认视为高覆盖 |

上述阈值是默认解释口径，不改变原始排名。若以后有历史回测或业务验证，可按用户确认的口径调整。

### 补充证据

仅使用现有字段识别以下补充证据：

- **跨周期确认**：同一证券同时进入日度和近30日同方向榜单。
- **方向切换**：同一证券的日度方向与近30日方向相反。
- **行业集群支持**：同一榜单、同一方向中，同一申万行业有不少于3只证券入榜。
- **极端历史位置**：源数据明确给出的近一年百分位或强度描述处于极端区间。该项属于压力强度证据，不是独立覆盖证据。

使用补充证据时遵守：

- 跨周期确认说明信号具有持续性，但不能证明资金一定执行，也不能证明机构来源独立。
- 行业集群只支持行业层面的方向判断。单只证券基金数量较少时，不得因为所属行业形成集群就把该证券升级为高代表性信号。
- 历史百分位、压力/ADV和压力排名可能来自同一上游计算体系，不得当作三个彼此独立的证据重复强调。

### 综合观察等级

在不改变原始排名的前提下，按以下规则形成内部观察等级：

| 观察等级 | 默认条件 | 使用方式 |
|---|---|---|
| 一级重点 | 广覆盖，且存在同方向跨周期确认 | 可进入核心结论，需列明基金数量与跨周期证据 |
| 二级关注 | 广覆盖但无跨周期确认；或中等覆盖且存在同方向跨周期确认 | 可进入重点观察，但表述保持审慎 |
| 三级线索 | 中等覆盖但无跨周期确认；或低覆盖但存在跨周期确认 | 作为辅助线索，不单独代表市场方向 |
| 四级异常 | 单基金驱动；或低覆盖且无跨周期确认 | 只进入低覆盖异常观察 |
| 等级未知 | 基金数量缺失或异常 | 披露数据不足，不做可信度判断 |

观察等级不因压力排名靠前而自动提高，也不因行业集群而提升单只证券的覆盖等级。

上述覆盖等级、观察等级及其数量分布属于内部推理过程。最终 HTML、PDF 和面向用户的正文不得出现“广覆盖”“中等覆盖”“低覆盖”“一级重点”“二级关注”“三级线索”“四级异常”“证据充分度概览”等内部分类标签。需要提示局限时，直接引用可核验事实，例如“仅涉及1只基金，代表性有限”。

## 核心分析

### 1. 单榜观察

分别观察四份 TOP20：

- 头部证券及压力集中程度。
- 头部与尾部的差距，是否由少数基金主导。
- 同行业、同主题或同类证券是否集中出现。
- 榜单内部是否存在明显断层、异常值或共同特征。

不得仅逐行复述榜单，应提炼最重要的结构信息。

### 2. 日度与近30日交叉

对买入榜和卖出榜分别匹配证券，重点识别：

- **持续型压力**：同时进入日度与近30日同方向榜单。
- **短期升温**：进入日度榜，但未进入近30日同方向榜单。
- **长期累积但当日降温**：进入近30日榜，但未进入日度同方向榜单。
- **压力强化或减弱**：结合排名与源数据已有指标，判断日度表现相对30日状态的边际变化。

“未进入 TOP20”只表示未出现在当前榜单中，不等于不存在压力，也不得被当作数值为零。

### 3. 买卖方向交叉

检查同一证券是否出现在不同周期、不同方向的榜单中，重点识别：

- 近30日偏买入、当日转为卖出。
- 近30日偏卖出、当日转为买入。
- 买卖方向发生切换的基金。
- 同一主题、指数或基金类别内部出现资金分化的情况。

方向切换只说明榜单信号变化。除非源数据提供充分证据，不将其解释为确定的投资者动机。

### 4. 结构归因

在字段支持的情况下，从以下维度归纳榜单特征：

- 基金类型与资产类别。
- 行业、主题、风格或跟踪指数。
- 宽基与行业主题、境内与跨境等产品结构。
- 规模层级或其他源数据已有分类。

仅对数据可以支持的维度进行分析。缺少分类字段时，可依据明确的基金名称或已知基础信息做有限归类，并标注为归纳判断。

### 5. 压力强度与证据充分度交叉

不得只根据压力排名形成结论。对头部记录同时判断：

- **高压力、证据较充分**：优先进入核心结论。
- **高压力、低覆盖**：作为异常观察，明确指出可能由少量基金映射放大。
- **压力一般、覆盖较广**：可作为结构性线索。
- **压力一般、低覆盖**：通常不进入重点观察名单。

原始压力 TOP20 保持上游顺序；内部优先选择一级、二级信号形成重点观察。三级仅作为辅助线索，四级通常不进入主要结论。

## 重点观察名单

综合四份榜单，优先形成以下观察组：

- 买入压力持续组：日度买入榜与近30日买入榜重合。
- 卖出压力持续组：日度卖出榜与近30日卖出榜重合。
- 当日买入升温组：仅进入日度买入榜，且排名或压力表现突出。
- 当日卖出升温组：仅进入日度卖出榜，且排名或压力表现突出。
- 方向反转组：日度方向与近30日方向相反。
- 主题共振组：同类、同主题或同指数产品集中进入同一方向榜单。

观察名单是数据线索，不等同于投资建议、交易信号或已实现的真实申赎结果。

核心结论的准入要求：

- 一级可以作为主要观察结论。
- 二级可以进入重点观察，但必须列明基金数量以及是否存在跨周期确认。
- 三级只作为辅助或次级线索。
- 四级不得单独作为市场方向结论，只能进入“低覆盖异常信号”。

以上等级只指导写作，不在最终报告中展示等级名称。

## 默认输出结构

### 一、核心结论

用 3—5 条结论回答：

- 当日最突出的买入和卖出压力集中在哪里。
- 近30日的主要持续方向是什么。
- 哪些证券或主题出现短长周期共振。
- 哪些证券出现压力升温、降温或方向切换。
结论生成后必须验证：
- 若存在排名靠前但仅由少量基金驱动、覆盖面有限或其他证据不足的信号，将相关限制合并为核心结论的最后一条。
- 不得把证据不足或单基金驱动作为第一条结论，也不得用它抢占报告开篇。
若不存在此类重要限制，无需强行增加负面结论。

核心结论先呈现证据相对充分、最能代表榜单结构的发现，再呈现行业特征与方向切换。重点证券可列明压力排名或压力指标、基金数量及跨周期事实，但不得展示内部覆盖等级或观察等级。不得以“排名第一”替代代表性判断。


### 二、四榜概览与明细

#### 2.1 概览

使用四个独立概览卡片分别呈现日度卖出、日度买入、近30日买入、近30日卖出。每张卡片内部按“榜单名称—头部证券—行业结构—观察摘要”自上而下排版，不得把多张榜单内容拼成一段连续文本，也不得使用 `>`、连续空格或手工制表模拟多列布局。

- 2.1 的标题、榜单名称与正文必须使用深色文字，正文颜色不得浅于 `#374151`；禁止使用低对比度浅灰正文。
- 榜单名称使用暗红色或深色加粗；证券名称、压力值和基金数量使用结构化字段或短句，不在一行堆叠多个证券。
- 四张卡片使用 CSS Grid/Flex 布局；桌面端建议两列，窄屏自动单列。
- 每张卡片最多保留 2—3 个头部证券和一条结构观察，避免概览退化成明细复述。

#### 2.2 明细榜单

四张明细表直接以“日度潜在卖出 TOP20”等榜单标题衔接表格。标题与表格之间、表格下方均不得添加“小字说明”“口径提示”“跨周期匹配说明”等辅助段落。统一口径和限制只放在报告末尾的数据说明中。

四份明细榜单按以下列规则展示：

- 日度潜在买入 TOP20、日度潜在卖出 TOP20：展示排名、证券代码、证券名称、行业、压力指标、分位描述和基金数量；可展示客观的跨周期状态，但禁止出现任何关联基金列及内部证据等级。
- 近30日潜在买入 TOP20、近30日潜在卖出 TOP20：展示核心排名、压力字段和基金数量，可展示客观的跨周期状态及源数据实际提供的关联基金代码或简称；不展示内部证据等级。

### 三、交叉观察表

至少包含：

| 证券代码 | 证券名称 | 日度方向及排名 | 近30日方向及排名 | 信号类型 | 观察要点 |
|---|---|---:|---:|---|---|

优先展示持续型、短期升温型和方向反转型证券。

### 四、结构与主题特征

总结基金类型、行业主题、指数或其他可用维度上的聚集和分化现象。

### 五、数据说明

注明：

- 数据截止日期。
- 页首数据来源统一显示为“Choice数据”。不得显示具体报表名称、MQL、取数方式或“Choice基金申赎行为-重仓股TOP20报表”等扩展描述。
- 实际取得的榜单数量。
- 缺失字段、日期不一致或异常记录。
- 结论仅基于四份 TOP20 榜单，榜外基金不代表没有压力。
- 潜在压力是情景映射，不代表资金一定执行，也不能证明机构来源独立。

- 页首元信息中的来源固定写为 `数据来源：Choice数据`，不得附加括号或更详细描述。
- HTML 必须支持 hover + click 溯源。悬停时提示“点击查看原始数据”；点击后打开弹层或侧边抽屉，直接展示对应 MQL 报表本次实际返回的数据表，而不是展示报表名称、路径、请求参数或 MQL 脚本。
- 点击单只证券或单个数值时，展示其所属榜单的完整 TOP20 数据表，并高亮对应记录；点击榜单标题时展示该榜单完整数据表；点击跨榜结论时，按涉及的榜单分标签展示各自完整数据表，并高亮所有支撑记录。
- 弹层表格字段、顺序和数值必须来自当次 MQL 实际结果，不得重新构造、改写、补值或只展示摘要。近30日榜可包含主要贡献基金列，日度榜不得出现该列。
- 所有可点击元素必须具有清晰但克制的视觉提示、键盘焦点状态和关闭机制；不得只使用浏览器 `title` 属性。
- 版式应适合桌面浏览，同时兼顾打印；长表格应有清晰表头、单位、排名和方向标识。
- 报告主色固定使用高端、低调的暗红色 `#8B1E2D`。表格表头、章节强调线、关键标题或重点组件优先使用该颜色，并搭配白色、浅灰和深灰等中性色。
- 不使用大面积高饱和红色背景；暗红色用于结构和重点强调，正文区域保持克制、清晰。
- 买入压力与卖出压力使用容易区分且色盲友好的视觉编码，不能仅依靠颜色传递含义。
- “2.1 概览”必须按独立卡片布局，正文使用深色且保证可读对比度；“2.2 明细榜单”不得出现表格之外的细小解释文字。

### PDF 要求

- PDF 内容、数字、结论和图表必须与最终版 HTML 一致。
- PDF 不要求保留交互，也不附加点击弹层中的原始数据副本；正文与 HTML 主报告保持一致。
- PDF 延续 HTML 的暗红主色 `#8B1E2D`，表头、章节强调和关键视觉元素的颜色保持一致。
- 使用支持中文的字体，避免乱码、缺字或字体替换导致的布局异常。
- 页面不得出现内容截断、表格越界、标题孤行、图表模糊或大面积无意义留白。
- 默认整份 PDF 使用单一页面方向。只要存在四榜宽表，优先整份使用 A4 横向；仅在已经用最小样例验证当前引擎确实支持混合方向时，才可使用纵向/横向切换。不得直接依赖 ReportLab 文档中途切换 PageTemplate。
- 宽表格依次通过合理列宽、表头换行、单元格换行、缩短展示列名和必要的拆表解决，不得删除关键字段，也不得用过小字号硬塞页面。
- 页眉或页脚宜包含报告名称、数据日期与页码。
- 生成后必须渲染检查各页；发现乱码、重叠、裁切或分页异常时，修正后重新生成。

### 生成与失败恢复

- HTML 是正文与数据的唯一事实源。先冻结最终 HTML 使用的数据、结论和格式化规则，再生成 PDF；不得分别维护两套数字或结论。
- 正式生成前先在目标工作目录完成最小写入测试和最小 PDF 测试。测试失败时先诊断权限、路径、依赖或引擎，不进入完整报告生成。
- 修改生成脚本时保留最近一次可运行版本。写入新文件名并通过语法检查和最小运行后，再替换旧版本；禁止先删除旧生成器再重写。
- 单次工具调用失败不等于报告内容失败。文件创建失败时缩小写入内容、确认目录与文件名并重试一次；图片分析失败时改为逐页、降低分辨率或使用其他可用查看工具。不得围绕同一失败动作无限重试。
- 不把 PyMuPDF、ReportLab 模板切换或任何单一图片分析工具视为必需依赖。按参考文件中的能力矩阵选择当前环境可用路径，并记录实际采用的路径。
- 每个失败点最多进行一次有明确变化的修正重试；仍失败则保留已经生成且验证通过的文件，说明未完成的 QA 项，不得删除可用成果或声称已通过相关检查。

### 一致性检查

交付前核对：

- HTML 与 PDF 使用同一批四榜数据和同一统计截止日。
- 两个版本的核心结论、排名、基金代码、名称和压力数据一致。
- 文件可以正常打开，HTML 无资源缺失，PDF 页数正常且文字可检索。
- 数值格式化在进入 HTML/PDF 展示层前统一完成；原始溯源数据保持源值，正文展示精度按字段类型固定，禁止因临时修复 PDF 而改变 HTML 数值。
- 最终回复中同时提供 HTML 和 PDF 文件链接，并简要说明数据日期与任何降级分析限制。

## 表达要求

- 使用中文，先给结论，再给证据。
- 对证券使用“代码 + 名称”，避免仅写简称造成歧义。
- 明确区分日度与近30日、买入与卖出，避免混称。
- 使用“潜在买入压力”“潜在卖出压力”，不得改写为已确认的实际净申购或净赎回。
- 结论必须能够回溯到四份榜单中的记录。
- 不逐条机械罗列全部数据，突出重合、反转、升温和结构集中等信息。
- 不基于榜单直接给出买入、卖出、收益预测或确定性市场判断。
- 使用“潜在压力衡量理论冲击强度，基金数量衡量产品覆盖广度，跨周期重合衡量持续性，行业集群仅支持行业层面判断”作为内部解释原则。
- 不向用户展示内部等级术语。证据相对充分时可使用“涉及基金较多”“获得跨周期确认”等事实性表述；证据不足时使用“仅涉及X只基金”“代表性有限”。
- 高压力但内部判断为三级或四级时，必须披露基金数量较少等具体原因，不得使用“市场最强买入”“机构共识”“广泛共识”或类似确定性表述。
- 推荐表述：“该证券潜在压力排名靠前，但仅涉及X只基金；即使压力/ADV较高，代表性仍然有限。”此类提示应放在核心结论最后一条。

## 边界与异常处理

- 不计算或解释上游压力指标的生成公式。
- 不把 TOP20 之外的基金默认视为无压力。
- 不把排名变化等同于压力数值同比例变化。
- 四榜统计日期不一致时，不做严格的短长周期对比，改为提示口径差异。
- 证券代码无法匹配时，不仅凭相似名称强行合并。
- 同一证券同时出现在看似冲突的榜单时，先核对日期和标识；无法解释则作为数据异常披露。
- 用户要求更深归因但四份榜单信息不足时，明确需要的补充字段或数据，不编造原因。
- 不因基金数量较多就称为机构共识；现有字段无法判断基金是否来自同一管理人。
- 不因行业集群就自动提高单只证券的观察等级。
- 不因日度与近30日同向重合就忽略低覆盖问题；持续性和覆盖度必须分别披露。
