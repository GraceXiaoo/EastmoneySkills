# MQL 取数参考

## 1. 文档用途

本文档供重仓股潜在买卖压力透视 Skill 直接参考，覆盖以下四张 TOP20 报表：

| 英文名 | 中文名 |
|---|---|
| `RPT_FUND_PAPER_TOPHOLD_DTOP20SELL` | 基金申赎行为_基金重仓股_日度潜在卖出TOP20 |
| `RPT_FUND_PAPER_TOPHOLD_DTOP20BUY` | 基金申赎行为_基金重仓股_日度潜在买入TOP20 |
| `RPT_FUND_PAPER_TOPHOLD_D30TOP20BUY` | 基金申赎行为_基金重仓股_近30日潜在买入TOP20 |
| `RPT_FUND_PAPER_TOPHOLD_D30TOP20SELL` | 基金申赎行为_基金重仓股_近30日潜在卖出TOP20 |

验证日期：2026-09-24；四张报表均按 `TRADE_DATE <= 系统日期` 成功返回最新可用交易日 2026-09-23 的 20 行数据。

## 2. 通用调用规则

- 四张报表均为 `ReportBlock`，报表路径位于 `Choice报表\报表指标\Choice金融终端\基金F9`。
- 四张报表均不支持标准证券代码入参，因此不要使用 `SetCodes()` 或 `GetSectors()`。
- 四张报表的统一入参为 `TRADE_DATE <= 系统日期`。对应 MQL 过滤字段为 `{交易日期}`，类型为 `datetime`，日期格式为 `yyyy-MM-dd`。
- MQL 写法为 `{交易日期} <= "系统日期对应的 YYYY-MM-DD"`，业务含义是取得不晚于系统日期的最新一期数据。
- MQL 本身不支持把“系统日期”作为未绑定占位符直接执行。调用方应在生成脚本时，把系统日期替换为 `YYYY-MM-DD` 字符串。
- 日度榜不提供“主要贡献基金代码/简称”；近30日榜提供。后续 Skill 不应给日度榜补造关联基金列。
- `潜在买入/卖出压力` 是带 `%ADV` 的展示字符串；`潜在买入/卖出压力值` 是可计算数值。分析时应保留两者原始口径，不自行重算。

## 7. Skill 接入建议

1. 每次运行先取得宿主系统日期，并替换四段脚本中的日期字面量。
2. 四张表分别执行，不要合并成一个报表路径；执行后检查每张表是否恰有 20 行。
3. 检查四张表返回的“交易日期”是否一致。若不一致，应披露日期差异并暂停严格的短长周期交叉比较。
4. 使用“股票代码带后缀”作为四榜匹配键；不要仅按股票简称匹配。
5. 保留报表原始排名和压力字段，不重新计算上游压力指标。
6. 日度榜只使用自身实际字段；关联基金信息仅来自近30日榜。
7. 若返回 0 行，检查是否正确传入 `TRADE_DATE <= 系统日期`，并进一步检查数据权限、报表更新状态和日期格式。
