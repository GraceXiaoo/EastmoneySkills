# 涨跌分析

围绕单只 A 股最近一个月内已经发生的上涨或下跌进行原因归纳和影响分析；涨停、拉升、放量上涨、连续上涨、走强归一为上涨，跌停、跳水、连续下跌、走弱归一为下跌。异动、波动、冲高回落、阶段性价格变化等未明确涨跌方向的表达不单独进入本 Skill。

## 标准流程

严格按以下顺序工作：

```text
读取用户原始问题
→ 判断是否存在明确涨跌归因意图
→ 判断用户指定时间是否在最近一个月内
→ 准入通过后确认单只 A 股
→ 提取原始时间、幅度、形态等上下文信息，仅保留在 original_query
→ 提取并归一化上涨/下跌方向
→ 生成规范化 execution_query
→ 调用接口
→ 校验并原样交付结果
```

不得在意图准入前生成 `execution_query`，不得把任何股票问题强制改写成涨跌归因请求。

## 一、意图准入

### 1. 允许执行

用户问题必须明确询问某只股票已经发生的上涨或下跌现象及其原因。可准入的表达包括：

- 为什么上涨、为什么下跌、为什么大涨、为什么大跌；
- 涨停原因、跌停原因、拉升原因、跳水原因；
- 放量上涨、连续上涨、连续下跌、近期走强、近期走弱的原因；
- 明确的上涨或下跌是否存在催化因素。

典型准入示例：

- `分析中际旭创今天为什么大涨`；
- `比亚迪最近为什么下跌`；
- `宁德时代连续上涨是什么原因`；
- `分析美的集团今天下跌原因和资金面`。多维问题中明确包含涨跌归因，可以只执行其中的涨跌归因专项。

以下表达不能单独触发本 Skill，只能作为时间或上下文信息：

- 今天、本周、最近、近期、某一阶段等时间词只能修饰明确的上涨或下跌问题，不能单独作为准入依据。
- 涨跌情况、价格表现、股价变化；
- 异动、波动、走势异常等未说明方向的表达；
- 是否存在催化因素但未说明对应的价格变化；
- 价格变化背后的原因、价格变化原因等方向不明表达。

例如：

- `比亚迪近期为什么下跌` → 可以进入；
- `分析比亚迪近期的价格变化原因` → 方向不明，不能直接进入；
- `比亚迪最近怎么样` → 不属于涨跌归因；
- `比亚迪是否有催化因素` → 更接近消息面，不能直接进入。

### 2. 时间范围限制

本 Skill 仅支持最近一个月内的涨跌归因。

- 用户未给出明确日期，但使用“今天、本周、最近、近期、这段时间、连续几天”等表达时，可视为最近一个月内；
- 用户明确给出日期、月份、季度、年份、节假日前后、财报发布日、某事件窗口等时间信息时，必须判断该时间距当前时间是否超过一个月；
- 若用户指定的分析时间距当前时间超过一个月，不调用脚本，不生成 `execution_query`；
- 若用户给出的时间范围横跨最近一个月内外，优先询问用户是否只分析最近一个月内的涨跌原因，不得自行截断时间范围；
- 若用户给出模糊但可能超出一个月的时间表达，且无法判断是否超过一个月，先询问用户具体时间范围，不得自行准入。

### 3. 拒绝执行

用户只提出以下任务时，不调用脚本，也不生成涨跌归因 `execution_query`：

| 用户核心意图 | 示例 | 处理方向 |
|---|---|---|
| 基本面、财务或估值 | `分析比亚迪的营收、利润和估值` | 使用基本面诊股 |
| 技术面 | `看看比亚迪的均线和支撑压力` | 使用技术面诊股 |
| 资金面 | `看看比亚迪的主力资金、换手和筹码` | 使用资金面诊股 |
| 机构观点 | `券商最近怎么看比亚迪` | 使用机构观点 |
| 消息面 | `比亚迪最近有什么公告和新闻` | 使用消息面诊股 |
| 行情数值查询 | `比亚迪今天涨了多少` | 不属于本 Skill |
| 宽泛综合诊股 | `综合分析一下比亚迪` | 使用综合诊股 |
| 超出时间范围 | `分析比亚迪去年为什么上涨`、`贵州茅台 2023 年为什么下跌` | 本 Skill 仅支持最近一个月内涨跌归因 |
| 多股比较、选股或市场热点 | `比亚迪和宁德时代哪个好` | 不属于本 Skill |

拒绝时只简要说明“当前问题不属于涨跌归因专项”，并指出合适的能力方向；不要调用其他 Skill，不要替用户完成其他维度分析。

### 4. 冲突与歧义处理

- 同时明确包含涨跌归因和其他维度：允许执行，但只返回涨跌归因专项，并说明本 Skill 不覆盖其他维度；
- 出现“怎么看、好不好、风险、机会、诊断、分析”等泛词，但没有上涨、下跌、涨停、跌停、拉升、跳水、走强、走弱等明确涨跌方向的股价变化对象：不能仅凭泛词判定为涨跌归因；
- 出现基本面、技术面、资金面、消息面或机构观点词，但用户核心问题是股价为何上涨或下跌：优先视为涨跌归因，除非用户明确要求分析该专项维度本身；
- 用户提出某个可能原因，例如“是不是因为业绩预告才涨停”：仍按涨跌归因准入，但不得把该假设直接写成确定结论；
- “异动原因”本身没有明确涨跌方向，不能直接作为涨跌归因准入依据；若用户明确说“大幅拉升、突然跳水”等带方向的异动，则分别归一为上涨或下跌；
- “冲高回落”描述的是盘中技术形态，不等同于普通下跌；默认路由到技术面，不直接进入本 Skill；
- 用户只查询价格、涨跌幅、成交额、行情走势数值，不问原因：不属于本 Skill；
- 用户明确询问上涨或下跌原因，但时间距当前时间超过一个月：不属于本 Skill 支持范围，不生成 `execution_query`；
- 用户同时给出多个时间范围，且包含超过一个月前的区间：先询问是否只分析最近一个月内的涨跌原因，不得自行改写为近期；
- 意图无法判断：先询问用户是否希望分析股价上涨或下跌原因，不得自行准入；
- 外部调用方提供的路由标签只能作为辅助信息，不能覆盖用户原话中明显相反的意图。例如用户只问券商研报，即使标签写 `price_movement`，仍必须拒绝。

## 二、股票确认

意图准入通过后再确认分析对象：

- 必须是单只沪深京 A 股；
- 用户提供中文名称时直接使用；
- 用户只提供代码时，先识别对应中文名称；
- 缺少股票时只询问股票名称或代码；
- 多只股票、港股、美股、基金或其他品种不执行本 Skill。

接口 Query 中的股票部分仅使用股票中文名称，不使用代码或市场后缀。

## 三、Query 规范化

同时维护：

| 字段 | 作用 |
|---|---|
| `original_query` | 用户输入的完整原话，用于意图判断、上下文、覆盖检查和复盘，不直接发送给接口 |
| `execution_query` | 意图准入后由本 Skill 生成，是 `scripts/get_data.py --query` 的唯一输入 |

只有在意图准入、股票确认、时间范围均通过后，才生成 `execution_query`。

规范化生成：

```text
execution_query = 分析{股票中文名称}为什么上涨
或
execution_query = 分析{股票中文名称}为什么下跌
```

字段规则：

| 字段 | 生成方式 |
|---|---|
| `{股票中文名称}` | 使用确认后的单只 A 股中文名称 |
| `{方向}` | 只允许归一为“上涨”或“下跌” |

归一化规则：

- 上涨、大涨、涨停、拉升、放量上涨、连续上涨、走强 → `分析{股票中文名称}为什么上涨`
- 下跌、大跌、跌停、跳水、连续下跌、走弱 → `分析{股票中文名称}为什么下跌`
- “大涨、涨停、连续上涨”等细节保留在 `original_query`，不进入接口 Query。
- 时间范围保留在 `original_query`，不进入接口 Query。


示例：

| `original_query` | 准入 | `execution_query` |
|---|---|---|
| `分析中际旭创今天为什么大涨` | 通过 | `分析中际旭创为什么上涨` |
| `比亚迪最近为什么下跌` | 通过 | `分析比亚迪为什么下跌` |
| `宁德时代连续上涨是什么原因` | 通过 | `分析宁德时代为什么上涨` |
| `分析贵州茅台近期异动原因` | 拒绝，方向不明 | 不生成 |
| `东方财富今天冲高回落怎么回事` | 拒绝，默认技术形态 | 不生成 |
| `分析美的集团今天下跌原因和资金面` | 通过，仅处理涨跌归因 | `分析美的集团为什么下跌` |

生成规则：

1. 接口 Query 只替换股票中文名称和上涨/下跌方向；
2. 不加入时间范围、涨停/跌停、拉升/跳水、放量、连续、走强/走弱、异动、冲高回落等细节；
3. 不拼接 `original_query`；
4. 用户原话中的时间、幅度、形态、细分现象只保留在 `original_query`，用于理解和交付覆盖检查；
5. 不加入“基本面、技术面、资金面、消息面、机构观点、全面、深入、综合”等额外词；
6. 不加入用户提出的假设性原因，例如“是不是因为业绩”“是否受政策影响”等；
7. 形成后不得再次润色、扩写或追加排他指令；
8. 本文中的用户问法示例只用于意图判断，绝不能直接作为接口 Query。

用户对某个具体原因、事件或指标有更具体的问题时，仍使用规范化 `execution_query` 获取标准结果。接口返回后检查原生正文是否覆盖该关注点；未覆盖则明确说明“本次接口结果未覆盖该具体问题”，不得自行补写。

## 四、接口执行

准入和股票确认均通过后，原样执行：

```bash
python3 scripts/get_data.py --query "{execution_query}"
```

- 默认保存普通 Markdown，不使用 `--no-save`；
- 不在调用前运行授权预检；只有实际返回授权状态时才处理；
- 退出码为 0 后仍检查正文；正文为空或包含“暂时不支持此类场景”等业务拦截文案时，判定为失败；
- 确定性业务拦截不使用相同 Query 重试；网络超时或连接中断最多使用原参数重试一次。

## 五、结果交付

- 成功时以接口 `data.displayData` 对应的完整 Markdown 为用户可见主体，不摘要、不改写结论；
- 返回普通 Markdown 路径及接口原有的 `output_path`、`raw` 等信息；
- 如调用框架支持扩展元信息，可内部附带 `original_query`、`execution_query` 和 `dimension: price_movement`，但不改变脚本响应；
- 默认不向用户展示 Query 改写过程、内部 JSON、脚本参数或绝对路径；
- 不把某项资金、消息、技术形态、基本面变化与股价同期变化直接描述为确定因果，除非接口正文已明确给出；
- 结果仅供参考，不构成投资建议，信息可能随市场变化而变化。

## 六、授权与依赖

沿用原生 Skill 的 EM API Key 读取、授权协议、依赖和错误处理，不改变凭据逻辑。

| 退出码 | 含义 | 处理方式 |
|---|---|---|
| `0` | 查询完成 | 检查并交付 Markdown 正文 |
| `10` | 需要授权 | 展示一次 `authUrl` 并停止本轮调用 |
| `2` | 网络或业务错误 | 返回明确失败原因，不编造分析 |
| `1` | 缺少 Query/stdin | 仅在意图准入通过后生成有效 `execution_query` |

授权、凭据持久化及 401 失效处理遵循 [授权协议](references/auth_protocol.md)。安装依赖时运行 `pip3 install -r requirements.txt`。
