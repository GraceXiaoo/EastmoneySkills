## 已知问题与规避方案

1. **MQL 报表路径已实测确认**：转债专项报表路径为「债券F9\专项分析\转债专项数据\存续可转债\存续可转债|826425973918861」和「到期可转债\到期可转债|826425973918861」，转债基本信息路径为「服务端\妙想服务\细分场景\可转债\转债基本信息\转债基本信息|830272205760536」。原文档中的「可转债F9\可转债信息」路径不存在。规避：首次使用时通过 `Search_Context` 的 `searchIndicator` 搜索"可转债"验证路径。

2. **取数方式必须用 SetCodes**：转债专项报表 `reportStandardCodeSupported=true` 且 `reportFilterColumns` 为空，**不能使用 `SetReportFilter`**，必须用 `SetCodes(["代码"])` 指定证券范围。规避：参照 `references/mql-spec.md` 中的脚本模板。

3. **MQL 字段名须使用含括号的完整中文名**：`REPORT_FIELD("...")` 中必须使用返回列中文名（含括号），如「转债近20日换手率（%）」「正股20日历史波动率（%）」。规避：若字段绑定报错，通过 `Search_Context` 返回的 `reportFields` 确认精确字段名。

4. **Block 编号每次调用从 #1 开始**：每次 `Execute_MQL` 调用中 Block 编号必须从 `#1` 连续递增，不能跨调用延续。规避：分批取数时每次重新从 `#1` 编号。

5. **单位转换须在客户端完成，并按精度规范保留 4 位小数**：MQL 返回的数据可能为原始单位（如发行规模为"元"），需在客户端按转换逻辑转为"亿元"或"万元"。转股溢价率需乘以100，ROE需乘以100等。所有数值字段在完成单位转换后**统一保留 4 位小数**（`toFixed(4)`），见 `references/mql-spec.md` 的「数值精度规范」。

6. **HTML 多图表变量冲突**：每个图表用 IIFE 包裹——`(function(){ var chart = echarts.init(document.getElementById('chartN')); chart.setOption(option); })()`。

7. **`in` 运算符不支持**：规避：用 `OR` 连接多个 `==` 条件替代。

8. **`Limit()` / `Top()` 不支持**：规避：使用 `OutputBlock();` 标记输出 Block。

9. **个券状态判断需优先执行**：必须先查询「转债基本信息」获取上市日期，判断个券属于新发/存续/到期，再选择对应分析模板和取数报表。

10. **数据缺失时维度跳过**：各分析维度根据数据实际提供情况决定是否输出。若某维度所需核心数据全部缺失，直接跳过该维度；若仅有部分数据缺失，仅基于已有数据展开分析，绝不编造或假设缺失数据。

11. **表格占位符替换**：JSON 中间结果的 `tables` 占位符（如 `{cbtable}`、`{stocktable}`、`{cbcxtable}`、`{cbtctable}`）须在渲染 HTML 时替换为实际 `<table>` HTML 代码。若该维度不满足表格输出条件，对应占位符省略。

## 质量检查清单

输出前必须自检：

1. 是否已通过 `Search_Context` 验证转债报表路径有效性，并使用 `SetCodes`（非 `SetReportFilter`）取数
2. 是否已先查询「转债基本信息」判断个券状态，再通过对应报表（存续/到期）获取全量指标数据
3. 是否已判断个券状态（新发/存续/到期）并选择对应分析模板
4. 是否已调用 `mx_finance_search_news` 与 `mx_finance_search_notice`（多关键词扩充）补充市场讨论
5. 是否没有编造缺失数据，数据缺失时省略或标注「依据不足」
6. 是否没有出现买入、卖出、持有、必定等禁止表述
7. 是否使用了「可能」「需关注」「若……则」「复盘显示」「或」等概率化表达
8. 标题格式是否为 `<h1>{转债简称}({转债代码})可转债研究</h1>`（英文括号）
9. 生成时间是否精确到秒（`YYYY年MM月DD日 HH时mm分ss秒`）
10. 每个段落是否由「`<h2>` 段落标题 + `<p>` 段落正文 + `<h3>` 图表标题 + `<div>` 图表容器」构成（先文后图：图表置于段落正文之后）
11. 段落标题是否根据内容二次总结凝练，而非使用固定模板标题
12. 可视化图表是否贴合段落内容（ECharts CDN 引入、Choice 色板 E001-E004、emptyCircle、2px 线宽等）
13. 每个图表是否用独立 IIFE 包裹，避免变量冲突
14. 正文分析字数（不含图表字符）是否 ≥ 800字
15. 是否包含 HTML `<table>` 数据表格（cbtable/stocktable/cbcxtable/cbtctable），且表格有 `<caption>` 表名
16. 是否未泄露任何 API Key、密钥、内部 token 或敏感配置
17. 是否所有报表数据均通过 MQL 相关 MCP 获取，而非直接调用 REST 接口
18. 是否在报告中暴露了底层接口字段名（如 CONV_PREMIUM_RATIO、BOND_VALUE 等），若有须改为业务语言
19. RAG 材料日期是否与报告生成日期吻合，是否引用了偏离超 30 天的陈旧材料
20. 单位转换是否正确执行（发行规模元→亿元、转股溢价率×100、ROE×100 等）
21. **所有数值指标是否统一保留 4 位小数**（单位转换后 `toFixed(4)`），表格单元、图表 tooltip/label/轴标签与正文引用的数值是否一致均为 4 位小数；字符串类与日期类是否原样输出未受影响
22. **输出是否为完整 HTML 文件**（含 `<!DOCTYPE html>`、`<html>`、`<head>`、`<body>`），而非 Markdown 或 JSON

## 超时与重复调用

脚本内部已实现有限次退避重试（最多 2 次，退避 30s / 90s），单次调用最长等待 1200 秒，超过该时长即判定为超时失败；模型不得因失败重复调用同一 `query`，同一 `query` 累计调用不超过 2 次。若命令超时被中断或返回非 0 退出码，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的重试。
