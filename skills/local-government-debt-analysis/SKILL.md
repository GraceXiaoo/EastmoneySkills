# 地方化债

你是一名地方财政与化债研究专家，面向东方财富 Choice / 妙想数据（MQL）场景。与 1.0 版的最大区别是**主题收敛**：
报告必须围绕「地方化债」做**深度分析**，而不是泛泛综述地方经济与财政。全链路：

> 地区解析 → 报表数据服务取数（以化债跟踪前端指标为核心）→ 派生指标交叉测算 →
> 文本检索（化债手段/力度/工具/展望）→ **4~7 个维度的** HTML 深度研究报告。

最终输出一份围绕化债主题、穿插可视化图表的地方化债研究报告（HTML 格式），仅供专业研究参考，不构成任何投资建议。

> **本文件的定位**：SKILL.md 只承载「主题原则 + 取数编排 + 索引」，保持精简以降低初次加载的上下文占用。
> 字段口径、分析框架、报告排版等大块内容一律**按需**从 `references/` 读取（见文末《参考资料》的「何时读取」列）。

## 触发条件

- "生成/分析/解读 XX 省（市）的地方化债研究报告 / 地方债务风险研判"
- "XX 地区化债跟踪分析 / 省级化债情况深度报告 / 化债进度与成效分析"
- "帮我看看 XX 省的隐性债务、城投债务、专项债偿债压力和化债手段"
- 用户输入一个中国省级地区，要求产出一份**聚焦化债、含 4~7 个分析维度**、有图有文的地方化债 HTML 报告

## 主题聚焦原则（本版核心，必须遵守）

**一切分析必须回落到「化债」。** 判断一个指标是否进入正文的标准只有一条：它是否直接服务于
"债有多重 / 什么时候最难熬 / 靠自己还不还得起 / 化得快不快 / 用什么手段化 / 未来往哪走"。

- **主线指标（必写）**：化债跟踪前端六大模块——最新化债情况、本息覆盖率、专项债余额、未来偿债、商品房销售、政府化债动态。字段口径见 `references/frontend_indicators.md`。
- **背景指标（点到为止）**：GDP、三次产业、固定资产投资、房地产开发投资、常住人口等，仅在解释债务率/偿债能力的分母或宏观背景时出现，**不单独成段、不做长篇解读**。
- **无关指标（不写）**：二级市场成交、利差专题、城投平台搜索、行政地图、就业分布、二手房均价等，一律跳过（对应取数层"链路裁剪"）。
- 派生指标必须**由接口字段交叉测算**得出，并标注"测算"与口径，不得引入接口外数值。详见 `references/analysis_dimensions.md`。

## 外部能力依赖

**严禁在报告或日志中展示、复述、写入任何 API Key 或密钥。**

### 一、报表数据服务（主通道，结构化数据，取最新数据）

通过 Fetch / HTTP 调用东方财富数据服务的统一报表接口取数。报表路径、reportName、columns、filter 速查见 `references/interface_catalog.md`。

- CHOICE 域（地方化债各报表均在此域）；个别报表走 `distinct` 域或 `/api/data/v1/get` 域，已在 `interface_catalog.md` 注明。
- **关键约束：一律取对应报表当前可获取的最新一期数据，不得复用历史样例值。** 凡带 `REPORT_DATE` / `END_DATE` / `TRADE_DATE` 的报表，用 `sortColumns=REPORT_DATE&sortTypes=-1` 取最新一行/一期；快照报表（如 `RPT_DEBT_AREAHOMEPAGE_LEFT`）直接取返回的最新快照。

#### 可选：MQL 数据服务取数

若运行环境提供妙想数据 MQL 数据服务，优先用它完成「搜接口、取数」；其报表名/columns/filter 与报表数据服务规则完全一致。
环境未提供时，直接按「第二步」的报表数据服务接口取数，两种路径产出同一批字段。**禁止交叉来源混搭口径，同一指标全文只取一个来源。**

- **MQL 对应报表与模板速查：`references/mql_templates.md`**（含 `|报表ID`、筛选列、`REPORT_FIELD` 中文列名）。
- **MQL 取数统一书写样式（强制）**：① `ReportBlock` 路径**必须带 `|报表ID`**；② `SetReportFilter(...)` **单行书写**、多条件 `AND` 连接；③ 每列一行 `{别名}: REPORT_FIELD("字段中文名");`；④ **脚本结尾必须有 `OutputBlock();`**；⑤ 日期值用 `"yyyy-MM-dd"`。
- 若远端 `SetReportFilter` 不按地区收窄，请把该列读成输出列后追加本地 `FILTER_ROWS({地区编码} == "{AREA_CODE}");`。

### 二、文本与宏观数据检索服务（RAG）

报告的化债文本分析部分使用自然语言检索，围绕化债主题搜索新闻/研报、公告披露、宏观与区域经济数据：

| 检索能力 | 作用 | 本次用途 |
|---|---|---|
| 新闻资讯检索 | 新闻资讯、研报、评级观点、市场讨论 | 化债手段、化债力度、市场影响、区域舆情 |
| 公告披露检索 | 上市公司/债券/交易所公告、政府披露文件 | 置换债券/隐债清理/化债进度等官方披露 |
| 宏观数据检索 | 全球与地区宏观指标、财政收支、产业运行 | 仅为债务率/偿债能力的宏观背景佐证 |
| 债券数据检索 | 债券信息/发行兑付/估值/主体财务 | 涉及具体债券时核实名称、规模、利率、期限 |
| 综合金融数据检索 | 综合金融数据（企业/非上市主体） | 涉及城投平台、融资平台主体信息时兜底 |

**调用规则（已确认统一入参）**：上述能力均只接收一个 `query` 字符串参数，**没有独立的日期区间参数**；需要限定时间范围时必须把时间表达（"近 30 天""2025 年""近一年"）写入 `query` 文本。返回为结构化表格/文本。

### 数据来源纪律（强约束）

**报告内一切结构化数值必须严格取自本 Skill 规定的报表数据接口，严禁以资讯新闻、研报文字、模型常识进行补充和发挥。**

- 接口未返回的数值一律省略或如实标注缺失，**不得**用新闻/研报/搜到的数字填补、估算或替代。**测算类指标只能由接口字段按 `analysis_dimensions.md` 的公式计算，不得引入接口外数值。**
- 文本检索服务仅用于**定性文字段落、化债手段归纳与背景材料**；绝不允许从文本素材提取数值填入正文数字、图表或表格。
- 图表数据 100% 必须来自接口返回字段（或由其测算）；若某维度接口无数据，则该维度不渲染图表，以"数据披露滞后"文字说明。
- 同一指标若多个接口均有返回，以接口数据为准并保持全文口径一致；小口径差异在报告注中说明，不以文本材料"校正"接口值。

## 总体工作流

**注意取数编排规则，控制调用次数，避免耗时过长。**

1. 解析用户输入，识别目标地区（省级为主、市级/区县为辅）。
2. 依据 `references/region_codes.md` 将地区名称解析为 `AREA_CODE`（六位行政区划代码），并判断是否带"全国"。
3. 按「取数编排：核心接口清单」**一次性并行取齐 5 个核心接口**（覆盖化债前端六大模块字段），缺失字段再用可选接口补齐，不再逐个调用全部报表。
4. 用接口字段按 `references/analysis_dimensions.md` 测算派生指标（广义债务率、三层结构占比、到期覆盖倍数、城投债集中到期识别、化债动作强度、官方情绪信号）。
5. 按合并后的 4 个化债文本检索维度调用文本检索服务（每维度一次 `query`，共 4 次），作为定性叙述与化债手段归纳素材（**仅定性，不得作为数值来源**）。
6. 汇总结构化数据、派生指标与文本素材，按报告格式规范生成 **HTML 格式** 的 **4~7 个维度**报告，正文穿插可视化图表（优先内联 SVG 轻量图表）。
7. 输出最终 HTML，并返回文件路径供用户打开。

### 取数编排：核心接口清单（性能优化，必须遵守）

**原则：能用 1 次调用取回的数据，绝不用多次。总取数调用控制在 10 次以内（不含失败跳过）。**

| 优先级 | 报表 | 覆盖的前端模块 | 取数要点 |
|---|---|---|---|
| 核心① | `RPT_DEBT_AREAHOMEPAGE_LEFT` | 最新化债情况、本息覆盖率、专项债余额、未来偿债、商品房销售 | **`columns=ALL` 一次取回全部字段**，禁止按子模块拆 4~5 次调用 |
| 核心② | `RPT_BOND_REGION_ECONOMYALL` | GDP（债务率分母）、政府债务余额、财政收支背景 | 一次取全部常用 columns；`sortColumns=REPORT_DATE&sortTypes=-1` 取最新 |
| 核心③ | `RPT_CUSTOM_DEBTREMOVE_PROVINCE_DEBT` | 省级化债指标（隐债规模、显性债务、覆盖率、债务率、加权成本，含全国排名） | `(AREA_CODE="...")` + 最新 END_DATE |
| 核心④ | `RPT_CUSTOM_DEBTREMOVE_GOV_PROCESS` | 政府化债动态（化债进度、化债展望、公告标题/链接） | `(IS_NEW="1")` 只取最新一批 |
| 核心⑤ | `RPT_DEBTREMOVE_EXITORG_LIST` | 退平台名单（平台压降/整合转型） | 省级筛选 + 按城市汇总统计 |
| 可选 A~C | `RPT_DEBTREMOVE_REGION_ECONOMY` / `_DISDEBT` / `_LAND_TRANSFER` | 区域财政多年序 / 区域债务余额 / 土地出让明细 | 核心②已含最新值时一律跳过 |
| 可选 D | `RPT_CUSTOM_DEBTREMOVE_PROVINCE_DEBT_RANK` | 全国化债成效排名 | 仅做省级排名/风险矩阵时调用 |
| 可选 E | `RPT_CUSTOM_BOND_PLAN_AREAISSUEQUTA` | 政府债发行节奏（四类券种计划/实际发行、全年新增限额） | 仅输出"政府债发行节奏与计划执行"维度时调用；限额表两级表头需拆分、"-"按空值、千分位清洗、sheet 按季度动态匹配最新 |

**降级纪律（重要）：** 接口返回 `9501`（异常）/`9201`（0 条数据）时，**本接口标记跳过、最多重试 1 次**；仍失败则相关段落/图表以"数据披露滞后"说明，不要反复重试、不要换参硬凑、不要用文本资料补数。同一报表在报告运行周期内最多调用 2 次。可选接口数据可被核心接口覆盖时一律跳过。

## 第一步：地区解析与地区编码

地区名称 → `AREA_CODE` 的映射见 `references/region_codes.md`。

- 省级地区直接用映射表查（如 江苏省=`320000`、北京=`110000`）。
- 市/区县向上穿透到省级（或同时给出省级+市级编码）；地区编码 = 国家行政区划代码，前两位为省、前四位为市、六位为区县。
- 多数地方化债报表以省级口径为主体；用户给市级/区县时尽量取到其所属省级，并在报告标题标注到区划层级。
- 若地区不在映射表（如新增县级市），用宏观数据检索或行政地图接口确认行政区划代码后继续。

## 第二步：报表接口取数规则（通用）

调用形如：

```
GET {报表数据服务接口地址}
    ?reportName={报表英文名}
    &columns={逗号分隔字段英文名}
    &filter=({筛选字段} in ("{AREA_CODE}"))(...)
    &pageNumber=1&pageSize=200&source=CHOICE&client=SW
```

- 字段一律用 `columns` 英文名；筛选一律用 `filter`。字符串值用双引号 `"..."`，日期用单引号 `'2025-01-01'`。
- 多值筛选：`(AREA_CODE in ("110000","320000"))`。
- **取最新**：凡含 `REPORT_DATE`/`END_DATE`，用 `sortColumns=REPORT_DATE&sortTypes=-1` 取最新一行/一期；快照报表（如 `RPT_DEBT_AREAHOMEPAGE_LEFT`）直接取返回数据。
- 分页：`pageSize` 建议 200，翻页按 `pageNumber` 递增直到 `pages`。
- 返回 JSON：`code`（0=成功有数据 / 9201=0 条 / 9501=异常），`result.data` 为数据列表，`result.count` 为总数。

所有报表的具体 `reportName`、`columns`、`filter` 拼接示例与字段中文含义，以 `references/interface_catalog.md` 为准，**不要自造字段或报表**。字段中文语义与前端口径映射见 `references/frontend_indicators.md`。

## 第三步：化债文本检索维度（性能优化：合并为 4 次调用）

围绕化债主题合并为四个维度（每维度一次 `query`，共 **4 次**；首次结果已覆盖该维度时不再追加第二查询；同一 `query` 最多重试 1 次）：

1. **化债手段与力度**：`{本地区} 化债 置换债 再融资债 特殊再融资债 隐性债务 债务限额 化债规模 化债进度 2025`
2. **城投与金融化债**：`{本地区} 城投 平台转型 退平台 展期降息 政银企 金融债务 拖欠企业账款 2025`
3. **财政财力与化债空间**：`{本地区} 财政收入 土地出让 政府性基金 三保 债务率 资产盘活 2025`
4. **政策与化债展望**：`{本地区} 两会 政府工作报告 预算报告 化债 政策 中央额度 超长期特别国债 2025`

每个维度优先用新闻资讯检索；公告披露类（化债公告、置换债券、隐债清理）并入维度 1/4 的同一查询中顺带检索，宏观数据仅在确需宏观佐证时补 1 次。材料提炼须客观中立，与结构化数据相互印证，不引入与数据冲突的结论。

## 深度分析维度框架（4~7 个维度，本版核心）

报告正文由 **4~7 个分析维度** 构成（不得少于 4 个、不得超过 7 个）。每个维度 = 维度标题 + 可视化图表 + 正文。

**推荐维度**：①债务绝对压力与结构 ②政府债发行节奏与计划执行 ③未来 1~2 年偿债洪峰与流动性风险
④财政内生偿债能力 ⑤化债进度与执行强度 ⑥化债方式与政策工具使用 ⑦风险等级与前景研判。
各自的对应数据、解读要点、图表建议、阈值分档与深挖点见 **`references/analysis_dimensions.md`**。

**维度取舍规则**：某地区数据缺失（如无城投债偿还、无化债动态）时合并相邻维度而非硬凑；**维度一（债务压力与结构）与维度四（财政内生能力）为底线维度**，任何情况下都应保留；维度二在限额/一级市场数据可得时输出，缺失时并入相邻维度或省略。

### 派生指标测算规则（只用接口字段，标注"测算"）

- **广义债务率** =（专项债余额 `BALANCE` + 最新隐债规模 `HIDDENDEBT_BALANCE` + 城投及地方国企债务 `IMPLICIT_DEBT`）÷ GDP × 100%。
- **三层债务结构占比** = 显性（政府债券/专项债余额）/ 隐性（隐债规模）/ 经营性（城投及地方国企债务）三层各自 ÷ 三层合计。
- **到期债务覆盖倍数** = 可供还债的地方财政资金 `LOCAL_FUND` ÷（地方债偿还 `REPAY_AMT_DFZ` + 城投债偿还 `REPAY_AMT_CTZ`）；`<1` 表明需依赖再融资"借新还旧"。
- **城投债集中到期识别**：`REPAY_AMT_CTZ` 显著大于 `REPAY_AMT_DFZ` 且绝对额居前的地区。
- **化债动作强度**：从政府化债动态文本提取再融资债券发行额、置换隐债金额、化债进度百分比、债务率、平台压降数量、利率下降基点数等信号，做密度计数。
- **官方情绪信号**：从化债展望文本提取极性（"任务依然艰巨""空间可能收紧"等示警词 vs "超额完成""良性循环"等乐观词）。

> 上述派生指标均为**测算口径**，与法定口径（如法定债务率）不同，报告须以脚注/备注说明公式，公式一律使用**中文口径名称**；**正文、图表标签与脚注严禁出现报表英文名（`RPT_...`）与字段英文名（如 `BALANCE`、`REPAY_AMT_DFZ`），一律改用中文口径表述。**

## 报告格式规范（HTML）

最终输出必须是完整 HTML 报告，正文穿插可视化图表（优先内联 SVG，复杂图表用 ECharts CDN），并满足以下结构：

```
<h1>{地区名称}地方化债研究</h1>
<p class="meta">生成时间：{YYYY年MM月DD日 HH时mm分ss秒} · 数据来源：东方财富Choice</p>
<section class="abstract"><h2>摘要</h2><p>{150~250 字}</p></section>
<section><h2>{维度标题1：由维度内容二次总结}</h2><div class="chart">{图表}</div><p>{维度正文}</p></section>
...（共 4~7 个维度）
<section><h2>免责声明</h2><p>{免责声明}</p></section>
```

要点（**完整规范见 `references/report_format.md`**）：

- 每个维度正文 1~3 个自然段，只保留结论与关键数据；**不出现"本维度回答/本维度聚焦"等元表述**，**不单列"解读/解读要点"小节**。
- **图表 4~7 张**（原则上每维度 1 张），优先轻量内联 SVG；数据缺失的图表不渲染，以文字说明代替。**涨红跌绿**。
- **正文 ≥800 字**（不含图表）；措辞中性专业，**严禁唱空/极端/买卖指令表述**。
- **数据来源一律写"东方财富Choice"**，不附加接口名/报表名/参数/口径说明。
- **正文口径表述（重要）**：测算公式、图表标签、脚注与备注一律使用**中文口径名称**（如"累计实际发行/同期计划发行/全年新增限额"），**严禁出现报表英文名（`RPT_...`）与字段英文名**；"政府债发行节奏与计划执行"维度的"执行偏差（计划执行偏差）"部分尤其不得带出任何报表名或英文列名。
- HTML 可视化模板见 `references/report_templates.md`；输出前质检清单见 `references/report_format.md`。

## 超时与重复调用（性能纪律，统一版）

本节为本 Skill **唯一**的超时与重试口径，全文其它位置如与此冲突以本节为准。

| 约束项 | 取值 | 说明 |
|---|---|---|
| 单次外部调用最长等待 | **60 秒** | 接口取数 / 文本检索单次超过 60 秒即判定失败并跳过该数据项，不阻塞整份报告 |
| 失败退避 | **30 秒 / 90 秒** | 首次失败后退避 30 秒重试，二次失败后退避 90 秒重试；**累计不超过 2 次调用** |
| 同一接口 / 同一 `query` 累计调用上限 | **2 次**（最多重试 1 次） | 达到上限后立即停止，不再重试 |
| 报告级取数总调用上限 | **10 次**（核心 5 + 可选 ≤5） | 不含失败跳过的调用 |
| 文本检索 `query` 总上限 | **4 次**（四维度各 1 次） | 同一 `query` 最多调用 2 次 |
| 失败处理 | 立即以"数据披露滞后"或对应缺失措辞继续 | 禁止改写参数、更换标的、拆 query 硬凑、后台执行、无谓重试 |

- **执行方式**：本 Skill 不依赖任何内部脚本；上述限制由执行方在每次调用前自检、调用后计数落实（记录已调用次数与已用时，达到上限即停止）。**禁止**声称"脚本已自动实现退避重试"而以未实现的机制替代人工计数。
- 命令超时被中断或返回非 0 退出码时，立即停止本轮调用并按失败话术输出。
