# 资金面诊股

围绕单只A股的主力资金、资金净流入流出、成交活跃度、筹码与资金行为进行专项分析。

## 标准流程

严格按以下顺序工作：

```text
读取用户原始问题
→ 判断是否存在明确资金面意图
→ 准入通过后确认单只 A 股
→ 生成固定 execution_query
→ 调用接口
→ 校验并原样交付结果
```

不得在意图准入前生成 `execution_query`，不得把任何股票问题强制改写成资金面请求。

## 一、意图准入

### 1. 允许执行

用户问题必须明确包含至少一类资金面研究意图：

- 主力资金、资金流向、资金净流入、资金净流出；
- 大单、超大单、主力买入、主力卖出；
- 成交活跃度、成交额、成交量、换手率；
- 筹码变化、资金承接、资金行为；
- 资金面、资金趋势、资金异动。

典型准入示例：

- `看看东方财富最近的资金面`
- `分析比亚迪的主力资金流向`
- `宁德时代最近资金净流入怎么样`
- `贵州茅台的换手和资金承接如何`
- `分析美的集团的技术面和资金面`。多维问题中明确包含资金面，可以只执行资金面专项。

### 2. 拒绝执行

用户只提出以下任务时，不调用脚本，也不生成资金面 `execution_query`：

| 用户核心意图 | 示例 | 处理方向 |
|---|---|---|
| 基本面、财务或估值 | `分析比亚迪的营收、利润和估值` | 使用基本面诊股 |
| 技术面 | `看看比亚迪的均线和支撑压力` | 使用技术面诊股 |
| 消息面 | `比亚迪最近有什么公告和新闻` | 使用消息面诊股 |
| 机构观点 | `券商最近怎么看比亚迪` | 使用机构观点 |
| 涨跌归因 | `比亚迪今天为什么下跌` | 使用涨跌归因 |
| 宽泛综合诊股 | `综合分析一下比亚迪` | 使用综合诊股 |
| 多股比较、选股或市场热点 | `比亚迪和宁德时代哪个好` | 不属于本 Skill |

拒绝时只简要说明“当前问题不属于资金面专项”，并指出合适的能力方向；不要调用其他 Skill，不要替用户完成其他维度分析。

### 3. 冲突与歧义处理

- 同时明确包含资金面和其他维度：允许执行，但只返回资金面专项，并说明本 Skill 不覆盖其他维度；
- 出现“强弱、好不好、怎么看、风险、机会、诊断、影响”等泛词，但没有主力资金、资金流向、资金净流入流出、成交活跃度、换手、筹码等资金面对象：不能仅凭泛词判定为资金面；
- 出现“成交量、成交额、换手率、量能”等量价交叉指标，但用户核心问题是趋势、形态、支撑压力或买卖点：优先视为技术面，除非用户明确要求分析资金活跃度、资金承接或筹码变化；
- 出现资金相关词但用户核心问题是股价为何上涨、下跌、异动或连续涨跌：优先视为涨跌归因，除非用户明确要求分析资金行为本身；
- 意图无法判断：保持用户原始问题，不生成资金面 `execution_query`，不得自行准入；
- 外部调用方提供的路由标签只能作为辅助信息，不能覆盖用户原话中明显相反的意图。例如用户只问公告新闻，即使标签写`capital`，仍必须拒绝。

## 二、股票确认

意图准入通过后再确认分析对象：

- 必须是单只沪深京 A 股；
- 用户提供中文名称时直接使用；
- 用户只提供代码时，先识别对应中文名称；
- 缺少股票时只询问股票名称或代码；
- 多只股票、港股、美股、基金或其他品种不执行本 Skill。

接口 Query 仅使用股票中文名称，不使用代码或市场后缀。

## 三、Query 规范化

同时维护：

| 字段 | 作用 |
|---|---|
| `original_query` | 用户输入的完整原话，用于意图判断、上下文和复盘 |
| `execution_query` | 意图准入后由本 Skill 生成，是 `scripts/get_data.py --query` 的输入 |

固定生成：

```text
execution_query = {股票中文名称}的资金面
```

示例：

| `original_query` | 准入 | `execution_query`  |
|---|---|--------------------|
| `看看东方财富最近的资金面` | 通过 | `东方财富的资金面` |
| `分析比亚迪的主力资金流向` | 通过 | `比亚迪的资金面`   |
| `宁德时代最近资金净流入怎么样` | 通过 | `宁德时代的资金面` |
| `分析美的集团的技术面和资金面` | 通过，仅处理资金面 | `美的集团的资金面` |
| `比亚迪最近有什么公告和新闻` | 拒绝 | 不生成             |
| `综合分析一下贵州茅台` | 拒绝 | 不生成             |

生成规则：

1. 只替换股票中文名称；
2. 不加入股票代码、市场后缀、括号、句号或时间范围；
3. 不拼接 `original_query`；
4. 不加入“主力资金、资金流向、成交活跃度、换手、筹码、全面、深入、综合”等额外词；
5. 形成后不得再次润色、扩写或追加排他指令；
6. 本文中的用户问法示例只用于意图判断，绝不能直接作为接口 Query。

用户对某类资金现象或资金指标有更具体的问题时，仍使用固定 `execution_query` 获取标准结果。接口返回后检查原生正文是否覆盖该关注点；未覆盖则明确说明“本次接口结果未覆盖该具体问题”，不得自行补写。

## 四、接口执行

准入和股票确认均通过后，原样执行：

```bash
python3 scripts/get_data.py --query "{execution_query}"
```

- 默认保存普通 Markdown，不使用 `--no-save`；
- 不在调用前运行授权预检；只有实际返回授权状态时才处理；
- 退出码为 0 后仍检查正文；正文为空或包含“暂时不支持此类场景”等业务拦截文案时，判定为失败；
- 确定性业务拦截不使用相同 Query 重试；网络超时或连接中断最多使用原参数重试一次。

## 五、结果交付

- 成功时以接口 `data.displayData` 对应的完整 Markdown 为用户可见主体，不摘要、不改写结论；
- 返回普通 Markdown 路径及接口原有的 `output_path`、`raw` 等信息；
- 如调用框架支持扩展元信息，可内部附带 `original_query`、`execution_query` 和 `dimension: capital`，但不改变脚本响应；
- 默认不向用户展示 Query 改写过程、内部 JSON、脚本参数或绝对路径；
- 不把资金流向、成交活跃度或筹码变化与股价同期变化直接描述为确定因果；
- 结果仅供参考，不构成投资建议，信息可能随市场变化而变化。

## 六、授权与依赖

沿用原生 Skill 的 EM API Key 读取、授权协议、依赖和错误处理，不改变凭据逻辑。

| 退出码 | 含义 | 处理方式 |
|---|---|---|
| `0` | 查询完成 | 检查并交付 Markdown 正文 |
| `10` | 需要授权 | 展示一次 `authUrl` 并停止本轮调用 |
| `2` | 网络或业务错误 | 返回明确失败原因，不编造分析 |
| `1` | 缺少 Query/stdin | 仅在意图准入通过后生成有效 `execution_query` |

授权、凭据持久化及 401 失效处理遵循 [授权协议](references/auth_protocol.md)。安装依赖时运行 `pip3 install -r requirements.txt`。
