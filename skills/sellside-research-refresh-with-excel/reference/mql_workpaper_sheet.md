# 独立 MQL 底稿 Sheet 规范

## 目标

完整仿写的研究底稿必须包含独立 `15_查数底稿`。该 Sheet 用于让审阅者在安装 Choice Excel 加载项后逐表刷新并回查完整查询脚本；不得用事实表中的静态值或一列脚本文本替代。

查询开始前必须先建立 `coverage_requirements` 原子级全集。`15_查数底稿` 的 Block 是该全集的执行结果，不是执行者自由挑选的少量示例；范围以参考件实际指标为准，不强制凑齐固定类别。普通 Choice 查询返回过某字段不构成跳过 MQL 的理由。

## 一个区块对应一个真实结果 Block

每个本次 `通过MQL工具链获取结构化数据` 成功返回、且被报告或预测模型使用的数据表/Block，都必须建立一个独立区块。一个区块至少登记：

- `table_id`：目标报告物理表或内部数据表的唯一编号；
- `source_page`：参考研报对应表或图所在页码；若属于目标公司新增事实表，填写 `目标公司公开资料/不适用`，不得留空；
- `source_page_index`、`source_order`：参考研报页码序号和页内出现顺序；所有区块先按这两个字段升序排列，再写入Sheet；
- `source_figure_name`：参考表名或图表名；
- `target_table_name`：目标报告或模型中的表名；
- `block_selector`：如 `#1`、`#2`；
- `layout_class`：`financial` 或 `non_financial`，用于说明内容类型，不直接决定行列方向；
- `mql_orientation`：Excel显示方向，`0`保持接口矩阵，`1`转置接口矩阵。先与参考研报对应表格的行列布局保持一致；参考研报没有对应布局时，再根据实际行列比例选择；
- `reference_orientation`：参考研报能明确判断方向时填写`0`或`1`，并优先于通用比例规则；无法判断时可省略；
- `mql_script`：实际发送给`通过MQL工具链获取结构化数据`并获得本次成功回执的完整纯 MQL，不含令牌、Markdown 围栏或解释文字；
- `context_request_ids`：生成该脚本时实际使用的上下文检索请求ID；脚本、执行ID、返回字段和结果矩阵必须来自同一条执行记录，不得在生成Excel时重写或拼接；
- `execution_run_id`、`result_as_of`、`execution_status`；
- `last_result`：本次接口执行返回的原始完整二维矩阵，包含字段名行；
- `expected_rows`、`expected_columns`：接口原始矩阵形状，必须与`last_result`一致；Excel显示形状另由`mql_orientation`计算；
- `mql_formula_cols`、`mql_formula_rows`：完整接口矩阵的列数和行数（含表头），仅作为布局审计元数据，不写入公式；
- `refresh_rows`、`refresh_columns`：Choice Excel实际刷新后占用的行数和列数，用于计算预留区域；
- `refresh_shape_evidence`：由生成器填写`result_matrix`，按原始完整接口矩阵和显式显示方向计算；
- `required_items`：该表适用的全部指标或报表字段；
- `returned_items`：本次成功返回的指标或字段；
- `omitted_items`：成功区块固定为空。未返回项回到取数计划，改变路径或拆成单字段后重新执行；最终不可得项登记在覆盖计划的失败记录中，不进入成功区块。

成功区块中`required_items = returned_items`。未登记的指标或报表字段视为仍待查询；利润表、资产负债表、现金流量表、财务比率、首页盈利预测、行情摘要、可比公司表分别形成原子覆盖项，不能用一个笼统说明覆盖整张表。

## 事实表与预测表的字段级闭环

`15_查数底稿`不是示例脚本展示区。每个被事实表、预测表或正式报告使用的 MQL 字段都必须真实出现在对应 Note 的脚本及该次执行返回结果中。

- `10_事实数据`中每条 MQL 记录至少保存 `block_id`、原始响应或对应工具调用中的真实 `execution_run_id`、证券代码与精确 `returned_field`、原始单位、换算公式和覆盖状态。
- 同一执行只返回营业收入时，不得将成本、费用、现金流或资产负债项目同时标记为该执行的 MQL 数据。
- `30_预测估值`逐行标记历史 MQL、Choice 一致预期、Excel 公式推导或自主模型预测。自主预测不得登记为 MQL 返回值。
- “应收账款及票据”“应付账款及票据”“无形资产及商誉”等组合科目必须分别取得基础字段，并在 Excel 中用公式相加；不得以单个基础科目冒充组合科目。
- 执行请求ID必须来自本次成功 `通过MQL工具链获取结构化数据` 返回；禁止 `historical-execution`、`latest-run`、`example` 等占位文本。
- 覆盖率必须按字段计算，不按区块数量、预留行数或工作表是否存在计算。

## 公式、批注和显示

- 公式锚点使用`=mql("#1",0)`（保持矩阵方向）或`=mql("#1",1)`（转置）。Note保存同次成功的单Block脚本。公式显式传方向，不使用猜测的cols/rows设置限制返回范围。本机Choice真实刷新已确认：锚点行显示“金融查数”，完整矩阵从下一行开始；hidden_key为工具展示元数据，加载项仍输出EM_CODE等字段，不能据此裁掉列。接口矩阵含表头N行×M列时，方向0占(N+1)行×M列，方向1占(M+1)行×N列（均含锚点状态行）。16引用矩形从anchor_row+1开始，按实际字段名与证券/期间/周期等记录键定位；日期同时兼容Excel日期序列和原始日期文本。
- `15_查数底稿`第一个标题从A1开始，不在顶部另写下载引导；每个锚点下两行的安装/下载提示以及`00_导读`下载地址保留。
- 注释作者名不影响执行，但对象类型必须是 Excel Note/legacy comment，不能是带头像和回复框的新版批注/Threaded Comment。导出后必须确认工作簿存在 legacy comments XML、VML drawing 及工作表注释关系，并确认不存在 `threadedComments`、`persons` 和线程回复关系。
- 注释正文必须是纯 MQL，不得带 `[Threaded comment]`、Office兼容性提示、微软帮助链接、`Comment:`、Markdown代码围栏、脚本标题、来源说明或其他自然语言。首个有效字符必须进入 `CrossSectionBlock`、`TimeSeriesBlock`、`ReportBlock` 或 `EdbBlock`；生成后必须逐条回读注释正文验证。Note与配对工具调用的完整实际请求逐字一致，多Block拆分或编号变化后必须重新执行。严禁出现`【说明】`、`注：`、`备注：`、`安装 Choice`、`加载项`、`刷新本锚点`、`复算`等说明性文字；`validate_mql_workbook_coverage.py` 会逐行扫描批注和 `mql_script` 字段，发现任何非 MQL 文本即判定 FAIL。
- 一个锚点注释只允许包含一个会产生结果的 MQL Block。若原始执行脚本包含多个 Block，必须按目标 Block 拆成自包含脚本，并将该脚本内的结果 Block 规范化为 `#1`；每个拆分脚本分别写入对应锚点注释。原始 Block 编号继续保存在元数据中用于追溯。
- `ReportBlock`使用本次上下文检索返回的完整`Choice报表\...|数字ID`路径；`CrossSectionBlock`和`TimeSeriesBlock`的每个输出字段使用完整`Choice指标\...|数字ID`路径。报表别名、指标简称和`{别名}: {同名别名}()`不能写入可刷新脚本。
- `REPORT_FIELD`名称必须与本次报表字段绑定结果逐字一致；`FILTER_ROWS`只引用已经绑定的显式字段和合法表达式。
- 区块标题显示查询名称；与单个报告对象一一对应时使用该对象数字编号及标题。一个查询支撑多个表/图，或一个表/图由多查询共同支撑时，查询块不另加表/图编号；对应数字编号及完整标题统一列在查询说明。生成器剥离输入中已有的前置编号，避免“表1 表1/表3/表6”，文字只写入未合并的A列单元格；禁止合并标题单元格。标题左对齐、缩进0、从左到右且不换行，标题底色可以横向铺满。标题下方只显示五行：`页码：`、`执行请求ID：`、`执行状态：`、`执行日期：`、`查询说明：`；标签和值均左对齐且不换行。
- 样式应用顺序固定为“通用样式 → 区块标题样式 → 导出回读”。区块标题使用深蓝色 `#1F4E78` 填充、白色粗体字和左对齐；标题带宽范围内的填充保持一致。禁止在标题样式之后对整张Sheet或包含标题行的大范围重新设置黑色字体。导出后必须回读每个标题单元格的填充色、字体色和粗体属性。
- 不得在每个区块右侧展示 `table_id`、`target_table_name`、`execution_run_id`、`result_as_of`、`execution_status`、`expected_rows × columns`、`required_items`、`returned_items`、`omitted_items` 或第二份“查询说明”。这些字段保留在生成输入、执行登记或核验材料中即可。
- `source_figure_name` 和原始 Block 仍必须在生成输入中保留以便审计，但不单独占用可见说明行；需要时可压缩写入“查询说明”的值。
- 公式所在行只放公式锚点；整个填充矩形（含锚点同行及后续行）除锚点外必须为空，不预填说明、表头、静态结果、公式、合并单元格或人工补值。
- 未安装加载项时允许公式显示 `#NAME?`；这不授权用静态矩阵覆盖溢出区。已取得的执行结果保存在其他事实/核验 Sheet 和生成输入中。

## 防覆盖布局算法

`15_查数底稿`先复现参考研报同类表格的行列关系。没有可参照布局时，比较接口矩阵的行列比例：当较长一边不少于12且达到另一边的3倍时，让较长一边纵向展开。例如“几十列、只有几行”的结果应转置；“几十行、只有几列”的结果保持原方向。比例接近时根据字段含义、可读性和图表需要选择。

图表位置根据表格实际占用范围动态计算。优先放在相关表格右侧并留至少2列空白；右侧空间不足或会使工作表过宽时，改放在表格下方并留至少2行空白。图表不得覆盖公式锚点、溢出区、标题、说明或其他表格。

先按参考报告确定方向，再从同次完整原始可见结果计算占用范围。锚点状态行和全部接口字段（含EM_CODE）及表头必须计入，返回8个季度就按8条数据记录布局，不能因目标是两年而假定2行；年度需求必须在查询时确认报告期频率。不得把行情/评级表写成1×1占位。后续刷新可能增加记录时，应使用固定截止日期及固定窗口，更新查询后重新按实际返回布局，不用盲目扩大预留。随后计算：

```text
spill_top    = anchor_row
spill_left   = anchor_column
spill_bottom = spill_top + refresh_rows - 1
spill_right  = spill_left + refresh_columns - 1
```

生成器必须维护所有区块的占用矩形，并在写入下一块前检查：

1. 新公式锚点不在任何既有溢出矩形内；
2. 新溢出矩形不与既有锚点、溢出矩形、合并单元格、说明区或静态表相交（锚点下方两格指定安装提示除外）；
3. 公式所在行除锚点外，整个填充矩形内除两格指定安装提示外不得放“公式说明”等文字；
4. MQL锚点下方第1、第2行A列（刷新区域左上角）分别写“安装choice终端及Excel加载项后，刷新本表数据。”和“下载choice→https://choice.eastmoney.com/downloads”，红色加粗、不换行、不合并，下载单元格使用原生超链接；在刷新区域与提示的最下边界之后保留3个空白行，下一块标题行不得早于`max(spill_bottom, spill_top+2)+4`；
5. 下一块起始行依据前一块真实`spill_bottom`动态计算，禁止使用固定行距；
6. 刷新前后均运行矩形检查；任一交集立即失败，不得交付可能产生`#SPILL!`或覆盖上下表的工作簿。
7. 若同Sheet存在图表，按全部溢出矩形的实际边界复核图表锚点，保证刷新前后均不相交。

## 顺序、下载链接与单位

- 区块、表格和图表按`source_page_index`、`source_order`升序排列；同一来源表的数据区与图表保持相邻。
- 这两个排序字段由原文清单page/source_order和plan.source_object_ids派生；source_page_index就是实际页码，不是对象全局序号。多个查询支撑同一对象时相邻排列；一个查询支撑多对象时在最早使用处登记。页码与标题不能从另一个参考块复制。
- 下载地址显示在可完整阅读的单元格中，B列宽度不低于48，并在最终通用样式完成后再次校准列宽与超链接。
- MQL原始溢出区保留原始单位。进入展示表或图表前，为每个数值系列登记`source_unit`、`target_unit`、`scale_factor`、`conversion_formula`和`presentation_range`。
- 图表系列只绑定完成换算的展示区域。元转百万元使用`1/1000000`，万元转百万元使用`1/100`，亿元转百万元使用`100`；轴标题、表头和脚注同步标注目标单位。

## 已知陷阱

1. **转置方向误判**：把字段型接口矩阵 `2 × N` 当成2行高，会低估纵向溢出高度；Choice Excel实际按 `N行 × 2列` 填充时，将压到下一区块标题、说明或MQL公式并触发 `#SPILL!`。
2. **溢出区被占用**：标题、五行说明、静态值、其他公式、合并单元格，除两格指定安装提示外，占据填充矩形会影响MQL结果展开。公式同行除锚点外同样必须为空。
3. **标题样式被覆盖**：区块标题设置为深蓝底白字后，再运行全表或首行 `Font(...)` 会把白字改回默认黑字。通用样式必须跳过 `15_查数底稿` 的标题行，或在通用样式完成后重新应用区块标题样式并回读核验。

## 写作前门禁

- `15_查数底稿` 覆盖本次所有成功 MQL 数据表/Block，数量与执行登记一致；
- 每个区块都有左对齐标题、五行指定说明字段，以及显式指定方向的MQL公式和同一单元格注释（Excel Note）中的单Block完整脚本；
- 每个区块标题均为 `#1F4E78` 深蓝底、白色粗体字；不存在蓝底黑字或被全表通用样式覆盖的标题；
- 每个Note脚本均从同一成功执行记录原样继承；脚本、执行ID、返回字段与结果矩阵属于同一次回执；
- 每个Note脚本和审计 JSON 中的 `mql_script` 均为纯 MQL：首字符为 Block 声明，不含`【说明】`、`注：`、`备注：`、Markdown围栏或任何自然语言说明文字；
- XLSX 包中不存在 Threaded Comment 及 persons 关系；
- `last_result`、`expected_rows`、`expected_columns` 一致，刷新形状与原始完整接口矩阵、方向及额外锚点状态行一致；
- 所有适用指标或报表字段都已取得成功回执，或在覆盖计划中保留重试与最终不可得记录；
- 所有溢出矩形除锚点下方两格指定安装提示外为空白且互不相交；
- `00_导读`和`15_查数底稿`均包含Choice终端下载链接 `https://choice.eastmoney.com/downloads`；
- 表格方向与参考研报一致；无参考时，明显失衡的行列比例已自适应转置，图表按真实刷新范围动态避让；区块与图表按原文页码和页内顺序排列；
- 下载链接完整显示；展示表和图表已按参考报告单位换算并标注；
- `mx-ds-mcp`、网页和人工预测不伪装成 MQL 区块。

任一项失败时，阶段四不完成，不能进入正式报告写作。

保存后运行 `scripts/validate_mql_workbook_coverage.py workbook.xlsx mql_audit.json`。校验器通过后仍需按本文件要求完成溢出区和视觉检查。
