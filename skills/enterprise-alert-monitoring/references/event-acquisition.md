# 事件库获取：已发生事件与未来预期事件

本文件规定事件库两个接口的检索目标、参数构造、原始返回保存和交接。接口调用与错误处理以运行平台的接口目录工具为准；本技能不复制其实现，只规定业务侧契约：**先在接口目录中检索接口获取其接口ID与真实输入参数，再按该参数调用；不得虚构接口ID、参数或枚举值。**

## 两个接口与检索目标

| 逻辑名称 | 接口目录中文名称 | 数据含义 | 关键输入 |
| --- | --- | --- | --- |
| 已发生事件 | 事件大全搜索 | 基本面层面已发生的实质性变化（重大投资、新业务布局、重大合同/订单、管理层变动、技术突破、产能扩张、政策利好等） | 关键词、起止时间（精确到秒）、时间类型、排序、分页 |
| 未来预期事件 | 未来行动事件搜索 | 预计发生的事件，预计对基本面有实质性影响 | 搜索类型、排序、关键词、起止时间、时间类型、排序字段、分页、公司代码列表 |

两接口各执行一次初始检索，登记`kind=initial`；确有明确缺口（如关键事项的事件标签缺失、已命中事项需要补充未来节点）才允许一次定向补查，登记`kind=supplement`及非空`reason`，结果回同一事件池。不为每章建立单独query或配额。

## 参数构造规则

- **时间**：已发生事件用监测期起止日期（`00:00:00`至`23:59:59`），`timeType=publishTime`、`sortType=desc`、`sortField=publishTime`；未来事件用同一企业同一监测期参数（起始于监测开始），`timeType=happenTime`、`sortType=asc`、`sortField=happenTime`，使预计发生时间升序排列，检索窗口覆盖至期末即可——未来事件的价值在预计发生时间，允许返回早于监测期的条目（已到期但标注仍在未来的事项是发酵判断的重要信号）。
- **对象**：优先使用企业全称或已确认证券代码（未来事件接口支持`securityCodeList`，已发生事件用关键词）；实体识别返回的机构代码可用时优先机构代码口径。
- **分页**：`pageNo=1`、`pageSize=50`；`total`超过一页时补一页并说明，不为凑量翻页。
- **检索后核对**：两个接口均按关键词/代码检索，返回中必然包含相关主体（同名、子公司、交易对手）的条目；主体归属核对在事件处理与分析阶段执行，不在检索阶段丢弃。

## 原始返回保存

每次调用的完整原始业务返回保存为JSON文件（含`total`、完整列表、风险标注、URL），按下列`event_runs.json`交接（与资讯的`search_runs.json`平行，正文不嵌入清单）：

```json
{
  "entity": {"name": "已确认企业全称", "confirmed": true},
  "context": {
    "start_date": "2026-10-01",
    "end_date": "2026-10-22",
    "data_as_of": "2026-10-22T17:00:00+08:00",
    "scope": "企业自身及事件库明确涉及的关联事项"
  },
  "event_searches": [
    {
      "api_id": "newsEventSearch",
      "query": "实际执行的事件检索说明（含关键词与期间）",
      "kind": "initial",
      "raw_result_path": "raw/events.json",
      "status": "success",
      "elapsed_seconds": 8.2
    },
    {
      "api_id": "futureEventSearch",
      "query": "实际执行的未来事件检索说明（含公司代码与期间）",
      "kind": "initial",
      "raw_result_path": "raw/future.json",
      "status": "success"
    }
  ]
}
```

`status`使用实际`success/empty/failed/need_auth`；`unsupported`由生成器对无法解析的返回结构自动标注。以上为虚构格式示例，`api_id`填接口目录检索返回的真实接口ID。

## 边界与核验

- 接口不可用、调用失败或空结果不写成“企业无已发生事件”或“无未来事件”，如实登记状态；事件库整体不可用时风险发酵链路章按空输入规则处理并在报告说明，前三章照常执行。
- 接口返回的风险标注（正面/中性/负面）是数据源情绪分级，不是企业风险等级，不作为发酵判断的依据，只作为线索排序参考。
- 未来事件的“预计发生时间”常为粗粒度（年份、月份、半年），不代表确定发生；预计时间早于截止时点的条目须核对是否已实际发生。
- 凭据、请求头与认证信息不进入底稿；原始返回中的内部追踪ID（如nrsTraceId）保留在底稿，不进入分析正文。
- 事件条目的摘要、分类、风险标注为接口原文，不改写、不重译；`highLight*`字段是HTML高亮版本，不作为独立材料。
- **渠道名禁入（V19）**：正文、图注与表格中一律不出现“事件库”“未来事件库”等渠道名；事件条目归属只通过溯源角标承载，预计时间写作“预计××（以披露为准）”。

## 与后续环节的交接

原始返回按[事件库处理](event-processing.md)进入`build_event_package.py build`建立候选池；模型阅读候选索引后提交一份`selected_ids`；`compose`回填单一标准事件包。事件包经`prepare-fermentation`排序、截止过滤后渲染进风险发酵链路任务。事件库条目不进入前三章、不进入词云与数量趋势统计（两图统计对象是资讯篇数）。
