# 从用户问句识别监测时间范围

时间范围是任务入口的明确参数，决定资讯检索期间。先解析企业和时间，再执行一次综合检索；不能获取后按返回日期反推用户期间。不增加业务渠道，解析结果随唯一共享资讯包上下文进入`shared-analysis`，企业名称及资讯各传一次，同一任务生成前三章。重点关注仅接收前三章最终正文及随文原始引用，继承其期间，不另查或额外传入时间与资讯包。

## 时钟与解析顺序

1. 使用客户端明确提供的当前日期/时点和时区。本项目为 Asia/Shanghai；相对期间按上海当地日期计算，不使用执行机器时钟。
2. 从完整用户问句提取时间表达，区分滚动时长、自然周期、明确日期区间和“截至某日”。企业名称中的数字不当成期间。
3. 明确日期优先；“截至某日＋近半年”将指定截至日作为回溯锚点。多个不相容区间、无法辨认的年份或可能要求未来预测时先确认，不能选择其中一个或退回默认。
4. 没有时间限制时默认“近三个月”（日历回溯3个月）。“近期/最近”但无具体长度时也按近三个月处理，并在报告中明示采用的范围。
5. 产出起始日期、结束日期、资讯截止时点及原始表达/解析依据。综合检索及明确缺口的定向补查共享同一任务期间，结果回同一资讯池；重点关注继承前序正文边界。

## 期间口径

起止日期均包含。日历月/年回溯使用目标月份同一日；该日不存在时取目标月最后一天。“近一月”和“上月”是两个不同范围。

| 问句表达 | 起始日期 | 结束日期 |
|---|---|---|
| 无时间限制、近期 | 截止日期回溯3个日历月的同日 | 截止日期 |
| 近一月/最近一个月 | 截止日期回溯1个日历月的同日 | 截止日期 |
| 近半年/最近六个月 | 截止日期回溯6个日历月的同日 | 截止日期 |
| 近N个月/近N年 | 回溯N个日历月/12N个日历月的同日 | 截止日期 |
| 近N天 | 截止日期减N−1天 | 截止日期 |
| 近一周/近N周 | 截止日期减7N−1天 | 截止日期 |
| 这周/本周 | 所在周的周一 | 当前截止日期 |
| 上周 | 上一自然周的周一 | 上一自然周的周日 |
| 本月/这个月 | 所在月的1日 | 当前截止日期 |
| 上月/上个月 | 上一自然月的1日 | 上一自然月最后一天 |
| 今年/本年 | 本年1月1日 | 当前截止日期 |
| 去年 | 上年1月1日 | 上年12月31日 |
| 明确起止日期 | 用户给出的起始日 | 用户给出的结束日 |

“本周/本月/今年”仅分析截至目前已公开的材料，不扩展到尚未到来的周日、月末或年末。完整历史期间以该期末为资讯截止时点，后续公开材料不倒填历史快照；用户明确要求查看历史事项的最新进展时，另行记录其指定的更新截止时点。遇到超过当前时点的明确日期区间，先确认用户要历史监测还是预测，不擅自修改范围。

资讯只有日期而无时分时，不补造00:00作为实际发布时间。历史日内截止与材料披露同日时，需核验其是否在指定时点前公开；未核验不能声称当时已知。

以客户端日期 **2026-10-13** 为例：

| 用户问句 | 解析后的检索区间 |
|---|---|
| 贵州茅台近半年的预警监测报告 | 2026-04-13 至 2026-10-13 |
| 江淮汽车这周的预警监测分析 | 2026-10-12 至 2026-10-13 |
| 江淮汽车预警监测 | 2026-07-13 至 2026-10-13（默认近三个月） |
| 江淮汽车近30天预警监测 | 2026-09-14 至 2026-10-13 |

示例是时间计算口径，不表示已完成企业名称识别或实际检索。

## 用于资讯获取与分析

将解析结果写入本地任务记录 `time_range`，保留原始表达、是否默认、解析依据和实际日期。将 `start_date/end_date/data_as_of` 写入资讯包 `context`，范围描述继续由任务提供；检索计划的每条 query 登记同一起止日期。

首轮query使用[资讯获取](news-acquisition.md)中的简短模板，写明已确认企业全称和实际起止日，例如：

> 请检索安徽江淮汽车集团股份有限公司在2026-10-12至2026-10-13期间公开的资讯、公司公告和重要新闻。

例中企业全称仅作格式演示，实际必须先核对主体。实际日期写入检索需求；如何传入该需求遵循运行平台的 mx-finance-search 技能。

服务返回结果仍须核对发布时间。主材料应对应本期披露或更新；此前发生但本期有进展的事项可以纳入，并标明真实发生日期。解释持续事项所必需的原始旧公告可以作为注明时间的背景材料，经同渠道定向补查，不延长本期统计范围，也不把旧闻转载算作新增。资讯截止过滤和未来计划规则继续按 [资讯处理](news-processing.md) 执行。

## 本地确定性辅助

`scripts/resolve_time_range.py` 支持常见表达与明确日期区间，只做本地计算。客户端时点由调用方提供：

```text
<可用Python> -X utf8 "<skill目录>/scripts/resolve_time_range.py" --query "贵州茅台近半年的预警监测报告" --as-of "2026-10-13T15:00:00+08:00"
```

成功返回 `status=resolved`、`time_range`、`context` 和 `query_constraint`。把 `context` 的三个日期字段加入原资讯包，并补入本次scope；`query_constraint`保留为内部时间解析记录。实际query使用企业全称和起止日构造，截止时点用于后续材料校验。原始时间表达和默认标记只留任务记录，不作为企业事实。

模块中的`build_news_query(subject, resolution, *, focus=None)`使用已核对企业全称和解析后的起止日，生成默认简短query；确有补查需要时，`focus`只填具体事项。未解析成功不能构造可执行query。该函数只拼接本地文字，实际查询仍由mx-finance-search完成。

辅助器不是完整自然语言理解模型。调用方先阅读原问句识别时间意图，只有确认没有具体时间限制或仅有宽泛时间词时才采纳 `defaulted=true`；若原问句有脚本未识别的明确时间，继续按原表达解析，不能采用默认结果。返回 `unsupported` 时，模型按本文件解析原表达并校验具体日期；返回 `clarification_required` 时先解决实际歧义。显式时间表达不得因脚本不支持就改用近三个月。准备器的默认期间与近三个月口径相同；调用主流程时应先解析问句并传入明确日期，不能靠准备器忽略问句后兜底。
