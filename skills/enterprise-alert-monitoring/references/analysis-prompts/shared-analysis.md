三个模块都是对同一保留材料集合的不同角度分析，不要求每条材料都在每章复述。共享包可能同时包含目标企业、股东、子公司及其他主体资讯，必须区分归属：关联主体的报道数量、情感和事件不能自动当作目标企业自身舆情或已承担责任。同一原文多片段、重复检索和转载应核验归并；同一事项的不同程序和进展合并说明，不重复累计金额。

本次生成前三模块正文，并单独整理舆情概览的词云事件标签、数量趋势统计及平台组合图需求，以及重点事件和关联主体两份表格；不建立风险影响独立章节。事件库（已发生事件与未来事件）由独立任务按[风险发酵链路](risk-fermentation.md)分析，不传入本任务；本章不使用事件库材料作为事实或引用。

重点关注由后续独立任务根据前三章正文及风险发酵链路正文提炼，本次不提前生成。

# 一、舆情概览的分析规则

分析时，先确认企业、监测期间、资讯截止、统计对象及去重口径，再概括期内趋势与情感，最后简述最重要的1—3个热点、影响、来源特征及有据股价联动。正文的组织顺序按下方“正文写作规范”执行。

- 数量默认仅为共享输入中最终实际纳入、可核验且属于本期的目标企业去重资讯，明确单位为“篇”；按事件统计时用“项”，不能混用。同原文片段、重复检索和同一转载不重复计篇，历史背景、日期不明及无法拆分的聚合回答不用于本期数量或趋势。关联主体资讯另按实际主体表述，不能全部计入目标企业。原资讯有覆盖明确的完整监测统计时，可按其原口径引用，并说明统计出处与范围；不能把有限搜索结果或重点筛选样本外推为全量声量。
- 趋势按真实披露日统计监测期内同口径日/周/月时间桶的数量变化，不以历史发生日代替。至少两个可比时段、覆盖范围和去重规则一致时才描述升降、集中或平稳，不把未覆盖日期补零，不由零散报道推断持续热度。只有同口径材料支持时才作上期或历史对比；重点筛选样本不能证明企业总体偏负面或负面占比上升。
- 情感针对目标主体，结合正文事实判正面、中性或负面；负面进一步分一般与严重。一般负面为影响有限、尚有处置空间的经营压力或争议；严重负面须有实质违约、重大停产、事故、违法等重大不利事实及对目标主体影响的证据，不以标题、报道多、金额大、来源等级或股价涨跌自动判级，传闻不当作已发生事实。分类互斥，负面总数与子类不重复加总；完整分级时一般加严重等于负面总数，有未判定情感或待分级负面时明确保留边界，不强塞中性或凑占比。这是材料分析分类，不是企业信用风险等级。
- 热点择要概括，不展开完整事件经过与机制。目标企业有公开交易股票，且资讯明确给出对应证券、市场和同期价格/舆情节点时，才简述时间联动；不用股东、子公司或关联公司股价代替，不拼接连续行情，不推断舆情导致涨跌。没股票、身份不明或同期材料不足时直接略去股价角度。
- 不强制凑齐所有角度，不逐章摘要；统计与判断均保留支持来源。

# 二、重点事件的分析规则

先筛选对目标企业重要的正面、负面或重要中性事件，再归并事实与阶段，最后在各事件内部说明必要影响、缓释及观察。讲清哪个主体、何时、发生什么、目前如何。

- 区分新增、持续、已缓释、已结束以及本期是否有重要更新；旧闻转载不算新增。重要订单、复产、兑付、整改完成、解除等正面进展同样保留。
- 对有依据的事件自然展开“事实变化—影响机制—已发生影响—条件性潜在影响—缓释因素—后续观察”。按实际材料选取经营连续性、回款、资金使用、融资接续、偿债、或有责任、治理合规、声誉等维度，不机械分析全部方面。
- 事实明确支持的后果写为已发生影响，有成立条件的推断写为潜在影响并说清条件。不能仅加“可能”就扩展无依据判断。计划、意向、获批授信不能写成已完成或资金到账；股东冻结、关联方被诉不直接等于公司资产冻结或公司损失。
- 各事件保留“事实—状态—影响—缓释/观察”的承接，不只堆日期和金额。不固定事件数量，不新增风险等级、违约概率、银行处置指令或观察期限。

完成本章正文后，按[视觉组件规则的重点事件表格](../visual-assets.md)将已核验并分析的重要事件归并为五列表格，单独保存和展示。表格字段、顺序、时间、主体、事件类型、舆情方向、行序及逐行来源均按该规范执行，不另扩未分析事项；表格与本章分析正文分别留档。

# 三、关联主体的分析规则

先核实主体关系、适用时间及事项归属，再概括关联主体本期重要舆情，最后解释与目标企业之间的有据传导及边界。

- 关系可涉及股东、实控人、母子公司、兄弟主体、参股企业、担保或资金交易对象、重要客户和供应商，均须资讯证实。区分登记集团与实际控股体系，不把兄弟主体写成母公司，历史关系须经当前核验。不因名称相似、同地域或同属行业推定关系，不补完整集团架构。
- 按实际材料选择说明该主体的舆情数量、可比趋势、情感、热点或重要事件及进展；这些统计须有明确主体、样本和期间，不能自动借用目标企业的统计，也不为每个主体凑完整舆情面板。关注重要正面支持、负面变化及已落实缓释。
- 经证实的控制权、担保、资金往来、业务依赖、经营或声誉联系解释传导。区分已经发生的影响与条件性影响；同属集团不证明代偿义务或资金占用，诉讼请求不等于实际损失。行业、政策和区域按“外部变化—企业实际暴露—影响或缓释”解释，不把外部统计改写为企业数据，政策或支持计划不等于企业已获支持。
- 不复述重点事件的完整论证，不把关联方事项归为目标企业自身事件；无有效关系或传导依据时略去本章。

完成本章正文后，按[视觉组件规则的关联主体表格](../visual-assets.md)将已核验并分析的关联主体、关系、事项和影响归并为五列表格，单独保存和展示。字段、行序、影响传导、舆情方向及逐行来源按该规范执行，保留条件与责任边界，不补全集团全图；表格与本章分析正文分别留档。

# 正文写作规范

本次三个模块的篇幅、段落与加粗要求统一按以下规则执行（V20：要点化、防密度堆积，先图/表后文；1.2/1.3 的表格为报告最终承载，文字仅补充表格外的流转与口径）：

| 模块 | 篇幅与段落 | 加粗重点 |
| --- | --- | --- |
| 舆情概览 | 200—260字：首句总述（≤40字）＋3—4个编号要点，每点≤35字；禁止长段与关键词串。 | 加粗有据的总体观察和重要变化。 |
| 重点事件 | 表格先行且**表格为报告最终承载**；文字仅保留表格外内容（如与上期流转对比、表内未覆盖的口径说明），1—3句，无此类内容则不写文字。 | 加粗重要事项、阶段或核心影响。 |
| 关联主体 | 表格先行且**表格为报告最终承载**；文字仅保留表格外内容（如跨主体关联结论），1—2句，无此类内容则不写文字。 | 加粗主要观点。 |

舆情概览采用「首句总述＋编号要点」结构：

1. **首句总述**：≤40字的一句话给出最重要变化或当前状态（如「本期融资落地、舆情正向主导」）。
2. **编号要点**：3—4 点，按 样本数量与情感/热点主线/风险观察 的顺序择要组织，每点≤35字、只含事实与判断，不展开完整事件经过。
3. 样本口径（N篇资讯）以一句话附在末要点之后，不外推全量声量。

首尾判断均限定于本次有据样本；缺少可比材料时只概述当前状态，不推断舆情升降或改善。上述结构是段内组织要求，不在正式正文中显示“总述、分述、总结”等步骤标签。

三个模块共用以下写作要求：

- 字数按去除Markdown控制符、列表编号、引用及来源控件后的可见正文字符计；标题、图表和图注不计，加粗正文照计。
- 使用成对Markdown粗体；重要数值须与其业务含义一起表达。不加粗整段、孤立企业名/日期/金额、链接或来源。引用在完整事实句之后、粗体之外。
- 不为达到参考篇幅重复事实、扩写无依据判断或凑内容。

# 共用来源与输出规范

- **渠道名禁入（V19）**：正文、要点与图注不得出现“事件库”“未来事件库”“资讯”“检索”等渠道性来源说明；事件条目预计时间写作“预计××（以披露为准）”，归属只经溯源角标承载。

- 全部业务事实只来自上方共享资讯，前序生成分析、模型先验、图表或审计不能成为新事实。只使用本次统一保留集合；被过滤或未入选的资料不能单独用于正文、统计或图表。
- 每个事实句与分析判断紧随其实际支持的原始引用，来源不能移到全章末尾。保留原生引用及真实URL；无引用标记时不自编，不用内部ID或查询代码冒充来源。跨章引用同一事实时沿用同一原始来源。
- 数值保留原企业、期间、币种、单位和披露口径；不重复累加同一司法事项金额，不以授信额度抵销债务，不把订单额当收入。来源冲突先核对并保留条件，不平均或任选结论。
- 在同一次输出中分别形成并保存上述三个模块的最终正文及随文引用。重点关注按三个固定输入槽位直接接收对应正文及引用，不要求模型重抄全文JSON。
- 词云标签和趋势统计分别作为内部记录交给词云生成器及平台图形能力，重点事件和关联主体两表分别作为独立组件保存。模块名用于内部定位，最终有效章节和图表的连续编号由整份报告组装统一分配。
- 展示顺序（V19）：1.1 舆情总结先展示“舆情词云”和“舆情数量趋势统计”两张图，再展示文字要点；1.2 事件总结、1.3 关联主体动态均**先展示同名五列表格，再展示文字要点**。生成范围只限[视觉组件规则](../visual-assets.md)的固定图表清单，不另加、拆分或替换，详细生成与展示按该规则执行。词云调用内置脚本；数量趋势向平台提出“生成柱状图和折线图组合图”需求，并提供同口径逐桶总篇数、各事件类型涉及的篇数及来源，平台返回实际成图后再展示。本Skill不自行编写该组合图的绘制代码。两表使用Markdown表格并在HTML转换为原生表格，正文与HTML复用同源图表及来源。
- 无有效角度就略去，不写无风险、全部风险可控或资料缺失清单，不凑字、图或事件。不输出检索词、工具状态、程序路径、审计、输入包装或方法步骤。

# 舆情词云事件标签

依据本次共享集合中已核验、属于目标企业且本期有原始资讯支持的事件，提炼简短清晰的事件类型标签。标签描述实际事实与截至时点的状态，例如“股票停牌”“立案调查”“业绩亏损”“产能不足”；有据的“订单增长”“债券兑付”“整改完成”等正面标签同样保留。示例只说明命名方式，不能作为默认词库或无资料时的填充内容。

- 标签须有实际支持材料；区分发生、计划、获批、传闻澄清与解除，不把调查传闻写成已被立案，不把融资获批写成到账，也不把已解除事项标成仍在发生。统一同义表述，采用事项类型，不用企业名称、完整新闻标题或金额代替。
- 先语义归并同一真实事件：转载、原文多片段和阶段更新共用一个`event_id`，同一事件同一标签只计一次。一个事件可有多个有据类型标签，不能把各标签频次合计当作事件总数。原始条目数、引用次数、权威度、金额和严重程度不作为字号权重。
- 仅统计目标企业自身的本期可核验事件。关联主体事件不直接算作本企业事件；历史背景、日期不明或无法拆分的汇总回答不作为本期标签计数依据。每个事件须至少有一条本期公开且不晚于截止时点的原始资讯及真实URL支持。
- 将标签整理为以下小型内部JSON，`source_ids`只引用上方材料ID，原文与URL由程序回填；`verified=true`仅在实际阅读核验后填写。材料ID只用于绑定，不能当作来源引用或展示在报告中。无合格事件时返回空`events`数组，不制造词语。

```json
{
  "events": [
    {
      "event_id": "同一已归并真实事项的标识",
      "subject": "目标企业全称",
      "labels": ["有据事件类型"],
      "source_ids": ["对应原始材料ID"],
      "verified": true
    }
  ]
}
```

生成器按各标签对应的去重事件数量计算词频并生成词云资源，格式及交互见[视觉组件规则](../visual-assets.md)；颜色只用于排版，不表达情感或风险等级。标签、频次、原始来源及生成资源保留为内部底稿，正式正文只展示词云及其必要图注和来源。

# 舆情数量趋势图交接

在同一次阅读中，依据概览的最终有效资讯样本及已核验发布时间整理时间桶、总篇数、各事件类型涉及的篇数及来源绑定，按[视觉组件规则](../visual-assets.md)的统计与分类、平台图像描述需求交给平台生成组合图。图中柱体反映各桶去重资讯总篇数，多条折线分别反映各事件类型涉及的资讯篇数变化；不能使用词云事件频次代替资讯篇数，也不能因资讯没有词云标签而将其排除。同一篇可有多个类型，各类型数量不可相加作为总量；情感判断仍用于概览正文。逐桶总量、统计范围及缺失值与概览一致，分类和计数细则只按视觉规则执行，不为成图重新检索、另建资讯包或重抄全文。内部统计与作图需求独立留档，正式报告展示平台实际图形及其必要图注和来源。

# 空输入

共享资讯为空、只有内部状态或没有可归属于目标企业的有效材料时，返回“暂无数据”作为内部结果。某章无有效内容时只将该章内部结果置空，不用其它章或模型先验补位；运行时省略空章，剩余章节连续编号。来源或事实修正后，重新核对受影响的前三章、统计及后续重点关注，再冻结正文和同源HTML。
