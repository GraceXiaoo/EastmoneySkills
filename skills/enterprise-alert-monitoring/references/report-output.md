# 报告输出与验收

## 交付顺序

最终报告按[报告结构与格式规范](report-format.md)的V20四章业务结构组装：一、监测信息总结（1.1 舆情总结／1.2 事件总结／1.3 关联主体动态；1.2/1.3 先表格，表格即全部内容，**不放重复文字总结**）；二、风险走势研判（2.1 风险发酵链路——先链路图、再五列表格，表格即全部内容／2.2 风险传导／2.3 未来风险预测）；三、分级预警清单（3.1 红色预警／3.2 黄色预警／3.3 蓝色观察／3.4 待验证事项，章首放预警分布图）；四、短期内关注（不设子章节，仅观察清单）。五任务链路产出的五章正文按此重组：前三章正文并入第一章，发酵链路正文拆入第二、三章，重点关注正文转为第四章短期关注清单。交付双格式同源附件：企业全称预警监测报告.html（主交互版）＋.docx（Word编辑版）；生成与验收规则见[多格式导出规范](report-export-formats.md)——Word 图表必须走 svg_inline→soffice→pdftoppm 200dpi 高清管线。不交付 Markdown/PDF/独立图片/数据底稿或审计文件；soffice/docx 工具不可用时仅交付 HTML 并注明。

交付顺序固定为：

1. 报告标题＋一行「监测期间：起至止」（V19：不写「（含两端）」，不加数据截至/样本口径附加行）；**标题强制单行**（V20：HTML/Word 放不下自动调小字号，不换行）。
2. 「报告目录」：四章及子节清单（无内容子节略去）。
3. 「核心概要」：5—8 条编号要点（每条≤40字），覆盖本期主线、最重要事件、预警档数、关键未来节点、待验证事项。
4. 独立一行：`内容由 AI 生成，仅供研究参考，不构成投资建议。`
5. 独立一行：`**附件：**`。
6. 紧接平台实际返回的 HTML 附件卡片（+Word 卡片）。

V20：对话**不**返回整篇报告正文、表格全文与图表；完整图文一律在附件中呈现。

“附件：”与 HTML 卡片之间不插入说明或清单，卡片后不追加总结。正文和 HTML 不得出现取数、检索、组装、校验等制作过程话术，也不得出现“事件库/未来事件库/资讯检索”等渠道性来源说明；未完成步骤应在免责声明前简洁说明，不能写成企业结论。

报告标题为“企业全称预警监测报告”。标题下仅一行「监测期间：起至止」（不带「（含两端）」）；截止时间、样本口径（N篇资讯＋M条事件）以一句话并入 1.1 舆情总结文本末尾（不出现“事件库”字样），首期与否在 1.2 注明。每个事实句紧跟真实原始引用，图注也必须保留支持图形的来源。交付前把内部引用绑定到可访问的原始URL，没有真实链接的材料只能用于内部核验，不能据此生成可点击溯源。

## 章节与写作规则入口

最终章节固定按“舆情概览、重点事件、关联主体、风险发酵链路、重点关注”排序。没有有效文字分析的章节略去，剩余章节从“一”连续编号。

前三章由一个`shared-analysis`模型任务使用同一份最终保留资讯生成，不能分别搜索、分包或重复传入。风险发酵链路由三章最终正文加共享事件包经`prepare-fermentation`生成；重点关注另由四章最终正文汇总；标题顺序不代表多次资讯分析调用。

各章的具体写作要求只在下列执行提示词中维护，本文件不复制写作规则：

| 章节 | 执行提示词 |
|---|---|
| 舆情概览 | [shared-analysis.md：舆情概览](analysis-prompts/shared-analysis.md) |
| 重点事件 | [shared-analysis.md：重点事件](analysis-prompts/shared-analysis.md) |
| 关联主体 | [shared-analysis.md：关联主体](analysis-prompts/shared-analysis.md) |
| 风险发酵链路 | [risk-fermentation.md](analysis-prompts/risk-fermentation.md) |
| 重点关注 | [key-concerns.md](analysis-prompts/key-concerns.md) |

分析职责、前后依赖和重点选取逻辑见[分析链路](analysis-workflow.md)。写作验收按对应执行提示词进行，HTML沿用已冻结正文的内容与样式。

## 统计与引用

统计只针对共享包经一次统一筛选、截止过滤及来源核验后最终保留且可核验的本期去重资讯。同一原文片段、重复检索及同一转载合并；日期不明、区间外背景和无法拆分汇总不计本期数量/趋势。目标与关联主体各自数量、情感分开判断，不把关联负面直接计为目标严重负面。补查或来源移除后重核数量与分类，不能继承失去支持的总数。资讯“篇”与事件“项”分开，未完整分类不编占比；一次检索及重点样本均不代表全量覆盖。

趋势至少有两个覆盖范围和口径一致的时间桶，未覆盖日期不补零；不要求另取上期比较。情感针对目标企业，正面、中性、负面互斥，负面子类与负面总数不重复加总；未判定样本不硬塞中性。股价联动只使用目标企业自身公开交易证券及可靠同期材料，不拿母子公司或关联公司股票代替，不由个别价格节点构造连续行情或推断因果。

## 图表与编号

舆情概览包含内置代码生成的词云及平台生成的数量趋势组合图，重点事件、关联主体和风险发酵链路各含同名五列表格。图表清单、字段、数据口径、生成方式、展示顺序、连续编号、图注、逐行来源及空数据处理只按[舆情图表与图文衔接](visual-assets.md)执行。组件放在所属章完整正文后，对话正文与HTML都必须展示实际图表，不能只在附件中出现，也不能用图像描述替代成图或用图片替代表格；所属章节略去时相应组件一并略去。

## HTML 附件

HTML与对话使用同一份冻结正文、引用和免责声明，保留四章业务结构内容与已有粗体。全部图表为纯静态SVG内联，禁止依赖JavaScript运行时渲染（CDN脚本在离线或受限环境下不执行会导致图区空白）；静态图表由`scripts/render_static_charts.py`按固定模式生成，图表位置、图例与徽章规范见[报告结构与格式规范](report-format.md)。转换只处理排版，不重新取数、分析、扩写、缩写或改章，也不重新决定正文强调位置或列表形式。正文实际使用的Markdown有序列表转换为原生`<ol>`与`<li>`，已有粗体转换为`<strong>`，不得留下可见Markdown控制符。

各章的图形数据与默认布局、三表各自列序和行内容、编号、图注及来源沿用冻结版本，不在HTML中重绘。三表转换为原生`<table>`；词云内联交互SVG，对话的呈现能力不足时使用同版静态预览。具体嵌入、交互、来源绑定及独立打开要求只按[舆情图表与图文衔接](visual-assets.md)执行。

HTML中的每个“溯源”标识为右上角上标样式（虚线下划线小字，点击或展开显示来源卡片：标题、发布时间、来源机构、原文链接），紧跟被支持的事实句之后；禁止行内大按钮式来源控件。事件库条目无URL时卡片如实标注，不编造链接。详情至少包含展示序号、标题、发布时间、来源机构和可点击URL；不得使用空链接、内部ID、会话路径或猜测拼接URL。来源标识紧跟事实句或图注，不能集中到章节末。

实际打开HTML，逐章核对文字、粗体、列表、图形、编号、范围、单位、来源弹窗及免责声明；按视觉规则验证词云逐词悬浮和键盘聚焦效果，确认下载后的HTML独立打开仍能显示并操作图形。任何版本不一致都回到同一份最终内容修正，再重新生成受影响组件。未返回真实HTML附件卡片时，不按文件名、任意ID或本地路径伪造卡片。

## 交付前检查

1. 主体、日期、阶段、单位、关系和来源准确；前三章共用同一保留集合，概览统计据最终统一样本，重点事件含必要影响和观察，关联主体边界清楚，发酵链路三档判断有据且已映射红黄蓝分级、每条预警含解除或升级条件，处置建议承接前四最终正文且每点可执行。来源或事实修正后重核概览、受影响章节并重新生成后续章节。
2. 五章顺序正确；各章写作符合对应执行提示词，引用紧跟事实。
3. 最终图表逐项对应[视觉规则](visual-assets.md)的固定清单，核对名称、形式及模块归属，清单外图表不得进入正文或HTML。分别核验词云事件频次、趋势图资讯总篇数及事件类型涉及篇数与时间桶、三表各自固定五列及单元格事实与逐行来源、主体与关系、影响传导、发酵判断与链路、监测期间、连续编号和实际成图。组合图复用平台实际返回资源，三表正文与HTML内容一致。事件库条目无URL时信息编码如实展示，不伪装可点击来源。
4. 双格式同源验收：HTML 可读、无内部占位符或伪造链接、溯源角标交互可用、静态SVG无网可显；docx 经 validate 零错误，Word→PDF 页图抽检图片内文字锐利完整无拉伸裁切；免责声明收尾且不追加「附件：」占位行。

离线输入和词云脚本测试不验证真实资讯或平台附件卡片；每次实际运行仍需核验原文、图片、HTML及来源交互。
