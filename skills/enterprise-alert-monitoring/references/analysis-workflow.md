# 共享资讯分析与正文汇总链路

## 运行顺序

用户query → 确认单一企业及时间范围 → 一次综合mx-finance-search检索＋事件库两接口各一次检索并保存原始返回 → 分别建立共享资讯候选池与共享事件候选池 → 模型各提交一份入选ID数组 → 程序分别回填标准资讯包与标准事件包 → 资讯包一次排序及截至过滤后完整渲染唯一shared-analysis输入 → 同一次分析任务生成前三章正文及各自内部记录 → 核实原始URL并同步修正前三章与统一样本统计 → 程序把三章最终正文与事件包（已排序、已截至过滤）渲染为唯一risk-fermentation输入 → 三档发酵判断及链路生成（含五列表格） → 程序按报告顺序完整交接四章最终有效正文与随文原始引用 → prepare-concerns五占位符渲染 → 重点关注合并角度并按重要性选5—6个正面或负面重点 → 冻结最终正文及引用 → 按report-format.md把五任务正文重组为四章业务报告（监测总结→风险研判→分级清单→短期内关注；发酵判断映射红黄蓝分级，静态图表经render_static_charts.py按V8视觉规范渲染）→ 交付。

组件使用各次分析已保存的记录：内置脚本生成词云，平台按图像需求生成数量趋势柱线组合图，三份五列表格分别对应重点事件、关联主体及风险发酵链路。组件按顺序放在所属章完整正文后，再核验同源HTML与来源交互，最终按完整正文、固定免责声明及HTML卡片交付。

默认资讯只有一次综合检索、事件库两接口各一次初始检索。有明确关键事实、关系、日期或来源缺口时，记录具体补查理由，通过同一渠道定向补查并合入对应共享池；不按章建立默认搜索或补查配额。一次检索不代表全量覆盖；事件库空结果不代表企业无风险或风险不会发酵。

## 程序与模型的分工

程序读取原始返回，保留标题、正文、机构、时间、URL、原始引用及分类元数据，建立稳定ID与平面候选目录。模型阅读候选并只提交一份`selected_ids`数组及必要最小`events`数组；程序回填一个无分章blocks的标准包。资讯不得要求模型转抄整篇正文、URL、citation或构造每章全文JSON；字段复制及来源绑定由程序执行，相关性、主体和事实归并由模型判断。

同URL不同内容片段保留，只有规范业务字段完全相同才复用同ID；同一新闻的片段、转载和不同事件在统计与事件归并时继续核验，ID数不等于篇数或事件数。聚合回答不按段落拆成假新闻。`verified=true`必须来自实际阅读核验，生成器不自动赋真。events可空，不为每篇资讯强建事件或冗长claims/developments。

来源保留原值，由共享规则另行确定五档V2。派生评估不参与原文稳定ID；组包和准备均从原始元数据重算，不信任模型填写的等级，不猜原始编码。资讯统一按V2→发布时间倒序→原始顺序排列，未知后置。准备输入只在词云来源绑定的窄用途下逐条提供材料ID，不能把它当作引用或输出到报告；查询、凭据及审计不进入分析正文。详细契约见[资讯处理](news-processing.md)。

## 同一次任务生成前三章

前三章唯一执行提示词是[shared-analysis.md](analysis-prompts/shared-analysis.md)，只渲染`{{企业名称}}`及`{{资讯}}`，各一次；舆情概览、重点事件、关联主体的完整规则均在该文件内维护。风险发酵链路单独使用[risk-fermentation.md](analysis-prompts/risk-fermentation.md)，渲染`{{企业名称}}`、`{{事件库}}`及三章正文各一次。重点关注单独使用[key-concerns.md](analysis-prompts/key-concerns.md)汇总四章正文，执行提示词目录保留这三个文件。

在统一任务内部，先核实重要事件的事实、主体、日期、阶段与影响，再核实关联关系及其传导，最后依据同一最终保留资讯集合组织总体概览。内部可按事件→关系→概览推理，但成文展示始终为舆情概览→重点事件→关联主体。这里是一个任务的内部组织，不是三次模型调用；前序生成文字只用于一致性核对，不替代共享原始资讯作为前三章证据。

共享任务包含固定提示词、企业名、业务上下文、完整有效原文与引用及有据事件。按权威度由高至低、同档发布时间由近及远稳定排序，并列保持原输入顺序，未知权威度及同档未知发布时间后置。排序与截止过滤只做一次，三个章节共用相同保留集合，完整保留有效资讯、来源绑定和核验事件。词云标签、数量趋势统计及重点事件、关联主体两份独立表格也是同一次阅读的输出，不增加资讯调用；口径、平台需求及图表交接只按[舆情图表与图文衔接](visual-assets.md)执行。补查或来源修正改变集合时，重核受影响事实、概览统计、词云标签、趋势数据及两表。

## 任务时钟

- 先按[时间范围识别](time-resolution.md)解析具体日期，用于综合query及全部定向补查。没有明确限制默认近三个月，按日历回溯3个月，不固定30天。
- 截止采用用户明确日/时；未指定采用客户端当前时区时点。本周为周一至当前，近一周为最近7天，完整历史期间以期末为截至。
- 发生日说明事项何时发生，披露日说明何时公开，更新日识别最新进展；不将转载日当发生日。
- 历史快照仅用截至时点已公开资料；期间发生但其后才披露的事项不回填。
- 旧事项本期有澄清、偿付、解除、裁判等进展可纳入并明确阶段；旧闻仅转载为背景，不算新增。
- 比较期只有材料和口径支持时启用，不从空白快照算增量，司法当前/历史不等于本期/上期。

## 五章分析职责

| 章节 | 先 | 再 | 最后 |
|---|---|---|---|
| 舆情概览 | 核定共享集合中的目标企业本期可核验去重资讯、统计对象及篇数/事件项数 | 概括期内可比数量趋势，针对目标判正中负及一般/严重负面，未知不硬归中性 | 简述最重要1—3个热点及有据影响，目标股票及同期证据充分时描述时间联动，不展开机制 |
| 重点事件 | 核实主体、发生/披露时间、事实、阶段、新增/持续/本期更新 | 按事件自然嵌入影响机制、已发生影响、条件性潜在影响及真实缓释 | 说明有据后续观察，不给企业风险等级，保留重要正面进展 |
| 关联主体 | 核实关系类型、主体与适用时间，再核实其本期舆情及事件归属 | 简述该主体舆情、热点与状态，按已证实资金/业务/担保/治理等关系分析传导 | 归纳重要影响、缓释及责任边界，不把关联事件直接当目标已发生负担 |
| 风险发酵链路 | 识别前三章与事件库中的已存在风险及已发生事件 | 三档判断（会发酵/不会发酵/待观察），会发酵的写五段式链路 | 核验链路每一环证据，断链降级；生成五列表格 |
| 重点关注 | 读取四章最终正文及随文原始引用，提炼重要既有判断、变化及影响 | 合并相近或因果角度，按实质影响、变化持续性和证据充分性选5—6个正面或负面重点 | 说明入选重点的必要依据、阶段与意义；不加事实或重新计算 |

章内阶段名和步骤不输出为报告方法说明，正文无需机械写“先、再、最后”。无依据的角度略去，不为补齐主题编造。风险发酵链路是预警监测的核心输出：会发酵的判断必须链路完整，不会发酵与待观察必须写明依据，不以“可能”补证据。重要已完成改善或风险解除可入选重点关注，不以未来节点为门槛，有效独立重点不足时据实选择，不拆分或编造。

各章具体写作要求只在执行提示词维护：前三章遵循[shared-analysis.md](analysis-prompts/shared-analysis.md)，发酵链路遵循[risk-fermentation.md](analysis-prompts/risk-fermentation.md)，重点关注遵循[key-concerns.md](analysis-prompts/key-concerns.md)。本文件仅说明分析职责和处理顺序。

## 统一样本统计

只统计共享集合经筛选、截至过滤和来源核验后最终保留的可核验本期材料，不继承候选总数。同一原文片段、重复返回和同一转载合并；篇数与事件项数分开。日期不明、区间外背景及无法拆分的聚合回答不计本期数量或趋势。目标企业及各关联主体的舆情分别判断；关联负面不直接计为目标严重负面。不能将重点样本外推全量声量。

趋势至少两个覆盖范围、统计对象和口径一致的时间桶，未覆盖日期不补零。情感互斥，负面父类与一般/严重子类不重复相加；严重负面须有重大不利事实及目标影响依据，不按措辞、报道量、来源级别提级，不等同企业信用风险等级。只在原始资讯明确提供范围完整且可核验监测统计时按原披露口径引用，并注明其范围。

股价仅用目标对应公开交易证券及mx资讯有据同期节点，保留证券、市场、日期和价格口径；无股票或证据不足略去。不能用关联股票替代、补连续行情或将同步变化写为因果。

## 重点关注正文交接

前三章完成并核验来源后，事件包经`prepare-fermentation`渲染：程序读取已保存三章最终正文、共享事件包及事件库材料，生成发酵任务输入。发酵章完成后，运行时/程序直接读取四章已保存最终正文及随文原始引用，形成`analysis_results`四槽位：`monitoring-overview/key-events/related-environment/risk-fermentation`，对应`{{舆情概览内容}}/{{重点事件内容}}/{{关联主体内容}}/{{风险发酵链路内容}}`，企业名称固定。各槽位仅保存对应章最终正文及随文引用，无有效正文或内部“暂无数据”的槽位置空，由程序完整交接，不让模型重抄整章JSON。

`prepare-concerns`使用独立`key-concerns.md`及五占位符，按固定报告顺序完整接收四章有效正文及随文引用，保持原正文和引用，不给生成正文赋V2。四槽全空时内部“暂无数据”，最终略去本章。

重点关注根据传入正文及随文引用整合既有观点，保留原事实、数值、单位与判断边界，不用先验补事实或评级。前序正文或来源修正后，先修正对应章，再重新交接并生成本章；报告采用修正后的最终内容。重点关注不反向作为资讯或事件，也不驱动新搜索形成循环。

## 事实推理与责任边界

每条事件先说明谁、何时、什么事项及阶段，再按证据说明新增、延后、澄清、整改、解除或完成。有据时分析经营连续性、回款、资金使用、融资接续、偿债、或有责任、治理合规及声誉。已发生影响与条件性潜在影响分别表述，条件性判断说明触发条件。计划/获批不等于落实，股东支持和国资背景不自动代表救助或代偿。无需每个事件写满全部角度。

| 已有事实 | 可以分析 | 不能自动推出 |
|---|---|---|
| 股东股份冻结 | 股份处置、控制权及股东支持的条件性变化 | 企业生产资产或银行现金已冻结 |
| 获批授信/融资注册 | 融资安排取得进展 | 资金已到账或可随时提款 |
| 对外担保公告 | 或有责任、对象及触发条件 | 已经代偿或等额现金流出 |
| 归母净利润下降 | 盈利结构及已披露原因 | 财务造假或必然违约 |
| 关联公司违约 | 按已证实担保/资金/业务关系讨论传导 | 目标也违约或承担全部债务 |
| 事件与股价同日变化 | 描述时间关联及原文解释 | 必然存在涨跌因果 |
| 无有效检索结果 | 本次该主题无可用材料 | 企业无风险、无担保或低风险 |

## 成文与最终核验

先剔除无有效文字章节，按展示顺序连续分配“一、舆情概览”等标题；各章初次生成不固定最终编号。在舆情概览完整正文后依次展示词云及数量趋势组合图，重点事件、关联主体和风险发酵链路完整正文后分别展示同名五列表格。具体字段、标签、数量统计、图像需求、连续编号、资源及HTML同源要求见[舆情图表与图文衔接](visual-assets.md)，最终交付见[输出规范](report-output.md)。

冻结前核实真实原文URL；事实无法有效溯源时，修正共享依据、相关正文与统计，再生成重点关注。内部底稿、审计、输入副本和正文分别留档，不把内部ID、query或制作过程写入报告。核对主体、期间、阶段、金额、关系、来源、样本范围、图文和HTML同源及来源弹窗；各章写作按对应执行提示词验收。

固定交付顺序：完整图文正文 → `内容由 AI 生成，仅供研究参考，不构成投资建议。` → `**附件：**` → 紧接真实HTML卡片。只交付一个完整报告HTML，不交Markdown、Word、PDF、独立图片附件或底稿文件；词云内部资源的交互嵌入及静态预览遵循[词云与图文衔接](visual-assets.md)。卡片后不追加总结。
