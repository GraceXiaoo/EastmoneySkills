# 企业主体识别与监测范围

本文件独立规定目标企业名称、身份标识和候选歧义的处理。当前平台的实体识别能力只用于确认主体身份，进入分析的事实材料仍须来自 mx-finance-search。

## 解析用户请求

从原问句分别保留企业全称、简称、曾用名、用户给出的完整机构代码或证券代码，以及时间表达。时间表达按 [时间范围识别](time-resolution.md) 转成具体监测区间，作为后续资讯检索参数。保留原始文本供核对，不把未经确认的名称扩写成另一个主体。

- 完整企业名称优先；用户同时给出名称和代码时，两者必须匹配，不能仅凭代码覆盖名称。
- 机构代码保留完整值，不截断、不补位。工具同时给出机构代码和带后缀实体标识时分别保存，不依固定长度截取或猜测转换。
- 股票代码与机构代码是不同标识。688630.SH 的六位证券部分不是企业机构代码；保留证券代码的市场后缀。
- 简称、曾用名只作检索别名。其与目标企业的对应关系须由实体候选或 mx-finance-search 返回的公告等材料核对。
- 没有明确企业、一次涉及多个企业或问句把母子公司混为一个对象时，先请用户确定本次单一主体，确认前不进行企业综合检索。主体明确后默认一次综合检索、一个共享包及同一次前三章分析任务；重点关注在这三章成文后汇总，不另行取资讯。

## 主体核对流程

1. 从问句提取名称与用户提供的身份标识，核对用户要监测的企业主体层级。
2. 当前平台有实体识别能力时，按其实际接口检索候选，阅读真实返回的全称、身份标识、实体类别及证券对应关系。不依赖固定工具名称、类型代码或安装路径。
3. 名称与标识应指向同一企业。股票、债券等证券记录只作交叉核对，证券简称不能自动当作企业全称；母公司、子公司及其他同名主体分别识别。
4. 唯一候选与用户意图一致，或用户明确确认唯一全称后，固定本次目标企业。后续查询、各章和标题始终使用该全称。

不以是否上市、发债或企业标签作为准入条件。没有证券代码的企业，在主体能够唯一确认后也可进入监测。

## 候选歧义与工具不可用

- 多个候选对应不同企业，或母公司、子公司、同名主体均可能满足问句时，展示可辨认的全称及工具实际返回的识别信息，请用户确认；不得按热度、上市地位或名称相似度自行选定。
- 用户名称和代码互相冲突时，明确给出两者分别对应的候选并请用户确定，不能继续使用混合主体。
- 实体识别能力不可用、调用失败或候选字段不足时，不记录为工具核验成功，也不伪造代码。用户已经明确提供并确认唯一企业全称时，可以以该全称继续，内部记录代码未验证；简称、同名或母子歧义未解决时，先完成用户确认。
- 检索结果无业务记录不构成主体无风险；本文件不做业务查询，也不把实体识别空结果解释为企业不存在。

## 主体交接记录

在内部工作记录中保留下列逻辑字段。它们是本技能的交接记录，不限定任何平台的实体接口格式：

| 逻辑字段 | 记录内容 |
|---|---|
| 原始请求 | 用户给出的名称、代码与监测区间 |
| 已确认全称 | 本次唯一分析主体 |
| 检索别名 | 已核实的简称、曾用名 |
| 完整机构代码 | 实体识别实际返回或经核对的代码；未验证时留空 |
| 证券候选 | 实际返回的股票、债券或发行人标识及其对应关系 |
| 确认方式 | 实体候选唯一匹配、用户明确确认等 |
| 识别状态 | 已确认、待确认、工具不可用或调用失败 |

这个记录只用于构造资讯 query、主体消歧和内部审计；不能作为基本画像或股东/集团关系的分析输入。其它形式的身份标识可保存在识别记录，资讯准备器的可选org_code仅在符合其本地契约时提供；不适配时以已确认全称交接，不改造或伪造标识。集团、关联方和股东的负面事项进入正文前，必须由资讯材料同时证明关联关系与事件主体，并区分本公司事件与关联主体事件。

## 验证边界

企业全称确认、代码核验和实际检索成功分别记录。本地格式校验不证明名称代码匹配，候选或用户确认也不能替代报告事实核验。
