# 企业预警监测

围绕单个企业，把资讯中的事实整理为“事实—进展—影响—缓释—跟踪”的监测报告，并通过事件库（已发生事件与未来预期事件）判断既有风险后续是否会发酵。重点说明监测期内的变化及历史事项本期更新，区分事实、媒体观点和条件性判断。

## 入参与单包原则

从用户query识别并确认企业名称和监测时间范围，再分别通过`mx-finance-search`获取全部分析资讯、通过事件库两个接口获取已发生事件与未来预期事件。资讯默认执行一次综合检索，形成一个共享资讯池、一个统一入选集合及一个标准资讯包；事件库执行两接口各一次检索，形成一个共享事件池及一个标准事件包。同一份资讯、同一份事件条目均只在本技能内各传入一次：资讯用于舆情概览、重点事件、关联主体三章，事件库条目只用于风险发酵链路章，两者不互串。

- 企业名称：从问句提取并核对的目标企业全称，全程固定。
- 时间范围：按[时间范围识别](references/time-resolution.md)将“近半年”“这周”等转成具体起止日期。无明确限制时默认近三个月（日历回溯3个月），报告明示实际区间。
- 资讯：一次综合检索及必要定向补查取得的实际材料，统一保留业务期间、真实出处和必要核验事件。补查只针对明确事实、关系或来源缺口，结果回到同一资讯池，不按章另建包。
- 事件库：`事件大全搜索`（已发生事件）与`未来行动事件搜索`（未来预期事件）各一次初始检索，原始返回按[事件库获取](references/event-acquisition.md)落盘、去重并组包。事件检索期间与资讯监测期间一致；未来事件的预计发生时间可以晚于监测期末，这正是发酵链路章的分析对象。

统一执行提示词共三份：前三章为[共享资讯分析](references/analysis-prompts/shared-analysis.md)，占位符`{{企业名称}}`和`{{资讯}}`各一次；风险发酵链路为[风险发酵链路](references/analysis-prompts/risk-fermentation.md)，占位符`{{企业名称}}`、`{{事件库}}`及前三章正文各一次；重点关注为[重点关注](references/analysis-prompts/key-concerns.md)，占位符为`{{企业名称}}`及四章正文。各章正文由运行时或程序直接交接，不回读资讯或事件库，不由模型转抄整章JSON。

## 来源及证据边界

1. 按[企业识别](references/entity-resolution.md)确认单一主体；实体工具只用于身份消歧，不获取财务、司法、评级或行情等分析材料。
2. 加载并遵循当前平台可用的`mx-finance-search`技能。调用、授权、依赖与错误处理由该技能负责；本技能只规定[检索目标及交接](references/news-acquisition.md)，不复制其实现。
3. 事件库两接口按[事件库获取](references/event-acquisition.md)执行：先经接口目录检索获取接口ID与真实输入参数，再按该参数调用并保存原始返回；不得虚构接口ID、参数或枚举值。事件条目的摘要、分类与风险标注是接口原文，保留原值，不按内容改写。
4. 每条事实核对主体、发生/披露/更新日期、事项阶段及来源。金额、比例和指标保留原期间、币种与单位，不由零散披露推算企业全量规模。
5. 一次检索不保证全量覆盖。检索条数、纳入篇数及事件项数均不代表全量声量、完整风险覆盖或企业风险等级；空结果与失败不能推导企业无风险，也不能推导风险不会发酵。
6. 关联关系须有资讯证据，关联主体事项不归为目标企业直接事件。保留重要正面进展、澄清、解除及实质缓释。
7. 事件库条目的事件主体与目标企业不一致时（关键词检索必然引入相关主体），该条目须先经资讯证实的关联关系才可作为传导介质进入发酵链路，不能直接当作目标企业自身事件。

## 主流程与按需加载

| 阶段 | 动作及资源 |
|---|---|
| 1 主体与期间 | 读取[企业识别](references/entity-resolution.md)及[时间范围识别](references/time-resolution.md)，确认企业、具体区间和截止时点。真实歧义先解决。 |
| 2 一次综合检索＋事件库两接口 | 使用已确认企业全称和实际起止日，按[资讯获取](references/news-acquisition.md)的简短句式构造一条query，保存原始返回。仅对已识别缺口定向补查，注明理由并回同池。同时按[事件库获取](references/event-acquisition.md)调用`事件大全搜索`与`未来行动事件搜索`各一次，原始返回落盘。 |
| 3 统一筛选与组包 | 按[资讯处理](references/news-processing.md)用`build_news_package.py`建立平面候选目录，按[事件库处理](references/event-processing.md)用`build_event_package.py`建立事件候选目录。模型各提交一份入选ID数组；程序回填原文、URL及真实引用，分别生成标准资讯包与标准事件包。 |
| 4 一次分析前三章 | `prepare_inputs.py prepare`对共享资讯一次性按权威度由高至低、同档发布时间由近及远排序并执行截止过滤，完整保留有效资讯、来源绑定及核验事件，渲染唯一`shared-analysis`输入。按[分析链路](references/analysis-workflow.md)在同一次任务内先核实重点事件与关系，再形成概览，最终展示顺序为舆情概览→重点事件→关联主体。 |
| 5 风险发酵链路 | 核实原始URL并修正前三章后，运行`prepare-fermentation`：程序把前三章最终正文与共享事件包（已排序、已截止过滤）渲染为唯一`risk-fermentation`输入，按[风险发酵链路](references/analysis-prompts/risk-fermentation.md)对已存在风险与已发生事件作会发酵／不会发酵／待观察三档判断，会发酵的生成“源头事实→传导介质→触发条件→未来节点→潜在影响”链路及五列表格。 |
| 6 正文汇总 | 保存四章最终正文；运行`prepare-concerns`按固定四槽位交接至[重点关注](references/analysis-prompts/key-concerns.md)，合并相近/因果角度，按重要性选5—6个正面或负面重点。 |
| 7 报告重组与交付 | 五任务正文按[报告结构与格式规范](references/report-format.md)重组为四章业务报告（监测信息总结→风险走势研判→分级预警清单→短期内关注）；展示顺序遵循 V20：1.1 先图后文、1.2/1.3 先表格（表格即全部内容，不放重复文字总结）、2.1 先链路图再五列表格（同理不放重复文字总结）；预警分级由发酵判断映射（红=会发酵、黄=待观察、蓝=持续观察、利好=不设预警），每条预警含解除或升级条件。静态图表由`render_static_charts.py`生成（声量/分布/链路/时间轴四模式纯SVG，链路图底框自适应、分布图字号与正文一致），溯源用右上角上标。对话仅交付目录框架＋核心概要，同源HTML＋Word按[输出与验收](references/report-output.md)交付。 |

只按阶段加载必要规则。资讯技能或事件库接口不可用时说明获取未完成，不用模拟材料生成实际企业结论；事件库整体不可用时风险发酵链路章按其空输入规则处理并说明，前三章照常。

## 四章职责

| 展示顺序／内部键 | 模块 | 主要职责 |
|---|---|---|
| 1 `monitoring-overview` | 舆情概览 | 简述最终统一样本的去重数量、可比数量趋势、目标企业情感及一般/严重负面、1—2个热点及有据影响，必要时观察目标股票同期联动。 |
| 2 `key-events` | 重点事件 | 核实主体、时间、事实、当前阶段及新增/持续/本期更新，直接嵌入必要的影响机制、已发生与条件性影响、缓释及观察；保留重要正面进展。 |
| 3 `related-environment` | 关联主体 | 说明有据关系、关联主体本期舆情与事件、当前状态及对企业的传导条件，不补集团全图。 |
| 4 `risk-fermentation` | [风险发酵链路](references/analysis-prompts/risk-fermentation.md) | 对已存在风险或已发生事件，结合资讯、已发生事件与未来事件判断后续是否会发酵；会发酵的生成“源头事实→传导介质→触发条件→未来节点→潜在影响”发酵链路及五列表格，不会发酵与待观察写明依据；不新增事实、评级或概率。 |
| 5 `key-concerns` | [重点关注](references/analysis-prompts/key-concerns.md) | 仅整合前四章最终正文，合并重复或因果角度，按重要性选5—6个正面或负面重点；不新增事实、评级、计算或金额换算。 |

前三章共享同一保留资讯集合，在统一任务中各按职责取证，不分章选择ID、组包或重复传入。内部分析先事实及关系、再概览，外部展示顺序不变；章名不是事实来源。风险发酵链路章在三章冻结后执行，输入为三章最终正文加共享事件包，不再回读资讯池。无有效内容的章略去且不占编号；前四章正文全部为空时重点关注内部返回“暂无数据”，最终略去，全篇无有效材料时说明无法形成有依据的报告。

原文由程序读取和搬运，模型不重写含全文JSON，不转抄URL及原生引用。内部ID只用于筛选与绑定，`citation`只保留实际返回标记。来源采用[五档V2](references/news-processing.md)：专业数据库最高、公司公告或官方网站等较高、研报或权威新闻媒体等中等、互联网检索较低、其它社区或自媒体极低；未知后置。保留原始字段，重算有据`source_assessment`，按V2→发布时间倒序→原序稳定排序；不猜等级编码。`verified=true`只来自明确阅读核验，程序不自动填真。

## 报告组装、统计与图表

五章齐全时标题依次为`## 一、舆情概览`、`## 二、重点事件`、`## 三、关联主体`、`## 四、风险发酵链路`、`## 五、重点关注`。略去空章后重新连续分配中文序号，单章输出不预置序号。

正文写作规范统一维护在三份执行提示词内：舆情概览、重点事件、关联主体使用[共享资讯分析](references/analysis-prompts/shared-analysis.md)；风险发酵链路使用[风险发酵链路](references/analysis-prompts/risk-fermentation.md)；重点关注使用[重点关注](references/analysis-prompts/key-concerns.md)。篇幅、段落形式、列点表达、加粗方式及计数口径均按对应提示词执行，调整时修改对应文件。最终报告的展示结构、预警分级口径、语言规范（术语即界定、风险先结论后机制）、静态图表与溯源上标格式维护在[报告结构与格式规范](references/report-format.md)；五任务产出按该文件重组为四章业务报告交付。

概览统计只针对共享包经统一筛选、截止过滤及来源核验后最终保留的可核验本期样本。同一原文片段、重复检索及同一转载合并，篇数与事件项数分开；日期不明、区间外背景和无法拆分的聚合回答不计本期篇数或趋势。目标企业与关联主体各自舆情数量、情感分别判断，不把关联方负面直接计为目标企业严重负面。不能继承筛选前总数或外推全量声量；任一来源或样本修正后重核全章统计。趋势至少两个口径与覆盖一致的时间桶，未覆盖日期不补零。情感分类互斥，负面父类与一般/严重子类不重复加总，未知不硬归中性；严重负面须有重大不利事实及目标企业影响，不等同企业信用风险等级。

股价联动仅用mx资讯明确支持的目标企业对应公开交易证券及同期节点，保留日期、市场及原口径；不得用母子或关联公司股价替代，不新增行情或数据库渠道。零散节点不拼连续行情，同期变化不直接写为因果；无股票、证券身份不明或依据不足时略去。

舆情概览正文后依次展示“舆情词云”和“舆情数量趋势统计”。词云使用内置Python生成交互SVG及静态预览；趋势图由平台内置柱线组合图展示去重资讯总篇数柱体及各事件类型涉及篇数的折线。重点事件、关联主体和风险发酵链路正文后分别展示同名五列表格。生成范围仅限[舆情图表与图文衔接](references/visual-assets.md)中的固定清单，不自行新增或替换；详细字段、口径、生成方式、交互、连续编号及HTML复用规则均在该文件维护。

## 本地辅助

- `scripts/resolve_time_range.py`：根据问句和显式客户端时点计算日期及query约束，不读主机时钟、不联网。
- `scripts/build_news_package.py`：读取原始返回，建立统一候选池、稳定ID及V2；按一份入选ID数组和可选最小核验事件回填单一标准资讯包，不自动核验或生成引用。
- `scripts/build_event_package.py`：读取事件库两接口原始返回，按已发生事件/未来事件归一、去重并建立稳定ID，按一份入选ID数组回填单一标准事件包；`inspect`可查看候选原文，不自动核验或生成引用。
- `scripts/prepare_inputs.py`：`prepare`对共享资讯一次排序、截止过滤及来源绑定，完整渲染唯一`shared-analysis`任务；`prepare-fermentation`把前三章最终正文与共享事件包渲染为唯一`risk-fermentation`输入（五个占位符：企业名称、事件库、三章正文）；`prepare-concerns`按报告顺序完整接收四章有效正文及随文引用，渲染五个占位符。详细CLI见[资讯处理](references/news-processing.md)与[事件库处理](references/event-processing.md)。
- `scripts/source_authority.py`：五档V2共享规则，保留原值、重算有据评估，不猜编码。
- `scripts/render_wordcloud.py`：按已核验事件类型及原始材料绑定计数，生成同源交互SVG、独立HTML预览、静态PNG及复用清单；样式配置为`assets/wordcloud-style.json`。
- `scripts/render_static_charts.py`：报告静态图表渲染器，四种模式（volume声量柱线／distribution预警分布环形／chain发酵链路／timeline未来事件时间轴）输出纯静态SVG，无JavaScript依赖；
- `scripts/svg_inline.py`：SVG样式内联工具（Word 位图管线前置步骤），把<style>类规则展开为元素属性规避 LibreOffice 对 SVG CSS 类渲染不全的问题；内置V7格式规则（图例无遮挡、徽章按字宽定容、业务语言标注）。
- `scripts/build_report_html.py`：通用 HTML 构建器（V20：标题单行自适应、图表说明唯一、图与说明间距、溯源3行间距），读取 `report_input.json` 一次性输出 HTML＋`report_build/content.json`＋`md_footnotes.json`，内置 HTML 校验；`scripts/build_report_docx.js`：通用 Word 构建器，读取 `report_build/content.json`＋`md_footnotes.json`。**构建流水线与输入契约见[快速构建流水线](references/report-build-pipeline.md)——模型只写一份 report_input.json，不再手写任何构建代码。**
- `scripts/self_test.py`、`scripts/test_build_news_package.py`、`scripts/test_event_package.py`、`scripts/test_key_concerns.py`、`scripts/test_static_charts.py`：虚构离线材料验证准备、组包、事件包、正文交接及静态图表，不证明实际检索或附件卡片成功。

本地脚本使用Python 3.10及以上；资讯处理脚本仅依赖标准库，词云脚本另依赖Pillow，安装与字体配置见[词云与图文衔接](references/visual-assets.md)。输出进入任务工作目录，审计及底稿不随报告交付。

## 交付与验收

冻结正文前核实真实原始URL。无法有效溯源的事实及依赖判断、统计和组件从同源内容同步移除；有其它充分来源时仅移除失效引用。前三章修正后重核共享样本及概览，同步更新受影响内容。

四章冻结后重新交接最终正文及引用，汇总生成重点关注，不形成循环。发酵链路章的事实修正回写事件包选择时，重新运行`prepare-fermentation`。

HTML事实句和图注后显示紧凑“来源”标识，点击、悬浮、聚焦及触摸可看标题、时间、机构及真实可点击原文链接；不得以内部ID、空href或附件地址代替，多个有效来源分别保留。实际打开HTML核对正文及其样式、编号、图片及来源交互。
