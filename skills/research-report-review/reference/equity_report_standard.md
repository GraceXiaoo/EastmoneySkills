# 个股研报底稿标准范式

## 1. 路由原则

MQL 路由由数据是否可结构化查询决定。财务缓存只加速常用且易错的财务路径；任何其他结构化数据即使没有缓存或未在示例中列出，也必须先检索并执行 MQL。通用结构化工厂按查询形态工作，不按业务领域设置白名单。

## 2. 每个来源对象的固定工件

1. 来源契约：`source_id`、原表字段、实际期间、行列轴、单位和实体。
2. 覆盖计划：每个字段标为 `DIRECT`、`DERIVED`、`REPORT_FORECAST` 或带执行证据的 `OMITTED`。
3. 专属脚本：脚本只输出该来源需要的字段；不同来源不得共用相同脚本哈希。
4. 执行结果：保存原始矩阵、方向、最终矩阵、执行编号和逐字段非空状态。
5. 底稿区域：成功对象写 MQL 锚点；阻塞对象仍显示状态、原因和证据，不得从底稿消失。

## 3. 常见来源类型

- 财务摘要、资产负债表摘要：使用专属字段集合，允许直接指标与公式依赖组合。
- 三大报表和财务比率：先运行全量来源科目编译器，再生成单表单锚点时序脚本。
- 交易数据：研报截止日行情、52周高低价、市值和股本均走 MQL。
- 区间升幅：标的与基准使用同一交易日调整规则，输出绝对收益和相对收益。
- 52周走势图：按来源真实观测频率查询完整标的和基准序列，统一基期归一化。
- 可比公司：按市场拆分脚本和锚点，统一字段顺序，分别记录币种；PE 优先直接指标，必要时以截止日价格和同口径 EPS 衍生。

## 4. 一次性构建

阶段工件合并后只调用 `scripts/research_report_pipeline.py`。该入口先检查全量覆盖、无关输出和跨来源脚本复用，再执行预检与构建。验证失败时回到拥有该字段的阶段工件修正，不临时改最终 JSON。

## 5. 回归样本与金标

失败产物和日志用于回归测试，只证明已知错误会被拦截。只有重新执行的工作簿同时满足完整覆盖、真实刷新、跨市场结果、视觉验收，并获得用户明确确认后，才允许通过 `golden_case_manager.py` 登记为金标。失败回归样本不能作为当前任务的已验证结果复用。
