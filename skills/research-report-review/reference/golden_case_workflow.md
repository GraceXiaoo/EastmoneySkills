# 金标准案例与反馈沉淀

## 适用场景

本流程只用于已由用户确认“效果达标”的研报底稿案例。案例用于两件事：精确输入的快速演示，以及相似任务的查询与质量回归。它不是通用数据源，也不能替代新研报的实时解析和查询。

## 目录约定

每个案例位于 `examples/golden-cases/<case_id>/`，包含：

- `source.pdf`：案例原始研报。
- `expected.xlsx`：用户认可或修正后的金标准底稿。
- `mql_scripts.md`：与金标准底稿对应、已执行成功的完整 MQL 脚本和方向说明。
- `manifest.json`：文件指纹、预期 Sheet、公式数、图片数和适用标签。
- `feedback_lessons.md`：已确认修正与可迁移经验；不得写入未经验证的模型猜测。

## 精确匹配与快速演示

1. 运行 `python scripts/golden_case_manager.py match --pdf <输入PDF>`。
2. 只有 `match_type=EXACT_SHA256` 且 `verify_status=PASS` 时才能快速导出。
3. 用户要求演示、快速复现或接受缓存样例时，运行 `export --case-id <id> --output <xlsx>`。交付时明确标注“已验收金标准复现”，不得称为本轮重新执行、实时刷新或最新查询。
4. 用户要求重新跑或检验当前链路时，完整执行 Skill，并把新结果与 `expected.xlsx` 比较。不得用金标准文件替换失败步骤。

文件名、标题、机构和日期只能用于相似度提示，不能授权直接导出。只有 PDF 内容哈希精确一致才允许快速路径。

## 相似研报复用

对同机构或同类“全球宏观与资产周报”，可以复用：

- 指标族到 MQL 路径的候选关系；
- 指数、行业、国债、商品、汇率的实体解析方式；
- 原表轴向与 MQL 方向的判断方法；
- 截图与解析表配对、可读简称、对象覆盖和执行日志要求。

必须重新确定并执行：研报日期、比较区间、对象集合、代码、指标可用性、接口返回、截图边界、数值、方向和完整性校验。不得复用旧 `raw_result`、`last_result`、缓存值、执行编号或取数时间。

## 反馈闭环

人工反馈和 AI 修正只有在以下条件全部满足后才能沉淀：

1. 反馈定位到稳定对象，如 `source_object_id`、Sheet+单元格、MQL 块或截图 ID；“看起来不对”必须先转化为可验证差异。
2. 保存原始产物、修正产物和差异说明。不得覆盖唯一一份原始证据。
3. 修正结果通过对应门禁：来源覆盖、截图完整性、MQL 真实执行、方向/溢出区、可读简称和工作簿校验。
4. 将反馈分类为 `CASE_SPECIFIC` 或 `GENERALIZABLE`：
   - `CASE_SPECIFIC` 只更新本案例的 `expected.xlsx`、`mql_scripts.md`、`feedback_lessons.md` 和 `manifest.json` 指纹。
   - `GENERALIZABLE` 除更新案例外，还要把目标行为写入最窄的核心 reference 或确定性脚本，并用本案例和至少一个不相关案例做回归，防止过拟合。
5. 只有用户确认、外部数据证据或可重复机械校验支持的结论才能标记 `accepted=true`。模型自我反思可以形成候选，不得自动升级为通用硬规则。

可先用 `feedback-template` 生成结构化记录。每条反馈至少填写：对象、现象、期望、证据、修正、影响范围和验收结果。

## 回归重点

- 五个固定 Sheet 齐全；`10_研报快照` 的截图与对应解析表相邻，且截图边界紧贴图表。
- `20_研报底稿` 覆盖所有可通过 MQL 查询的对象；代码和 ID 必须同时有可读简称。
- 原文为纵向指标、横向日期时，底稿保持相同业务轴；每个 MQL 的方向由返回矩阵与目标轴比较决定。
- 宏观、利率、指数、申万一级行业、全球指数、商品和汇率不能因第一次代码或路径错误而被省略或直接切换数据源。
- 快速演示只证明金标准案例可复现，不证明当前远程服务可用。
