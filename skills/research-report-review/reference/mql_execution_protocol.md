# Choice 数据核验执行协议

## 一、适用范围与边界

核心财务指标缓存仅解决财务路径高频、层级深和口径易错的问题，不定义 MQL 的适用边界。任何可结构化查询的数据都先走 MQL；未命中缓存表示需要检索指标路径，不表示可以跳过 MQL。行情、交易数据、区间收益、连续股价/指数走势、估值、股本和跨市场证券数据必须执行与财务相同的“检索路径→真实执行→覆盖验收”流程。

本协议仅用于本 Skill 的 Phase 2 数据核验和 Phase 4 一致预期比较。执行时直接调用当前环境可用的 Choice 数据检索与执行工具，通过MQL工具链获取结构化数据。MQL 是所有可结构化数值指标的首选接口，范围包括证券、财务、宏观、行业经济、利率、债券、基金、指数、外汇、商品、估值和报表指标；`mx-ds-mcp` 是MQL确认缺指标、无所需结果或返回明确服务故障且符合本协议准入后的缺失项兜底接口，也是资讯、新闻、公告和研报原文检索的直接接口。

仅以下指标进入历史数据准确度核验：

- 数值性质为 `ACTUAL`。
- 已通过 Phase 0 的 I1-I12 摄取门禁。
- 具备证券代码、报告期、单位、口径和来源定位。

`FORECAST`、`JUDGMENT` 与 `DERIVED_RPT` 不作为历史准确度的核验分母；它们转入预测框架分析或研报内部勾稽。

## 二、输入与输出契约

**输入字段**：证券代码、指标名称、研报值、单位、报告期、口径、数值性质、数据获取类别、来源定位、来源告警。资讯类指标另须输入原文摘录、事件日期、主体和事件关键词。

**运行期输出（四层工件，不得混同）**：

| 层 | 工件 | 允许动作 | 禁止动作 |
|---|---|---|---|
| ① 原响应 | `Execute_MQL` 完整结构化结果 | 原样（不做格式转换）落盘或由工具托管引用，仅用于本次本地校验、审计与服务故障证据 | 改写为 HTML、Excel 或其它交付文件；摘录、重排或摘要后冒充原响应 |
| ② 选中 Block 矩阵 | `raw_result` | 取原响应中本次选中 Block 的**无损切片**，以 JSON 字段保存，作为 `cached_table` 与公式覆盖校验的基准 | 与 ① 混同；改写为其它格式交付 |
| ③ 派生审计结果 | `last_result`、`cached_table`、`raw_result_summary`、`orientation_reason` | 标注为派生视图，仅用于本地校验与执行日志审计 | 声称等同或替代原响应 |
| ④ 公式空白溢出区 | `20_研报底稿` 锚点 | 只含 `=mql()` 公式批注与空白矩形 | 写入任何数据；以派生产物替代原始结构化结果 |

**与工具契约的边界**：实时 `Execute_MQL` 的 `globalConstraints` 规定「完整结构化结果不得被客户端改写为 HTML、Excel 或其它文件」。本表逐层区分原样落盘、无损切片、派生视图与公式空白；其中 ① **「原样落盘」是否属于该条「或其它文件」的禁止范围，须由 MQL 工具/服务契约维护方明确**，登记为外部依赖 `EXTERNAL_CONTRACT_PENDING`（机器可读定义见 [mql_artifact_contract.json](mql_artifact_contract.json)）。边界明确前只允许原样落盘且不得做任何格式改写，**不得据此宣称冲突已解决**。

核验数据集与执行记录的必填内容如下（均属 ③ 派生审计层）：

| 工件 | 必填内容 |
|---|---|
| 核验数据集 | 指标名称、研报值、核验值、归一化单位、数据日期、口径、数据源、查询接口、指标路径或检索条件、原始 Block/记录编号、取数时间、原始链接 |
| 执行记录 | 数据源、接口、当前工具链元数据（仅 MQL）、检索关键词、检索结果、失败和重试记录、原始链接 |

每条派生核验数据必须保留原始 Block 编号和取数时间。PDF/静态值、旧缓存与人工补值不得进入 ② 或 ③。

## 三、强制执行顺序

同一任务的初始MQL工具发现、语法知识及调用规范只加载一次，将工具链标识、知识定位及完成状态保存到已有run_manifest的mql_session。后续所有查询复用，续跑读取已有完成状态；只有工具链实际变化或原有知识被真实语法错误证明失效时才刷新受影响部分。指标元数据、市场路径、实体和期间按需要补查，不是重复加载通用语法。

所有远程参考、检索和执行调用都按 [execution_stability.md](execution_stability.md) 以服务批次接入统一保护器，并分别使用稳定服务名 `mql_reference`、`mql_search`、`mql_execute`；`mx-ds-mcp` 调用使用 `mx_data`。保护一次指标族或执行组，不为组内每个正常调用增加独立 shell 前后置步骤。一次端点异常只熔断对应服务，不得因此跳过应有路由，也不得把超时解释为“无候选”“无数据”或“不支持”。

### Step 2.1：数据源路由与当前工具链

1. 所有数值型或表格型数据类别先走 MQL，包括 `STD`、`CONSENSUS`、`VALUATION`、`SHARE`、`REPORT_*`、`HR_RD`、`EDB` 和可由结构化指标计算的 `DERIVED`。指标属于宏观、行业经济、利率、债券、基金、指数、外汇或商品，不构成跳过 MQL 的理由。
2. `INFO`、`NEWS`、`ANNOUNCEMENT`、`RESEARCH_REPORT` 等原文/事件检索直接走对应的 `mx-ds-mcp` 接口；其中若同时包含需进入可刷新底稿的结构化数值，应把数值部分另行先走 MQL。
3. 所有结构化数据先通过MQL工具链获取结构化数据。实际检索确认无支持候选或有效查询无所需结果，或实际MQL调用返回明确服务故障且按有限预算停止重试，才允许自动对受影响缺失项使用妙想兜底。服务故障登记SERVICE_FAILURE_CONFIRMED及原始请求/响应证据，不冒充指标无数据。未调用、PENDING、IN_PROGRESS、ABANDONED、中断或仅因等待/耗时停止不能换源；语法、参数、证券代码、日期或缓存路径错误先修正，修正耗尽本身不允许换源。正常结果继续复用，替代来源标明故障或缺指标原因，不能伪装成MQL可刷新数据。明确超时必须是工具返回的超时终态，不以等待时长推断故障。
4. `NON_MQL` 仅表示当前无已知数据服务路径；在归类前必须完成本步骤的 `mx-ds-mcp` 检索。

对结构化数据通过MQL工具链获取结构化数据。依当前工具链完成指标发现、实体解析、完整路径确认和真实执行，不依赖固定工具名称、当前工具链元数据确认接口或旧参数契约。

财务指标先匹配内置核心缓存及本地运行时缓存；缓存仅存路径与口径，不存公司结果。缓存失效时立即标记失效，通过MQL工具链获取结构化数据并重新确认完整路径，真实执行成功后更新同一语义key，记录元数据来源和执行标识。未匹配项批量处理，只补缺口。参数及返回结构以当前工具链为准，不凭经验拼写路径。

失效时使用`financial_indicator_cache.py invalidate --key KEY --reason 原因 --cache 可写缓存路径`阻止再次选择旧路径；成功后使用upsert保存修正元数据，安装目录只读时显式选择任务可写缓存路径。

通过`financial_workpaper_factory.py generate`生成最终脚本，真实执行后用assemble读取原始响应和`--executed-request`指定的同次实际请求，生成raw_result/last_result/cached_table与真实跟踪标识。只读取当前result.blocks，执行标识使用traceparent或`--tool-call-id`。不读取历史回执字段，不接受人工构造的成功响应。仅删除提供方声明hidden_key的列，保留日期轴和首个指标。每张底稿必须单独实际执行一个Block，不能默认截取多Block中的第一块。原始响应和请求保持不变，不从对话手抄结果。

#### 财务取数场景分流：整表优先报表，单点优先指标

- 整篇财报表格（资产负债表、利润表、现金流量表、财务摘要、财务比率与每股指标等以“科目 × 报告期”完整覆盖为目标的整表对象）优先使用报表路径 `ReportBlock` 整表直取，登记 `financial_query_mode=REPORT_FULL_TABLE`，只需 `report_selection_reason` 说明整表口径与模板出处，不要求先证明指标路径失败。报表科目名最接近研报口径且按报告期整表返回，是整表底稿的首选；脚本参考 `reference/mql_templates/` 中对应报表科目模板。
- 个别财务指标或科目（单点补充、财务比率、估值、图表序列，或整表中少量缺失科目）优先检索标准指标路径。指标与报表都能返回目标值时选择指标；只有指标实际无候选或有效查询无所需结果后，才允许对缺失项使用报表或派生计算兜底。
- 个别科目使用报表兜底时，必须保存指标候选、真实执行结果、缺失科目及 `report_selection_reason`。证据必须是结构化的 `indicator_attempt_ids`，每个 ID 引用执行日志中同一来源、`data_path_type=INDICATOR` 的检索或执行尝试，并带状态和失败分类。模型自写的说明、无对应 ID 的摘要或批量补字段均不能证明指标路径已失败。
- 报表结果无论整表直取还是兜底，仍须逐科目核对单位、报告期、合并口径和调整类型；不能因为整块执行成功就推定每个字段准确。

#### 来源时间形态门禁

- 在生成查询前把来源对象分类为 `CROSS_SECTION`、`TIME_SERIES` 或 `REPORT_MATRIX`。横轴是连续日期/报告期、折线或面积随时间变化的对象属于 `TIME_SERIES`；若只是若干命名区间的汇总值，属于 `CROSS_SECTION`。
- `TIME_SERIES` 必须在 `通过MQL工具链获取结构化数据` 中显式检索时序候选，并优先使用 `TimeSeriesBlock` 或等价的原生时序返回。若取得价格序列而来源图表示基期累计涨跌幅，应在 MQL 中按共同基期归一化并对齐交易日。
- 横轴标注频率不等于观测频率。分别记录 `axis_tick_frequency` 和 `observation_frequency`，根据曲线拐点/点密度、证券交易语义、图注和候选元数据给出 `frequency_evidence`。按来源起止日期和观测频率计算 `expected_min_points`，返回点数未达门槛时不得通过。一年左右的证券日频走势不能只返回 12 个月末点。
- 单个区间收益率、期末截面或多个独立截面点不能替代完整时序。时序候选不存在或真实执行无数据时标记阻塞或按终止失败规则处理，不得降格为截面后声称覆盖图表。
- 股票与基准指数走势图必须按来源观测频率分别查询完整价格或涨跌幅时序，再按共同基期归一化并合并；横轴只标月度节点不改变日频观测。不得因为区间涨跌幅查询已经成功就省略走势图工作底稿。

财务报告期序列单独处理。整张财务报表优先按报表路径整表直取（`REPORT_FULL_TABLE`，脚本参考 `mql_templates/` 对应科目模板），资产负债表、利润表、现金流量表分别建立独立底稿区块和独立锚点；不把三表合并成一个锚点。选择时序指标路径时遵守 [A股三大报表时序模板](mql_templates/a_share_financial_timeseries.md)，每张表内部用一个 `TimeSeriesBlock(#1)` + `SetWindow` 覆盖全部 `source_periods`，不得拆成多个单期锚点。报表口径不可用或按用户指定指标口径取数时，没有适用时序候选才使用指标原生多期；两者均不可用时才按期间建立标准指标 Block并合并为 `REPORT_MATRIX`。只有个别科目的上述指标路径均无候选、真实执行无数据或覆盖不完整时，才允许 `REPORT_FALLBACK` 兜底。

#### 逐项指标覆盖与检索批次

- `queryable_fields` 必须直接继承快照中的完整科目名称和顺序。先按原文逐项科目名检索，再补充规范同义词；不得只用宽泛表名、模糊缩写或自行添加“累计同比”等口径词后据此宣称无候选。
- EDB 来源表默认指标应存在，首次未命中只能标记为“待补查”，不能直接省略。检索计划必须保存“原文科目→检索词→候选路径→最终指标→口径变换”的覆盖矩阵。
- 为避免大请求超时，每批建议 8–12 个科目，最多 15 个；超时后按未完成科目继续拆批，不重复已经命中的科目。批次拆分不改变最终全量覆盖要求。
- 指标返回值与研报展示值口径不同时，必须识别并记录确定性变换。例如以上年同月为 100 的定基指数转换同比增速时使用 `值-100`；不得把定基指数直接当作百分比，也不得因需要变换而放弃已命中的指标。
- 查询结束时，快照每个可查询科目必须属于“成功指标”“有证据的报表兜底”或“有结构化失败证据的省略”之一；未检索、模糊检索或批次超时未续查不属于合法省略。

#### 实体、跨市场代码与板块解析门禁

- 证券、指数、基金、外汇和商品必须逐一保存“原文标签→标准实体→标准代码→市场”的解析结果。跨市场代码及后缀必须来自业务知识或上下文返回，不得按经验拼接。若一组查询只有少数代码有值、其余代码均为空，先按 `ENTITY_CODE_ERROR` 处理并重新检索实体，不得直接判为远端无数据。
- 行业或主题截面先确认分类体系、版本和层级，再调用上下文返回的板块枚举能力（例如 `GetSectors`）取得目标行业集合，之后查询行业指数或板块指标。股票筛选/选股结果不能替代行业板块枚举，也不能作为行业指数区间涨跌幅的最终数据集。
- 区间指标必须保存研报起止日期、实际查询起止日期及交易日调整规则；返回区间与研报区间不同属于 `DATE_ERROR`，不得作为核验值或兜底证据。
- 可比公司涉及多市场时，按 A 股、港股、美股等市场分别建立已确认代码集并分段执行。各段必须输出相同字段、期间标签、单位/币种元数据，再按研报原始实体顺序纵向合并。不允许因某市场需要单独查询就省略该市场实体。
- 每个市场段形成独立 workpaper 和锚点，使用共同 `market_schema`。`market_segment` 保存市场、币种、实体与代码，代码必须等于该段最终脚本选中 Block 的 `SetCodes`；`market_output_order` 保存研报原始实体顺序。任一市场段不得追加未在该段真实执行中验证的简称或其他字段。
- 可比公司长表、证券×年度返回或分市场结果必须在 MQL 内整理为研报目标矩阵；“原始返回需要透视”不是阻塞理由。A 股、港股、美股各段成功后再拼接，任一市场失败只省略有证据的该市场对象。

### Step 2.4：查询生成与执行

1. 读取 `generation_contract.md` 阶段产生的来源语义、来源布局、完整 `queryable_fields`、`source_periods` 和 `display_label_map`。先生成逐项覆盖计划，按“实体 + 指标族 + 完整期间集合 + 参数口径”去重并按 8–12 个科目拆批检索，再选择截面、时序、分组、报表或合并数据组织方式；不得逐表重复检索相同指标，也不得从候选中只挑选少数容易成功的指标。整张财报表格优先报表路径整表直取，个别财务指标或科目优先标准指标；具体顺序见 `generation_contract.md` G2 的权威 `financial_query_mode` 优先级链。连续报告期先检索同口径 `time_series` 候选并通过单一 `TimeSeriesBlock + SetWindow` 查询，时序优先级高于截面拼接。
2. 证券池仅可使用已确认的单一方式，不得混用。
3. 日期、单位、枚举和参数必须严格遵从本次候选返回。
4. 指标、报表路径和参数不得凭经验补写；无参数指标仍使用空参数调用。
5. 财务来源必须继承快照的 `FINANCIAL_STATEMENT/FINANCIAL_METRICS` 和 `FINANCIAL_METRIC × REPORTING_PERIOD`。连续期间的优先级链以 `generation_contract.md` G2 为唯一权威（`REPORT_FULL_TABLE` → `FINANCIAL_TIME_SERIES` → `NATIVE_MULTI_PERIOD` → `PERIOD_BLOCK_MERGE` → `REPORT_FALLBACK`）：整张财报表格先按 `REPORT_FULL_TABLE` 整表直取；报表口径不可用或按用户指定指标口径取数时，再按该链依次回退。财务时序候选必须是本次 `通过MQL工具链获取结构化数据` 返回的普通指标且 `indicatorTimeShape=time_series`；当前实时参考若用完整 metric ID 的 `_s` 后缀识别财务报告期序列，必须保留该完整路径，不得给普通指标自行追加 `_s`。执行脚本使用 `TimeSeriesBlock`、`SetCodes` 和唯一一个 `SetWindow`，窗口覆盖全部 `source_periods`。没有同口径时序候选只会进入后续指标路径，不构成 `TABLE_BLOCKED`，也不允许直接跳到报表。成功时序块必须真实覆盖所有目标期间；窗口、周期和候选路径等可从脚本或执行结果取得的审计元数据应由生成器自动补全，元数据缺失不得成为删除正确结果或清空整张底稿的理由。
6. 执行前检查语句结束符、名称包裹、比较符、时间格式、数据组织方式与指标时间形态的一致性。若输出轴含实体/品种/序列，同时检查脚本已输出可读简称或名称；以实体为行时至少输出“技术键 + 可读名称 + 数值”。
7. 调用执行工具，并根据当前工具链实际返回的成功状态判断结果。成功时先检查可读名称列/序列标题、全量字段覆盖、全部历史期间覆盖与来源布局，再组装底稿；缺少名称字段、字段或期间子集过小、语义被降级或方向与原文不同时，回到本步修正脚本，不得直接进入工作簿生成。失败时记录阶段、错误代码和消息。
8. 生成 `04_query_results.json` 前建立来源覆盖表：每个 `snapshots[].table_id` 与每个具有可查询数据的 `chart_data[].data_block_id` 必须对应成功 workpaper 或带最终证据的阻塞项。执行日志中已有成功结果但未形成 workpaper，或仅因矩阵需要转置/透视而省略，均属于装配错误，必须在生成 Excel 前修复。
9. 每个最终 Excel 锚点先生成其最终 `mql_script`，直接执行该字符串，并将相同字符串原样写入锚点批注。workpaper 与执行日志同时保存规范化脚本的 SHA-256；禁止从综合执行结果裁切子矩阵后配入另一段未执行脚本。选中 Block 的输出别名必须与实际返回表头逐项一致。报表脚本公开声明的 `{报告期}` 列为结构键，比对口径以 `workbook_spec.md`「声明式报告期结构键」为唯一权威，本协议不重列。
10. 数值字段在执行前建立单位契约。原始单位、展示单位、比例语义或缩放因子发生变化时，在最终 MQL 输出表达式中完成转换，并保存可机械定位的 `script_transform_token`；说明文字、JSON 后处理和 Excel 数字格式都不能替代取值转换。

### Step 2.5：失败处理

**本表的标准失败类别集合与兜底准入是本 Skill 的唯一权威**；`SKILL.md`、`workbook_spec.md`、`execution_stability.md` 只引用本表，不再各自重列类别清单。允许 `mx-ds-mcp` 兜底的类别固定为下表最后一行的四个：

| 失败类别 | 处理动作 |
|---|---|
| `SYNTAX_ERROR` / 数据组织错误 | 修正生成内容后重新执行 |
| `PARAMETER_ERROR` / `PATH_ERROR` | 回 Step 2.3，仅补检索缺失分区 |
| `ENTITY_CODE_ERROR` / `SECTOR_UNIVERSE_ERROR` / `DATE_ERROR` | 回 Step 2.3 重新确认实体、板块集合或日期；禁止兜底 |
| `UNSUPPORTED` / `NO_CANDIDATE_AFTER_SEARCH` / `REMOTE_NO_DATA_AFTER_VALID_QUERY` / `SERVICE_FAILURE_CONFIRMED` | 保留结构化证据后改用 `mx-ds-mcp`；兜底仍无结果才转入未匹配项归因 |

累计修改达到 3 次仍失败时必须停止重试。达到次数上限不会把可纠正错误自动变成允许兜底的类别：此时将对象标为 `BLOCKED` 并继续其他对象。只有上述四个允许类别可改用 `mx-ds-mcp`；兜底也无结果时记录已尝试内容并转入未匹配项归因；不得伪造核验值。

### Step 2.6：`mx-ds-mcp` 兜底查询与资讯比对

1. 依据路由调用最匹配的 `mx-ds-mcp` 接口：EDB/宏观序列使用宏观或综合数据接口；新闻使用资讯新闻接口；公告使用公告接口；研报使用证券、行业或综合资讯检索接口。接口能力不足时记录原因，不得伪称已核验。
2. 请求中至少传递已知代码/主体、指标或事件关键词、报告期或事件日期和原文摘录；返回多条资讯时，按主体、日期、主题和原文事实匹配，保留所有候选与最终采用理由。
3. 保存完整结构化返回、查询条件、记录标识、发布时间/数据日期、数据源和 `raw_source_url`。返回存在原始链接时必须原样写入 `raw_source_url`；无链接时明确记录“未提供原始链接”。
4. 数值型 EDB 结果按本协议第四节归一化并计算“核验值－研报值”。资讯、新闻、公告和研报类结果不得虚构数值差额：将研报原文摘录与采用记录逐项比对，填写“事实一致/表述差异/时间不一致/未找到对应记录”等结论和具体差异说明。

## 四、单位、口径与结果读取

1. 先记录原始返回值及其单位，再将数值统一为研报单位后计算差异。
2. 比例值必须区分小数和百分数；例如 0.338 应先转换为 33.8%。
3. 研报未标注口径时，按 `tolerance_rules.md` 的双口径检测矩阵取得候选口径，选择满足容差且误差最小者。
4. 所有口径均不匹配时，不得任意选择最接近值；须转入“口径定义不一致”或“需人工确认”。
5. 核验结论仅说明研报数据与 Choice 核验值的比较，不评价数据查询工具本身。

## 五、完成条件

- 每条已核验数据均可回溯到数据源、查询接口、原始 Block 或记录编号、取数时间、指标路径或检索条件和本次检索结果。
- 每条资讯、新闻、公告和研报核验记录均保留研报原文摘录、差异说明和可用的原始链接。
- 未取得数据或未能匹配口径的指标均有可审查的失败或检索记录。
- 最终用户报告不展示查询脚本、工具名、Block、指标技术路径、版本或重试过程；这些信息仅保存在原始工件和 Excel 执行日志中。

## 六、Excel 加载项衔接

- 表格和图表回读数据执行同一 MQL 门禁。表格 `workpapers` 使用 `source_type=TABLE` 和表格 ID；图表 `workpapers` 使用 `source_type=CHART`、图表 ID 与 `source_data_block_id`。一张图表可因实体类型或查询口径不同拆成多个唯一 `mapping_id`。
- `=mql()` 读取当前单元格批注中的完整 MQL，并输出脚本默认 Block（最后一个数据 Block）；`=mql("#2")` 显式选择第 2 个 Block。未提供第二参数时，加载项默认 `orientation=1`。生成器不得在未指定 Block 时擅自替换为 `#1`。
- 返回值为二维矩阵，第 1 行是输出字段名。因此 `20_研报底稿` 中一个 MQL 锚点对应一个独立数据块，公式下一行是完全空白的溢出区，不是静态缓存区。`orientation=0` 是正常表格，表头是指标；`orientation=1` 是行列转置表格，指标在第一列，表头通常是日期或证券编码。省略第二参数与 `1` 等价；是否省略或显式填写都必须与目标布局一致。
- 脚本必须一次输出目标表所需的完整字段集合。执行成功并通过形状检查后才允许写入公式；工作簿生成时不得把执行结果、PDF 值或人工补值预填到溢出区。任何不一致均视为本表阻塞，不写公式、不写静态替代值。
- 动态底稿的唯一写入门禁是真实执行成功。含服务端妙想专用路径的脚本真实执行通过后允许作为 `20_研报底稿` 公式批注，不再作为禁止项。
- 利润表、资产负债表、现金流量表、财务摘要、财务比率与每股指标在执行前生成 `source_fields` 和全部历史实际 `source_periods`；执行后分别用 `covered_fields/omitted_fields` 与 `covered_periods/omitted_periods` 做不重不漏的分割。`omitted_periods` 每项都要有检索或执行证据 ID，不能仅用说明文字省略一期。可比公司表另对实体、期间和指标三个维度分别做覆盖分割；跨市场实体必须先解析标准代码并尝试。PE 等可直接取数的估值指标优先直接指标；需衍生时使用研报截止日价格与同期 EPS，不得使用最新价。
- “脚本声明了全部字段”不等于“整表执行成功”。必须读取 `通过MQL工具链获取结构化数据` 的实际 Block，应用 Excel 公式所用 orientation，生成最终二维矩阵后再逐单元格比对缓存表。未执行、执行失败、形状不符、字段缺失或仅部分单元格有返回值时，均不得生成 MQL 公式或标为 `MQL-READY`。
- 每张成功表都必须生成执行后记录：`result_origin=通过MQL工具链获取结构化数据`、本次 `execution_run_id`、`result_as_of`、执行工具返回的完整 `raw_result` 和 `orientation_reason`。先从研报快照或用户要求确定目标行轴与列轴，再计算 `raw_result` 的保持版本和转置版本。`mql_orientation` 缺省时有效值为 `1`；若转置版本不符合目标布局则必须显式设置为 `0`。有效值为 `0` 时 `last_result` 必须等于 `raw_result`；有效值为 `1` 时 `last_result` 必须等于 `raw_result` 的行列转置。财务多期表通常要求纵向科目、横向报告期；指数截面通常要求纵向指数、横向指标，但这些只是目标布局提示，不能替代对本次原始矩阵的检查。`cached_table` 必须由 `last_result` 建立并逐单元格一致；不得从 PDF、旧缓存或人工修补生成。单表失败时写为 `TABLE_BLOCKED`，保留原因但不保留结果矩阵、缓存或公式；这不会阻止同一新 JSON 中其他成功表生成 `20_研报底稿`。
- 方向必须通过轴语义验收：`target_row_axis`、`target_column_axis`、`row_axis_labels`、`column_axis_labels` 必填，应用方向后第一列和第一行分别与声明标签一致。财务多期表的目标固定为纵向财务科目、横向报告期；若原始结果每行是报告期、每列是科目，必须转置。当真实执行返回的期间表头与研报期间标签逐列不同时，第一行改为与该期间映射的 `key` 序列一致，并在 `display_label_map` 逐列补 `kind=REPORTING_PERIOD` 条目（权威定义见 `workbook_spec.md`）；`column_axis_labels`/`covered_periods` 仍保留研报标签，不得改写 `last_result`。装配阶段不得把不同工作底稿的方向统一设为同一个值。财务来源拆出的非财务形态锚点（如估值截面 `ENTITY × METRIC`）登记 `source_semantic_type=OTHER` 的豁免条件以 `workbook_spec.md`「财务来源 OTHER 锚点豁免」为唯一权威。
- 连续时间图必须记录 `source_start_date`、`source_end_date`、`query_start_date`、`query_end_date`、`frequency` 和 `temporal_point_count`。查询必须使用时序形态：证券等实体时序使用 `TimeSeriesBlock`，宏观指标时序允许使用 `EdbBlock`；两者都必须通过真实执行和本地 Choice Excel 加载项兼容性评估。起止日期必须一致，每条序列至少两个有效点；`CrossSectionBlock`、区间累计值只能进入核验记录，不能进入走势图 `workpapers`。走势展示类锚点可把 `SetWindow` 结束时间写为不带引号的 `N()`（普通时序）或 `MRQ()`（仅限 `_s` 报告期时序），此时必须填写 `query_end_date_dynamic`，`query_end_date` 填写生成时记号解析出的快照日期并与来源结束日期一致；带引号的记号写法会被运行时拒绝，不得写入。
- 时序窗口策略在应用层记录为 `window_policy`：`SOURCE_FIXED`（默认，保留原图事实）、`LATEST_1000_TRADING_DAYS`（以已确认最新交易日为闭区间终点取最近 1000 个交易日；起点必须来自已确认交易日历，不足如实截断并标注；原生滚动起点未获验证，只交付固定窗口并置 `rolling_implemented=false`，不得用固定起点加 `N()` 冒充滚动或发明 `GetTradingDate` 等未确认函数）、`EDB_FIXED_FREQUENCY`（EDB 按频率桶处理，不套期货交易日历）。`source_start_date/source_end_date` 保留原图事实，`query_start_date/query_end_date` 另存本次窗口，两者不得互相覆盖。同一窗口只对应一个交易市场，跨交易所按各自日历拆块。普通时序的市场写入 `SetWindow` 的已确认可选 `{市场类型}`；`_s` 报告期时序不写市场。可选 `{预加载周期}` 仅当用户明确要求额外历史期数时填写，正式查询期数与额外期数合计不得超过 1000。
- 启用动态结束时间的脚本跨日期重放时返回形状会延伸，重放验证以生成时首次执行快照为基线：校验输出字段、单位口径与生成时形状，不再要求跨日期逐单元格一致；生成当日的首次执行仍必须与固定日期写法逐单元格一致（基线等价）。此类锚点独占 `22_TS_NNN` Sheet，主底稿仅提供跳转入口，Sheet 内锚点下方与右侧不放置其他内容。
- 非财务 PDF 表若是品种×期限等截面布局，而本次只有部分 EDB 指标真实执行成功，不得因无法重构原截面而删除成功结果或把整表降为 `TABLE_BLOCKED`。该工作底稿使用 `PARTIAL/SUCCESS`，保留原 `source_fields` 的覆盖分割与映射说明，实际结果按 `DATE × SERIES` 输出；每个 `EdbBlock` 锚点写入独立 `21_EDB_NNN` Sheet，主底稿仅提供跳转入口。独立 Sheet 的锚点下方不得放置其他单元格内容，以容纳刷新后的时序增长。
- 根据应用方向后的 `last_result` 记录 `expected_rows` 和 `expected_columns`，并以此预留溢出矩形。若范围包含另一 MQL 公式、合并单元格或相邻表格，必须先改造 MQL 输出形状或重新布局；不得用转置参数弥补布局错误，也不得依赖 Excel 打开后再发现 `#SPILL!`。
- 图表回读表是 PDF 来源证据，只进入 `10_研报快照`。若图表指标的 MQL 执行成功，必须形成对应 `workpapers` 和公式锚点；不得只在执行日志记录成功查询后仍把 PDF 回读值静态写入 `20_研报底稿`。部分指标成功时只为成功子集生成 `PARTIAL/SUCCESS` MQL，并在 `covered_metrics` 与 `omitted_metrics` 中完整说明。
- 对利润表、现金流量表、资产负债表、财务比率和可比公司表，生成脚本前必须建立快照可查询科目清单；脚本输出字段逐项与清单核对。遗漏一个可查询科目即不得标记 `SUCCESS/MQL-READY`。分析师独有预测若按用户要求不在 `20_研报底稿` 展示，应在建表前从查询范围中显式排除，而不是刷新后留下静态预测单元格。
- `mx-ds-mcp` 没有 Excel 加载项公式，其结果、查询条件、记录编号和原始链接只写入执行日志（核验数据仍记录于 JSON 的 `verification` 字段），不写入 `20_研报底稿`。批注中只存纯 MQL 查询脚本，不存令牌或凭证。未安装加载项时 MQL 锚点可显示 `#NAME?`，其下方保持空白。
- 任何数值型 `mx-ds-mcp` 工件必须同时保存 `fallback_from_mql=true`、`mql_failure_category` 和 `mql_failure_evidence`。失败类别必须是 `UNSUPPORTED`、`NO_CANDIDATE_AFTER_SEARCH`、`REMOTE_NO_DATA_AFTER_VALID_QUERY` 或 `SERVICE_FAILURE_CONFIRMED`；自由文本说明不能替代类别和检索/执行证据。
- 每个成功执行记录必须包含 `metric`、`source_block`、`query_path`、`execution_run_id`、`queried_at`、`raw_result_summary`、`unit` 和 `status`。这些字段来自真实执行结果；仅写“SUCCESS”和时间的空壳日志不合格。

SERVICE_FAILURE_CONFIRMED仅用于实际MQL调用已经返回的明确终态服务错误。保存mql_service_failure对象：tool_call_id、evidence_locator、status（FAILED或工具返回的TIMEOUT）及failure_type（NETWORK_ERROR、HTTP_5XX、RATE_LIMIT、AUTH_INVALID、TOOL_UNAVAILABLE或PARSE_FAILED）。mql_failure_evidence定位原始请求/响应；自由文本、未完成调用、未加载Skill、未查找工具或单纯修正耗尽不能证明故障。连续两次明确服务错误停止重试，鉴权失败首次停止；按此准入自动兜底受影响项，评测和底稿标明原因及替代来源。
