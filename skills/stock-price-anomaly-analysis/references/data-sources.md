# 数据获取与溯源规范（三级取数框架）

> 本文件定义异动分析的数据采集链路：**优先 MQL 取数 → 妙想 MCP 搜索 → 模型自带兜底链路**。执行场景一（涨跌幅榜）与场景二（单票复盘）前必读。

## 1. 前置环境校验（必须留下记录）

开始取数前必须检查当前环境是否具备 MQL 能力，并记录校验结论：

1. 确认 MQL 工具链（参考、上下文检索、执行入口）在当前环境中是否可用；
2. 若环境提供 MQL 能力说明，先核对其版本要求与当前执行器是否兼容；
3. 通过上下文检索确认目标市场证券池、行情指标、资金指标、龙虎榜指标、板块/指数指标是否可覆盖；
4. **记录结论**：`MQL 可用（证券池/指标覆盖）`或`MQL 不可用（原因：xxx）`；
5. 若 MQL 工具缺失或不可连接：
   - 涉及**结构化数据**（行情、榜单、资金流、龙虎榜、估值、财务）时，不虚构 MQL 数据，降级路径见第 5 节，并在交付时明确列出缺失能力与实际采用的数据渠道；
   - 不静默把网络搜索结果当作 MQL 结构化数据使用，须标注口径差异。

> 即使主观判断 MQL 可能不适用（如“无指定标的批量筛选”），也必须先完成校验并尝试 L1；禁止以成本高、路径长为由跳过 L1。

## 2. 取数优先级（三级链路）

| 级别 | 通道 | 适用数据 | 定位 |
|---|---|---|---|
| **L1** | **MQL 取数（强制首选）** | 行情、涨跌幅榜、资金流向、龙虎榜、融资融券、估值、财务、板块/指数行情、可比公司行情等一切结构化数据 | **必须先尝试**；凡 L1 可得的数据不降级；MQL 可用时不得以妙想 MCP 更便利为由绕过 |
| **L2** | **妙想 MCP 搜索**（东方财富妙想 MCP：资讯检索、公告检索、行情数据等工具） | 个股新闻资讯、公告披露、互动平台内容、行业事件线索、研报观点；**以及 MQL 失败后的行情/榜单/资金降级补齐** | MQL 未覆盖的非结构化/资讯维度；L1 失败维度的降级补齐 |
| **L3** | **模型自带兜底链路**（WebSearch / WebFetch，及可用的金融检索工具） | 海外原始信源、公众号/社群传播样本、行业垂直媒体、交易所官网原文 | L1/L2 均不可用或未覆盖的维度 |

例外：**用户提供的材料**（截图、研报、复盘笔记）直接采信，注明"用户提供"，不走上述链路。

**强制顺序**：每个数据维度必须先尝试 L1 → 失败后 L2 → 再失败后 L3。不得以效率、成本、返回体量大为由跳过 L1。**全链路所有 MCP 工具调用均受 SKILL.md 2.0 节调用限制约束**：单次调用最长 1200 秒、失败退避重试最多 2 次（30s/90s）、同一 query 累计 ≤ 2 次、超时/失败立即停止本轮并按失败话术输出（禁止后台执行、改写 query、更换标的重试）。

降级规则：任一维度在高层通道失败时，逐级降级到低层通道补齐，但必须在报告数据说明中标注该维度实际获取渠道、降级原因与口径差异；**结构化数据经 L3 兜底获取时，口径可能与 MQL 存在差异，须并列注明**。

## 3. MQL 取数规范（L1）

### 3.1 执行纪律

按当前平台的 MQL 调用规范执行，要点：

1. **最小化初始化一次**：全任务只做一次 MQL 语法参考、业务知识与报表元数据准备；首次元数据检索仅覆盖目标实体与所需报表；
2. **单接口单 ReportBlock**：一次结构化数据查询只提交一个报表路径、一个 `ReportBlock`，禁止拼接报表；
3. **报表路径以当次元数据检索为准**：通过上下文检索工具定位目标报表（如涨跌幅榜、个股行情、资金流向、龙虎榜等）的完整路径、`reportFilterColumns` 与 `reportFields`，不硬编码未经当次验证的路径；
4. **日期处理**：统一入参 `交易日期 <= 系统日期`，调用前将系统日期转换为 `YYYY-MM-DD` 字符串替换进 MQL，不得把"系统日期"作为未绑定占位符直接执行；盘中场景按观测时点取当日数据，盘后取最新收盘数据；
5. **超时与退避（硬性）**：单次调用最长等待 **1200 秒**，超时即判失败；调用失败后最多**退避重试 2 次**（退避等待 30s / 90s）；确定性错误（路径错误、参数错误、元数据无效）不做退避重试，仅当执行层明确报告路径/字段/过滤器校验错误时，定向检索元数据一次并修正后重试一次；
6. **调用计数**：同一 query 在一次任务内累计不超过 2 次，不得因失败重复调用同一 query，也不得通过同义改写、空格变化或字段换序规避计数；
7. **失败即停**：调用超时被中断或重试耗尽仍失败时，立即停止本轮，按失败话术输出（失败原因 + 已获取部分 + 建议重新运行）；**禁止后台执行、禁止改写 query 重试、禁止更换标的绕过**；
8. **局部失败继续**：单一报表失败（未达超时/重试耗尽阈值，如返回为空、口径缺失）记录原因后继续其他取数，不阻断全局；核心报表（如涨跌幅榜、个股行情）最终失败时，按第 5 节降级并在交付说明中披露；
9. **状态区分**："执行成功但为空"与"执行失败"分别记录；空记录不得当作零值解读；
10. **审计**：记录每张报表的行数、数据日期、执行状态与报表路径，供报告数据说明与溯源使用（审计在工作记忆中维护，不约定具体存储路径）；
11. **大结果压缩**：逐日明细、资金流序列等高容量结果在会话内压缩为统计摘要、极值、分位数、趋势与关键拐点，写作阶段只传递摘要；
12. **并行取数**：相互无依赖的取数调用（不同维度的报表查询、资讯与公告检索、板块与可比公司行情）应在**同一轮并行发起**，不串行等待；仅存在真实依赖时才串行——元数据检索 → 报表查询、榜单结果 → 入选个股明细、公告命中 → 公告全文。并行不影响第 2.0 节调用限制与同 query 计数。

### 3.2 常用 MQL 取数场景（以降低执行层边际成本）

以下路径/指标需以当次元数据检索为准，但可作为快速启动模板（避免从零摸索）：

| 数据维度 | 推荐 MQL 检索关键词 / 实体 | 关键指标示例 |
|---|---|---|
| **A股涨幅榜/跌幅榜** | `A股行情` / `沪深A股行情` / `全部A股` + `涨跌幅` | 代码、名称、最新价、涨跌幅、成交额、换手率、所属申万行业 |
| **港股涨幅榜/跌幅榜** | `港股行情` / `港股市场` / `全部港股` + `涨跌幅` | 代码、名称、涨跌幅、成交额、换手率 |
| **个股日行情** | 证券实体（股票代码）+ `日行情` / `行情指标` | 开盘价、收盘价、最高价、最低价、涨跌幅、成交额、换手率、振幅、总市值 |
| **板块/行业指数行情** | 板块 fullPath（如`申万行业\传媒\影视动漫制作`或`板块\港股\港股市场类\全部港股`）+ `行业指数行情` / `板块行情` | 板块涨跌幅、成交额、成分股区间涨跌幅 |
| **可比公司行情** | 多证券实体 + `日行情` | 收盘价、涨跌幅、成交额、换手率 |
| **资金流向** | 证券实体 + `资金流向` / `主力净流入` / `DDE` | 主力净流入、大单净流入、特大单净流入、散户净流入 |
| **龙虎榜** | 证券实体 + `龙虎榜` / `异动席位` | 上榜日期、买入金额、卖出金额、席位性质 |
| **融资融券** | 证券实体 + `融资融券` / `融资余额` | 融资余额、融资买入额、融券余额 |
| **估值指标** | 证券实体 + `估值` / `PE` / `PB` | 市盈率PE(TTM)、市净率PB(LF)、市净率PB(MRQ) |

> 注：指标 ID 与报表路径必须以当次 MQL 上下文检索返回为准；上表仅用于提示检索方向，不得未经检索直接硬编码。

### 3.3 MQL 执行审计记录表（工作记忆专用，不进入任何交付物）

每个数据维度至少记录：

| 维度 | MQL 是否尝试 | MQL 结果 | 实际通道 | 降级原因（如适用） | 口径差异说明 |
|---|---|---|---|---|---|
| 个股日行情 | 是/否 | 成功/失败/不可用 | MQL / 妙想 MCP / WebSearch | 如：MQL 路径缺失 / 超时（>1200s）/ 退避重试耗尽 / 返回为空 / 单轮取数预算受限（预算已用于：XX 调用） | 如：妙想 PE 为 PB(MRQ)，MQL 候选为 PB |
| 涨跌幅榜 | 是/否 | 成功/失败/不可用 | MQL / 妙想 MCP | 如：未尝试 / 单轮取数预算受限 | 无 / 妙想榜单口径含 B 股 |
| 资金流向 | 是/否 | 成功/失败/不可用 | MQL / 妙想 MCP | 如：MQL 失败 | 口径一致 / 妙想为主力净流入口径 |
| 龙虎榜 | 是/否 | 成功/失败/不可用 | MQL / 妙想 MCP | 如：非交易日无榜 | 无 |
| 板块行情 | 是/否 | 成功/失败/不可用 | MQL / 妙想 MCP | 如：板块 fullPath 未命中 | 无 / 成分加权方式差异 |

> 该表在**工作记忆**中维护，作为内部质量机制（保障"禁止静默降级"可核验）；**禁止输出到对话正文或报告正文**——交付物不暴露内部取数链路（SKILL.md 2.4 节）。

### 3.4 单轮取数预算受限时的处理

当执行层受单轮取数预算（调用次数 / token / 时间预算）约束时，按下述规则组织取数——**预算受限不是跳过 MQL 的理由，而是改变取数组织方式的信号**：

1. **预算分配优先级（强制）**：
   - 第一优先：L1 MQL 核心结构化报表（涨跌幅榜、个股行情、资金流向、龙虎榜）；
   - 第二优先：L2 妙想资讯/公告/研报检索（非结构化维度，MQL 无法覆盖）；
   - 第三优先：L3 兜底；
   - **禁止**把预算花在"妙想 MCP 取结构化数据"上而同时声称"预算不足未调 MQL"——这等于预算错配，视为违反强制 L1 优先。
2. **合并取数降耗**：MQL 单报表一次返回多个字段（如个股行情报表同时拿涨跌幅/换手/振幅/成交额/市值），按 3.2 节模板把同一实体、同一报表的指标合并进一次查询；多标的（可比公司）合并进一次证券实体查询；元数据检索全任务只做一次——用更少的调用覆盖更多的维度，而不是放弃 MQL。
3. **预算耗尽才降级**：仅当预算在 MQL 部分维度确实耗尽（已尝试合并取数仍不够）时，剩余维度降级 L2，且必须：
   - 在工作记忆审计表"降级原因"中写明"单轮取数预算受限（预算已用于：XX 调用）"；
   - 口径差异影响结论时，在报告《方法说明与局限》以**数据口径限制**形式呈现（不提通道、预算等执行细节）；
   - **报告与对话正文中均不出现"预算受限""未走 MQL""妙想补齐"等内部取数链路表述**（SKILL.md 2.4 节与硬性规范第 12 条）。
4. **禁止裸披露**：工作记忆审计记录不得只写"受单轮取数预算控制，未单独调用 MQL"——必须伴随预算去向说明与降级通道，否则视为静默降级；**报告正文中不得出现该类执行细节表述**。

### 3.5 实际通道命名规范

工作记忆审计表与报告《数据说明》中的数据来源口径标注使用以下固定名称，禁止用模糊词替代：

- `MQL` 或 `Choice数据`（MQL 取数，含经二次处理展示时使用，标注形如"Choice数据，数据日期 2026-09-29"）
- `妙想 MCP - 行情数据`
- `妙想 MCP - 资讯检索`
- `妙想 MCP - 公告检索`
- `妙想 MCP - 研报检索`
- `用户提供`
- `WebSearch / WebFetch`
- `待补`（表示该维度未取到）

禁止使用：`交易所行情`、`行情数据`、`公开数据`、`市场数据` 等未说明实际通道的表述。

## 4. 妙想 MCP 搜索规范（L2）

**检索降噪三规则（资讯/公告检索 query 必须遵守，L2/L3 检索均适用）**：

1. **限定时间窗**：query 必须显式限定发布时间范围为**异动日 ±7 天**（盘中场景为"今日"），禁止无时间限定的全历史检索——时间窗外的资讯对归因无增量价值，只会稀释相关性排序；
2. **限定返回形态**：query 中明示"只要标题 + 一句话摘要 + 日期 + 链接"四个字段，禁止默认返回全文（全文是最主要的 token 浪费源）；确需全文时，仅对最终入选证据矩阵的关键信源（通常 ≤3 条）单独逐条获取；
3. **公告类型白名单**：公告检索限定类型白名单——异常波动公告、定增/回购/增持减持、业绩预告/快报、重大合同、问询回复、互动平台答复、停复牌、股权激励、股东变动、监管处罚；白名单外的常规公告（定期报告例行披露等）不检索；
4. **超量截断**：单次返回超过 20 条时，按"标题相关性 + 时间接近度"排序只保留最相关的 **10 条**进入分析，其余丢弃并在工作记忆记录"已截断（原始 N 条）"。

1. 使用妙想 MCP 的**资讯检索**工具查个股与板块新闻（按标的代码/名称精确匹配，限定目标交易日前后窗口），**公告检索**工具查公司公告与披露（异动公告、问询回复、定增/回购、互动平台答复）；
2. 可用行情数据工具核对 MQL 未覆盖或失败的行情/资金维度；
3. 检索结果须记录：信源渠道、发布时间（精确到日/时点）、关键事实，进入证据矩阵；
4. 妙想返回的资讯注意与公告原文交叉验证——转述类内容以法定披露渠道为准；
5. MQL 不可用时的结构化数据降级：优先尝试妙想 MCP 的行情数据工具补齐行情、榜单、资金流；仍不可得再进入 L3，并在交付时说明降级路径。

## 5. 降级与模型自带兜底链路规范（L2/L3 与降级披露）

1. **必须先 L1 后降级**：任何结构化数据维度，必须先尝试 MQL（L1）；MQL 执行成功则不得降级；MQL 失败/不可用/**预算耗尽（须先按第 3.4 节做合并取数降耗）**时，才允许降级到 L2 妙想 MCP 或 L3 WebSearch；
2. **降级原因必须留痕**：每个降级维度必须在工作记忆审计表中写明：
   - MQL 是否可用；
   - 未使用/失败的具体原因（如：MQL 路径缺失、参数校验失败、超时、返回为空、证券池未覆盖、单轮取数预算受限——须注明预算实际用于哪些调用）；
   - 实际采用的通道与口径差异（口径差异影响结论时，在报告《方法说明与局限》以数据口径限制形式呈现，不提通道与执行过程）；
3. **禁止模糊表述**：不得以"交易所行情""Choice 数据""公开数据""行情数据"等未说明实际通道的表述替代第 3.5 节的固定通道名称；
4. L3 使用 WebSearch / WebFetch 检索公开信源，重点覆盖：海外原始信源（公司 IR、FDA、ClinicalTrials.gov、SEC EDGAR、交易所披露）、公众号/社群传播样本（情绪指标）、行业垂直媒体；
5. 海外信源以原始平台发布时间戳为准（注意时区换算），不以国内媒体转述时间为准；
6. L3 获取的结构化数据（价格、成交额等）须标注"公开信源整理，口径可能与交易所数据存在差异"；
7. L1、L2、L3 全部不可用或数据严重缺失时：明确告知用户数据受限，输出降级版分析（框架 + 待补数据清单），**不得编造数据**。

## 6. 数据维度与口径

| 维度 | 必需内容 | 优先通道 | 口径要求 |
|---|---|---|---|
| 个股行情 | 收盘价/现价、涨跌幅、开高低、成交额/量、换手率、振幅、总市值 | **L1 MQL（强制）** | 注明交易日与收盘/盘中时点口径；MQL 可用时不得降级 |
| 区间表现 | 近 5 个交易日逐日涨跌幅 | **L1 MQL（强制）** | 判断"单日孤立事件"还是"趋势延续" |
| 分时节点（盘中） | 集合竞价、封板/开板时点、量能分布、均价线位置 | **L1 MQL（强制尝试）**，不可得时按用户材料/盘口数据整理 | 标注观测窗口与数据来源 |
| 板块与可比 | 所属行业/概念指数当日涨跌幅、3–5 只可比公司涨跌幅 | **L1 MQL（强制）** | 反事实检验的基准；板块 fullPath 以当次检索为准 |
| 资金流向 | 主力/大单/特大单净额（单日 + 近 3/5 日累计）、融资余额 | **L1 MQL（强制）** | 各终端口径有差异，注明"仅作方向参考" |
| 龙虎榜 | 榜单席位、买卖性质（盘后可得） | **L1 MQL → L2 妙想** | 以交易所披露为准；MQL 可用时优先 MQL |
| 公司公告 | 异常波动公告、定增/回购/持股计划、问询回复、调研纪要 | L2 妙想（公告检索）→ L3 | 法定信息披露渠道为唯一权威来源 |
| 行业与政策 | 产业政策、海外竞品/巨头动态、监管动态 | L2 妙想（资讯检索）→ L3 | 海外信源核对发布时间戳与股价启动时点先后 |
| 券商研报 | 评级变动、目标价调整、核心观点 | L2 妙想 → L3 | 注意研报发布时间与异动日的关系 |
| 社媒传播 | 公众号/社群热文标题与集中出现时段 | L3 | 仅作情绪指标，不作因果证据 |
| 财务底色 | 最新财报营收/利润/现金流增速、估值（PE/PB/市值） | **L1 MQL（强制）** | 区分"预期差行情"与"业绩差行情" |

> **强制原则**：凡上表标注"L1 MQL（强制）"的维度，只要 MQL 环境校验通过，就必须先尝试 MQL；不得以妙想 MCP 取数便利为由绕过。

**分时数据取数路径（盘中模式与分钟级时间轴专用）**，逐级尝试、逐级降级并披露：

1. **MQL 分钟级行情报表**（先经上下文检索确认当次可用的分时/分钟级报表路径与周期口径）；
2. **妙想 MCP - 行情数据**（分时、盘口、量能分布）；
3. **用户提供材料**（盘口截图、Level-1 快照、交易软件分时图）；
4. 全部不可得时**降级为日级时间轴**，在《方法说明与局限》声明"时间轴仅到日级"及具体原因；**禁止用日级数据拆解、虚构分钟级节点**。

## 7. 溯源规范

1. **每个关键事实标注信源**：证据矩阵逐条给出信源渠道 + 日期（如"公司公告 2026-09-30""资讯 2026-09-30""公告 2026-09-30""研报 2026-09-30""Choice数据，数据日期 2026-09-29"）；对于 MQL 取数与妙想 MCP 取数，使用各自工具自带默认的溯源效果；
2. **数据冲突处理**：不同源数据不一致时（如主力净流出 6.13 亿 vs 5.99 亿），并列列出并注明口径差异，不擅自取舍；
3. **信息截止时间**：报告头部与尾部均注明（精确到日或时点）；
4. **时区与交易日历**：非 A 股市场注意交易日历差异（节假日、半日市），跨市场事件须标注当地时间；
5. **溯源链接**：通过妙想 MCP 搜索与模型自带兜底链路获取的每条信息，均须在证据矩阵中提供对应的溯源链接（原文 URL），供用户一键核验。

## 8. 涨跌幅榜（场景一）数据规范

- 涨幅榜口径：当日涨幅 ≥ 5%；跌幅榜口径：当日跌幅 ≤ -5%（港股/美股可按市场惯例调整，如 ±8%，但须说明）；
- 两榜均按**成交金额降序**排列，默认各取 10 只（合计 Top 20）；
- 数据获取：**必须先通过 MQL 检索涨跌幅榜类报表（交易日期 <= 系统日期）**；MQL 尝试失败或不可用时，降级妙想 MCP 行情数据工具，再降级 L3，降级原因与口径差异记录于工作记忆审计表（不进入报告，SKILL.md 2.4 节）；

**榜单问句模板（固化为默认表述，避免口径失真）**：

- 涨幅榜：`{YYYY-MM-DD} A股涨幅榜：当日涨幅 ≥ 5% 的股票，剔除停牌，按成交额降序，返回代码、名称、最新价、涨跌幅、成交额、换手率、所属申万行业`；
- 跌幅榜：`{YYYY-MM-DD} A股跌幅榜：当日跌幅 ≤ -5% 的股票（剔除上涨和平盘股票），按成交额降序，返回代码、名称、最新价、涨跌幅、成交额、换手率、所属申万行业`——**"剔除上涨和平盘股票"为必写表述**，缺省时筛选口径可能失真（返回 -0.5% 以内标的）；港股/美股按市场惯例替换阈值，剔除表述保留；

**返回结果校验（方向性校验，必做）**：榜单返回后必须核验方向与量级——跌幅榜出现上涨/平盘股票、涨跌幅落在口径阈值以内（如跌幅榜返回 -0.5% 以内）、或两榜标的高度重合，均判定为查询口径失真；此时在 query 中补入"剔除上涨和平盘股票"表述构成**语义修正后的新 query** 重试一次（不属于规避同 query 计数），仍失真则按降级链路处理并披露。

> **校验为内部执行动作**：校验的过程与结果说明不进入对话正文（对话层降噪见 SKILL.md 硬性规范第 12 条）；场景一榜单**默认产出 HTML 报告**（`assets/templates/top_movers_template.html`），数据口径信息（来源、数据日期、筛选阈值）落报告《数据说明》模块——**通道审计表只留工作记忆，不进入报告正文**；仅用户明确要求对话内展示榜单时，对话中只保留一句话口径标注（通道名 + 数据日期 + 筛选阈值口径），失真重试与降级决策只记录于工作记忆。
- 每只标的展示：代码、名称、最新价、涨跌幅、成交额、换手率、所属行业/概念、异动线索（一句话，若无可靠线索则标注"待查"）；
- 剔除规则：上市首日新股、停牌复牌首日无涨跌幅限制的标的，视用户需求决定是否剔除并说明；
- 盘中模式注明"数据截至 HH:MM，榜单随行情实时变动"。
