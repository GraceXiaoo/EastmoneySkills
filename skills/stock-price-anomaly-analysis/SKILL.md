# 个股异动原因分析（Abnormal Move Attribution）

## 1. 目的

在交易日盘中或盘后，针对发生异动涨跌的个股，快速产出一份**可溯源、可交叉验证、可指导投资决策**的归因复盘报告，回答三个问题：

1. **发生了什么**——异动的强度、形态、资金特征；
2. **为什么发生**——直接催化剂、传导链条、主因/辅因/背景分层归因；
3. **接下来盯什么**——验证信号、情景推演、操作阈值。

服务对象为二级投研分析师，重点覆盖标的发生股价异动时使用。所有结论必须区分**事实（可证）**与**判断（推测）**，无据可查的原因必须明确标记"原因未完全确认"。

## 2. 触发场景

- 用户询问某交易日盘后/盘中"当前市场哪些个股异动涨跌"（场景一）
- 用户指定 Top 榜个股或重点覆盖标的，要求分析异动原因/复盘归因（场景二）
- 典型话术："XX为什么涨/跌""XX异动分析""帮我复盘今天的胜宏科技""今天 A 股有哪些异动股""盘中快评一下康希诺"

## 3. 核心参数（开始前先确认或合理默认）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 市场 | A股（沪深京三市） | 可指定港股、美股（纽交所/纳斯达克）、日/韩/中国台湾等 |
| 日期 | 最近一个交易日 | 盘中场景为当日实时，盘后场景为当日收盘口径 |
| 模式 | 盘后复盘 | 用户说"盘中/午间/现在"则为盘中模式，结论标注隔夜失效 |
| 标的 | 场景一先给榜单，场景二由用户指定 | 个性化模式下优先展示与用户兴趣相关标的，不足时按全市场同方向口径补足，并说明补足逻辑 |
| Top N | 各 10 只，合计 20 | 涨幅榜筛选口径：涨幅 ≥ 5%；跌幅榜：跌幅 ≤ -5%；两榜均按成交金额降序 |
| 输出格式 | HTML（专业投研风格） | 用户要求 Word 时产出 DOCX |

## 4. 工作流程

### 第一步：意图识别与参数确认

按第 3 节确认市场、日期、模式、标的与输出格式。若用户只给股票名，默认盘后复盘模式、最近交易日。

### 第二步：数据采集（场景一 / 场景二共用）

#### 2.0 工具调用硬限制（强制）

> 本 skill 为提示词型流程（无可执行脚本），调用 MQL 等 MCP 工具须遵守：单次调用最长等待 1200 秒，超时即判失败；单个工具调用失败后最多退避重试 2 次（退避等待 30s/90s）；同一 query 累计调用不超过 2 次；调用超时被中断或返回失败时，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 query 或更换标的重试。

具体执行要求：

1. **超时上限**：单次工具调用最长等待 **1200 秒**，超过该时长即判定为超时失败，不得继续等待或挂起；
2. **退避重试上限**：单个工具调用失败后，最多**退避重试 2 次**（退避等待 30s / 90s）；两次重试后仍失败即停止该调用；
3. **同 query 计数上限**：同一 query 累计调用**不超过 2 次**；不得因失败重复调用同一 query，也不得通过同义改写、空格变化或字段换序规避计数；退避重试与同 query 上限冲突时以**更严格者**（累计 ≤ 2 次）为准；
4. **失败即停止本轮**：调用超时被中断或返回失败时，立即停止本轮，按失败话术向用户输出——仅包含三要素：本次取数未能完成、已成功获取的部分（如有）、建议（如"请稍后重新运行本任务"）；**失败原因（超时 / 重试耗尽 / 预算受限等执行偏离细节）不进入对话正文**，只留工作记忆与报告审计（有报告时）；**禁止后台执行、禁止改写 query 重试、禁止更换标的绕过**；
5. **确定性错误不重试**：路径错误、参数校验错误、元数据无效等确定性失败，不做退避重试，直接按降级或失败话术处理；
6. **禁止静默挂起**：任何等待中的调用不得转入后台继续执行——用户收到的回复必须反映调用链的真实终态（成功 / 失败 / 降级）。

#### 2.1 前置环境校验（必须留下痕迹）

按 `references/data-sources.md` 第 1 节执行，**并在工作记忆中记录结果**（不约定具体存储位置）：

1. 确认 MQL 工具链（参考/上下文检索/执行入口）在当前环境中是否可用；
2. 确认 MQL 能力说明中列出的版本要求与当前执行器是否兼容；
3. 确认目标市场证券池、行情指标、资金指标、龙虎榜指标等核心字段能否通过 MQL 工具链覆盖；
4. **记录结论**：MQL 可用 / MQL 不可用（附具体原因）。

> 即使判断 MQL 可能不适用，也必须先完成上述校验并尝试 L1；禁止以"成本高""路径长""返回体量大"为由跳过 L1。

#### 2.2 先 L1 后 L2 的强制顺序

对每个数据维度，**必须先尝试 L1，再决定是否降级**。三级链路：

1. **L1 MQL 取数（强制首选）**：结构化数据（行情、涨跌幅榜、资金流向、龙虎榜、融资融券、估值、财务、板块/指数行情、可比公司行情）**一律优先通过 MQL 获取**。执行规范（单接口单 ReportBlock、日期字面量替换、定向元数据检索与有限重试、同一 query ≤ 2 次、局部失败继续、执行审计）见 `references/data-sources.md` 第 3 节。
2. **L2 妙想 MCP 搜索**：仅用于 MQL 未覆盖或执行失败的维度（个股新闻资讯、公告披露、互动平台内容、行业事件线索、研报观点）；**MQL 已覆盖的行情/榜单/资金流/龙虎榜等结构化维度，即便妙想 MCP 取数更便利，也不得绕过 MQL 直接使用**。资讯/公告检索 query 必须遵守 `references/data-sources.md` 第 4 节**检索降噪三规则**（时间窗异动日±7天、只要标题+一句话摘要+日期+链接、公告类型白名单；超 20 条只保留最相关 10 条）。
3. **L3 模型自带兜底链路**：L1/L2 均不可用或未覆盖的维度（海外原始信源、公众号/社群传播样本等）用 WebSearch / WebFetch 补充。
4. 用户提供的研究材料直接采信并注明"用户提供"，不走上述链路。

#### 2.3 预算受限场景（单轮取数预算 / 调用次数 / token 预算）

预算受限**不是跳过 MQL 的理由，而是改变取数组织方式的信号**，处理规则：

1. **预算分配优先级**：预算必须优先分配给 L1 MQL（核心结构化数据），其次妙想资讯/公告检索，最后 L3。禁止"预算不够就不调 MQL、却把预算花在妙想 MCP 取结构化数据"——这等于把预算花在低优先级通道；
2. **合并取数降耗**：MQL 单报表天然支持一次返回多个字段（如个股行情报表一次拿齐涨跌幅/换手/振幅/成交额/市值），应通过合并字段、合并证券实体减少调用次数，而不是放弃 MQL；元数据检索全任务只做一次；
3. **预算耗尽才允许降级**：仅当预算在 MQL 部分维度确实耗尽时，剩余维度才降级 L2，降级事实与预算去向记入**工作记忆审计表**（"单轮取数预算受限，预算已用于：XX 调用"）；**报告与对话正文中均不出现预算受限、通道替代、补取建议类表述**——内部取数链路信息不进入任何交付物（见 2.4 节）；
4. **禁止裸披露**：工作记忆审计记录不得只写"受单轮取数预算控制，未单独调用 MQL"——该记录必须伴随预算去向与降级通道说明，否则视为静默降级；**报告正文中不得出现"受单轮取数预算控制""未单独调用 MQL"等执行细节表述**。

#### 2.4 执行审计与降级留痕（审计表仅限工作记忆，不进入任何交付物）

- 在**工作记忆**中维护一张 `MQL 执行审计表`（维度、MQL 尝试结果、实际通道、降级原因、口径差异，表式见 `references/data-sources.md` 第 3.3 节），作为内部质量机制，保障"禁止静默降级"可核验；
- **审计表不进入任何面向用户的输出**：对话正文与报告正文均不输出数据通道审计表、逐维度通道清单、MQL 尝试/失败原因、预算去向等内部取数链路信息；
- 报告《数据说明》**保留既有的数据口径与溯源**：数据来源口径标注（如"Choice数据，数据日期 XXXX-XX-XX"）、时间轴粒度声明（分钟级/日级降级）、资金流等口径限制说明、证据矩阵逐条信源+日期+链接；口径差异影响结论时，在《方法说明与局限》以数据口径限制形式呈现（不提通道与执行过程）；
- 三级链路全部不可用时不编造数据，输出降级版分析（框架 + 待补数据清单）。

> **审计信息的呈现位置**：审计表与全部取数执行偏离说明（降级、通道替代、预算受限、口径差异、补取建议）**只留工作记忆，不进入对话正文，也不进入报告正文**；报告仅保留数据口径与溯源（见第六步"对话正文约束"与硬性规范第 7、12 条）。

#### 2.5 采集维度

必须覆盖：个股行情（价格/涨跌幅/换手/振幅/量能）、分时关键节点（盘中模式）、板块与可比公司表现、资金流向（主力/大单/融资余额/龙虎榜）、公司公告与互动平台、行业政策与事件、海外原始信源、券商研报、公众号/社群传播样本。

### 第三步：场景一——异动涨跌幅榜

- **默认 HTML 产物（强制）**：场景一与场景二一样，**默认产出 HTML 报告文件**并调用 present_files 呈现——基于 `assets/templates/top_movers_template.html`（双榜模板）生成，杜绝"只在对话内输出、事后无处回看"的丢产物问题；仅当用户明确要求"只在对话里看 / 不要文件"时，才降为对话内 Markdown 表格，并在该表格仅附一句话数据口径标注（通道名 + 数据日期 + 筛选阈值口径），**不得附数据通道清单、口径校验的过程性说明与取数执行偏离说明**（硬性规范第 12 条）；
- 输出实时涨幅榜与跌幅榜，默认各 10 只（合计 Top 20），两榜按成交金额降序排列；
- 榜单 query 使用 `references/data-sources.md` 第 8 节固化问句模板（跌幅榜必含"剔除上涨和平盘股票"），返回后做方向性校验；
- 每只列示：代码、名称、涨跌幅、成交额、换手率、所属行业/概念、一句话异动线索（若有）；
- HTML 报告须包含要点摘要（领涨/领跌方向、两榜结构、值得深挖标的）与《数据说明》模块（仅数据口径标注：来源、数据日期、筛选阈值；**不含通道审计表**，见 2.4 节）；
- 若无符合 ±5% 口径的标的，放宽/收紧口径时必须在报告中说明并记录实际口径（对话中一句话带过实际口径即可，不展开校验过程）。

### 第四步：场景二——单票异动归因复盘

按 `references/report-framework.md` 中对应框架执行，核心动作：

1. **行情还原**：日K + 当日分钟级分时关键节点（关键时点涨跌幅、量能、大单方向、与指数同步性；无法取分时数据时在局限中声明降级）、量价特征（放量形态与质量、跳空性质按 `references/analysis-playbook.md` 第 1 节判定）、相对板块超额收益；**单日分析场景的 HTML 报告须同时包含两张图（模块二）——①近期走势图（近 5–10 日收盘价/日K + 成交量，定位本次异动在近期趋势中的位置）②当日日内分时图（分时价格线 + 成交量，标注催化发布时点）**；无法获取分时数据时，日内分时图降级为分时表并在局限中声明；
2. **归因拆解**：按 `references/attribution-method.md` 的方法论——分钟级时间轴对齐（催化晚于启动只解释放大段，不解释启动）、反事实检验（同期板块与可比公司对比）、证据分级交叉验证、**归因分层（主因=必要且充分 / 辅因=放大幅度与速度 / 背景=不是原因）**；贡献度百分比仅为可选排序参考，须标注研究判断值并注明严格量化路径（事件窗口 CAR）；政策类催化按 playbook 第 2.2 节做增量识别与交易阶段判定，公司事件按第 2.3 节判定时序与成色，海外映射按第 2.4 节判定映射真伪；资金面按 playbook 第 4 节区分资金行为性质并遵守表述纪律（主力净流入≠机构买入）；
3. **证据矩阵**：逐条列示信源、关键事实、可信度等级、对归因的支持方向；**必须包含反证与反例**（可能证伪归因的信号、矛盾口径、同期未涨的同类标的）；每只股票默认做交叉验证，单一信源不足以定论；
4. **三角错位**：股价与基本面显著背离时单列"基本面—估值—股价三角错位"模块（已验证 / 未验证 / 结论：下份财报是证伪/确认点），不得塞进风险附注；
5. **多空博弈**：多头可验证支点 vs 空头未计价风险（含资金流与价格的背离信号，正面呈现不弱化）；
6. **后续跟踪清单**：验证信号 + **归因失效条件（置于情景推演之前）** + 情景推演（乐观/中性/悲观，盘中模式另含概率与操作阈值）；市场环境与情绪温度计按 playbook 第 3 节量化校准；
7. **买方视角结论**：已持仓/未持仓/做空对冲三类持有状态的操作含义，并声明"本研究是对本次异动的解释性归因，不是对该股的看多/看空建议"；
8. **方法与局限**：必须包含，注明时间轴粒度（分钟级/日级降级）、数据口径与无法获取的信息；涉及资金推动时注明"大单主导的边际定价，不等同于机构共识形成"；涉及历史对照类统计论断时遵守 playbook 第 5 节纪律。

### 第五步：产出报告

- **HTML 输出**：场景一基于 `assets/templates/top_movers_template.html`（双榜模板）生成；场景二基于 `assets/templates/post_close_template.html`（盘后）或 `assets/templates/intraday_template.html`（盘中）生成。替换占位符（`{{...}}` 形式），保留配色、涨红跌绿（A股口径）、标签体系（证据等级 A/B/C、异动等级红>橙>黄>蓝）；盘中版须保留"数据以实际通道（MQL / 妙想 MCP - 行情数据）为准"与隔夜失效声明；
- **HTML 新增图表**：唯一权威规范见 `references/analysis-playbook.md` 第 6 节（按需加载）。仅一条硬性红线常驻此处：在模板基础上新增内联 `<script>` 图表时，交付前必须完成 JS 语法自检（`node --check` 或等价方式），通过才允许交付；
- **DOCX 输出**：用户明确要求 Word 时，按当前模式（盘后/盘中）对应的报告框架产出 DOCX，内容模块不变，排版遵循 Word 文档规范；
- 报告尾部必须包含：主要信源清单、信息截止时间、"仅供研究参考，不构成投资建议"声明。

### 第六步：交付

**产物交付可靠性纪律（强制，防丢产物）**：

1. **两场景默认必有 HTML 产物**：场景一（双榜）与场景二（单票复盘）默认均产出 HTML 文件——这是产出的硬性组成部分，不以"耗时/token 考虑"为由省略；仅用户明确拒绝文件时才只做对话内输出；
2. **生成后校验**：HTML 写入后必须确认**文件存在且非空**（读回检查），通过后才进入交付；
3. **呈现成功才收尾**：调用 present_files 呈现产物，呈现成功前不得结束回合；呈现失败时重试一次（含重新生成文件），仍失败才在对话中如实告知"产物未能生成"（此为交付状态说明，不属取数偏离细节）；
4. **回复与产物同时完成**：要点摘要与 present_files 在同一回合内完成，禁止"先回复、产物稍后补"的分离交付。

生成文件后调用 present_files 呈现，并在回复中给出 200–300 字的要点摘要。摘要采用结构化短句，**核心标签加粗**，示范格式：

> **直接催化剂**：……；**传导链条**：「A → B → C」的一句话版本；**主因**：……；**辅因**：……；**背景（非原因）**：……；**关键分歧**：……；**下一步盯**：……。

上述标签（直接催化剂、传导链条、主因/辅因/背景（非原因）、关键分歧、下一步盯）必须在对话正文要点摘要中加粗展示。

**交付话术规范（对话摘要降噪）**：数据通道审计与取数执行偏离说明只留工作记忆（不进入对话正文，也不进入报告正文）；对话摘要只输出结论、直接催化剂、归因分层（主因/辅因）、多空关键分歧与跟踪信号。**取数执行偏离说明（降级、口径替代、预算受限、补取建议等）一律不进入对话摘要**；全链路失败无报告可承载时，按 2.0 节失败话术输出（仅"未能完成 + 已获取部分 + 建议重试"三要素）。

**对话正文约束（全对话适用，不限于摘要）**：对话中出现的任何输出——场景一对话内表格、要点摘要、盘中快评、降级与失败提示——**不得出现数据通道清单**（逐维度列通道的清单/表格）、**口径校验的过程性说明**（方向性校验、剔除规则执行、问句模板使用等执行过程叙述）、**以及取数执行偏离说明**（降级、通道替代、预算受限、口径差异与补取建议）；除用户明确要求对话内展示榜单/表格时可附一句话数据口径标注（通道名 + 数据日期 + 筛选阈值口径）外，对话正文不携带任何通道与执行信息。校验、执行过程与偏离记录只留工作记忆；报告正文同样不输出审计表，仅保留既有的数据口径标注与溯源（见 2.4 节）。

**产物存储路径约定**：本 skill 不约定任何具体存储路径——产物（HTML/DOCX 报告、审计中间记录）一律按当前会话/平台的默认输出机制交付，不要求写入任何指定目录，也不在报告中描述文件落盘位置。

## 5. 硬性规范（不可违反）

1. **结论先行**：报告第一模块必须直接给出归因结论，再展开论证；
2. **事实与判断分离**：所有量化数据标注口径与截止时点；贡献度、概率等主观判断明确标注为"研究判断值，非模型输出"；
3. **溯源**：每个关键事实与结论须可追溯到信源（公告/行情/研报/媒体，含日期）；无法溯源的传闻不得作为归因证据；
4. **信息甄别红线**：盘中流传的"小作文"一律按未经证实处理，直至公司在法定信息披露渠道确认；公众号/社群内容定性为情绪放大器，不得作为因果证据，只用于证实传播路径；
5. **资金面表述红线**：主力/游资/散户是资金流算法分类，不是真实账户身份——禁止"主力净流入=机构买入/机构建仓"式断言；涉及资金推动须注明"大单主导的边际定价，不等同于机构共识形成"；资金流与价格背离信号不得删除或弱化；
6. **强制 L1 优先**：结构化数据（行情、榜单、资金、龙虎榜、估值、财务、板块/指数行情、可比公司行情）**必须先尝试 MQL（L1）获取**；MQL 可用时，不得以妙想 MCP 取数更便利、单轮取数预算/调用次数受限为由绕过 MQL——预算受限时优先保障 MQL 的预算份额（通过合并取数降耗），预算耗尽后的降级须按 2.3 节记入工作记忆审计表；
7. **禁止静默降级（内部留痕）**：凡最终未采用 MQL 的维度，必须在**工作记忆执行审计表**中列明实际通道（MQL/妙想 MCP/WebSearch/用户提供）与降级原因，作为可核验的内部记录；**报告正文不输出审计表与逐维度通道清单**；报告《数据说明》保留数据来源口径标注（如"Choice数据，数据日期 XXXX-XX-XX"），禁止使用"交易所行情""行情数据"等模糊表述替代数据来源口径；
8. **诚实标注**：无据可查的涨跌原因明确标记"原因未完全确认"，不得强行编造归因；
9. **盘后 vs 盘中差异**：盘中报告不预设结果、明确标注待核验项、结论仅限当日有效，并注明收盘后须回填检验；
10. **合规**：所有产出附"不构成投资建议"声明；涉及前瞻表述用情景推演而非预测口吻；报告定位为解释性归因而非买卖建议；
11. **工具调用限制**：调用 MQL / RAG 等 MCP 工具时——单次调用最长等待 1200 秒（超时即失败）；失败后最多退避重试 2 次（30s/90s）；同一 query 累计调用不超过 2 次；超时被中断或返回失败时**立即停止本轮并按失败话术输出**，禁止后台执行、禁止改写 query、禁止更换标的重试（详见 2.0 节）；
12. **对话层降噪**：**对话正文**（含场景一对话内表格、要点摘要、盘中快评、降级与失败提示）中不披露内部执行细节（调用次数、重试/退避过程、错误码），**不得出现数据通道清单（逐维度列通道的清单/表格）、口径校验的过程性说明（方向性校验、剔除规则执行、问句模板使用等执行过程叙述）、以及取数执行偏离说明（降级、通道替代、预算受限、口径差异与补取建议）**——完整审计与偏离说明**只留工作记忆，不进入对话正文，也不进入报告正文**（报告正文同样不输出数据通道审计表，见 2.4 节与 `references/data-sources.md` 第 3.3 节；报告《数据说明》仅保留既有的数据口径标注与溯源）；仅用户明确要求对话内展示表格时可附一句话数据口径标注（通道名 + 数据日期，可含筛选阈值口径）。全链路失败时对话只输出三要素：未能完成、已获取部分、建议重试，不展开原因。
