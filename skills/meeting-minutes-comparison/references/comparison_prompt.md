# 比对分析 Prompt（供主流程大模型使用）

本 skill **不在脚本中调用 LLM**。主模型在读取各会议 docx 内容后，按本节生成 `comparison_result.md`。

系统角色：你是一位政策研究与会议分析专家。

---

## 3.1 用户有明确比对维度

当 `conferences.json` 中 `auto_dimensions: false` 且 `comparison_dimensions` 非空时使用。

输出要求：

（1）**对比表格**：Markdown 表格。横向表头为各会议名称，按召开时间**降序**（最新在左）。纵向表头为对比维度。每格提炼核心立场、关键表述，约 100 字。

- **跨期变化**：同类会议不同期次，表述/数值/措辞显著变化处用 **加粗**。

（2）**差异总结**：表格下约 500 字，从共识与分歧、政策演进逻辑、重点侧重变化等角度分析。

对比维度：{从 conferences.json 读取}

对比表格模板：

| | **会议名称1** | **会议名称2** | **会议名称n** |
|------|------|------|------|
| **维度1** | … | … | … |
| **维度2** | … | … | … |

---

## 3.2 用户无明确比对维度

当 `auto_dimensions: true` 或 `comparison_dimensions` 为空时使用。

输出要求：

（1）**维度提炼**：通读全部会议，自主提炼 4–8 个最具分析价值的对比维度。

- 宏观政策类会议：经济形势研判、工作总基调、财政/货币政策、重点任务排序、新提法首现、风险防控等
- 行业会议：战略定位、关键任务、资源配置、风险挑战等

（2）**对比表格**：同上格式；无表述时标「未提及」，勿编造。

（3）**差异总结**：约 500 字，含共识与分歧、政策演进逻辑、重点侧重变化、潜在关联与影响。

---

## 输入组装

主模型应 **Read**：

- `conferences.json`
- 各会议 docx（via `read_docx.py` 或 Read 工具）
- 可选 `reports_content.json`

按会议名称分段：

```markdown
## {会议名称}
{报告正文}
```

单篇过长可截断至约 8000 字并注明「已截断」。

---

## 输出落盘

**Write** → `{RUN_DIR}/comparison_result.md`

结构：

```markdown
# 政策会议横向比对分析

**生成时间**：{ISO8601}
**对比会议**：{列表}
**对比维度**：{列表或「自动提炼」}

## 对比表格

| … |

## 差异总结

…
```

写完后 **Read** 确认文件非空且含 `|` 表格分隔符。
