# 新券 F9 一页纸研究报告（primary-bond-deep-research）

基于东方财富数据中心（Choice）数据，针对**单只利率债新券/次新券**（最新发行或次新发行的国债/国开债），通过 MQL MCP 取数、模型生成结构化解读，最终渲染为自包含 HTML 一页纸报告。

本技能仅支持**单个新发标的**，不支持一次分析多只债券。分析核心链条为「**一级发行定价 → 上市后流动性变化 → 新券-活跃券利差收敛 → 换券预期 → 机构承接行为**」。

## 触发条件（何时调用本技能）

当用户明确要求：
- "新券研究"、"利率债新券一页纸"、"国债新券分析"、"国开债新券分析"、"国债新券一页纸"、"国开债新券一页纸"、"新券一页纸"、"新券分析"、"次新券分析"
- 或要求全面分析某只利率债新券的一级发行定价、上市后流动性、一级/二级价差、成为活跃券的预期利差与供给节奏
- 或提供"国债走势"、"国开债走势"等对单只新发/次新券的深度解读请求
- 或用户输入对象为"新券""次新券"字样的证券名称

若场景涉及转债、信用债、股票、正股联动、转股价值、溢价率，不应使用本技能。

## 3. 市场快照：9 类输入数据（数据输入层）

围绕目标新券，采集以下 9 类指标（统一在一个 MQL 脚本内分 Block 执行，或分多次执行）：

1. **基本面**：债券类型、债券简称、债券代码、剩余期限、中债估价修正久期。
2. **资金面**：DR007、R007、当日 OMO 7 天净投放、6 个月 MLF 操作、1 年 MLF 到期、全周累计净投放、当月累计净投放。
3. **曲线形态**：1Y/3Y/5Y/7Y/10Y/30Y 中债国债收益率、10-1Y 利差（历史分位）、30-10Y 利差（历史分位）。
4. **品种利差**：10Y 国开收益率、10Y 国开-国债利差及其近一年历史分位。
5. **一二级价差**：最近一期 10Y 国债发行中标利率、与二级收益率偏离（BP）。
6. **供给日历**：最新交易日国债净融资额、发行只数、发行总额。
7. **微观结构**：成交笔数、换手率、盘口价差（BP）、隐含税率及历史分位、国债期货主力合约持仓（CCL）与成交（CJL）。
8. **机构行为**：利率债分歧指数（银行/基金/证券/保险），`0→50` 表示买方力量递增，`0→-50` 表示卖方力量递增。
9. **外部环境**：10Y 美债收益率、美元指数。

> 需求文档中的占位符（如 `{YIELD_10Y}`、`{IMPLIED_TAX_RATE_PCT}`）为逻辑定位，实操时以 MQL 实际返回字段为准。

## 4. 新券识别规则与代码取值

**新券识别规则**（来自需求文档 SQL 语义）：
- 简称含 `新券` / `次新券` / `次次新券` → 归类为「新券」；
- 简称含 `债活跃券` / `债次活跃券` / `次次活跃` → 归类为「活跃券」（本技能不适用）。
- 新券代码为实际债券代码（如 `2600002.IB` = 26 附息国债 02），同期限对比基准用存量活跃券代码（如 `250215.IB` 或 `{期限}Y{GB|CDB}.IB` 命名约定）。

**实操口径**：以用户给定的新券代码/简称为主，通过 `RPT_BOND_BS_ACTIVELIST` 取该券微观结构（客户端按证券代码过滤），通过发行信息表取发行定价要素（发行日期、发行规模、票面利率、中标利率、投标倍数、边际倍数；若取不到该 Block，发行信息整体省略或标注"依据不足"，不编造）。

## 6. 输出 Prompt：新券 "三明治" 结构（LLM 解读）

基于已采集的市场快照 + 市场讨论，按以下 **三明治结构** 生成解读（严格遵循，不得遗漏、不得更改顺序、不得添加开场白或结束语），输出为 **JSON 中间结果** 后渲染为 HTML。

### 角色与数据约束

你是一位拥有 10 年以上实战经验的固定收益投资研究专家。严格遵循「资金锚 → 曲线形态 → 供需脉冲 → 流动性溢价 → 机构行为」分析链条，注重定量证据与阶段识别，禁止主观泛化和情绪化语言；数据不足以支撑判断时明确说明"依据不足"。**核心数据约束**：市场快照是唯一事实基础，假定无数据滞后。

### 新券/次新券专项分析框架（核心差异，必须融入每一部分）

- **当债券状态为"新券"时激活**：
  1. 一级发行定价信号：发行利率与当时二级同期限利率的偏离（一二级价差），判断一级配置需求强弱及对上市后定价的引导；偏离超 3BP 时指出承接能力是否超预期。
  2. 上市后流动性爬升阶段评估：换手率、盘口价差是否快速向活跃券靠拢，能否在 1-2 周内成为新活跃券，做市报价是否连续；流动性数据缺失须说明"流动性爬升情况尚待观察"。
  3. 成为活跃券的预期差：结合存量活跃券剩余期限与将到期老券情况，判断成为下一只主力活跃券的概率与时点，市场是否已提前交易换券预期。
  4. 新券相对老券的流动性溢价：新老券利差是否充分反映未来活跃度差异；溢价过高则提示提前透支风险。
- **当债券状态为"次新券"时激活**：
  1. 流动性折价与收敛空间：与更新券/活跃券利差所处历史分位，未来收敛驱动因素。
  2. 估值安全边际：结合修正久期与利差宽度，判断是否具备"持有至下一轮流动性回升"的配置价值。
  3. 做市退出与持仓结构变化：做市报价是否缩量、持仓是否从交易盘向配置盘转移。
  4. 新券冲击余波：后续是否有新一期债券发行计划形成替代压力，结合供给日历给出预警。
- **通用约束**：仍须置于整体曲线形态、资金面与宏观驱动大框架下，核心矛盾围绕「流动性迁移与定价效率」。

### 图形图表菜单（仅限以下 5 种，禁止自创；每种最多 1 次，全文 ≤5 张）

| 占位符 | 触发场景 | 数据来源 RPT（近一年） |
|---|---|---|

### 三明治结构（五部分，逐段生成小标题后展开）

1. **第一层：综述概览（置于最前）**：输出核心摘要（≤400 字，1 分钟把握全局），覆盖今日核心驱动逻辑、最关键矛盾、最具价值的相对价值机会或风险（紧扣新券/次新券个券特性）；**不插入任何图表**。
2. **第二层：分段深度解读（严格按序，融入专项框架）**：
   - 第一部分 核心矛盾与阶段判断（≤400 字）：资金锚与短端中枢、牛/熊陡/平判断及驱动端、长端风险溢价、**该券阶段定位**（新券：一级定价→二级上市→流动性爬升→成为活跃券；次新券：流动性峰值已过→利差走阔→配置盘承接）、今日核心驱动一句话。
   - 第二部分 驱动因素的四维拆解（≤400 字）：宏观事件冲击、资金面与短端传导、供需与一级发行（关注新券所在期限段供给脉冲）、交易情绪与微观结构（新券流动性聚拢 / 次新券流动性萎缩；数据缺失须说明并标注推测）。
   - 第三部分 估值与相对价值图谱（**≤200 字，核心差异部分**）：新券看一二级价差修复与流动性溢价水平、次新券看新老券利差分位与收敛催化剂、曲线相对位置凸点/凹陷。
   - 第四部分 机构行为解码（≤400 字）：边际定价者（新券看一级分销后持仓转移；次新券看交易盘/配置盘切换）、行为趋势（结合近 5 日净买卖）、微观异动（一级套利/上市首日对倒/老券抛售换新）。
   - 第五部分 策略逻辑与观察清单（≤400 字，**不插入图表**）：未来 1-3 个交易日博弈主线与多空推演（逻辑展示，不构成投资建议）、期货替代评估（新券/次新券往往非 CTD，提示基差风险与 beta 调整）、未来 1 周关键微观验证指标与阈值。
3. **第三层：图表决策回填**：重新审视全文，确保符合条件的论点已插入对应 `{图表名称}` 占位符；对重复图表去重。

### 结构化输出格式（JSON）

```json
{
  "title": "核心摘要",
  "abstract": "≤400字摘要正文（不含小标题，不带图表）",
  "sections": [
    {
      "heading": "自行凝练的小标题1",
      "content": "对应分析正文（不含图表占位文本）",
      "tables": ["{图表名称}"]
    }
  ]
}
```

- `sections` 中每个 section 代表一个维度；某维度被跳过则不加入数组。
- `tables` 存放该维度末尾输出的图表占位符（若有，最多 1 个），否则为空数组。
- 小标题须另行凝练，不得与结构标题保持一致；重点文案可用 `** **` 标出。

## 8. MQL 语法约束（严格执行，来自实战验证）

- Block 编号必须从 `#1` 开始且**连续递增**（`#1`、`#2`、`#3`…）。
- `SetReportFilter` 条件用 `==`（不是 `=`），值用双引号，多条件用 `AND` 连接。
- **不支持 `in` 运算符**；多值用 `OR` 链。
- **不支持 `Limit()` / `Top()` / `STRFTIME`**；用 `OutputBlock()` 控制输出。
- `SetReportFilter` 只能用于**加载列**（花括号中文名），不能用于报表返回列；加载列在左侧 `{列名}`，值在右侧。
- `Sort()` 必须放在**所有 `REPORT_FIELD` 声明之后**。
- 路径分隔符用**单个反斜杠** `\`。
- `REPORT_FIELD("中文列名")` 使用完整中文列名（含括号），例如 `REPORT_FIELD("估价修正久期（中债）")`。
- 输出列名以中文为准；不使用未经验证的英文列名。

5. **重点加粗**：`<strong>` 标签，同一自然段不超过 3 处。
6. **字数**：正文分析全篇 ≥800 字。
7. **摘要**：不插入图表；第五部分（策略逻辑）不插入图表。
8. **数据表格**：至少包含 1 张 `<table class="data-table">`（如新券微观结构表、发行信息表、曲线形态利差表）。
9. **输出**：完整 HTML 文件（含 DOCTYPE/html/head/body），单文件内联 CSS/JS，无外部依赖（除 ECharts CDN）。

### 输出纪律（语言与格式）

- 全程中文，术语规范。
- **禁止**输出词汇：`买入`、`卖出`、`持有`、`必定`、`稳赚`；避免极端看空措辞（`看空中国`、`做空中国`、`崩盘`、`危机`、`衰退`）；对收益率上行、债市调整使用 `回调`、`盘整`、`区间震荡`、`中枢上移`、`再定价` 等中性化、技术化措辞。
- 使用 `可能`、`需关注`、`若……则`、`复盘显示`、`或` 等概率化、条件化表达。
- 不暴露底层原始接口字段名（如 `DIFF`、`TURNOVER`、`CLOSE_YIELD` 等），统一用中文语义。
- 数据缺失的指标：省略该节或明确标注"依据不足"，**不得编造数据或结论**。
- 报告定位为专业研究参考，不构成投资建议，含免责声明。

## 11. 已知问题与规避

1. MQL 报表路径必须经 `Search_Context` 校验，禁止臆造（臆造会触发 422）。
2. `SetReportFilter` 误用 `=` 会静默失败——必须用 `==`；左侧必须是加载列（花括号中文名），不能是返回列。
3. `in` / `Limit()` / `Top()` / `STRFTIME` 均不支持——用 `OR` 链 / `OutputBlock()` / 客户端过滤替代。
4. Block 编号必须从 `#1` 起连续，跳号会导致脚本报错。
5. 新券发行信息 Block（#10）路径若无法获取，对应发行信息表整体省略，不编造发行数据。
6. 画图数据点过多时采样至 25-30 点；新券上市初期收益率序列短时缩短区间或以活跃券替代并标注。
7. 新老券利差 MQL 不直接返回——取新券与活跃券 `收盘收益率` 后逐日计算差值生成利差序列。
8. 中文目录名在磁盘上可能被误存为乱码，技能标识以 frontmatter `name` 为准；工作区文件使用 ASCII 命名中间产物。
9. `RPT_CUSTOM_SCREEN_SPDETE` / `_HIS` 重名区分：按时间窗口选对表（现价 vs 历史）。
10. 机构分歧指数为 -50~50 区间，超出视为数据异常需复核；`0→50` 买增，`0→-50` 卖增。
11. 外部环境图（美债/美指）更新慢于利率表，需时间对齐。
12. 新券/次新券往往不是国债期货 CTD：期货替代评估必须提示基差风险与久期 beta 调整。

## 13. 操作流程（端到端）

1. 解析用户输入的新券标的（代码/简称），确认单标的；若为活跃券/可转债，提示改用对应技能。
2. 校验 MQL 路径：`Get_MQL_Reference` → `Search_Context`（关键词含 RPT 接口名或指标中文名）确认各 Block 路径与可用列名；不臆造。
3. `Execute_MQL` 采集 9 类市场快照数据（Block #1-#10，可拆多次执行，中间产物存工作临时目录）。
4. `Execute_MQL` 采集画图数据（Block #11-#14，近一年区间，对应 ≤5 张图）。
5. 调用妙想搜索接口（query="新发利率债市场讨论"，窗口 T-30~T）获取市场讨论并拼接；不可用时退化为 `Search_Business_Knowledge`。
6. 组装"三明治" Prompt（§6，含新券/次新券专项框架），按 §7 参数生成 JSON 解读。
7. 校验 JSON：摘要 ≤400 字、5 节结构、图表占位符规则、正文 ≥800 字（对照 §12 清单）。
8. 渲染 HTML：标题、meta（秒级时间）、摘要框、5 节正文（四件套 + IIFE ECharts 图）、数据表格、免责声明。
9. 交付：输出 HTML 文件绝对路径，附 `computer://` 链接，2-3 句中文总结。

## 超时与重复调用

本 skill 为提示词型流程（无可执行脚本），调用 MQL / RAG 等 MCP 工具时须遵循以下限制：单个工具调用失败后最多退避重试 2 次（退避等待 30s / 90s）；单次调用最长等待 1200 秒，超过该时长即判定为超时失败。模型不得因失败重复调用同一 `query`，同一 `query` 累计调用不超过 2 次。若调用超时被中断或返回失败，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的重试。
