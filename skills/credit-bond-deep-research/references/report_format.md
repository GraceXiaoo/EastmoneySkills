# 报告格式规范（信用债skill）

> 本文件由 `SKILL.md` 按需引用。**仅在准备生成报告时读取**（取数阶段无需加载）。
> 页面骨架 / CSS / 图表脚本的完整模板见 `references/html_report_template.md`。

## 一、输出方式

**默认输出 HTML 格式**（内嵌 ECharts 离线库的单文件，可离线打开/分享/双击预览）；仅当用户明确要求"Markdown/MD"时输出 Markdown。

- **HTML（默认）**：生成完整独立 HTML 文件，写盘后用结果呈现工具（present_files）打开预览。
- **Markdown（用户要求时）**：直接输出完整 Markdown 文本，结构遵循下方规范。
- **HTML 生成方式**：优先**复用 skill 目录内已有 HTML 报告的内嵌离线 ECharts 库**（从旧报告 `<script>...</script>` 中提取 ~1MB 的 echarts 压缩代码，避免联网加载），重建页面骨架与图表 `<script>`；也可用 CDN 引入 `echarts.min.js`（联网环境）。

## 二、HTML 报告格式规范（默认）

完整 HTML 必须包含以下部分（CSS 骨架、head 结构、ECharts 初始化方式、resize 处理详见 `references/html_report_template.md`，可直接套用）：

1. **`<head>`**：`lang="zh-CN"`、UTF-8 编码、viewport、标题 `<title>{债券名称}（{债券代码}）信用债研究</title>`、内嵌 CSS、内嵌 ECharts 库 `<script>`。
2. **页头 `.head`**：深蓝渐变背景（`linear-gradient(135deg,#10316b,#1e4f9e)`），标签胶囊（如 城投债/科创债/绿色债/存续中）、债券名称 H1、生成时间+数据截至行（**数据截至行注明"Choice 数据中心"**，如"生成时间：{时间} · 数据截至：{日期} · 数据来源：Choice 数据中心"）。**头部 meta 是报告来源标注的位置之一。**
3. **摘要 `.summary`**：左侧蓝色边框卡片，150-250 字摘要。
4. **KPI 卡片 `.kpis`**：4 个关键指标卡（如 债券余额/票面利率/最新估价收益率/剩余期限；到期券可替换为 持有期年化回报率/最终估价全价 等）。
5. **章节 `.sec`**：每个章节 = `h2 二次总结标题 + 正文段落 + 数据表格(可选) + 图表容器 div.chart + 图表说明 .chart-note`。
6. **图表**：`<div class="chart" id="ch{n}"></div>`，底部统一 `<script>` 块中 `echarts.init` + `setOption`，并添加 `window.addEventListener('resize', ...)` 统一重绘。
7. **免责声明 `.disc`**：浅橙底色虚线边框卡片，内容见下方免责声明模板。
8. 配色沿用历史报告金融风格：主蓝 `#10316b`、强调橙 `#FF9044`、主图表红 `#E6432D`；涨红跌绿（中国市场约定）。

## 三、建议报告段落结构（按标签差异化）

结合各页面需求文档的篇章结构，存续/到期通用段落组织如下（**段落标题需二次总结，不得照搬栏目名**）：

- **城投债**：
  1. **平台层级与政府亲疏度**：城投平台基本资料表（公司名称、行政级别、所属地区、实际控制人、实际控制人控股穿透比例、是否市场化声明）+ 存续城投债（发行人全称、城投地位、主体/债项评级、银行授信总额、未使用额度）。
  2. **估值合理性及投资风险评价**：估价收益率及信用利差走势（图一 信用利差 BP 折线；图二 估价收益率 % 折线）。
  3. **债务结构与偿债能力**（若有可用字段）：债券余额、发行规模、剩余期限。
  4. **区域信用与化债环境**（若区域财政数据可取）：所属地区财政数据、化债进度（注意硬卡点降级方案）。
- **银行金融机构债**：
  1. **发行人画像**：发行人名称、是否系统重要银行、是否 TLAC 债。
  2. **盈利能力与资产质量**：不良贷款率、拨备覆盖率、核心一级资本充足率、净息差、ROE、总资产。
  3. **存贷结构与负债端**（若有）：存款总额、贷款总额。
  4. **估值与利差**：估值收益率、最新与国开利差。
- **非银金融机构债**：
  1. **发行人画像**：发行人名称、实际控制人、实际控制人类型、主体/债项评级。
  2. **估值与利差**：估值收益率、剩余期限、最新与国开利差。
- **科创债**：
  1. **科创属性**：科创领域、科创称号、专利数量。
  2. **融资与估值**：发行规模、票面利率、估值收益率、可比科创债利差。
- **绿色债**：
  1. **绿债认证**：绿债口径、绿债等级、绿色债券认证机构、募投领域、挂钩目标、是否符合中欧《共同分类目录》。
  2. **环境效益**：绿债环境效益。
  3. **估值与利差**：估值收益率、可比绿色债利差。
- **到期券通用复盘段落**：一级发行（发行规模/票面利率/发行日期）、存续期表现（上市首日收益率、存续期最高/最低收益率）、最终兑付（实际兑付情况/违约类型、实际到期日、最终估价全价、持有期年化回报率）。

每只债券 3-6 张图，**图表下方统一标注来源**：图注一行灰色说明文字，**必须包含"数据来源：Choice"**。

## 五、各部分要求（HTML 与 Markdown 通用）

- **标题**：格式为 `<债券名称(债券代码)信用债研究>`。
- **生成时间**：精确到时分秒，格式 `YYYY年MM月DD日 HH时mm分ss秒`。
- **摘要**：开头陈列，约 150-250 字，概括债券画像、核心结论、关键数据与关注点。
- **段落**：每个段落 = `<段落标题 + 可视化图表 + 段落正文>`。
  - **段落标题需根据段落内容进行二次总结**，提炼核心观点，不得照搬"基本条款""财务分析"等原始栏目名。
  - 段落重点内容可适当用 `**加粗**`（HTML 中用 `<b>`/`<strong>`），同一自然段加粗不超过 3 处。
  - 图表要贴合段落内容且美观，类型可选折线/柱状/雷达/仪表盘/饼图等。
  - 每只债券建议 3-6 张图表，**图表下方统一标注来源**：图注一行灰色说明文字，**必须包含"数据来源：Choice"**（如"图{n}：{图表说明} · 数据来源：Choice"）。
- **来源标注纪律（强制）**：**正文段落内不出现"（Choice）"等来源括注**——来源只在头部 meta（数据截至行）、图表图注（`数据来源：Choice`）与页脚免责声明三处体现；报告末尾**不加"来源与说明"章节**。
- **结尾**：仅保留免责声明（一行："本报告数据来源于 Choice 数据中心，仅供参考，不构成投资建议"）。
- **字数**：不含图表字符数，正文分析字数至少 800 字以上。
- **格式**：默认 HTML，用户要求时 Markdown。

## 六、措辞纪律（重要）

- 措辞专业严谨，尽可能规避极端观点。
- **在中国市场语境下，看空/唱空属于高度敏感表达，严禁出现。**不使用"崩跌""暴雷""必然违约""资不抵债"等极端或唱空词汇。
- 使用"可能""需关注""若……则""或""综合来看""边际变化"等概率化、条件化、中性表达。
- 禁止"买入""卖出""持有""必定""稳赚"等操作指令或绝对化表达。
- 区分事实、公告披露与市场观点；**某维度无 MQL 数据时省略该维度表述，不写"暂无数据""数据缺失"等缺口说明，不引用其他来源补齐**。
- 不编造缺失数值，不用模型常识替代接口数据。

## 七、免责声明模板

```
## 免责声明

本报告数据来源于 Choice 数据中心，仅供参考，不构成投资建议。
```

> **备注**：报告末尾**不加"来源与说明"章节**；页脚仅保留免责声明一行。报告中数据来源只在头部 meta（数据截至行"Choice 数据中心"）、图表图注（`数据来源：Choice`）与页脚免责声明三处体现，正文段落内不出现"（Choice）"等来源括注。

## 八、ECharts 图表规范

每个图表必须包含：

- 图表标题（`title.text`）。
- **HTML 格式**：`echarts.init(document.getElementById('ch{n}')).setOption({...})`，可直接嵌入页面底部统一 `<script>` 块。
- **Markdown 格式**：可直接复用的 JS 代码块，`option` 为合法 JavaScript 对象。
- 涨用红色、跌用绿色（中国市场配色约定），颜色、标签、单位服务于金融报告阅读，不过度装饰。
- 数据不足的图表直接不输出。

JS 代码示例格式（以"存续期收益率走势"为例）：

```js
const option = {
  title: { text: '存续期收益率走势', left: 'center' },
  tooltip: { trigger: 'axis' },
  grid: { left: 56, right: 24, top: 64, bottom: 48 },
  xAxis: { type: 'category', data: ['上市首日', '存续期最低', '存续期最高', '最新'] },
  yAxis: { type: 'value', name: '%' },
  series: [{ type: 'line', smooth: true, data: [2.85, 2.10, 3.42, 2.66], itemStyle: { color: '#E6432D' } }]
};
```

## 九、数值与格式约定

- 日期统一 `YYYY-MM-DD`；生成时间含时分秒。
- 金额保留 2 位小数；比例/利率/收益率保留 2 位小数；价格保留 2 位小数。
- 亿元/万元换算注意接口原始单位（详见各报表字段说明，必要时元÷100000000 转亿元）。
- 负值（负收益率、负增速、负 ROE）如实展示，不自动转正。
- 区间字段保持接口原格式。

## 十、质量检查清单

输出前必须自检：

1. 是否已通过债券标签报表逐只判定 6 个标签与是否存续。
2. 是否按标签数量正确路由（0/1/≥2）并选择对应需求文档；是否将纯地方政府债正确引导至【地方债skill】。
3. 是否按存续/到期正确分流取数口径。
4. 是否跳过所有已知硬卡点报表与规避字段，未做无效重试。
5. 是否按需补充了 RAG 新闻/公告材料。
6. 是否先输出摘要，再输出分段分析。
7. 每个段落是否包含二次总结的段落标题、可视化图表与正文。
8. 正文分析字数是否达到 800 字以上（不含图表）。
9. 措辞是否专业严谨、无唱空/极端/买卖指令表述。
10. **默认输出是否为完整 HTML 文件**（含 head/CSS/内嵌 ECharts/图表脚本/resize/免责声明），是否生成在 skill 目录并已打开预览；用户要求 Markdown 时是否输出完整 Markdown 并包含生成时间（精确到秒）与免责声明。
11. 是否未泄露任何 API Key、密钥、内部 token 或敏感配置。
12. **报告中所有数据与对应分析、文字是否均来源于 Choice 数据中心并经 MQL 取数**（无模型常识/外部网页/新闻数值替代）。
13. **无数据维度是否已整体省略**（不写缺口说明、不引用其他来源补齐、不输出空图表）。
14. **来源标注位置是否符合纪律**：正文段落内无"（Choice）"等来源括注；来源只在头部 meta（数据截至行注明"Choice 数据中心"）、图表图注（`数据来源：Choice`）与页脚免责声明三处体现。
15. **报告末尾无"来源与说明"章节**；页脚免责声明确认无误。
